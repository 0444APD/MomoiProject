# 직접 확인할 것 (Momoi Project) — 순서대로

코드·오프라인 테스트로는 확인한 상태이고, Unity 화면·마우스·소리·빌드로만 알 수 있는 것을 **위에서 아래 순서대로** 적었다. 단계마다 **할 일 → 보이면 정상**이다. 이상하면 단계 번호와 함께 알려 주면 된다. 확인된 줄은 지운다.

> 2026-10-04: 이 개발 프로젝트의 테스트 요소(Assets/Code·DB 데이터·생성 코드·테스트 씬·ProjectSettings/MomoiProject·GBIBLE_ 심볼·저장 파일)를 `MomoiProjectBackups/2026-10-04 1851 테스트 요소 정리/`로 옮겼다(되돌리는 법은 그 안의 README). 그래서 예전 데이터를 옮기는 확인(옛 키워드 에셋·옛 형식 DB 항목)은 이 목록에서 뺐다.

## 단계 3. DB 화면 — 첫 게임 프로젝트에서

예전에는 확인용 패널·샘플(`check…` 항목·확인용 패널)로 확인했는데, 2026-10-06에 지웠다. 미도리에서는 확인도 프로젝트의 테스트 씬·테스트 명령으로 한다. 단계 3~5의 기능은 코드·오프라인 테스트로는 확인했다. Unity 화면에서는 **AI가 첫 게임 프로젝트를 만들 때** 그 게임의 항목과 테스트 명령으로 확인한다. 그때 AI가 각 줄을 "어느 항목·테스트 명령 → 보이면 정상"으로 다시 적는다.

- **상태 효과**: 지속 방식을 바꾸면 길이·셀 이벤트·가진 쪽 필드 칸이 방식에 맞게 보이고 숨는다. 가진 쪽 필드를 누르면 셀 이벤트·트리거 이벤트의 필드가 나온다. 능력치 보정의 칸은 플랫/퍼센트/독립 곱, 의도 고치기의 방법은 값으로 바꾸기/더하기/곱하기/막기(한글)로 보인다. '주기(초)'·'아이콘'·'화면에 숨김'·`kind`(없음·버프·디버프)·`silencesPassives` 칸이 있다.
- **밸런스 값**: 곡선 방식을 바꾸면 그 방식의 칸만 보인다. '최솟값으로 자르기'·'최댓값으로 자르기'를 켜야 그 값 칸이 보인다.
- **가중치 표**: 항목 칸에서 DB 항목(모든 종류)을 고른다. 무게를 모두 0으로 하면 검증 오류가 난다. 줄의 **줄 종류**를 `플레이어 데이터 목록`으로 바꾸면 항목 칸이 숨고 플레이어 데이터·필드(목록) 칸이 보인다. **뺄 목록** 칸, '무게를 밸런스 값에서'를 고르면 '단계(플레이어 데이터)'·'단계 필드' 칸.
- **패시브**: 가진 목록·발동·가진 쪽 필드·결과·아이콘 칸, 발동이 비면 검증 오류. 기믹 칸(이름표는 변수 이름, 마우스를 올리면 한글 설명): `matchField`·`matchVia`·`perElement`·`levelField`·`modifiers`(줄마다 attribute·kind·value·perLevel·byLevel·target)·`modifierTarget`·`modifierWhen`·`stacking`·`rules`·`pulse`·`pulseByLevel`. `rules` 줄의 트리거를 비우면 검증 오류, 발동·보정·주기를 모두 비워도 오류 없음(스위치 패시브), 결과만 있고 트리거·주기가 없으면 경고. 가진 쪽 필드를 누르면 발동 트리거의 이벤트·의도 필드가 나온다. `modifierTarget`에 `units[]`처럼 `[]`가 든 경로를 넣을 수 있다.
- **설정**: 종류를 바꾸면 칸이 바뀐다. 적용 대상과 종류가 안 맞으면 검증 오류가 DB에 보이는 이름으로 나온다.
- **개발 명령**: '선택 요구' Block(후보·최소·최대·고른 것에 효과·고른 뒤 결과), '가중치 표에서 고르기' Block과 요약("…에서 3개 보여 0~1개 고르기 … 넣기").
- **시작 파일 › Bootstrap**: 판 저장 칸에 'N초마다 저장'·'이벤트를 받을 때 저장'이 있고, 고르면 '저장 간격(초)'·'판 저장 이벤트' 칸이 그때만 보인다. 새로 만든 DB의 Undo 보관 수가 200이다.
- **CSV**(DB 목록 맨 위 폴더 줄의 CSV 버튼): 목록 필드는 `entries[0].item`·`entries[0].weight` … 칸으로 나간다. 시트에서 줄을 하나 더해 가져오면 "1개 고침"과 함께 줄이 늘고, 마지막 줄의 칸을 모두 비우고 가져오면 그 줄이 사라진다. enum은 코드 이름(Linear)으로 나가고, 가져올 때는 DB에 보이는 이름도 읽힌다.
- **Block 메뉴**(구조 편집을 열고 볼 때 — 단계 7): 조건 '확률'·'자리 검사'·'사용자 필드 검사'·'상태 효과 검사', 대상 '자리로 고르기'·'상태 효과로 거르기'·'플레이어 데이터 목록'·'이벤트의 개체'·'조건으로 거르기'·'무작위 n개'·'정렬해서 n개', 효과 '필드 바꾸기'·'상태 효과 줄이기', 결과 '빌려 쓰기'·'비용 내기'·'가중치 표에서 주기'·'가중치 표에서 고르기'·'선택 요구', 가로채기의 의도 '상태 효과 걸기'·'확률'·'사용'·'비용 지불'·'효과 배율'. '자리 검사'의 자리에 '같은 열 맨 앞'·'같은 열에 혼자', '자리로 고르기'의 방향에 '같은 열 맨 앞'·'같은 열 맨 뒤'와 기준 '없음'(기준 없음 + 방향 오른쪽이면 검증 오류). '의도 고치기'·'필드 바꾸기' 값 칸 설명에 틀 `{user:경로}`·`{event:경로}`·`{data:키.경로}`·`{count:키.경로}`.

## 단계 4. 플레이 — 첫 게임 프로젝트의 테스트 씬에서

테스트 씬(매뉴얼 38장)을 플레이하고, 테스트 패널(F1)의 테스트 명령과 모니터(메뉴 `MomoiProject › 모니터`)로 본다. 그 게임에 있는 기능만 확인한다.

- **상태 효과**: 걸면 중첩·남은 횟수가 보이고, 턴(또는 주기)마다 효과가 난 뒤 끝나면 사라진다. 다시 걸면 중첩이 늘고 남은 횟수가 처음으로 돌아간다. 능력치 보정(+20% 등)이 걸린 동안만 보이고, 가로채기로 받는 피해가 줄어든다.
- **예약**: n초 뒤에 실행되고 타임라인에 '예약 실행'이 남는다.
- **미리보기**: 행동 결과만 보여 주고 타임라인·Undo에 아무것도 남지 않는다. 비용이 모자라면 "할 수 있음: 아니오 — …이(가) 모자랍니다(1 / 2)."와 플레이어용 실패 글.
- **Undo**: 누를 때마다 바로 앞 행동이 돌아간다(상태 효과·값 함께).
- **선택 대기**: 고르기를 요구하면 Busy가 '예'가 되고 모니터 › 명령 탭 맨 위에 선택 대기 패널(후보 버튼 ✓ → 답하기)이 뜬다. 답하면 타임라인에 "선택: …", Undo하면 같은 후보로 다시 기다린다.
- **가중치 표**: 뽑기는 서로 다른 n개(꽝이 나오면 적게), 고르기는 고른 것이 목록에 들어가고 다음 후보에서 빠진다(뺄 목록). Undo 후 다시 하면 같은 결과다.
- **밸런스 값**: 플레이 중에 DB의 값·증가량을 고치면(저장 전이라도) 0.5초 안에 숫자가 바뀐다.
- **연출 대기열**: 연출이 하나씩 끝나고 그동안 Busy. 속도를 올리면 빨라지고 Skip은 남은 것을 빠르게 끝낸다. done을 부르지 않는 연출은 30초 뒤 콘솔 경고와 함께 넘어간다.
- **슬롯**: 슬롯을 바꾸면 새 세션으로 시작하고 `%USERPROFILE%\AppData\LocalLow\…\MomoiProject\slots\<슬롯>\`에 저장이 생긴다. 하이어라키의 `[MomoiProject]`는 하나뿐. 지금 슬롯을 자기 자신으로 복사하면 막힌다.
- **설정**: 음량을 바꾸면 소리 크기가, 언어를 바꾸면 다국어 글이 바뀐다. 전체 화면은 에디터에서 바뀌지 않는 것이 정상(빌드에서만). 플레이를 멈췄다 다시 해도 값이 남는다(`MomoiProject\settings.json`).
- **월드 상태**: 값을 바꾸면 모니터에 보이고 Undo로 돌아간다. 모니터 › 명령 › 저장의 '판 저장' → '판 불러오기'로 이어진다.
- **기믹**(그 게임에 있는 것만): 놓인 순서(자리)에 따라 점수가 달라진다, 빌려 쓰기는 옆 조각을 한 번 더 낸다, 레벨별 보정은 레벨마다 정한 값(정한 레벨부터 그대로), 가로채기로 걸릴 상태 효과를 다른 것으로 바꾼다, 확률을 2배로 올리면 대략 2배 나온다, Undo 후 다시 굴리면 같은 결과.
- **화면**(UI Toolkit, 매뉴얼 35장)
  - binding-path로 연결한 값이 코드 없이 바뀌고, 목록 칸(예: 유닛 이름 + 체력 막대)이 따라 줄어든다. Undo로 화면도 돌아간다.
  - 할 수 없는 행동을 누르면 화면 아래에 실패 알림이 2.5초 뜬다. 연출 중(Busy)에는 버튼이 아무 일도 하지 않는다.
  - 기본 고르기 창: 어두운 덮개 + 후보 버튼, 누르면 바로 답하고 닫힌다. 떠 있는 동안 Esc로 닫히지 않는다.
  - 설정 화면(DB › 설정의 항목이 분류마다 토글·슬라이더(%)·드롭다운, '기본값으로' → 확인 팝업), 슬롯 화면(요약·플레이 시간, 지우기는 확인), 일시정지 메뉴(시간 멈춤, 그 위에 설정 → Esc가 설정부터 닫음), 확인 팝업(Esc = 아니오).
  - Window › UI Toolkit › Debugger에서 `[MomoiProject] 화면` 패널을 고르면 층(`momoi-layer-base`·`-window`·`-popup`·`-toast`) 아래에 열린 화면 ID가 보인다. 메뉴 `MomoiProject › 화면 › 화면 준비`를 다시 누르면 "이미 되어 있습니다".
  - DB › 화면 설정 › 글꼴이 비어 있으면 한글이 □로 보일 수 있다. 한글 TTF를 넣으면 모든 화면(기본 화면 포함)에 쓰인다.

## 단계 5. 화면 컴포넌트·입력(그 게임이 쓸 때)

- **데이터 연결**: UI(Text 또는 TMP) + 컴포넌트 '데이터 연결'(키·필드·글자 틀) → 그 값이 바뀌면 글자가 바뀐다(연출이 끝난 뒤).
- **월드 상태 연결**: 컴포넌트 '월드 상태 연결'(이름, 맞을 때 켤 것·끌 것) → 월드 상태 값에 따라 오브젝트가 켜지고 꺼진다.
- **입력(키 바꾸기)**: 게임 코드에서 `GameInput.Use(…inputactions)`를 부르면 확인한다(Rebind로 바꾼 키가 다음 실행에도 남는지, 같은 맵의 다른 키와 겹치면 Conflict, Esc 취소, ResetBindings).
- **씬 흐름**: 판 데이터에 씬 이름 필드가 있는 게임에서 확인한다(Build Settings에 없는 씬이면 타임라인 경고).

## 단계 6. 예전부터 남은 확인

**에디터 기본**

(예전 PlayMode 샘플 테스트는 샘플과 함께 지웠다.)
- Mirror: 플레이 중 플레이어 데이터(클래스)의 필드를 게임 코드에서 바꾸면 타임라인에 `경로  옛 값 → 새 값`으로 남고 Undo로 돌아간다. "예전 방식(리플렉션)으로 비교합니다" 경고가 뜨면 그 클래스에 [Serializable]이 빠진 것. "읽기 코드가 없어 리플렉션으로 읽습니다"도 같다.
- 공유 객체: 플레이어 데이터 안에서 같은 객체를 두 곳에 넣고(장착 칸 = 인벤토리 안의 아이템) 고치면 기록이 한 번만 남고 Undo가 맞다.

**DB 목록·편집**
- 목록: 폴더 줄 클릭으로 접기·펼치기, 항목 클릭으로 열기, 이름순(폴더 먼저). 항목·폴더를 다른 폴더 위에 끌어 놓으면 옮겨지고(분홍으로 밝아짐, 자기 안쪽에는 안 놓임), 폴더 만들기·이름 바꾸기·지우기 → Ctrl+S, 적용 대기 목록 표시, 그룹을 새 창(↗)으로, 창 탭 막대 숨기기 모양.
- 클래스·이벤트 탭: 만들기·끌어 옮기기가 없고(읽기 전용), 클래스를 누르면 필드 이름·형식·키워드 그룹·[Hide]·[ShowIf](보기만), `→ 클래스` 이동, `cs 열기`.
- 키워드 탭(읽기 전용): 그룹 = 폴더, 키워드 = 줄, 그룹마다 '연결된 필드'와 `cs 열기`. 코드에서 키워드를 더하고 다시 컴파일하면 그대로 보인다. 키워드 필드의 드롭다운·칩, 없는 값이면 검증 오류. 드롭다운 끝의 '연결 보기(클래스 상세)'.
- 인스턴스: 형식을 고르면 값 칸이 열리고 [Hide]는 안 보이고 [ShowIf]는 조건대로. 기능 필드는 '+ 기능'로 붙고 빼기로 빠진다(구조 편집을 열었을 때). 스프라이트가 있으면 게임 사본에도 같은 스프라이트.
- [BindTo]: Reward 클래스·static 함수에 `[BindTo(id)]`를 붙이면 그 항목의 결과 칸이 잠기고 클래스 이름·cs 열기만 보인다(상태 효과는 '결과' 칸만 잠기고 걸릴 때·끝날 때는 그대로). 같은 ID에 둘 붙이면 검증 경고.
- 트리거·결과 편집: 로그(이벤트 트리거 + 고정 '로그에 기록', 반영할 값 목록이 트리거 이벤트의 필드), 도전과제(이벤트·조건을 AND·OR로, + 결과 추가), 능력(기본 '사용' + AND 사용 조건, 새 칸 '쓸 수 없을 때 글'), 잠금 밖 종류가 목록에 안 보임, 검증 오류(NOT 안 이벤트 등), 딕셔너리 필드 보상 `[키] → [값]`.
- DB › 개발 › 개발 명령: 결과 Block을 넣으면 모니터 › 명령 탭에 버튼, 누르면 "[개발] …"이 남고 Undo. DB › 개발 › 저장 변환: 종류에 따라 칸이 보이고 숨는다, 검증 오류.

**판 저장·Bootstrap 동작**(시작 설정 뒤 게임 코드가 조금 생기면)
- '행동마다 저장': 행동 뒤 `run.json` 갱신. 판 끝 이벤트를 쏘면 `run.json`이 지워지고 `profile.json`이 바로 써지고, 새 판 행동 뒤 다시 저장. Undo 끊는 이벤트·시작할 때 이어 하기·프로필도 행동마다 저장.
- `SubscribeAfterAction`으로 받은 연출이 실패한 행동에서는 안 뜨고, `GameView.Redraw`로 그린 화면이 값·언어가 바뀔 때 한 번씩 다시 그려진다.

**처음 상태로 되돌리기**(단계 0에서 기록이 생겼으므로 이제 시험할 수 있다 — 되돌리면 그 사이 만든 것이 백업으로 옮겨진다)
- 시작 설정·스크립트·씬·설정을 바꾼 뒤 `MomoiProject › 처음 상태로 되돌리기…`: 확인 창의 파일 수, 되돌린 뒤 Unity가 다시 열리고 시작 설정 창이 다시 뜨는지, 바꾼 Player Settings가 돌아왔는지, `MomoiProjectBackups/<시각>/`에 옮겨진 파일. 백업을 덮어써 되돌리기 전으로 돌아오는지.

**빌드(PC, IL2CPP)**
- 위 기능(이벤트 기록 문장·Mirror·저장)이 빌드에서도 돈다(생성 코드가 구조체를 상자 안에서 고치고 enum을 상자에서 꺼내는 부분). 출시 빌드에서 Steam '다시 시작'(exe를 바로 켜면 Steam으로 다시 켜짐), 전체 화면·해상도 설정 적용.

## 단계 7. 미도리 — 관리·테스트 도구(2026-10-05)

GBible이 '개발자가 만드는 도구'에서 'AI가 만든 것을 개발자가 읽고·바꾸고·테스트하는 도구'로 바뀌었다(구버전 백업 = `D:\Unity\Projects\Momoi`). 사람용 안내는 `Documentation~/Guide/`(운영 가이드).

- **구조 잠금**(DB 창)
  - 능력·패시브·상태 효과·도전과제 탭: 머리의 **+ 새로 만들기**가 없고, 캡션 끝에 "값을 바꿉니다(추가·삭제·구조는 AI에게)". 상세 창 아래 **삭제** 없음, 제목(ID)을 눌러도 고칠 수 없음.

# 직접 확인할 것 (Momoi Project) — 순서대로

코드·오프라인 테스트로는 확인한 상태이고, Unity 화면·마우스·소리·빌드로만 알 수 있는 것을 **위에서 아래 순서대로** 적었다. 단계마다 **할 일 → 보이면 정상**이다. 이상하면 단계 번호와 함께 알려 주면 된다. 확인된 줄은 지운다.

> 2026-10-04: 이 개발 프로젝트의 테스트 요소(Assets/Code·DB 데이터·생성 코드·테스트 씬·ProjectSettings/MomoiProject·GBIBLE_ 심볼·저장 파일)를 `MomoiProjectBackups/2026-10-04 1851 테스트 요소 정리/`로 옮겼다(되돌리는 법은 그 안의 README). 그래서 예전 데이터를 옮기는 확인(옛 키워드 에셋·옛 형식 DB 항목)은 이 목록에서 뺐다.

---

## 단계 0. Unity 열기 — 저절로 일어나는 것

할 일: 프로젝트를 연다(처음에는 패키지를 받느라 오래 걸린다).

- Steamworks.NET(2025.164.1)을 받고 콘솔에 컴파일 오류가 없다. 프로젝트 폴더에 `steam_appid.txt`(480)가 생긴다.
- `Unity.GBible.CodeGen`(Mirror 비교 코드 생성) 오류·경고가 없다(콘솔에 "Mirror 비교 코드 생성 실패"가 없어야 함).
- 콘솔에 "처음 상태를 기록했습니다"가 나오고 프로젝트 폴더에 `MomoiProjectBaseline/`이 생긴다(지금이 '깨끗한 처음 상태'로 기록된다).
- 시작 설정 창이 저절로 한 번 열린다.

## 단계 1. 시작 설정과 DB › 시작 파일

할 일: 시작 설정 창에서 이름·언어 등을 고르고 **적용**.

- `Assets/Code/Rules·Client·Editor·Tests`와 asmdef, `Client/Bootstrap.cs`, `Rules/PlayerData.cs`, DB › 플레이어 데이터 `run`·`profile`이 생긴다. 다시 컴파일된 뒤 `GameIds.cs`에 `Game.Data().Run`·`Profile`이 생긴다(콘솔에 "식별자 코드를 만들었습니다").
- DB 창(메뉴 `MomoiProject › DB`) 사이드바 맨 위 **시작 파일 › Bootstrap**: 칸을 고치면 바로 저장된다(Undo 방식에 따라 칸이 바뀜, 고급 접기). 새 칸 **고정 틱(초당 틱 수)**·**씬 흐름(플레이어 데이터·필드·빈 값일 때 씬)**이 보이고 값이 남는다(창을 닫았다 열어도). RunState·Profile을 누르면 cs가 열린다.
- 시드 고정을 켜면 플레이할 때 모니터 머리의 시드가 그 값이다. `Bootstrap.cs`의 Configure에서 같은 값을 바꾸면 타임라인에 "코드(Configuring)가 … 바꿨습니다"가 남는다.

## 단계 2. 선택 기능 켜기

할 일: DB 사이드바에서 **확인용 패널·샘플**, **입력(키 바꾸기)**, **Steam** 그룹의 첫 줄 **기능 활성화**로 켠다(다이얼로그·인벤토리는 단계 6).

- 켤 때마다 Player Settings › Scripting Define Symbols에 `GBIBLE_SAMPLES`·`GBIBLE_INPUT`·`GBIBLE_STEAM`이 들어가고 다시 컴파일된다(오류 없이). 끄면 빠진다.
- Steam을 켜면 DB › 개발 그룹에 **Steam** 탭이 생긴다.

## 단계 3. 확인용 항목 만들기와 DB 화면

할 일: 메뉴 **MomoiProject › DB 추가 › 확인용 항목** → 창에 "…개를 적용 전으로 만들었습니다" → DB에서 항목들에 '새 항목 · 적용 전' 표시 → **Ctrl+S**.

- **DB › 상태 효과**(`checkPoison`·`checkGuard`): 지속 방식을 바꾸면 길이·셀 이벤트·가진 쪽 필드 칸이 방식에 맞게 보이고 숨는다. 가진 쪽 필드(지속 안·걸려 있는 동안)를 누르면 셀 이벤트·트리거 이벤트의 필드가 나온다. 능력치 보정의 칸은 플랫/퍼센트/독립 곱, 의도 고치기의 방법은 값으로 바꾸기/더하기/곱하기/막기(한글)로 보인다.
- **DB › 밸런스 값**(`checkEnemyHp`): 곡선 방식을 바꾸면 그 방식의 칸만 보인다. '최솟값으로 자르기'·'최댓값으로 자르기'를 켜야 그 값 칸이 보인다.
- **DB › 가중치 표**(`checkLoot`): 항목 칸에서 DB 항목(모든 종류)을 고른다. 조건 칸을 편집할 수 있다. 무게를 모두 0으로 하면 검증 오류가 난다.
- **DB › 설정**(그룹 선언, `checkMasterVolume` 등): 종류를 바꾸면 칸이 바뀐다. 적용 대상과 종류가 안 맞으면 검증 오류가 DB에 보이는 이름으로("적용 대상 '전체 음량'에는 종류 '숫자(슬라이더)'만 …") 나온다.
- **DB › 개발 › Steam**: 항목을 하나 만들고 App ID를 고치면 프로젝트 폴더의 `steam_appid.txt`가 따라 바뀐다(시험은 480으로 되돌려 둔다).
- **DB › 개발 명령**(`checkChoice`): 결과에 '선택 요구' Block(후보·최소·최대·고른 것에 효과·고른 뒤 결과)이 보인다.
- 아무 결과 칸의 **+ 결과 추가**: 플레이어 데이터를 줄 수 있는 칸에 '비용 내기'·'가중치 표에서 주기', '대상에게 효과'가 되는 칸에 '선택 요구'가 있다.
- **CSV**(DB 목록 맨 위 폴더 줄의 CSV 버튼):
  - 가중치 표 탭 → CSV로 내보내기 → `entries[0].item`·`entries[0].weight` … 칸이 보인다. 시트에서 무게를 고치고 `entries[4]` 줄을 하나 더해 가져오기 → 결과 창 "1개 고침" → 항목이 적용 전으로 바뀌고 줄이 하나 늘어난다(새 줄의 조건은 비어 있음). 마지막 줄의 칸을 모두 비우고 가져오면 그 줄이 사라진다.
  - 밸런스 값 탭 → 내보내기 → `curve.kind`·`curve.useMax` 같은 칸, enum은 코드 이름(Linear)이다. 가져올 때 DB에 보이는 이름(일정하게(+단계마다))도 읽힌다.
  - 인스턴스 탭 → CSV에 'CheckItem 내보내기…'가 있다.

## 단계 4. 플레이 — 확인용 패널

할 일: 아무 씬에서 **플레이**. 왼쪽 위에 "GBible 확인용 패널"이 뜬다. 모니터(메뉴 `MomoiProject › 모니터`)도 함께 연다.

- **규칙 탭**
  - '적에게 독' → 적 줄에 `checkPoison×1(남음 3)`. '턴 끝'을 누를 때마다 적 체력 −2(중첩만큼), 3번 뒤 사라진다. 두 번 걸면 ×2, 남은 횟수가 3으로 돌아간다.
  - '영웅에게 보호막' → 영웅 공격력 12(+20%). '적이 영웅 때리기(6)'가 3만 깎는다. 2턴 뒤 사라지고 공격력이 10으로 돌아간다.
  - '2초 뒤 적 때리기(예약)' → 2초 뒤 적 체력 −5, 타임라인에 '예약 실행'.
  - 미리보기 줄이 '에너지 2 내고 때리기'를 하면 적 체력이 얼마가 되는지 보여 준다(타임라인·Undo에 아무것도 안 생김). 에너지가 1 이하면 "할 수 있음: 아니오 — 에너지이(가) 모자랍니다(1 / 2).", 버튼을 누르면 '플레이어용 실패: …'.
  - Undo를 누를 때마다 바로 앞 행동이 돌아간다(상태 효과·체력·에너지 함께).
- **선택·뽑기 탭**
  - '고르기 요구' → '기다리는 선택' 줄과 버튼, 위쪽 Busy가 '예'. 모니터 › 명령 탭 맨 위에도 '선택 대기 · 하나 고르세요' 패널(후보 버튼 ✓ → 답하기)이 보인다. 어느 쪽으로 답해도 '고른 것'이 바뀌고 타임라인에 "선택: shield"처럼 남는다. Undo하면 다시 기다린다.
  - 모니터 › 명령 탭의 '선택 요구 시험'(확인용) → 후보 `checkHero`·`checkFoe`(텍스트 표에 이름이 없어 ID로 보임) 중 하나를 고르면 그쪽이 3 깎인다.
  - '전리품 3개 뽑기' → 서로 다른 3개(꽝이 나오면 적게). 확률 줄이 보인다. Undo 후 다시 뽑으면 같은 결과다.
  - 밸런스 값 줄(1층 20 · 2층 25 …). 플레이 중에 DB › 밸런스 값 `checkEnemyHp`의 값·증가량을 고치면(저장 전이라도) 0.5초 안에 숫자가 바뀐다.
- **연출 탭**: '연출 3개 넣기' → '연출 중·Busy'가 '예'가 되고 하나씩(0.8초) 끝난다. 속도 막대를 올리면 빨라지고, Skip은 남은 것을 빠르게 끝낸다. 'done을 부르지 않는 연출'은 30초 뒤 콘솔 경고와 함께 넘어간다.
- **슬롯·설정 탭**
  - '1' 쓰기 → 패널 값이 처음으로(새 세션), `%USERPROFILE%\AppData\LocalLow\DefaultCompany\UnitySystemProject\MomoiProject\slots\1\`에 저장이 생긴다(플레이를 멈추거나 판 저장 때). 다시 기본으로 바꾸면 기본 슬롯 값으로 돌아온다. 하이어라키의 `[MomoiProject]`는 하나뿐이다. '지금 슬롯을 슬롯 2로 복사'는 지금 슬롯이 2면 막힌다는 글이 나온다.
  - 설정: 전체 음량 막대를 움직이면 소리 크기가 바뀐다(소리가 나는 것이 있을 때). 언어를 바꾸면 다국어 글이 바뀐다(텍스트 표가 있을 때). 전체 화면은 에디터에서 바뀌지 않는 것이 정상(빌드에서만). 플레이를 멈췄다 다시 하면 값이 남아 있다(`MomoiProject\settings.json`).
- **월드 탭**: '상자 열기/닫기' → 값이 true/false로, Undo로 돌아간다. 모니터 › 명령 › 저장의 '판 저장' → '판 불러오기'로 이어진다.
- **Steam**(Steam 클라이언트를 켠 채, DB › Steam 항목 480): 콘솔에 경고 없이 붙고, Steam 친구 목록에 Spacewar 플레이 중으로 보인다. Shift+Tab 오버레이를 열면 게임이 멈추고(패널의 연출도 멈춤) 닫으면 이어진다. Steam을 끈 채 플레이하면 "Steam에 붙지 못해 Steam 없이 시작합니다" 경고 하나만 나온다. 도전과제 달성 경고는 480에서 정상이다(그 앱에 도전과제가 없음).

## 단계 5. 화면 컴포넌트·입력(선택, 시간 날 때)

- **데이터 연결**: 씬에 UI(Text 또는 TMP) 하나 + 컴포넌트 '데이터 연결'(키 `checkRun`, 필드 `energy`, 글자 틀 `에너지 {value}`, onText → 글자) → 패널에서 에너지를 쓰면 글자가 바뀐다(연출이 끝난 뒤).
- **월드 상태 연결**: 오브젝트 두 개(열린 상자·닫힌 상자) + 컴포넌트 '월드 상태 연결'(이름 `check.chest`, 맞을 때 켤 것 = 열린 상자, 끌 것 = 닫힌 상자) → 패널의 상자 버튼으로 바뀐다.
- **입력(키 바꾸기)**: 게임 코드에서 `GameInput.Use(Settings/InputSystem_Actions.inputactions)`를 부르는 곳이 생기면 확인한다(Rebind로 바꾼 키가 다음 실행에도 남는지, 같은 맵의 다른 키와 겹치면 Conflict, Esc 취소, ResetBindings). 지금은 확인용 패널에 없다.
- **씬 흐름**: 판 데이터에 씬 이름 필드가 있는 게임을 만들 때 확인한다(Build Settings에 없는 씬이면 타임라인 경고).

## 단계 6. 예전부터 남은 확인

**에디터 기본**
- EditMode 테스트(Window › General › Test Runner): 전체 통과. 특히 `TriggerSlotTests`, `CodexTreeTests`, `ContractTests`, `MirrorTests`(모든 생성 코드가 실행 가능, 생성된 읽기·쓰기로 멤버를 다룸), `SavedIdRenameTests`, 새 테스트(`AttributeInterceptTests`·`StatusScheduleTests`·`ChoiceTests`·`BalanceTableTests`·`WorldStateTests`·`TickPreviewTests`). PlayMode 샘플 테스트 3개는 메뉴 `Tests › 샘플 › 샘플 데이터 만들기` 뒤에.
- 저장 후 멈춤("Hold on") 재현 여부: 클래스를 만들고 필드 2개를 더한 뒤 저장.
- Mirror: 플레이 중 플레이어 데이터(클래스)의 필드를 게임 코드에서 바꾸면 타임라인에 `경로  옛 값 → 새 값`으로 남고 Undo로 돌아간다. "예전 방식(리플렉션)으로 비교합니다" 경고가 뜨면 그 클래스에 [Serializable]이 빠진 것. "읽기 코드가 없어 리플렉션으로 읽습니다"도 같다.
- 공유 객체: 플레이어 데이터 안에서 같은 객체를 두 곳에 넣고(장착 칸 = 인벤토리 안의 아이템) 고치면 기록이 한 번만 남고 Undo가 맞다.

**DB 목록·편집**
- 목록: 폴더 줄 클릭으로 접기·펼치기, 항목 클릭으로 열기, 이름순(폴더 먼저). 항목·폴더를 다른 폴더 위에 끌어 놓으면 옮겨지고(분홍으로 밝아짐, 자기 안쪽에는 안 놓임), 폴더 만들기·이름 바꾸기·지우기 → Ctrl+S, 적용 대기 목록 표시, 그룹을 새 창(↗)으로, 창 탭 막대 숨기기 모양.
- 클래스·이벤트 탭: 만들기·끌어 옮기기가 없고(읽기 전용), 클래스를 누르면 필드 이름·형식·키워드, `→ 클래스` 이동, `cs 열기`. 폴더 이동이 실제 `Assets/Code` 폴더 이동으로 적용된다.
- 키워드 탭: 그룹 = 폴더, 키워드 = 줄. '+ 새 그룹'·'+ 키워드'·'+ 하위 그룹'·이름 바꾸기·✕·그룹 지우기 → Ctrl+S 하면 코드 파일이 고쳐지고 다시 컴파일된 뒤 그대로 보인다. 키워드 필드의 드롭다운·칩, 없는 값이면 검증 오류. 클래스 상세에서 키워드 그룹을 바꾸면 코드에 `[Keyword(typeof(…))]`.
- 인스턴스: 형식을 고르면 값 칸이 열리고 [Hide]는 안 보이고 [ShowIf]는 조건대로. 기능 필드는 '+ 기능'로 붙고 빼기로 빠진다. 클래스 상세 '인스턴스에서 숨김 [Hide]' → 저장하면 코드에 [Hide]. 스프라이트가 있으면 게임 사본에도 같은 스프라이트.
- [BindTo]: Reward 클래스·static 함수에 `[BindTo(id)]`를 붙이면 그 항목의 결과 칸이 잠기고 클래스 이름·cs 열기만 보인다(상태 효과는 '결과' 칸만 잠기고 걸릴 때·끝날 때는 그대로). 같은 ID에 둘 붙이면 검증 경고.
- 트리거·결과 편집: 로그(이벤트 트리거 + 고정 '로그에 기록', 반영할 값 목록이 트리거 이벤트의 필드), 도전과제(이벤트·조건을 AND·OR로, + 결과 추가), 능력(기본 '사용' + AND 사용 조건, 새 칸 '쓸 수 없을 때 글'), 잠금 밖 종류가 목록에 안 보임, 검증 오류(NOT 안 이벤트 등), 딕셔너리 필드 보상 `[키] → [값]`.
- DB › 개발 › 개발 명령: 결과 Block을 넣으면 모니터 › 명령 탭에 버튼, 누르면 "[개발] …"이 남고 Undo. DB › 개발 › 저장 변환: 종류에 따라 칸이 보이고 숨는다, 검증 오류.

**판 저장·Bootstrap 동작**(시작 설정 뒤 게임 코드가 조금 생기면)
- '행동마다 저장': 행동 뒤 `run.json` 갱신. 판 끝 이벤트를 쏘면 `run.json`이 지워지고 `profile.json`이 바로 써지고, 새 판 행동 뒤 다시 저장. Undo 끊는 이벤트·시작할 때 이어 하기·프로필도 행동마다 저장.
- `SubscribeAfterAction`으로 받은 연출이 실패한 행동에서는 안 뜨고, `GameView.Redraw`로 그린 화면이 값·언어가 바뀔 때 한 번씩 다시 그려진다.

**처음 상태로 되돌리기**(단계 0에서 기록이 생겼으므로 이제 시험할 수 있다 — 되돌리면 그 사이 만든 것이 백업으로 옮겨진다)
- 시작 설정·스크립트·씬·설정을 바꾼 뒤 `MomoiProject › 처음 상태로 되돌리기…`: 확인 창의 파일 수, 되돌린 뒤 Unity가 다시 열리고 시작 설정 창이 다시 뜨는지, 바꾼 Player Settings가 돌아왔는지, `MomoiProjectBackups/<시각>/`에 옮겨진 파일. 백업을 덮어써 되돌리기 전으로 돌아오는지.

**빌드(PC, IL2CPP)**
- 위 기능(이벤트 기록 문장·Mirror·저장)이 빌드에서도 돈다(생성 코드가 구조체를 상자 안에서 고치고 enum을 상자에서 꺼내는 부분). 출시 빌드에서 Steam '다시 시작'(exe를 바로 켜면 Steam으로 다시 켜짐), 전체 화면·해상도 설정 적용.

**다이얼로그·인벤토리·오디오**(선택 기능 다이얼로그·인벤토리를 켠 뒤)
- 다이얼로그 화면: 글상자 블러(`backdrop-filter`가 게임 화면까지 흐리게 하는지), 모션, 로그 창, 장소 표시, 창 모드 스탠딩, 이미지 창, 한글 폰트(`DialogueUI.font`에 TTF), 클릭·키 입력. 그래프 창 마우스 조작(범위 선택, 그룹 상자 크기), 미리보기 막대.
- 인벤토리: 아이템 '사용' 기능이 능력과 같은 칸.
- 오디오 실제 소리·페이드 체감. 스파인 스탠딩(이 프로젝트에 스파인이 없어 실행 못 함). `내 코드 범위` 드롭다운 체감.

## 확인이 끝나면

- 선택 기능 **확인용 패널·샘플**을 끈다(확인용 코드가 빠진다). DB의 확인용 항목(`check…`)은 지우거나, 메뉴 `MomoiProject › 처음 상태로 되돌리기…`로 단계 0의 상태로 돌린다.

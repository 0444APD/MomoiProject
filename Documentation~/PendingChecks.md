# 직접 확인할 것 (Momoi Project)

사용자가 Unity에서 직접 봐야 확인되는 항목을 쌓아 두는 목록이다. 코드·오프라인 테스트로는 확인한 상태이고, 실제 에디터·화면·소리·마우스 조작으로만 알 수 있는 것만 적는다. 확인되면 지운다. 사용자가 "뭐부터 차례대로 확인하면 돼?"라고 물을 때 이 목록을 순서대로 안내한다(위에서 아래 = 권장 순서).

## 1. 컴파일·기본 동작 (먼저)
- 이름 변경(GBible / MomoiProject) 뒤 Unity가 다시 컴파일하고 오류가 없는지. 상단 메뉴가 `MomoiProject`로 보이는지. 다이얼로그 기능이 켜진 채인지(옛 심볼 `GAME_SYSTEMS_*`가 `GBIBLE_*`로 바뀌어야 함, Player Settings › Scripting Define Symbols). DB의 에셋(도전과제·대화 등)에 "형식을 찾을 수 없음"·빈 블록이 없는지. Addressables 그룹 이름 `MomoiProject Default`. 열려 있던 DB·상세 창이 이상하면 닫고 다시 열기.
- Unity에서 다시 컴파일했을 때 콘솔 오류가 없는지. 특히 `Unity.GBible.CodeGen`(Mirror 비교 코드 생성, ILPostProcessor)이 오류·경고 없이 도는지(콘솔에 "Mirror 비교 코드 생성 실패"가 없어야 함).
- Mirror가 실제로 도는지: 플레이 중 플레이어 데이터(클래스)의 필드를 게임 코드에서 바꾸면 모니터의 기록에 `경로  옛 값 → 새 값`으로 남는지, 행동 Undo로 돌아가는지. 기록에 "예전 방식(리플렉션)으로 비교합니다" 경고가 뜨는 플레이어 데이터가 있으면 그 클래스에 [Serializable]이 빠진 것.
- 저장 후 멈춤("Hold on") 재현 여부: 클래스를 만들고 필드 2개를 더한 뒤 저장.
- EditMode 테스트(Test Runner): 특히 `TriggerSlotTests`, `CodexTreeTests`, `ContractTests`. PlayMode 샘플 테스트 3개는 `샘플 › 샘플 데이터 만들기` 후.
- 생성된 멤버 읽기·쓰기(실행 중 리플렉션 제거): EditMode `MirrorTests` 전체 통과(특히 "모든_생성_코드가_실행_가능한_코드다", "생성된_읽기_쓰기_코드로_멤버를_다룬다"). 플레이 중 콘솔·모니터에 "읽기 코드가 없어 리플렉션으로 읽습니다" 경고가 뜨면 그 클래스에 [Serializable](이벤트면 [GameEvent])이 빠진 것. 조건(필드 비교)·로그에 기록·플레이어 데이터에 주기·저장 후 불러오기가 전과 같이 도는지.
- 빌드(IL2CPP, PC): 위 기능과 이벤트 기록 문장이 빌드에서도 도는지(생성 코드가 구조체를 상자 안에서 고치고 enum을 상자에서 꺼내는 부분이 IL2CPP에서 맞는지 보는 것).
- 공유 객체: 플레이어 데이터 안에서 같은 객체를 두 곳에 넣고(예: 장착 칸 = 인벤토리 안의 아이템) 그 객체를 고치면 모니터 기록이 한 번만 남는지, Undo가 맞는지.

## 1-1. 시작 설정과 DB › 시작 파일
- 빈 새 프로젝트(또는 이 프로젝트)에서 시작 설정 창이 처음 한 번 저절로 열리는지. '적용' 뒤 `Assets/Code/Rules·Client·Editor·Tests`와 asmdef, `Client/Bootstrap.cs`, `Rules/PlayerData.cs`, DB › 플레이어 데이터 `run`·`profile`이 생기는지. 다시 컴파일된 뒤 `GameIds.cs`에 `Game.Data().Run`·`Profile`이 생기는지(콘솔에 "식별자 코드를 만들었습니다").
- DB 사이드바 맨 위 '시작 파일': Bootstrap 화면이 열리고 칸을 고치면 바로 저장되는지(Undo 방식에 따라 칸이 바뀌는지, 고급 접기). 'cs 열기'. RunState·Profile을 누르면 cs 파일이 열리는지(클래스를 다른 파일로 옮겨도).
- Bootstrap 화면 값이 플레이에 적용되는지: 시드 고정 → 모니터 머리의 시드, Undo 보관 수. Bootstrap.cs의 Configure에서 같은 값을 바꾸면 모니터 타임라인에 "코드(Configuring)가 … 바꿨습니다"가 남는지.
- 판 저장 "행동마다 저장": 행동 뒤 `run.json`이 갱신되는지. 판 끝 이벤트를 골라 두고 그 이벤트를 쏘는 행동을 하면 `run.json`이 지워지고 `profile.json`이 바로 써지는지, 그 뒤 새 판 행동을 하면 다시 저장되는지.
- Bootstrap의 선택 칸: Undo 끊는 이벤트에 턴 끝 이벤트를 고르면 턴을 넘긴 뒤 Undo가 안 되고 타임라인에 "Undo 기록을 비웠습니다"가 남는지. 시작할 때 이어 하기 + 새 판 행동: 저장이 없으면 새 판 행동이 실행되고, 있으면 이어 하는지. 프로필도 행동마다 저장: 행동 뒤 `profile.json`이 갱신되는지.
- DB › 개발 › 개발 명령: 항목을 만들고 결과에 "플레이어 데이터에 주기"·"이벤트 쏘기"를 넣으면 모니터 › 명령 탭에 버튼이 생기고, 누르면 타임라인에 "[개발] …"이 남고 Undo되는지. 이벤트 쏘기의 값 줄(필드 고르기)이 고른 이벤트의 필드를 보여 주는지. [BindTo]를 붙인 명령은 결과 칸이 코드로 잠기는지.
- DB › 개발 › 저장 변환: 항목 칸(종류에 따라 경로·새 키 칸이 보이고 숨는지), 검증 오류.
- 화면 도우미: `SubscribeAfterAction`으로 받은 연출이 실패한 행동에서는 안 뜨는지, `GameView.Redraw`로 그린 화면이 값·언어가 바뀔 때 한 번씩 다시 그려지는지.
- EditMode `SavedIdRenameTests`(출시 뒤 DB 항목 ID를 바꾸면 저장 안의 [DataRef] ID가 불러올 때 바뀜).

## 1-2. 처음 상태로 되돌리기 (반드시 복사본 프로젝트에서 먼저)
- 새 빈 Unity 프로젝트에 GBible을 넣고 열면 콘솔에 "처음 상태를 기록했습니다"가 나오고 프로젝트 폴더에 `MomoiProjectBaseline/`이 생기는지.
- 시작 설정 적용·스크립트·씬·설정을 바꾼 뒤 `MomoiProject › 처음 상태로 되돌리기…`: 확인 창의 파일 수가 맞는지, 되돌린 뒤 Unity가 다시 열리고 시작 설정 창이 다시 뜨는지, 바꾼 Player Settings(Product Name 등)가 돌아왔는지, `MomoiProjectBackups/<시각>/`에 옮겨진 파일이 있는지.
- 백업 폴더 내용을 덮어써서 되돌리기 전 상태로 돌아오는지.
- 기록이 없는 프로젝트(예: 이 개발 프로젝트의 복사본)에서는 "시스템이 만든 것만 치우기"만 나오는지.

## 2. DB 열기와 예전 데이터 옮기기
- DB를 처음 열 때 예전 형식(로그 규칙·도전과제 조건/보상·능력 대상/효과) 에셋이 새 트리거·결과 칸으로 옮겨지고 콘솔에 한 줄씩 남는지, 옮긴 뒤 내용이 같은지.

## 2-1. 키워드 이전과 키워드 탭
- 처음 열 때 콘솔에 "예전 키워드 에셋을 코드로 옮겼습니다"가 한 번 나오고, `Assets/Code/Keywords/`에 그룹 파일이 생기는지(컴파일 오류 없이). 옛 에셋은 프로젝트 폴더의 `_RemovedAssets/키워드 에셋 …`에 있는지.
- DB › 키워드 탭: 그룹 = 폴더, 키워드 = 줄. '+ 새 그룹'·'+ 키워드'·'+ 하위 그룹'·키워드 이름 바꾸기·✕·그룹 지우기 → Ctrl+S 하면 코드 파일이 고쳐지고 다시 컴파일된 뒤 그대로 보이는지. 'cs 열기'.
- 키워드 필드(`[Keyword(typeof(그룹))]`)의 드롭다운·리스트 칩이 그룹의 키워드를 보여 주는지, 없는 값이면 검증 오류.
- 클래스 상세에서 필드의 키워드 그룹을 바꾸면 저장할 때 코드에 `[Keyword(typeof(…))]`가 쓰이는지.

## 2-2. 클래스 탭(읽기 전용)
- 클래스·이벤트 탭에 만들기·끌어 옮기기가 없고, 클래스를 누르면 필드 이름·형식·키워드가 보이는지. `→ 클래스` 이동, `cs 열기`.

## 2-3. 인스턴스
- DB › 인스턴스(예전 템플릿) 탭 이름·항목 만들기. 형식을 고르면 값 칸이 열리고, [Hide] 필드는 안 보이고 [ShowIf]는 조건대로 보이는지.
- 기능 필드(`[SerializeReference]` 클래스 필드): 비어 있으면 '+ 기능'로 붙고, 붙은 기능 줄의 빼기로 다시 빠지는지.
- 클래스 상세의 '인스턴스에서 숨김 [Hide]'을 켜고 저장하면 코드에 [Hide]가 붙는지.
- 인스턴스에 스프라이트가 있으면 게임에서 받은 사본에도 같은 스프라이트가 있는지.

## 2-4. 코드 결과 연결 [BindTo]
- `[BindTo(GameIds.Achievement.…)]` Reward 클래스를 만들면 그 도전과제 상세의 결과 칸이 잠기고 클래스 이름·cs 열기만 보이는지, 달성하면 그 코드가 도는지. 로그도 같다.
- static 함수에 `[BindTo(id)]`를 붙여도 같은지(결과 칸에 `클래스.함수`와 받는 이벤트 이름, cs 열기). 사용 기능이 붙은 인스턴스 ID에 연결하면 `Game.Use`로 그 함수가 도는지.
- 행동 하나를 하고, 같은 값을 행동 밖에서 바꾼 뒤 되돌리면 모니터에 "행동 밖에서 바뀐 값을 덮었습니다" 경고가 뜨는지.

## 3. DB 목록(모든 탭 = 클래스 탭 모양)
- 폴더 줄 클릭으로 접기·펼치기, 항목 클릭으로 열기, 이름순(폴더 먼저).
- 끌어 놓기: 항목·폴더를 다른 폴더 위에 놓으면 그 안으로 옮겨지는지, 놓을 폴더가 분홍으로 밝아지는지, 자기 안쪽에는 안 놓이는지.
- 폴더 만들기·이름 바꾸기·지우기 후 Ctrl+S 저장, 적용 대기 목록 표시.
- 클래스·이벤트 탭: 폴더 이동이 실제 `Assets/Code` 폴더 이동으로 적용되는지.
- 키워드·스프라이트 규격 탭: 그룹 안에 그룹 두기.
- 다이얼로그 그래프·연출 프리셋 창 왼쪽 목록(폴더 변경이 바로 저장).
- 그룹을 새 창(↗)으로 열기.
- 창 탭 막대 숨기기(유틸리티 창) 실제 모양.

## 4. 트리거·결과 편집 화면
- 로그: 트리거(이벤트만)와 고정 결과 '로그에 기록' 하나, 반영할 값·배수만 보이는지. 반영할 값 목록이 트리거 이벤트의 필드인지.
- 도전과제: 트리거에 이벤트·조건을 AND·OR로 섞기, `+ 결과 추가` 목록.
- 능력: 기본 '사용' 트리거 + AND 사용 조건, 결과(대상에게 효과·플레이어 데이터·코딩한 결과).
- 아이템 '사용' 기능(인벤토리 모듈): 능력과 같은 칸.
- 잠금 밖 종류가 목록에 안 보이는지, 검증 오류(NOT 안 이벤트, 읽을 이벤트 없는 기록 등) 표시.
- 플레이어 데이터 보상: 딕셔너리 필드의 `[키] → [값]` 줄과 `+`.

## 5. 모니터
- 도전과제 '트리거로 달성': 조건을 채우고 이벤트를 쏴서 스스로 달성되는지, Undo하면 로그가 돌아가는지. '강제 달성'.

## 6. 다이얼로그·오디오 (이전부터 남은 것)
- 다이얼로그 화면 실제 모습: 글상자 블러(`backdrop-filter`가 게임 화면까지 흐리게 하는지), 모션, 로그 창, 장소 표시, 창 모드 스탠딩, 이미지 창, 한글 폰트(`DialogueUI.font`에 TTF), 클릭·키 입력.
- 그래프 창 마우스 조작(범위 선택, 그룹 상자 크기), 미리보기 막대(플레이 모드 진입·재생·시간 이동).
- 오디오 실제 소리·페이드 체감.
- 스파인 스탠딩(이 프로젝트에 스파인이 없어 실행 못 함).
- 상세 창에서 기능 목록 편집(샘플 아이템).
- `내 코드 범위` 드롭다운 체감.

## 7. 게임 규칙 부품 (능력치·가로채기·상태 효과·선택 대기·밸런스·슬롯·설정·입력)
- 칸·방법 같은 enum이 DB에서 한글로 보이는지(능력치 보정의 칸 = 플랫/퍼센트/독립 곱, 의도 고치기의 방법 = 값으로 바꾸기/더하기/곱하기/막기).
- `+ 결과 추가` 목록에 '비용 내기'·'가중치 표에서 주기'(플레이어 데이터를 줄 수 있는 칸), '선택 요구'('대상에게 효과'가 되는 칸)가 보이는지.
- DB › 상태 효과: 지속 방식을 바꾸면 길이·셀 이벤트·가진 쪽 필드 칸이 방식에 맞게 보이고 숨는지. '가진 쪽 필드'(지속 안·걸려 있는 동안)의 필드 고르기가 각각 셀 이벤트·트리거의 이벤트 필드를 보여 주는지. 효과 '상태 효과 걸기/풀기'의 상태 효과 칸이 DB › 상태 효과 항목만 보여 주는지.
- 상태 효과 실제 동작(예시 게임에 독 하나 만들어 보기): 걸면 모니터 › 데이터의 '상태 효과'에 생기고, 턴 끝마다 결과가 돌고 횟수가 줄다가 끝날 때 결과가 도는지, Undo가 맞는지.
- 선택 대기: 결과 '선택 요구'를 가진 능력을 쓰면 모니터 › 명령 탭 맨 위에 '선택 대기' 패널이 생기고, 후보 버튼(✓)·답하기로 이어지는지. 개수가 틀리면 알림이 뜨는지, 답하기가 타임라인에 "선택: …"으로 남고 Undo하면 패널이 돌아오는지.
- DB › 밸런스 값: 곡선 방식을 바꾸면 그 방식의 칸만 보이는지. 플레이 중에 값을 고치면(저장 전이라도) Game.Balance가 바로 새 값을 돌려주는지.
- DB › 가중치 표: 항목 칸의 DB 항목 고르기(모든 종류), 조건 칸 편집, 검증(빈 항목·자기 자신·무게 0).
- 슬롯: `GBibleRuntime.UseSlot("1")` → `persistentDataPath/MomoiProject/slots/1/`에 profile.json·run.json·slot.json이 생기는지, 다시 실행하면 마지막 슬롯으로 시작하는지, 하이어라키의 `[MomoiProject]` 오브젝트가 하나뿐인지, 모니터가 새 세션으로 바뀌는지. `DeleteSlot`·`CopySlot`, slot.json의 플레이 시간·요약(SlotSummary).
- DB › 설정(선언 그룹): 종류를 바꾸면 칸이 바뀌는지, 적용 대상과 종류가 안 맞으면 검증 오류. 플레이 중 `GameSettings.Set`으로 음량·언어가 바로 바뀌고 `settings.json`에 남는지, 다시 실행하면 그 값으로 시작하는지. 전체 화면·해상도는 빌드에서만 적용(에디터에서는 바뀌지 않는 것이 정상).
- 입력(선택 기능 '입력(키 바꾸기)'): 켜면 GBIBLE_INPUT 심볼이 들어가고 컴파일되는지. `GameInput.Use(asset)` 뒤 `Rebind`로 키를 바꾸면 다음 실행에도 남는지, 같은 맵의 다른 키와 겹치면 `Conflict`가 오고 바뀌지 않는지, Esc 취소, `ResetBindings`.

# 05. 테스트하기

AI가 프로젝트마다 **테스트 씬**(`Assets/Scenes/Test.unity`)을 만들어 둔다. 게임과 같은 화면 위에서, 원하는 상황을 만들고 기믹·밸런스·버그를 시험한다.

## 흐름

1. 메뉴 **MomoiProject › 테스트 › 테스트 씬 열기** → 플레이.
2. 화면 왼쪽 위 **테스트 패널**(F1로 펼치고 접기)이 뜬다.
   - **시간**: ×0.5 · ×1 · ×2 · ×4, 멈춤, Undo, 새 판
   - **테스트 상황**: 이름을 적고 '지금 저장' / 저장된 상황 '불러오기'
   - **테스트 명령**: AI가 만든 버튼(유물 얻기 · 적 만들기 · 화상 걸기 · 보스 직전으로 …)
3. 숫자가 이상하면 DB에서 바꾸고(03장) 다시 시험한다. 밸런스 값은 플레이 중에도 바로 반영된다.

테스트 씬은 **'test' 슬롯**에서 돈다 — 개발자의 실제 저장(기본 슬롯)을 건드리지 않는다.

## 테스트 상황

지금 판·프로필·난수·시각을 이름 붙여 저장한 파일(`Assets/MomoiProject/Data/Tests/이름.json`)이다. 프로젝트와 함께 커밋된다.

- 테스트 씬의 인스펙터(오브젝트 '[테스트]' › 컴포넌트 '테스트 씬')에서 **시작 상황**을 고르면 플레이할 때 그 상황으로 바로 시작한다.
- 모니터 › 명령 탭에서도 저장·불러오기가 된다.
- 버그를 보고할 때 상황 이름을 적으면 AI가 같은 상황으로 재현한다.

## 테스트 명령

DB › 개발 › 개발 명령의 항목이 버튼이 된다. 문장 안의 값을 바꿔 쓸 수 있다 — "적 만들기: `슬라임` × `3`"에서 적과 수를 드롭다운으로. 새 버튼이 필요하면 AI에게 "보스전 바로 시작하는 버튼 만들어 줘".

> [!note]- 자동 시뮬레이션(밸런싱)
> 같은 상황을 시드만 바꿔 수백 번 돌려 승률·평균 턴·피해를 표로 보는 기능이다. 플레이어의 수를 대신 두는 규칙(자동 플레이)이 프로젝트마다 다르므로 AI에게 "보스 직전 상황으로 200번 돌려서 승률 보여 줘"라고 요청한다. 결과는 `Assets/MomoiProject/Data/Tests/Reports/`에 CSV로 남는다. 턴제에 잘 맞고, 실시간은 AI가 근사 판정을 만들어야 한다.

## 멀티 시험

게임이 멀티(친구 방·매칭큐)면 테스트 패널의 **멀티**에서 시험한다.

- **혼자 시험 — 시험 모드**: 서버를 이 프로그램 안에 띄우고 이 화면은 그 클라이언트가 된다. 지연(기본 0.08초)이 있어서 "행동하고 결과가 늦게 와도 화면이 괜찮은가"를 본다. 지연·흔들림은 패널에서 바로 바꾼다. 모니터 머리에서 **서버**를 고르면 서버 쪽 데이터·기록이 보인다.
- **둘이 시험 — 직접 접속**: 한 사람이 **방 생성**(포트 7777), 다른 사람이 주소(`IP:7777`)를 적고 **방 참가**. 집이 다르면 둘 다 가상 랜 도구(Tailscale 등)에 들어가 그 주소를 쓴다(공유기 설정 필요 없음). 처음 열 때 Windows 방화벽 허용 창이 뜨면 허용.
- **매칭큐 시험**: 한 곳에서 **매칭큐 서버**를 열고, 각자 **매칭 찾기** → **줄 서기** → 성사되면 **수락**. 매치가 끝나면 점수가 바뀌어 로비로 돌아온다.
- 테스트 씬 인스펙터의 **멀티플레이**를 '시험 모드'로 두면 플레이하자마자 시험 모드로 시작한다.
- 빌드 여러 개를 띄워 시험할 때는 실행 인자로: `-momoi-host`(방 생성) · `-momoi-join 주소 -momoi-name 이름`(방 참가) · `-momoi-matchserver`(매칭큐 서버).

클라이언트에서는 Undo·새 판·테스트 상황이 서버(판을 가진 쪽)에서 돈다. 플레이어가 누르는 '무르기'는 멀티에 없다.

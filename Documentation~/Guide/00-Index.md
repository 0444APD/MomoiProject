# 프로그래머 가이드

Momoi Project(코드 이름 `GBible`)로 **프로젝트를 시작해서 출시할 때까지 프로그래머가 하는 일**을 순서대로 안내한다. 장마다 "지금 이 단계에서 무엇을 정하고, 어떤 기준으로 고르고, 무엇을 만드는가"를 설명하고, 설명을 돕는 짧은 코드를 붙였다.

[매뉴얼](../Manual/00-Index.md)과의 관계: 매뉴얼은 기능별 사전(모든 문법과 옵션)이고, 이 가이드는 진행 순서와 판단 기준이다. 가이드에서 처음 나오는 기능은 장 끝 '더 보기'에서 매뉴얼의 해당 장으로 잇는다.

---

## 예시 게임: 카드 던전

모든 장이 같은 게임 하나를 조금씩 키워 가며 설명한다. 턴제 덱빌딩 로그라이크다.

- 판(런)을 시작하면 주인공이 시작 덱·유물·물약을 가지고 1층 전투에 들어간다.
- 전투는 턴제다. 턴마다 에너지를 받아 손패의 카드를 내고(피해·방어도·상태), 턴을 끝내면 적이 공격 패턴대로 행동한다.
- 이기면 골드를 받고 다음 층으로, 상점에서 카드를 사고 상점 주인과 대화한다. 쓰러지면 판이 끝나고 기록이 프로필에 남는다.
- 도전과제(첫 승리, 한 턴 30 피해), 로그(처치 수, 한 턴 최대 피해, 번 골드), 유물(전투 시작 방어도, 승리 때 회복)이 붙는다.

이 게임이 쓰는 것: 플레이어 데이터(판 = 세션 구역, 프로필 = 메타 구역), 인스턴스(카드·몬스터·물약 원본), 키워드(등급·속성·카드 종류·상태), 이벤트, 행동과 Undo, 효과·대상 Block, `[BindTo]`, 도전과제·로그, 프로젝트 고유 기능(유물), 인벤토리(물약 칸), 다이얼로그, 텍스트·현지화, 오디오, 필드 규칙, 모니터·디버그 명령, 저장과 이어 하기. 덱빌딩에 맞지 않는 기능(실시간 스냅샷 되감기 등)은 장마다 '다른 장르라면'에서 다룬다.

## 읽는 순서

처음 프로젝트를 시작한다면 01부터 차례로 읽는다. 01–04가 뼈대(시작 → 설계 → 루프 → 콘텐츠)이고, 05–08은 팀으로 만들 때, 09–11은 프로젝트 내내 지킬 것과 출시 준비다. 12는 필요할 때 찾아 쓰는 부록이다.

## 장 구성

01–11장은 같은 순서로 쓰여 있다.

1. **이 단계의 목표** — 한두 문장
2. **할 일 순서** — 번호 목록
3. **판단 기준** — "이럴 때는 이것"
4. **카드 던전에서 실제로** — 이 게임에서 어떻게 했는지(설명 + 짧은 코드)
5. **다른 장르라면** — 해당할 때
6. **체크리스트** — 이 단계를 끝냈는지
7. **더 보기** — 매뉴얼 링크

(09–11장은 판단 기준과 카드 던전 사이에 그 장만의 절이 더 있어 절 번호가 조금 다르고, 10장에는 '다른 장르라면'이 없다.)

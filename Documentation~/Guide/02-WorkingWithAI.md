# 02. AI와 일하기

## 진행 단계

| 단계 | AI가 하는 일 | 개발자가 하는 일 |
|---|---|---|
| **0 흡수** | 자료를 읽고 명세서를 채우고 질문한다(예외 사냥) | 답하고, 시스템 목록을 확인한다 |
| **1 시스템층** | 규칙·흐름·데이터·화면 뼈대·테스트 씬 | 테스트 씬을 돌려 본다, 적용(Ctrl+S) |
| **2 콘텐츠** | 카드·적·유물을 DB에 넣고 조각마다 테스트 명령 | 목록을 주고, 적용하고, 숫자를 맞춘다 |
| **3 레벨 디자인** | 배치할 데이터 모양과 도구 | 레벨 배치, 다이얼로그 그래프 |
| **4 연출·UI·사운드** | 화면·연출·사운드 연결, 넣을 에셋 목록 | 에셋 가져오기 |
| **5 밸런싱·테스트** | 테스트 상황·시뮬레이션, 버그 고치기 | 값 바꾸기, 버그 보고 |
| **6 출시 준비** | Steam·저장 호환·빌드 점검 | Steamworks 설정, 빌드 |

지금 어느 단계인지는 `Docs/Decisions.md` 맨 위 '지금 단계'에 있다.

## 질문에 답하기

AI는 질문을 한 번에 번호로 보낸다. 질문마다 선택지·추천·이유·"답이 없으면"·뒤집기 비용이 붙어 있다.

- 번호로 답한다: "1 가, 2 추천대로, 3 나 — 보스는 두 칸을 차지해."
- "알아서" · "추천대로"면 추천값으로 간다.
- 모르는 것은 "모르겠다" — AI가 추천값으로 가고 기록한다. **뒤집기 비용이 높은 질문**(데이터 구조·메인 룰·흐름)은 될 수 있으면 지금 답한다.

## 결정 기록 — `Docs/Decisions.md`

AI가 질문·답·추천값으로 정한 것을 번호(`D-1`, `D-2` …)로 쌓는다. 같은 것을 다시 묻지 않고, 세션이 바뀌어도 이어 간다. AI는 같은 내용을 채팅에도 한 줄 남긴다("기록: D-12 보드는 열 우선").

- 추천값으로 정한 것은 단계가 끝날 때 한 번에 보여 준다. 다르게 하고 싶으면 "D-7은 나로 바꿔 줘".
- 파일을 직접 고쳐도 된다. AI가 다음에 읽고 따른다(코드와 다르면 알리고 맞춘다).

## 변경 요청

기획을 바꾸거나 새 기믹을 넣고 싶으면 그대로 말한다: "유물 하나가 다른 유물을 흉내 내게 하고 싶어."

- 지금 틀 안이면 AI가 바로 만든다.
- 틀(메인 룰·데이터 구조)을 바꿔야 하면 AI가 **영향 범위·비용·대안**을 붙여 묻는다. 예외 코드로 때우지 않는다.

## 버그 보고 양식

```
상황: (테스트 상황 이름, 또는 '지금 상황 저장'으로 저장한 이름)
한 일: (누른 테스트 명령·한 조작)
기대: (이렇게 되어야 한다)
실제: (이렇게 됐다)
기록: (모니터 타임라인·저널의 한 줄, 콘솔 오류)
```

AI는 같은 상황으로 재현 테스트를 만든 뒤 고친다. 테스트 상황 저장은 [05장](05-Testing.md).

> [!note]- AI가 일을 끝내면 끝에 적어 주는 것
> 개발자가 할 일(적용할 DB 항목 · 넣을 에셋 · 돌려 볼 테스트 상황·명령 · Unity에서 볼 것), 이번에 기록한 결정, 보여 줄 추천값, 지금 단계와 다음 할 일. 이 목록대로 하면 된다.

# 09. 문제가 생기면

| 증상 | 할 일 |
|---|---|
| DB 아래에 검증 오류 | 항목을 눌러 본다. 빠진 참조면 드롭다운에서 다시 고르고, 모르겠으면 오류 글을 AI에게 붙인다 |
| 콘솔에 빨간 오류 | 오류 글 전체를 AI에게 붙인다. AI의 응답 끝 컴파일 검사가 대부분 미리 잡는다 |
| AI가 만든 항목이 DB에 안 보인다 | 컴파일이 끝났는지(Unity 아래 진행 표시) 본다. 메뉴 `MomoiProject › DB 반영 스크립트 › 모두 다시 돌리기` |
| 적용 전 변경을 버렸다 | 다음 컴파일 뒤 AI의 반영 스크립트가 다시 들어온다. 개발자가 바꾼 값은 다시 바꾼다 |
| 플레이하면 이상한 상황에서 시작한다 | 테스트 씬이면 '[테스트]' › 시작 상황을 확인한다. 게임 씬이면 이어 하기(저장)가 남아 있을 수 있다 — 모니터 › 명령 › 저장 |
| 값을 바꿨는데 그대로다 | Ctrl+S로 적용했는지. 밸런싱 값 말고는 플레이를 다시 시작해야 반영되는 것이 있다 |
| 구조를 바꿔야 하는데 잠겨 있다 | AI에게 요청한다. 급하면 메뉴 `MomoiProject › 개발 › 구조 편집 열기(라이브러리 개발용)` — 고친 뒤 AI에게 무엇을 바꿨는지 알린다 |
| 크게 잘못됐다 | Git으로 되돌린다(AI에게 "어제 커밋으로 되돌려 줘"). DB 적용 전이면 '버리기' |

> [!note]- 확인할 것을 한곳에
> Unity에서 직접 봐야 확인되는 것(창 모양·소리·입력)은 GBible 저장소의 `Documentation~/PendingChecks.md`에 쌓여 있다.

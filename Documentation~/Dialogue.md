# 다이얼로그 시스템

**켜고 끄기.** 다이얼로그 시스템은 프로젝트마다 켜고 끄는 선택 기능이다. DB 사이드바의 다이얼로그 시스템 아래 **기능 활성화** 버튼으로 켜면 스탠딩 프로필·장소 탭과 메뉴가 열린다. 기능의 클래스(DialogueData·EffectPresetData·StandingProfileData·LocationData)는 DB › 클래스 목록에 나오지 않는다(클래스 탭은 개발자가 선언한 클래스만 보인다). 스탠딩 프로필·장소의 필드는 그 탭 머리 **필드 연결**로 연다(잠김). 끄면 모두 빠지고 빌드에도 들어가지 않으며, 만든 데이터는 남는다(스크립팅 심볼 `GBIBLE_DIALOGUE`, 상태는 `ProjectSettings/MomoiProject/Features.json`의 `enabled` — AI는 여기에 `dialogue`를 더해 켜고, Unity가 다시 컴파일한 뒤에 다이얼로그 형식을 쓰는 코드를 쓴다. 관례 0절).

다이얼로그는 **선택 모듈**이다(`Optional/Dialogue`: 어셈블리 GBible.Dialogue · .Editor · .Tests — asmdef `defineConstraints`가 `GBIBLE_DIALOGUE`라 끄면 컴파일에서 빠진다). 코어는 다이얼로그를 참조하지 않는다. 화자·스탠딩은 다이얼로그 전용 **스탠딩 프로필**로, 게임의 캐릭터 데이터와 따로 관리한다.

다이얼로그는 노드 그래프로 만든다. `MomoiProject › 다이얼로그 시스템 › 그래프` 창의 격자 배경에서 우클릭해 노드를 만들고, 점을 끌어 잇는다. 대사 한 줄이 노드 하나다. 연출 그룹은 `MomoiProject › 다이얼로그 시스템 › 연출 프리셋` 창에서 효과 노드로 만들고, 다이얼로그 그래프에서는 '연출 프리셋' 노드 하나로 쓴다.

## 두 종류의 선

**흐름**(흰 선, 둥근 점)은 다이얼로그가 어디로 가는지다. 시작 → 대사 → 선택지 → 조건 분기 → … 순서로 이어지고, 나가는 흐름 점 하나는 한 곳으로만 간다.

**신호**(분홍 선, 네모 점)는 연출이 언제 시작하는지다. 대사 노드는 진입·타이핑 완료·넘김 신호를 내고, 모든 효과는 시작·진행 지점(n%)·완료 신호를 낸다. 신호를 다른 효과의 '재생'에 이으면 체인이 된다(예: 배경 교체 90% → 스탠딩 등장, 스탠딩 등장 완료 → 흔들기). 신호 점 하나는 여러 곳으로 갈 수 있다. 진행 지점은 효과의 '진행 신호 지점' 목록에 퍼센트를 더하면 점이 생긴다.

대사 노드의 '대사 시작' 점에 신호를 이으면 그 신호가 올 때까지 글자가 나오지 않는다. 예: 연출이 90% 진행된 뒤 대사를 시작하려면 대사 진입 → 배경(진행 지점 90%) → 대사 시작.

## 노드

흐름 노드는 시작(시작 ID), 대사(화자·표정·원문·선택지·타이핑 속도·자동 넘김), 조건 분기(도전과제와 같은 조건 블록), 값 바꾸기(보상 블록: 플레이어 데이터에 주기 …), 신호 보내기(게임 코드로 `Signaled`), 다른 다이얼로그로(다이얼로그 ID·시작 ID), 끝이다. 선택지마다 흐름 점이 생기고, 선택지에 조건을 달면 맞을 때만 보인다(흐리게 보이기 선택 가능). 조건이 모두 안 맞아 고를 선택지가 없으면 클릭으로 '고를 선택지 없음' 점으로 간다(잇지 않았으면 다이얼로그 끝 — 그래프 창이 경고한다).

효과 노드는 두 가지다. **상태 효과**는 유지되는 화면 모습을 바꾼다: 배경, 배경 어둡게, 레터박스, 카메라, 배경 음악, 스탠딩 등장·퇴장·바꾸기·이동·강조, 창 바꾸기, 이미지 표시·지우기. **큐 효과**는 한 번 일어나고 끝난다: 흔들기, 번쩍임, UI 모션, 이펙트 생성, 효과음, 기다리기. 칸마다의 이름은 매뉴얼 24장 2절. 모든 효과에 시작 전 기다림, 진행 시간, 움직임 곡선, 진행 신호 지점, '다음 대사로 넘어가도 계속'이 있다. 캐릭터 칸을 비우면 현재 화자를 가리킨다(프리셋 안에서는 프리셋 노드가 정한 대상).

## 연출 프리셋

프리셋 창에서 '프리셋 시작' 노드의 신호로 효과들을 잇는다. '신호 내보내기' 노드를 두면 그 이름의 점이 다이얼로그 그래프의 프리셋 노드에 생긴다(예: 프리셋 안의 흔들기 시작 → 내보내기 "hit" → 다이얼로그에서 hit → 대사 시작). 프리셋 노드의 '완료'는 안에서 시작한 효과가 모두 끝났을 때 나온다.

## 스킵·되감기·저장

상태 효과는 시작하는 순간 논리 상태(`StageState`)를 끝 모습으로 바꾸고, 화면은 앞뒤 모습 사이를 그린다. 그래서 클릭(연출 중이면 체인 끝까지 마무리 후 대사 시작, 타이핑 중이면 글자 모두 보이기), 빨리 감기(`FastForward`), 다음 줄로 넘기기(이 줄에서 시작한 효과를 끝 모습으로 마무리, '계속' 효과 제외)가 모두 같은 결과 화면을 만든다. 스킵(`SkipToChoice`)·저장 이어 가기·미리보기 시간 이동은 지나가는 줄의 한 번짜리 연출(효과음·이펙트·번쩍임·흔들기·UI 모션·프로젝트 효과·목소리)을 내지 않고, 멈춘 곳의 끝 모습만 한 번 그린다(아직 진행 중인 효과는 그 시점의 진행도로). 지나온 줄마다 그때의 상태가 `History`에 남고, `Snapshot()`/`Resume()`으로 다이얼로그 중간 저장·불러오기를 한다.

효과끼리 신호가 고리로 이어지면(A 완료 → B 재생 → A 재생) 끝없이 반복된다. 첫 바퀴만 클릭을 막고(효과 시간 보장), 빨리 감기·넘기기는 고리를 한 번씩만 끝내며, 그 줄을 넘기면(계속 설정이 아니면) 고리도 멈춘다. 그래프 창이 "신호가 고리로 이어진 효과"로 알린다.

## 코드

```csharp
var runner = DialogueRunner.FromDatabase(GameDatabase.Load());
runner.Session = GBibleRuntime.Session;   // 조건·값 바꾸기·대사 속 {run.gold}
runner.Stage = myStage;                         // IDialogueStage: 화면 그리기
runner.Signaled += signal => { if (signal == "openShop") OpenShop(); };
runner.Start("shopIntro");
// 매 프레임 runner.Tick(Time.unscaledDeltaTime), 클릭 runner.Advance(), 선택 runner.Choose(i)
```

게임 코드는 보통 `Dialogues.Play("다이얼로그 ID")`(아래 '다이얼로그 관리자')로 연다. 위처럼 `DialogueRunner`를 직접 만드는 것은 화면을 따로 그릴 때다 — 그때 `Session`을 비우면 조건은 늘 참, 값 바꾸기는 하지 않는다.

대사 글자는 대사 키(`line.xxxxxxxxxx`, 자동·고정)로 텍스트 표를 찾고, 없으면 노드의 원문을 쓴다. 원문은 다국어 문장 틀 문법(`{run.gold}` — 플레이어 데이터 ID + 필드 경로, `{item:을}`, `[[burn]]`)을 그대로 쓴다. 번역 시트로 나가는 모양은 아래 '시트'.

## 화면: 템플릿 프리팹

`DialogueTemplate.Create()`(에디터 — AI가 DB 반영 스크립트에서 부른다, 메뉴 없음)는 `Assets/MomoiProject/Data/DialogueUI/`에 한 벌을 만든다 — GBible 다이얼로그 기본 디자인(UI 가이드 1-10, 2026-10-21): `DialogueSystem.prefab`, `DialogueUI.uxml`·`DialogueUI.uss`(그라데이션 글 띠 · 이름과 오른쪽 소속 · 대사 · 로그 버튼 · 선택지 · 레터박스 · 번쩍임 · 검은 화면 · 툴팁), `DialogueChoice.uxml`(선택지 하나), 패널 설정·런타임 테마, 기본 모션 3개(열림·선택지 나타남·고름), 흰 스프라이트, 그림(글 띠 · 로그 아이콘). 건너뛰기 · 자동 진행 버튼과 클릭 대기 표시는 기본에서 뺐다(이름 규격 요소를 더하면 켜진다). 프리팹을 씬에 놓고 `GetComponent<DialoguePlayer>().Play("다이얼로그 ID")`로 재생한다. 한글이 네모로 보이면 UI 오브젝트의 `DialogueUI > font`에 한글 TTF를 넣는다.

프리팹 구성: `DialoguePlayer`(실행기·입력·게임 시간 멈춤·신호 이벤트) › `Stage`(`DialogueStage`: 게임 카메라 앞에 배경 두 장·배경 어둡게·스탠딩·이펙트, 음악·효과음, 카메라 확대·이동·흔들기) · `UI`(`UIDocument` + `DialogueUI`).

**모양 바꾸기(프로젝트마다).** UXML·USS를 고친다. 코드는 요소를 **이름**으로만 찾으므로 이름만 지키면 배치·스프라이트·크기·클래스는 자유롭다. 이름이 다르면 `DialogueUI`의 이름 칸을 고친다. 인스펙터 아래 '요소 연결 확인'이 UXML에 이름 규격의 요소가 있는지(필수/선택) 바로 보여 준다. 필수는 `dialogue-root`·`dialogue-name`·`dialogue-text`·`dialogue-choices`이고, 나머지는 없으면 그 기능만 꺼진다. 여러 모양을 두려면 프리팹 변형(Prefab Variant)에서 UXML·모션만 바꾼다.

**애니메이션.** UI Toolkit 요소는 Animator·AnimationClip으로 움직이지 않는다. 대신 두 층을 쓴다. 나타나기·사라지기·색 변화처럼 '상태가 바뀌면 부드럽게'는 USS 전환(`transition`)과 루트의 상태 클래스(`dialogue--open`·`--staging`·`--typing`·`--waiting`·`--choosing`·`--narration`·`--speaker-<ID>`)로 USS 안에서 끝낸다(참조 연결 없음). 키프레임·반복·스프라이트 프레임 애니메이션은 **UI 모션** 에셋(`Create › MomoiProject › 다이얼로그 시스템 › UI 모션`: 투명도·이동·크기·회전·색 곡선, 프레임 목록, 한 번/반복/왕복)을 만들어 `DialogueUI`의 모션 칸(순간 × 요소 이름 × 모션)에 넣는다. 순간은 열림·닫힘·줄 시작·화자 바뀜·클릭 대기·선택지 나타남·선택지 고름이다. 다이얼로그 그래프에서도 'UI 모션' 효과 노드로 원하는 순간에 어느 요소든 모션을 재생할 수 있다(체인에 들어간다).

**스탠딩.** 캐릭터의 '스탠딩 프리팹'이 비어 있으면 표정 스프라이트 두 장을 겹쳐 크로스페이드한다(`SpriteStandingView`, 높이는 `standingHeight`). 스파인은 프리팹에 `SpineStandingView`를 붙인다(스파인 런타임 들이기는 매뉴얼 39장 5절): 스파인 런타임을 직접 참조하지 않고 이름으로 찾아(`SkeletonAnimation`·`SkeletonGraphic`·`SkeletonMecanim`) 표정 ID와 같은 이름의 애니메이션을 재생하고(다르면 짝 목록), 밝기·투명도는 스켈레톤 색으로 준다(이름으로 찾는 일은 붙일 때 한 번만 — 매 프레임 리플렉션 없음). 다른 방식(Live2D 등)은 `StandingView`를 상속한다.

**멈추지 않는 시간.** `DialoguePlayer.pauseGame`(기본 켬)은 게임 시간(`Time.timeScale`)을 멈춘다. 다이얼로그 연출은 멈추지 않는 시간으로 돌고, 다이얼로그가 만든 스탠딩 프리팹·이펙트 프리팹의 파티클(`useUnscaledTime`)·애니메이터(Unscaled Time)·스파인 스켈레톤(`unscaledTime`)도 멈추지 않는 시간으로 바꿔 둔다. 프로젝트 효과(`CreatePlayer`)가 만든 것은 그 효과가 맞춘다.

**그리기 방식.** 상태 효과는 효과 종류와 상관없이 '앞 모습 → 뒤 모습'에서 바뀐 값만 섞는다(배경 크로스페이드·검은 화면 경유, 어둡기, 레터박스, 카메라, 음악 교차, 스탠딩 등장·퇴장·위치·밝기·표정). 그래서 새 상태 효과를 더해도 화면 코드를 고칠 일이 거의 없다. 큐 효과는 흔들기(화면=카메라, 캐릭터=스탠딩), 번쩍임(UI 덮개), 이펙트(프리팹 생성, 진행 시간이 있으면 끝날 때 지움 — 남은 이펙트는 다이얼로그가 끝날 때 모두 지움), 효과음, UI 모션이다.
## 스탠딩 프로필

DB › 다이얼로그 시스템 › '스탠딩 프로필'에 스탠딩 목록(스탠딩 ID · 스프라이트)을 채운다. 그래프의 스탠딩 칸(스탠딩 등장·스탠딩 바꾸기·대사의 화자 스탠딩)은 캐릭터 칸이 정한 프로필의 스탠딩 ID를 드롭다운으로 고른다(캐릭터를 비우면 현재 화자라서 모든 프로필의 스탠딩이 프로필별로 묶여 나온다). 예외로 그 자리에만 다른 그림을 쓰려면 '예외 스프라이트'를 꽂는다(스탠딩 ID보다 우선, 스파인 스탠딩에는 쓸 수 없다).

## 프로젝트별 확장

**글 더하기(코드 없음).** 소속·직함·장소처럼 프로젝트마다 다른 글은 스탠딩 프로필 또는 대사 노드의 '추가 글'에 키와 글을 적고(대사가 우선), UXML에 `name="dialogue-extra-<키>"` Label을 둔다. 글이 비면 그 요소에 `dialogue-extra--empty`, 있으면 루트에 `dialogue--has-<키>`가 붙어 USS로 숨기거나 배치를 바꾼다. 번역은 `<캐릭터 ID>.<키>`·`<대사 키>.<키>` 텍스트가 있으면 그것을 쓴다. 템플릿에 소속(`affiliation`) 예시가 들어 있다.

**UI 동작 더하기.** `DialogueUIExtension`(또는 `IDialogueUIExtension`)을 상속한 컴포넌트를 다이얼로그 UI 오브젝트나 자식에 붙이면 열림·닫힘·대사(`DialogueLineInfo`: 대사 노드·프로필·이름·글·추가 글)·선택지 순간에 불린다. 요소는 `ui.Element("이름")`으로 찾는다.

**노드 더하기.** 효과는 `EffectNode`를, 흐름은 `CustomFlowNode`(Run이 다음 점 ID를 돌려준다 — 고른 점은 진행 기록에 남아 불러올 때는 Run을 다시 부르지 않는다. 미리보기 시간 이동처럼 `runner.Replaying`일 때도 불릴 수 있으니 그때는 값을 바꾸지 않는다)를 상속하고 `[GraphNode("이름", Category = …)]`를 붙이면 우클릭 메뉴에 나온다. 효과의 화면 그리기는 `CreatePlayer(stage, …)`에서 직접 만들고, 유지되는 값(날씨 등)은 `ApplyTo`에서 `state.Custom("키", true)`에 적으면 스킵·저장·되감기에 함께 따라간다.
## 클릭과 시간

한 번 클릭하면 그래프가 한 단위(대사 한 줄) 진행하고 다음 대사에서 멈춘다. 클릭은 연출 대기 중이면 막지 않는 효과를 끝 모습으로 보내고 대사를 시작하며, 타이핑 중이면 글을 다 보이고, 다 나왔으면 다음 대사로 간다.

**효과 시간 보장.** 효과마다 '진행 중 클릭 막기'가 있고 기본으로 켜져 있다(음악·효과음은 꺼짐). 켜진 효과가 도는 동안(시작 전 기다림 포함) 클릭과 선택은 무시된다. 끄면 그 효과는 클릭으로 끝 모습까지 건너뛴다. 연타로 두 줄씩 넘어가지 않도록 클릭을 받은 뒤 잠깐(0.12초) 다음 클릭을 무시한다.

**대사 넘기는 방식.** 대사 노드의 '넘기는 방식': 클릭 / 시간 진행(클릭 무시: 글이 다 나오고 머무는 시간 뒤 스스로 넘어가는, 애니메이션처럼 흐르는 대사) / 시간 진행(클릭 가능). 머무는 시간은 막는 효과가 끝난 뒤부터 잰다.

**자동 진행**(`DialoguePlayer.autoMode`, `autoDelay`): '클릭' 대사가 다 나오고 막는 효과가 끝나면 지연 뒤 클릭한 것으로 친다. **스킵**(`SkipToChoice`): 막는 효과까지 모두 끝 모습으로 보내며 다음 선택지가 뜰 때까지(또는 다이얼로그 끝까지) 건너뛴다. 지나가는 줄의 효과음·이펙트·목소리는 내지 않고, 값 바꾸기·신호는 그대로 한다.

**값 바꾸기가 실패하면**(골드가 모자람처럼 `Game.Fail`): 그 대사를 떠나기 전에 다음 대사까지의 값 바꾸기를 미리 해 보고(미리보기 — 아무것도 남지 않는다), 실패하면 실패 글을 알림으로 보이고 그 대사에 머문다. 선택지면 다른 것을 고를 수 있다. 고른 선택지·결정은 이동이 끝까지 됐을 때만 남는다.

## 미리보기

다이얼로그 그래프 창 위의 막대: '▶ 선택한 노드부터'(노드를 고르지 않으면 시작 노드부터), 일시정지, 시간 막대, 다음(클릭), 자동, 선택지까지 스킵, 정지. 연출 프리셋 창은 '▶ 프리셋 재생'. 실제 화면으로 보이도록 플레이 모드에서 씬의 `DialoguePlayer`로 재생한다(씬에 없으면 다이얼로그 UI 템플릿 프리팹을 잠시 꺼내 쓴다). 효과 노드를 골라 재생하면 그 효과 체인만 돈다.

시간 막대를 끌면 일시정지하고 그 시점으로 간다: 처음부터 다시 시작해 그 시점까지 클릭 없이 감으므로, 3초짜리 효과를 1.5초에 놓으면 50% 지점부터, 그 사이 늦게 시작된 효과도 각자의 진행도에서 이어진다. 트윈으로 그리는 모든 효과(배경·어둡게·스탠딩·카메라·흔들기·UI 모션 …)가 정확히 맞고, 스파인 애니메이션과 파티클은 자기 시간으로 흐르므로 이동한 시점에서 처음부터 다시 돈다. 감는 동안 '클릭' 대사는 글이 다 나오고 막는 효과가 끝나면 바로(`DialoguePlayer.previewClickDelay`초 뒤) 넘어간 것으로 치므로, 여러 줄에 걸친 시점으로도 바로 간다. 선택지가 나오면 그 앞에서 멈춘다. 감는 동안은 값 바꾸기·신호를 하지 않고(시간을 옮길 때마다 살아 있는 세션의 값이 쌓이지 않게), 지나간 한 번짜리 연출도 내지 않는다. 미리보기는 판 저장의 다이얼로그 진행 칸을 건드리지 않는다.

## 음성·오디오

다이얼로그는 코어 오디오(`GameAudio`, `Documentation~/Audio.md`)를 쓴다: 배경 음악 → 브금 채널(다이얼로그가 끝나면 다이얼로그 전 브금으로 — 음량·반복 포함), 효과음 → 효과음 채널, 대사의 '목소리' → 목소리 채널(목소리 없는 대사에서 멈춤, 자동 진행은 목소리가 끝날 때까지 기다린다). 다이얼로그가 끝나면 목소리를 멈추고 브금·카메라를 되돌린다(`DialogueStage.clearOnEnd`를 꺼도 — 그 설정은 배경·스탠딩·이미지·어둡게·레터박스를 남길지만 정한다).
## 장소·화자·등장인물

배경은 **장소**를 고른다(DB '장소': 배경 이미지 + 이름 `<id>.name` + 추가 글). 그 자리에만 다른 그림이 필요하면 '예외 배경 이미지'. 지금 장소는 상태(`StageState.location`)에 남고, UI의 `dialogue-extra-location` 요소에 장소 이름이 보이며(템플릿 왼쪽 위), 시트에도 나간다. 스탠딩 등장 = 그 캐릭터 등장이고, 여러 명이 동시에 나와 각자 자리·표정·강조를 따로 가진다.

대사의 화자는 대사와 스탠딩을 묶지 않는다. 화자는 스탠딩 프로필(나와 있든 없든), '다른 이름'(???, 병사 A처럼 프로필 없이 이름만; 번역 키 `<대사 키>.speaker`), 해설(이름 없음) 중 하나이고, '생각'을 켜면 속마음(UI 클래스 `dialogue--thought`)이다. **화자 자동 강조**(기본 켬, `DialogueRunner.AutoHighlightSpeaker`): 화자가 나와 있으면 화자만 밝게·나머지 어둡게, 화자가 없거나 해설이면 모두 원래대로. 대사 노드에서 '그대로'를 고르면 그 줄은 건드리지 않는다.

## 시트

`MomoiProject › 다국어 › 시트 내보내기 (CSV)`에 다이얼로그 대본이 함께 나간다: 다이얼로그마다 재생 순서대로(분기·선택지는 차례로 모두) 대사·선택지 한 줄씩, 문맥 열 `dialogue`(다이얼로그 ID) · `location`(그때 장소 이름) · `speaker`(화자 이름, '(생각)', 해설, 선택지는 '▶ 선택지'), 원문 칸은 그래프의 원문, 메모 칸은 대사 노드의 '메모'. 그 밖의 연출은 내보내지 않는다(필요하면 메모에 적는다). 화자 다른 이름·추가 글·프로필과 장소의 추가 글, 원문 표에 아직 없는 프로필·장소 이름도 함께 나간다. 가져올 때 다이얼로그 키의 원문 칸은 읽지 않는다(원문은 그래프가 기준). 코어는 다이얼로그를 모르고, 다이얼로그 시스템이 `ITextSheetSource`로 행을 더한다.

## 이전 시스템의 연출 조각

배경 검은 화면 경유의 **유지 시간**(진행 시간 안에 포함, 검은 동안 배경이 바뀜), **창 모드 스탠딩**(등장 또는 '창 바꾸기'에서 창 이미지·창 모양 마스크를 주면 창 안에만 보인다, 스프라이트 스탠딩), **이미지 창**('이미지 표시'·'이미지 지우기': 자리마다 CG 한 장, 나타나기·바꾸기·이동·크기).

## 다이얼로그 관리자

`Dialogues.Play("다이얼로그 ID")`를 어디서든 부른다. 씬에 `DialoguePlayer`가 있으면 그것을, 없으면 설정(`Assets/MomoiProject/Data/Resources/MomoiProject/DialogueSettings.asset`, 다이얼로그 UI 템플릿을 만들 때 함께 생성)의 프리팹을 만들어 씬이 바뀌어도 남겨 둔다. 게임 시작 때 미리 만들어 숨겨 두므로(설정에서 끌 수 있다) 첫 다이얼로그도 바로 뜬다. 보상·값 바꾸기 블록 **'다이얼로그 재생'**으로 코드 없이 연다(도전과제 달성 연출 등). 이 블록은 규칙 안에서 바로 열지 않고 요청 이벤트(`DialoguePlayRequested`)를 쏜다: 행동이 성공한 뒤에 열리고(미리보기·`CanDo`·실패한 행동에서는 열리지 않음), 멀티에서는 그 행동을 한 플레이어 화면에서 열리며, 스냅샷 되감기가 도전과제 보상을 다시 줄 때는 다시 열지 않는다.

## 저장

다이얼로그 진행(시작 위치, 분기 결과·고른 선택지·프로젝트 흐름 노드가 고른 점·'고를 선택지 없음'으로 간 줄의 순서, 지난 대사 수)이 세션 상태 `dialogue.progress`에 남아 판 저장(run.json)에 함께 들어간다. 판을 불러온 뒤 `Dialogues.ResumeSaved()`를 부르면 같은 길을 조용히 다시 밟아(값 바꾸기·신호·프로젝트 노드의 `Run`은 다시 하지 않고, 분기·선택지 조건도 지금 값으로 다시 보지 않고 기록한 결정을 따른다 — 산 뒤 골드가 줄어 숨은 선택지도 그대로) 저장한 대사부터 이어 간다. 화면(장소·스탠딩·이미지·카메라 …)은 지나온 연출의 끝 모습으로 맞춰지고, 지나온 줄의 효과음·이펙트는 내지 않는다. 길이 맞지 않아 이어 가지 못하면 거짓을 돌려주고 저장된 진행은 그대로 둔다.

멀티플레이: 진행은 플레이어마다 `dialogue.progress:<번호>` 칸(그 플레이어만 보는 칸)에 행동(`DialogueProgressAction`)으로 남는다. 클라이언트의 값 바꾸기는 서버 결과를 기다린 뒤 흐름을 이어 가고(뒤의 조건 분기·`{값}`이 바뀐 값을 읽는다, 거절되면 그 대사로 돌아온다), 서버는 그 플레이어가 마지막으로 알린 대사에서 실제로 닿는 값 바꾸기만 한 번씩 실행한다.

## 대사 로그

로그 버튼이나 글상자 위에서 휠을 위로 굴리면 열린다. 위에서 아래로 읽는 목록이고 가장 최근 줄부터 보인다. 줄마다 말하는 이 · 얼굴(정사각형: 프로필의 '로그 얼굴' → 그때의 스탠딩 그림 → 기본 스탠딩, 스파인은 로그 얼굴을 넣는다) · 대사, 내가 고른 선택지는 오른쪽 정렬이다. 로그를 보는 동안 다이얼로그 시간은 멈춘다. 줄 모양은 `DialogueUI.logEntryTemplate`(UXML)로 바꿀 수 있다.

## 그래프 편집

빈 곳을 끌면 범위 선택(Shift로 더하기), 가운데 버튼·Alt·Space를 누르고 끌면 화면 이동. Ctrl+C·Ctrl+V는 다른 다이얼로그·프리셋 창으로도 되고(그 그래프에서 못 쓰는 노드는 건너뜀), Ctrl+D는 선과 함께 복제, Ctrl+F는 노드 찾기(종류·요약·대사 글). '정리' 분류의 **메모**와 **그룹 상자**(제목·색, 머리를 끌면 안의 노드도 함께, 오른쪽 아래로 크기)는 실행에 영향이 없다.

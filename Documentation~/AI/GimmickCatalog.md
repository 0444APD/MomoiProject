# 기믹 목록 (AI용)

GBible 프로젝트의 기믹은 네 게임이 보여 주는 범위 안에 있다고 본다: **발라트로·와일드프로스트·매지크래프트·세피리아**. 이것은 기믹(규칙의 다양성)의 범위일 뿐이다. 장르·화면·시간 방식·싱글/멀티는 자유다. 아케이드·비주얼 노벨·보스 러시·탄막 피하기 위에 이 네 게임의 기믹이 얹힐 수 있다.

- 기획 명세서의 효과 문장은 이 목록의 **갈래**(2절)로 쪼갠다. 갈래마다 정해진 GBible 부품으로 만든다.
- 명세서 4-2 '메인 룰 구조'에 표시된 것은 시스템층에서 **자리**를 먼저 만든다(3절). 자리를 미리 만들면 콘텐츠 단계에서 예외 코드가 생기지 않는다.
- 갈래에 없는 기믹은 4절 기준으로 판단하고, 필요하면 묻는다.
- DB 칸의 이름표는 코드 변수 이름이다(한글 이름은 마우스를 올리면 보인다). 이 문서는 `변수`(한글)로 적는다.
  - 패시브 효과: `ownerKey`·`ownerPath`(가진 목록 — 플레이어 데이터 키·경로) · `holderField`(가진 쪽 필드 — 이벤트·행동 직전 이벤트의 이 필드가 가진 쪽 id일 때만 발동) · `matchField`(일치 필드) · `matchVia`(원본에서 읽기) · `perElement`(놓인 것마다) · `levelField`(레벨 필드) · `rules`(발동 더) · `pulse`·`pulseByLevel`(주기) · `modifiers`(가진 동안 스탯 보정 — 줄마다 `perLevel` 레벨마다 · `byLevel` 레벨별 값 · `target` 받을 대상) · `modifierTarget`(보정 받을 대상) · `modifierWhen`(보정 조건) · `stacking`(여럿일 때)
  - 상태 효과: `kind`(종류) · `silencesPassives`(걸린 쪽의 패시브 효과를 끔). 가중치 표에서 고르기: `countBonus`(후보 수에 더할 숫자)
- 이 문서에서 '레벨'은 GBible 패시브 효과 레벨(1부터, 0 이하 = 꺼짐)이다. 원작의 ★(0부터)·콤보 개수와 섞지 않는다.

## 1. 뼈대 — 놓인 것들이 자리를 갖고, 정해진 순서로 발동한다

네 게임의 메인 룰은 모두 같은 모양이다. **조각**이 **자리**에 놓이고, 메인 룰이 정한 **순서**로 발동한다. 시스템층은 이 메인 룰 하나를 행동·규칙 함수로 만든다. 조각 하나하나의 효과는 DB(패시브 효과·액티브 효과·상태 효과)에 둔다.

| 게임 | 조각 → 자리 | 순서 | GBible에서 |
|---|---|---|---|
| 발라트로(턴제) | 조커 → 조커 칸(한 줄), 카드 → 핸드 | 족보 → 낸 카드 왼쪽부터(카드마다 조커 왼쪽부터) → 손에 든 카드 → 조커 독립 효과 | 행동 `PlayHand`가 단계마다 이벤트를 쏜다. 조커 = 패시브 효과 '놓인 것마다'라 칸 순서대로 발동한다. 칩·배수는 판 데이터의 점수 칸 |
| 와일드프로스트(턴제) | 유닛 → 보드(양편, 3칸 깊이 × 위·아래 2줄), 참(Charm) → 덱 카드에 붙임 | 적 보드 → 내 보드, 각 보드 앞 칸 위→아래 → 가운데 → 뒤(열 우선). 카운터가 0이 되면 발동 | 보드 목록을 **열 우선으로 담는다**(줄 길이 2, 앞 칸부터) → 목록 순서 = 턴 순서이고, 원작의 '같은 줄(레인)'이 여기서는 '같은 열'이다. 턴 행동이 목록 순서로 돌며 카운터 필드를 줄이고, 0이면 `Game.TryUse`(유닛 액티브 효과). 반응 = 패시브 효과 '놓인 것마다' + 가진 쪽 필드. 공격 대상 = '자리로 고르기'(다른 목록, 같은 열 맨 앞). 키워드 = 유닛의 글자 목록(`matchField`). 참 = 붙이는 순간 덱 카드 필드를 한 번 바꾸는 액티브 효과(가진 동안 보정이 아님) |
| 매지크래프트(실시간) | 주문 → 지팡이 칸(지팡이마다 한 줄), 유물 → 유물 목록 | 왼쪽부터 읽는다. 강화는 다음 발사 주문에 붙고, 연계는 왼쪽 주문이 끝나거나 맞힐 때 오른쪽을 쏜다 | 규칙 함수(주문 해석기)가 시전 계획을 만든다. 계획 틀은 칸 배치가 바뀔 때만 판 데이터에 쓰고, 화면의 발은 (틀, 노드, 발 번호)만 들고 다니다 끝남·명중을 판정 보고 행동으로 보낸다. 해석기가 연계를 시전하고, MP는 `Game.TryPay`(틱 묶음 안에서 모자라면 그 연계만 건너뜀) |
| 세피리아(실시간) | 아티팩트·석판 → 가방 격자(6열) | 배치가 바뀌면 레벨·제약·콤보를 다시 계산한다. 전투 중에는 이벤트·주기로 발동 | 배치 행동 끝의 계산 함수가 석판 무늬(`Placement.Pattern`, 회전)로 레벨을 더하고 제약(`Placement.Is`)을 본다. 결과는 **조각마다 최종 레벨 필드**(제약으로 꺼지면 0)와 '콤보 수' 딕셔너리. 아티팩트 = 가방 목록 자체를 가진 목록으로 삼는 패시브 효과(`levelField` = 최종 레벨). 원작 ★0부터면 최종 레벨 = ★+1 |
| 연쇄형(매치-3 · 테트리스류 — 네 게임 밖의 메인 룰 모양) | 조각 → 보드 칸 데이터(`Grid` 칸 키 딕셔너리 `Dictionary<string, 조각>` 또는 줄 목록 + 줄 길이) | 묶음 찾기 → 지우기 → 떨어짐 → 채우기를 연쇄가 끝날 때까지 | 메인 룰 행동(옮기기·떨어뜨리기 하나)이 네 단계를 연쇄가 끝날 때까지 돌며 단계마다 이벤트를 쏜다(지움 — 지운 칸 · 개수, 콤보 수). 판정 자리 = 행동 직전 이벤트(지우기 규칙 — 몇 개부터 · 모양, 새 조각 — 무엇이 떨어지나, 콤보 배율). 조각의 효과(특수 블록 · 스킬)는 DB(패시브 효과 · 액티브 효과). 연쇄의 중간 모습 연출은 단계 이벤트에 그때의 사본을 싣는다(매뉴얼 32장 2-2) |

**조각 데이터의 모양**:

| 무엇 | 어디에 |
|---|---|
| 판의 조각 | 객체 목록. 객체마다 고유 `id` + 원본 ID 필드(`joker`·`card`·`artifact`) + 쌓이는 값(`mult`·`counter`) + 레벨. 같은 조각을 둘 가질 수 있다 |
| 등급·최대 레벨·콤보 태그·제약 같은 고정 값 | 원본(DB › 인스턴스) |
| 조각의 패시브 효과 | 원본이 DB 항목이 아니면(판 데이터의 원본 ID만 — 조커) 원본 ID가 곧 패시브 효과 ID → `matchField` = 원본 ID 필드. 원본이 DB › 인스턴스면 ID가 겹칠 수 없으므로(DB ID는 종류를 통틀어 하나) 패시브 효과는 `원본.fx`(명명 가이드라인 1-1)이고 원본의 패시브 효과 ID 칸에 적는다 → `matchField` = 원본 ID 필드 + `matchVia` = 원본의 패시브 효과 ID 목록 필드(원본 하나에 패시브 효과 여럿인 유닛도 같다). 판에서 붙는 것(참이 더한 키워드) → 조각의 글자 목록 필드 |

켜진 목록을 계산할 때마다 새로 만들지 않는다. 새로 만들면 조각에 쌓인 값이 사라진다. 꺼짐은 레벨 0으로 나타낸다.

**다른 갈래 — 일정형**(미연시 · 생활 시뮬): 조각이 칸에 놓이는 대신 **날짜 · 하루의 칸(아침 · 낮 · 밤)이 판을 이끈다.** 자리 = 일정(판 데이터의 날짜 · 칸 필드), 순서 = 칸 차례, 플레이어의 행동(데이트 · 일 · 공부)이 칸을 쓰고 칸이 넘어갈 때 그 날짜 · 칸의 이벤트가 온다(이벤트 표 — 진행 매뉴얼 9절). 시스템층이 만드는 것: 칸 넘김 행동(칸 · 하루가 바뀌면 이벤트를 쏜다 — 상태 효과 · 패시브 효과의 셀 이벤트가 된다) · 그 칸의 이벤트를 고르는 규칙 함수 · 마지막 칸의 엔딩 판정. 단계 0에 묻는 것: 이벤트가 칸(시간)을 쓰나 · 한 칸에 이벤트가 여럿이면 차례(모두 차례로 — 다이얼로그는 행동이 연 차례대로 열린다 / 하나만) · 마지막 칸과 엔딩(어느 칸에 무엇으로 정하나) · 칸 · 하루 · 주가 지나면 무엇이 초기화되나(행동 횟수 · 하루 한 번 이벤트).

## 2. 갈래 → GBible

이름은 DB에 보이는 그대로다(효과·조건·대상 Block, 패시브 효과 칸, 행동 직전 이벤트). "시스템층"은 메인 룰을 만들 때 미리 둘 것이다. 장르와 상관없는 기본 문법(받는 피해 −5·면역·대신 맞기·반사·쿨다운 …)은 `PlanningSpecGuide.md` 7절에 있다.

### 2-1. 자리·순서

| 기믹 | 네 게임의 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 놓인 순서대로 발동 | 조커 +배수 다음 ×배수, 보드 앞 칸부터 | 패시브 효과 '놓인 것마다'. 같은 목록을 보는 패시브 효과끼리 목록 순서로 섞여 발동하고, 사용자 = 그 조각. 경로에 `[]`(`wands[].slots`)면 모든 목록이 한 줄로 이어진 순서 | 조각 목록 = 객체 목록. 순서가 열 우선이면 목록을 열 우선으로 담는다 |
| 옆 칸·같은 줄·주변 | Blueprint의 오른쪽, Brainstorm의 맨 왼쪽, 레이에 별조각의 왼쪽 칸, 조화의 수정의 주변 8칸, 헌신의 휘장의 같은 줄 | 대상 '자리로 고르기'(방향·거리·줄 길이), 코드 `Placement.Around`. 기준 없이 목록 전체(핸드 맨 오른쪽) = 기준 '없음' | 목록마다 줄 길이(한 줄 0, 가방 6, 와일드프로스트 보드 2) |
| 맞은편을 겨눔 | 와일드프로스트 공격 = 맞은편 레인 맨 앞, Longshot = 맨 뒤, Barrage = 레인 전체 | '자리로 고르기'의 '다른 목록에서 고르기' + 같은 열 맨 앞·같은 열 맨 뒤·같은 열(열 우선 보드). 플레이어마다 칸(`players[].charms`)이면 기준이 든 목록, 맞은편도 같은 순번 | 양편 보드 목록 |
| 자리 조건 | 은접시(맨 아래 줄), 차가운 자물쇠(양옆 빈 칸), 용골 파편(가장자리), Fury(레인에 혼자) | 조건 '자리 검사'. 발동이면 트리거와 AND, 가진 동안 보정이면 패시브 효과 `modifierWhen`(보정 조건) | — |
| 다른 칸의 레벨 바꾸기 | 석판(무늬·회전·줄 전체·끝 칸일 때만), 친타마니(칸 레벨 +3) | 계산 함수에서 `Placement.Pattern(칸, 개수, 열, 무늬, 회전)`(줄 밖 칸은 버린다) → 칸마다 보너스 → 최종 레벨 | 칸 레벨 목록, 석판의 무늬·회전 필드 |

### 2-2. 반복·배율

| 기믹 | 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 액티브 효과를 한 번 더(재발동·광란·추가 발동) | Frenzy, 얼음무구 추가 발동, Multi-Shot | 행동 직전 이벤트 '사용' 받기 → `times` 더하기 1(`{level}` 가능) | 조각의 발동을 `Game.Use`·`Game.TryUse`로 |
| 메인 룰 단계를 한 번 더 | Hack·Mime·Seltzer(카드 점수 재발동), Arcane Nova(발 수 ×20, 피해 반) | 그 단계의 행동 직전 이벤트(재발동 행동 직전 이벤트·발 수 행동 직전 이벤트의 `times`)를 패시브 효과가 행동 직전 이벤트를 받아 고친다 | 단계마다 반복 횟수 행동 직전 이벤트 |
| 효과 수치 배율 | Lumin(이 카드 수치 2배), Critical(맨 오른쪽이면 2배) | 행동 직전 이벤트 '효과 배율' 받기 → `multiplier` 곱하기 2. Lumin = 상태 효과(가진 쪽 필드 `userId`), Critical = 놓인 것마다 패시브 효과(가진 쪽 필드 `userId`) + 조건 '자리 검사'(목록 맨 끝). 액티브 효과를 쓸 때·패시브 효과가 발동할 때 한 번 거치고, 기본 효과 Block이 곱한다 | 프로젝트 효과 Block은 수치에 `Use.Context.Power`를 곱한다 |
| 동사 하나만 배율 | 받는 피해 2배, 회복 ×1.3 | 그 동사 행동 직전 이벤트의 `amount` 곱하기 | 동사 행동 직전 이벤트에 양·횟수 필드 |

### 2-3. 복사·흉내

| 기믹 | 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 다른 조각의 패시브 효과를 빌려 씀 | Blueprint(오른쪽), Brainstorm(맨 왼쪽) | 결과 '빌려 쓰기'(빌릴 조각 = 자리로 고르기). 원본 조각의 값을 읽고(사용자 = 원본), 원본 자신의 쌓이는 값은 바꾸지 않고, 서로 빌리는 고리는 끊는다. 가진 쪽 필드는 빌리는 쪽 기준("이 조커의 차례" 이벤트, 빌린 결과 안에서 또 빌리면 처음 빌린 조각 — Brainstorm → Blueprint). 코드는 `Game.BorrowPassive(ID, 원본)` | — |
| 메인 룰이 읽는 조각을 흉내 | Mimicry Cube(오른쪽 주문을 자기 레벨까지), Autonomous Grimoire(오른쪽 주문을 기록해 소환수가 씀) | 메인 룰(주문 해석기)이 오른쪽 조각을 한 번 더 읽는다 | 3절 '빌려 쓰기' 자리 |

### 2-4. 변환·대체

| 기믹 | 예 | GBible로 | 시스템층 |
|---|---|---|---|

### 2-9. 가진 동안의 스탯

| 기믹 | 예 | GBible로 |
|---|---|---|
| 가진 동안 +N | 힘의 부적(물리 피해 +2/3/4/6), Merlin's Hat(최대 MP +30) | 패시브 효과 '가진 동안 스탯 보정'(칸·값, 레벨마다 또는 레벨별 값, 보정 받을 대상). 트리거가 없어도 된다. 잃으면 저절로 빠진다 |
| 장비를 낀 동안 +N | 철검(공격력 +5), 가죽 갑옷(방어력 +3) | 같은 패시브 효과 '가진 동안 스탯 보정' — 가진 목록 = 장비 칸(`hero.equipped` · `units[].equipped`), `matchField` = 원본 ID 필드, 패시브 효과 ID는 `원본.fx`(원본이 인스턴스면 `matchVia` — 1절). 보정 받을 대상은 비운다 — 가진 쪽 = 장비 칸을 품은 유닛이 받는다. 벗으면(목록에서 빠지면) 저절로 빠진다. `Game.AddModifier`·`RemoveModifiers`로 낄 때 붙이고 벗을 때 떼지 않는다(그것은 코드가 잠깐 거는 보정 — 매뉴얼 28장) |

| 조건일 때만 +N | Fury(레인에 혼자), Berserker(체력 절반 이하), 든 지팡이일 때만 | `modifierWhen`(보정 조건) — 읽을 때 가진 쪽마다 검사 |
| 같은 것이 여럿 | 같은 아티팩트 둘(값을 따로 더함), [고유](가장 높은 하나만) | `stacking`(여럿일 때): 레벨 합 / 가진 쪽마다 값 / 가장 높은 하나 |
| 여러 곳에 | 모든 동료 +2, 지팡이마다 다른 스탯 | 보정 받을 대상 `party[]`(그 모두), 보정 줄마다 `target` |
| 받는 쪽이 조건에 맞을 때만(시너지) | 불 속성 동료만 공격 +2, 기사 셋이면 기사마다 방어 +5 | 보정 줄의 `receiverWhen`(받는 쪽 조건) — 받는 대상마다 사용자로 놓고 검사(`party[]` 중 참인 것만). 가진 쪽을 보는 `modifierWhen`과 다르다. "셋이면"은 조건 안에서 판 데이터의 수를 센다 |
| 같은 원본의 조각마다 | 렌즈 건물마다 생산 +10%, 같은 카드 모두 +1 | 보정 받을 대상 `buildings[template=lens]`(필드 거르기 — 그 필드가 그 값인 요소 모두, 매뉴얼 11장 3-1) |

### 2-13. 2인 대전(멀티 — 명세서 0절이 '있음')

| 기믹 | 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 내 것 / 상대 것 | 내 유닛 모두 +1, 상대 하수인 하나에 피해 | 조각의 주인 칸(`owner` — 플레이어 번호)을 비교한다. 조건 '사용자 필드 검사'는 값 틀 `{event:player}`(받은 이벤트의 플레이어 필드)와 비교한다. 대상 '조건으로 거르기'는 값 틀을 펼치지 않으므로, "상대 것 모두"는 프로젝트 대상 Block(`TargetSelector` — 주인 ≠ 그 행동의 `actorId` 또는 이벤트의 `player`)으로 만든다 | 조각마다 주인 칸, 이벤트마다 `player` 필드, '내 것 / 상대 것' 대상 Block |
| 숨긴 조각(비밀) | 놓은 사람만 내용을 알고 상대에게는 개수만 | 비밀 목록 = 플레이어마다 데이터 '그 사람에게만 보임', 상대에게 보일 개수 = 공개 칸을 그 행동 안에서 함께 고침(매뉴얼 40장 1-2). 발동은 '놓인 것마다' 패시브 효과 + 공개 결과(드러날 때 공개 이벤트·공개 칸으로 옮긴다) | 비밀 목록(플레이어마다) · 공개 개수 칸 |
| 상태 효과 지속을 '가진 쪽 주인의 턴'으로 셈 | 내 턴이 끝날 때만 줄어드는 독 | 턴 끝 행동이 그 주인의 조각마다 이벤트(`UnitTurnEnded { unitId }` 같은)를 쏘고, 상태 효과의 셀 이벤트 + 가진 쪽 필드(`unitId`)로 거른다 — 가진 쪽 필드는 id와 같은 글자만 거르므로 주인 번호로는 거를 수 없다 | 조각마다 턴 끝 이벤트 |

## 3. 메인 룰에 미리 둘 자리

명세서 4-2 '메인 룰 구조'에서 표시된 것은 시스템층이 자리를 만든다. 표시가 없는데 콘텐츠 단계에서 나오면 그때 메인 룰을 고친다(예외 코드로 덧붙이지 않는다).

| 표시 | 메인 룰에 둘 것 |
|---|---|
| 다른 것의 액티브 효과를 빌려 쓴다 | 조각이 패시브 효과면 이미 된다(결과 '빌려 쓰기'). 메인 룰이 해석하는 조각(주문 칸 같은)이면 해석기에 "이 칸이 가리키는 조각을 한 번 더 읽기"와 레벨 한도·고리 끊기 |
| 놓인 순서·위치가 효과를 바꾼다 | 조각 목록 = 객체 목록(1절 '조각 데이터의 모양'), 줄 길이, 순서가 열 우선이면 열 우선으로 담기 |
| 한 조각이 여러 칸을 차지한다 | 조각에 크기 필드. 계산 함수가 칸을 셀 때 반영(목록에는 머리 칸만 두고 나머지 칸은 '차지됨' 표시) |
| 위치·조건으로 태그·속성이 바뀐다 | 계산 함수에 "태그 정하기" 단계(세기 전에) |
| 자원을 다른 곳에서 내거나 나눠 쓴다 | 모든 지불을 `Game.Pay`·`Game.TryPay` 하나로(행동 직전 이벤트 '비용 지불' 받기가 `key`·`path`·`floor`를 바꾸고, `forId`·`userId`로 거른다) |
| 효과가 반복 발동한다 | 조각 발동은 `Game.TryUse`(행동 직전 이벤트 '사용' 받기의 `times`), 메인 룰 단계에는 반복 횟수 행동 직전 이벤트 |
| 판정 규칙이 바뀐다 | 판정 함수 안의 스위치(`Game.Owned`)를 한곳에 |
| 반응은 발동이 끝난 뒤에 | 반응 대기열: 패시브 효과 결과(프로젝트 Block)는 대기열에 넣기만 하고, 메인 룰이 조각 발동이 끝날 때마다 턴 순서로 비운다 |

이미 되는 것(자리 불필요): 발동 중에 목록이 바뀜('놓인 것마다'는 그 순간 남은 조각만), 효과 수치 배율(프로젝트 Block이 `Use.Context.Power`를 곱하기만 하면 됨), 조각 끄기(침묵 상태 효과·레벨 0).

## 4. 이 목록 밖

- **네 게임의 범위를 넘는 기믹은 아니지만 GBible 밖인 것**: 물리 판정 자체(궤도·유도·반사·튕김·끌어당김·충돌·대시·가드)는 화면(Unity)이 맡는다. 규칙은 결과만 받는다(판정 보고 행동, 관례 3절).
- **물어야 하는 것**: 규칙이 화면의 결과 없이 물리 결과를 알아야 하는 것, 저장을 넘어 과거로 되감기, 되감은 뒤 난수를 다시 굴리기. 관례 13절대로 표시하고, 만드는 방법(화면 쪽·별도 시스템·근사)과 비용을 붙여 묻는다.
- 장르 부품(대화·달력·현실 시간·칸 맵·큰 수·키 바꾸기 …)은 기믹이 아니라 **부가 기능**이다. 명세서 6절에서 켜면 붙는다(참조 문서 2-6). 단 달력이 판을 이끄는 게임(행동이 시간을 쓰고 정해진 날에 이벤트가 온다)은 달력이 메인 룰이다 — 1절 '일정형'. 대화 모듈의 지금 동작(대사 진행은 행동 밖 등)은 매뉴얼 24장 8절 '현재 동작'.

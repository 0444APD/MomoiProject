# 기믹 목록 (AI용)

GBible 프로젝트의 기믹은 네 게임이 보여 주는 범위 안에 있다고 본다: **발라트로·와일드프로스트·매지크래프트·세피리아**. 이것은 기믹(규칙의 다양성)의 범위일 뿐이다. 장르·화면·시간 방식·싱글/멀티는 자유다. 아케이드·비주얼 노벨·보스 러시·탄막 피하기 위에 이 네 게임의 기믹이 얹힐 수 있다.

- 기획 명세서의 효과 문장은 이 목록의 **갈래**(2절)로 쪼갠다. 갈래마다 정해진 GBible 부품으로 만든다.
- 명세서 4절 '메인 룰 구조'에 표시된 것은 시스템층에서 **자리**를 먼저 만든다(3절). 자리를 미리 만들면 콘텐츠 단계에서 예외 코드가 생기지 않는다.
- 갈래에 없는 기믹은 4절 기준으로 판단하고, 필요하면 묻는다.

---

## 1. 뼈대 — 놓인 것들이 자리를 갖고, 정해진 순서로 발동한다

네 게임의 메인 룰은 모두 같은 모양이다. **조각**이 **자리**에 놓이고, 메인 룰이 정한 **순서**로 발동한다. 시스템층은 이 메인 룰 하나를 행동·규칙 함수로 만든다. 조각 하나하나의 효과는 DB(패시브·능력·상태 효과)에 둔다.

| 게임 | 조각 → 자리 | 순서 | GBible에서 |
|---|---|---|---|
| 발라트로(턴제) | 조커 → 조커 칸(한 줄), 카드 → 손패 | 족보 → 낸 카드 왼쪽부터(카드마다 조커 왼쪽부터) → 손에 든 카드 → 조커 독립 효과 | 행동 `PlayHand`가 단계마다 이벤트를 쏜다. 조커 = 패시브 '놓인 것마다'라 칸 순서대로 발동한다. 칩·배수는 판 데이터의 점수 칸 |
| 와일드프로스트(턴제) | 유닛 → 보드(2줄 × 3칸, 양편), 참 → 카드의 참 목록 | 적 먼저, 줄마다 앞에서 뒤로. 카운터가 0이 되면 발동 | 턴 행동이 보드를 `Placement` 순서로 돌며 카운터 필드를 줄이고, 0이면 `Game.TryUse`(유닛 능력)를 부른다. 반응 = 패시브 '놓인 것마다' + 가진 쪽 필드. 공격 대상 = '자리로 고르기'(맞은편 같은 줄 맨 앞) |
| 매지크래프트(실시간) | 주문 → 지팡이 칸(한 줄), 유물 → 유물 목록 | 왼쪽부터 읽는다. 강화는 다음 발사 주문에 붙고, 연계는 왼쪽 주문이 끝나거나 맞힐 때 오른쪽을 쏜다 | 규칙 함수(주문 해석기)가 시전 계획을 만든다. 화면이 쏘고, 끝남·명중을 행동으로 보고한다(판정 보고 행동). 해석기가 연계를 시전하고, MP는 지팡이 필드에서 `Game.Pay` |
| 세피리아(실시간) | 아티팩트·석판 → 가방 격자(6열) | 배치가 바뀌면 레벨·제약·콤보를 다시 계산한다. 전투 중에는 이벤트·주기로 발동 | 배치 행동 끝의 계산 함수가 석판 무늬(`Placement.Pattern`, 회전)로 레벨을 더하고 제약(`Placement.Is`)을 본다. 그 결과로 '켜진 아티팩트'(id·원본 ID·레벨) 목록과 '콤보 수' 딕셔너리를 쓴다. 아티팩트·콤보는 그 목록을 가진 목록으로 삼는 패시브 |

조각 목록은 **객체 목록**으로 둔다. 객체마다 고유 `id`와 원본 ID 필드(`joker`·`card`·`artifact`)를 둔다. 그래야 같은 조각을 둘 가질 수 있고, 조각마다 쌓이는 값을 둘 수 있다. 패시브는 '일치 필드'로 원본 ID 필드를 본다.

## 2. 갈래 → GBible

이름은 DB에 보이는 그대로다(효과·조건·대상 Block, 패시브 칸, 의도). "시스템층"은 메인 룰을 만들 때 미리 둘 것이다. 장르와 상관없는 기본 문법(받는 피해 −5·면역·대신 맞기·반사·쿨다운 …)은 `PlanningSpecGuide.md` 7절에 있다.

### 2-1. 자리·순서

| 기믹 | 네 게임의 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 놓인 순서대로 발동 | 조커 +배수 다음 ×배수, 보드 앞에서 뒤로 | 패시브 '놓인 것마다'. 같은 목록을 보는 패시브끼리 목록 순서로 섞여 발동하고, 사용자 = 그 조각 | 조각 목록 = 객체 목록, 패시브 '일치 필드' |
| 옆 칸·같은 줄·주변 | Blueprint의 오른쪽, Brainstorm의 맨 왼쪽, 레이에 별조각의 왼쪽 칸, 조화의 수정의 주변 8칸, 헌신의 휘장의 같은 줄 | 대상 '자리로 고르기'(방향·거리·줄 길이), 코드 `Placement.Around` | 목록마다 줄 길이(한 줄 0, 가방 6, 보드 3) |
| 맞은편을 겨눔 | 와일드프로스트 공격 = 맞은편 같은 줄 맨 앞, Longshot = 맨 뒤, Barrage = 줄 전체 | '자리로 고르기'의 '다른 목록에서 고르기' + 같은 줄 맨 앞·맨 뒤·같은 줄 | 양편 보드 목록 |
| 자리 조건 | 은접시(맨 아래 줄), 차가운 자물쇠(양옆 빈 칸), 용골 파편(가장자리), Fury(같은 줄에 혼자), Critical(손패 맨 오른쪽 = 목록 맨 끝) | 조건 '자리 검사' | — |
| 다른 칸의 레벨 바꾸기 | 석판(무늬·회전·줄 전체·끝 칸일 때만), 친타마니(칸 레벨 +3) | 계산 함수에서 `Placement.Pattern(칸, 개수, 열, 무늬, 회전)` → 칸마다 보너스 → 최종 레벨 | 칸 레벨 목록, 석판의 무늬·회전 필드 |

### 2-2. 반복·배율

| 기믹 | 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 능력을 한 번 더(재발동·광란·추가 발동) | Frenzy, 얼음무구 추가 발동, Multi-Shot | 가로채기 '사용' → `times` 더하기 1(`{level}` 가능) | 조각의 발동을 `Game.Use`·`Game.TryUse`로 |
| 메인 룰 단계를 한 번 더 | Hack·Mime·Seltzer(카드 점수 재발동) | 그 단계의 의도(예: 재발동 의도 `times`)를 패시브가 가로챈다 | 단계마다 반복 횟수 의도 |
| 효과 두 배 | Lumin, Critical, Arcane Nova(×20, 피해 반) | 동사 의도의 `amount` 곱하기 | 동사 의도에 양·횟수 필드 |

| 기믹 | 예 | GBible로 | 시스템층 |
|---|---|---|---|
| 걸리는 상태 효과를 바꿈 | 화상 → 푸른 화상, 먹구름 → 눈보라 구름 | 가로채기 '상태 효과 걸기' + 의도 고치기 `statusId` 값으로 바꾸기 | — |
| 둘이 겹치면 하나로 | 화상 + 감전 → 플라즈마 | 가로채기 '상태 효과 걸기' + 조건 '상태 효과 검사'(이벤트의 개체 = `targetId`) → `statusId` 바꾸기, 이벤트 '상태 효과 걸림'에 남은 쪽 '상태 효과 풀기' | — |
| 능력치를 다른 능력치로 | 변환의 서, 날개(추가 공속 N%당 증폭), 가장 높은 속성 피해, 베루트의 낫(치명 100% 초과분 → 처형) | 프로젝트 능력치 함수 한 곳(`Rules.Stat`)이 `Game.Attribute`를 읽어 공식을 적용한다 | 능력치 함수(파생·변환 단계) |
| 위치에 따라 태그·속성이 바뀜 | 캘세더니 열쇠(줄마다 콤보), 대립의 천칭(왼편 화염·오른편 얼음), 영원의 식 | 계산 함수의 '태그 정하기' 단계 | 3절 '태그가 바뀜' 자리 |
| 진화(조건을 채우면 다른 것으로) | 버려진 금반지(특수 공격 40처치) → 절대반지 | 효과 '필드 바꾸기'(횟수 +1) + 조건(필드 검사) → `[BindTo]`가 원본 ID 필드를 바꾼다 | 조각 객체에 횟수 필드 |

### 2-11. 보상·선택·경제

| 기믹 | 예 | GBible로 |
|---|---|---|
| N개 중 고르기·건너뛰기 | 부스터 팩, 유물·주문 선택 | '가중치 표에서 고르기'(최소 0 = 건너뛰기) |
| 후보 +1 | Lucky Bunny Ear, Fortune Earrings | '후보 수에 더할 숫자'(플레이어 데이터) |
| 다시 뽑기 | Hexa-gonal Die, 상점 리롤 | `Game.RerollChoice(선택 id)` + 비용은 그 행동(`Game.Pay`) |
| 공짜·할인 | Black Mark, Astronomer, Chaos the Clown(상점마다 한 번) | 가로채기 '비용 지불' → 막기·곱하기, 한 번만이면 상태 효과(지속 = 이벤트 1번) |
| 판매가·이자·돈 비례 | Egg, Gift Card, To the Moon, Bull, Enchanting Coin | 숫자 필드 + 이벤트(라운드 끝) + '필드 바꾸기', 비례 계산은 `[BindTo]` |

## 3. 메인 룰에 미리 둘 자리

명세서 4절 '메인 룰 구조'에서 표시된 것은 시스템층이 자리를 만든다. 표시가 없는데 콘텐츠 단계에서 나오면 그때 메인 룰을 고친다(예외 코드로 덧붙이지 않는다).

| 표시 | 메인 룰에 둘 것 |
|---|---|
| 다른 것의 능력을 빌려 쓴다 | 빌려 쓰기 함수 하나(대상 조각의 패시브·능력을 지금 순간으로 검사하고 결과를 냄) + 서로 가리키면 끊는 방문 표시 + "복사 중" 표시(쌓는 결과는 원본만 쌓게 '필드 바꾸기' 앞에 조건) |
| 놓인 순서·위치가 효과를 바꾼다 | 조각 목록 = 객체 목록(고유 id + 원본 ID 필드), 줄 길이, 패시브 '놓인 것마다'·'일치 필드' |
| 한 조각이 여러 칸을 차지한다 | 조각에 크기 필드. 계산 함수가 칸을 셀 때 반영(목록에는 머리 칸만 두고 나머지 칸은 '차지됨' 표시) |
| 위치·조건으로 태그·속성이 바뀐다 | 계산 함수에 "태그 정하기" 단계(세기 전에) |
| 자원을 다른 곳에서 내거나 나눠 쓴다 | 모든 지불을 `Game.Pay` 하나로(가로채기 '비용 지불'이 `key`·`path`·`floor`를 바꾼다) |
| 효과가 반복 발동한다 | 조각 발동은 `Game.TryUse`(가로채기 '사용'의 `times`), 메인 룰 단계에는 반복 횟수 의도 |
| 판정 규칙이 바뀐다 | 판정 함수 안의 스위치(`Game.Owned`)를 한곳에 |
| 발동 중에 목록이 바뀐다 | 이미 된다: '놓인 것마다'는 그 순간 목록에 남은 조각만 발동한다 |

## 4. 이 목록 밖

- **네 게임의 범위를 넘는 기믹은 아니지만 GBible 밖인 것**: 물리 판정 자체(궤도·유도·반사·튕김·끌어당김·충돌·대시·가드)는 화면(Unity)이 맡는다. 규칙은 결과만 받는다(판정 보고 행동, 관례 3절).
- **물어야 하는 것**: 규칙이 화면의 결과 없이 물리 결과를 알아야 하는 것, 저장을 넘어 과거로 되감기, 되감은 뒤 난수를 다시 굴리기. 관례 13절대로 표시하고, 만드는 방법(화면 쪽·별도 시스템·근사)과 비용을 붙여 묻는다.
- 장르 부품(대화·달력·현실 시간·칸 맵·큰 수·키 바꾸기 …)은 기믹이 아니라 **부가 기능**이다. 명세서 6절에서 켜면 붙는다(참조 문서 2-6).

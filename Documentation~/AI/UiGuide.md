# UI 가이드 (AI용)

GBible로 만드는 **모든 프로젝트의 화면**에서 AI가 지키는 문법 · 레이아웃 · 디자인이다. 장르와 상관없이 같다. 프로젝트 명세서나 결정 기록이 다르게 정한 것만 그쪽을 따른다.

- 언제 읽나: 단계 2(UI·샘플)를 시작할 때 끝까지, 화면을 만들거나 고칠 때마다 해당 절(진행 매뉴얼 7절).
- 함께 보는 것: 관례 6절(화면·연출)·21절(화면 쪽 도구) · 매뉴얼 35장(화면)·24장(다이얼로그)·32장(씬 오브젝트) · `NamingGuide.md`(화면 글).
- 개발자는 **화면마다 전체 레이아웃만** 참고 그림으로 준다(세부 UI는 참고 대상이 아니다). 버튼 하나하나의 자리·크기 같은 세부는 묻지 않고 AI가 이 문서대로 정해 가안으로 올린다.
- 화면은 **UI 키트**(`Templates/UI/` — 키트 USS `Kit.uss` · 코드 `KitPanel` · `KitOutline` · `KitAccent` · `KitLine` · `KitIcon` · 견본 화면 `Samples/`)로 짠다. 프리팹이 아니라 프로젝트마다 복사해 쓰는 UI Toolkit 틀이다(2026-10-13 새로 — 옛 배치 A~H · 형식 A~D는 버렸다). **키트에는 범용 기능만** 두고 모양 · 색은 언제든 바꿀 수 있게 한다(개발자 2026-10-13) — 색은 `Kit.uss` 맨 위 변수(`--kit-…`), 시간 · 크기 · 모서리는 속성 · 매개변수, 견본 전용 모양은 `Samples/Samples.uss`.
- 화면 확인은 AI가 Unity를 직접 돌려서 한다(4절 — 플레이 요청 `Play.request`: 화면을 열고 누르고 찍어 그림으로 본다).

## 0. UI 템플릿 — 무엇이고 지금 어디까지

**UI 템플릿**(개발자 정의, 2026-10-12) = 앞으로의 모든 프로젝트에서 그 프로젝트의 UI 디자인이 확립되기 전에 임시로 쓰는 UI 디자인 · 양식 · 체계 · 규칙 전부. 이 문서와 UI 키트(`Templates/UI/`)가 그 그릇이다. 이루는 것:

- **샘플 리소스** — 배경·캐릭터 일러스트, 애니메이션을 포함한 캐릭터 리소스, 아이콘. 항목별로 더해 두고, **다른 UI 템플릿 요소와 그림체·분위기가 어우러지는 것**이 가장 중요하다. 일러스트·그림은 개발자가 구하고, 정보 아이콘(뒤로 가기·상점 …)은 개발자가 AI에게 제작을 요청한다(참고: Astrae Oratio 풍). 받기 전에는 단색 상자·샘플 아이콘이라 분위기·몰입감이 떨어진다 — 화면을 객관적으로 판단하려면 샘플 리소스가 먼저다.
- **기본 리소스와 규칙** — 글꼴 · 패널 · 정보를 나타내는 규칙(여백 크기 · 제목과 본문 간격 · 크기 · 두께 · UI 요소 사이 간격)을 문서로 정한다.
- **패널 연출** — 카드·팝업 패널 하나를 띄우고 끝내지 않고, **간단한 선 · 둥글기 · 각**의 조합으로 모양에 변칙을 준다(3-1). 디자인을 위해 판을 덧대도 된다(하나로 센다). 기울인 패널·메모·쪽지 디자인, 클립·테이프 같은 물건 소품은 쓰지 않는다. 여러 패턴을 준비해 개발자가 승인한 것을 템플릿으로 둔다.
- **UI 애니메이션** — 3-5. 더 면밀히 분석해 확립한다.

만드는 법: 빈 Unity 프로젝트에서 부품을 배치·조합해 **한 화면이 완성된 게임 같은 분위기**가 날 때까지 다듬고, 그때 괜찮은(개발자가 승인한) 템플릿을 GBible 자산으로 옮긴다. 프로젝트마다 꺼내 쓰거나 이 문서대로 조립한다(UI 자원 재활용).

**2026-10-13에 고친 것**(키트로 옮김): 결 텍스처 패널 → 단색 + 아주 옅은 조각(`KitPanel` — GBible의 옛 재질 클래스 · 결 텍스처는 지웠다) · GBible 기본 화면의 늘 흐림 → DB › 화면의 **'뒷배경' 칸**(일반 배경 · 블러 · UI 배경) · 팝업 안의 정보 정리 → 키트 `kit-info-*`(승인한 간격) · 움직임 → 3-5(견본에서 정함) · 글꼴 → 화면 설정의 '글꼴 에셋'(굵기 표).

**남은 것**: 샘플 리소스(배경 · 캐릭터 일러, 정보 아이콘) · 플레이 화면(HUD) · 거점 · 이벤트의 새 견본 · GBible 기본 화면 중 설정 · 세이브 슬롯을 나눈 배치 + UI 배경으로 다시 짜기(지금은 일반 배경).

**작업 자리**: 실험실 프로젝트 `D:\Unity\Projects\UITemplateLab`(가안 문서 `Docs/UiTemplateDraft.md`, 견본 그림 `Docs/Review/`). 패널은 코드로 그리는 `KitPanel`(모양 · 조각 · 선), 선 포인트는 `KitAccent`, 나누는 선·반짝임은 `KitRule`·`KitSpark`, 라인 디자인은 `KitOutline` — 키트로 옮겼다(2026-10-13). 새 견본은 실험실에서 만들어 승인받은 뒤 키트에 더한다.

## 1. 문법

### 1-1. 화면 하나

- 화면 = `Assets/MomoiProject/UI/Screens/<이름>.uxml` + 공통 USS + DB › 화면 항목(층·뒤로로 닫기·열 씬, 반영 스크립트) + 필요하면 `Code/Client/Screens/<이름>Screen.cs`(`[BindTo(GameIds.Screen.X)] : GameScreen`).
- 순서: UXML·USS·반영 스크립트 → Unity 새로 읽기(`RunTests.request`) → `GameIds.Screen` 상수가 생긴 뒤 화면 코드(관례 15절). 상수가 없는 동안 그 상수를 쓰는 코드를 넣으면 컴파일이 막혀 반영 스크립트도 돌지 않는다.
- 기본 화면(고르기·확인·설정·슬롯·일시정지·알림)은 새로 만들지 않는다. 모양은 테마로만 맞춘다.

### 1-2. 파일과 이름

| 무엇 | 규칙 |
|---|---|
| USS | 테마 `UI/Theme.uss` = 변수 · 기본 화면 덮어쓰기만. UI 키트 `UI/Kit/Kit.uss`(GBible `Templates/UI` — 글 · 패널 색 · 버튼 · 메뉴 · 칸 · 틀의 모양). 프로젝트 화면 모양은 `UI/Screens/<프로젝트>.uss` **한 파일**(첫 줄에서 키트를 `@import`, 화면마다 절로 나눔)을 모든 화면 항목에 붙인다 |
| 목록 칸 | `UI/Items/<이름>Item.uxml`(또는 `<이름>.uxml`), 쓰는 화면 UXML에 `<ui:Template>`으로 적는다 |
| 클래스 | 키트는 `kit-`(프로젝트마다 같다), 프로젝트 것은 접두어 2~3자(`br-`) + 블록(`br-card`) · 부분(`br-card-title`) · 상태(`br-card--picked`). 부분은 `-`, 상태는 `--` |
| 요소 이름(`name`) | 코드가 찾는 것만, kebab-case(`hand`, `route-from`). **모양은 클래스로만** 정한다(`#이름` 선택자·인라인 `style`을 쓰지 않는다 — 한 줄 간격 조정 정도만 예외) |
| `momoi-*` | 라이브러리 클래스. 프로젝트 USS에서 다시 정의하지 않는다(덮어쓰기는 테마에서만) |
| UXML 주석 | **`--`를 쓰지 않는다**(XML이 막는다 — 그 파일은 가져오기에 실패하고, 화면은 예전 모습이나 빈 채로 열린다). 변형 클래스는 주석에 `kit-bt +pill`처럼. 컴파일 검사 훅이 UXML을 XML로 읽어 보고 막는다 |
| 쓰는 클래스 | UXML·코드가 쓰는 클래스는 키트·프로젝트 USS 어딘가에 있어야 한다(없으면 그 칸은 모양 없이 왼쪽 위에 쌓인다) — USS를 고쳐 쓸 때 옛 클래스를 지웠는지 본다 |

### 1-3. 글

- 화면 글은 텍스트 키로만: 고정 글은 UXML `binding-path="@키"`, 값이 든 글은 코드 `Texts.Get`(프로젝트의 짧은 도우미 `Ui.T`), DB 항목 이름은 `Texts.NameOf(id)`.
- **코드가 쓰는 Label에는 `binding-path`를 달지 않는다** — 다시 그릴 때마다 바인딩이 코드 글을 덮는다.
- 값을 보이기만 하는 칸은 `binding-path="run:경로"`. 계산·조건이 들어갈 때만 코드.

### 1-4. 화면 코드

| 자리 | 하는 일 |
|---|---|
| `OnOpen` | 버튼 잇기(`OnClick(이름, () => 행동)`), 목록 만들기(`List<T>`), 코드로 만드는 칸(격자·지도 노드) |
| `Draw` | 데이터에 따라 바뀌는 것(`Watch` 키가 바뀌면 프레임 끝에 한 번). 가볍게 |
| `Tick` | 시간에 따라 흐르는 것 — 타이머·게이지·진행 막대·월드 오브젝트를 따라가는 칸의 위치 |

- 상태 변경은 행동으로만(`OnClick`·`GameScreens.Do` — Busy·실패 알림이 따라온다). 다른 화면은 `GameScreens.Open(id, 값)`.
- 화면에만 있는 고르기 상태(카드를 골라 대상을 기다리는 중 · 고른 아군)는 `Code/Client`의 작은 static 도우미에 둔다. 규칙 데이터가 아니다.
- 데이터가 바뀌지 않는 화면 상태를 바꿨으면 `Draw()`를 직접 부른다(목록은 데이터가 바뀔 때만 다시 그린다).

### 1-5. 목록

- `List<T>(컨테이너, Item("칸"), () => 항목들, (칸, 항목) => …)`, 클릭은 `OnCreate`에서 한 번 잇는다. 칸 번호가 필요하면 그릴 때 `element.userData`에 적는다.
- 목록 칸의 뿌리는 **TemplateContainer**다 — 절대 위치로 놓을 칸(캐릭터를 따라가는 막대 등)은 그 뿌리의 `position`·`left`·`top`·`width`를 정하고, 안쪽 요소는 `flex-grow: 1`로 채운다.

### 1-6. 배치의 토대

- GameScreens는 모든 화면 트리를 화면 전체(왼쪽 위 기준 절대 위치)로 깐다. 그래서 **창은 `전체 + 가운데` 감싸개 안에** 둔다(`<VisualElement class="xx-full xx-center">` → 창). 감싸개 없이 두면 왼쪽 위에 붙는다.
- HUD 요소는 1920×1080 틀 기준 절대 위치(`position: absolute` + `left/top/right/bottom`).
- 화면을 덮는 장식·감싸개 요소는 `picking-mode="Ignore"` — 아래(다른 화면·월드)를 누를 수 있게.
- 가운데 맞춤은 `left: 50%` + `translate: -50% 0`. 그 요소에 `translate` 전환(등장 움직임)이 있으면 대신 `margin-left: -(너비/2)`.

### 1-7. 층과 입력

| 층 | 무엇 | 메모 |
|---|---|---|
| 바탕(Base) | HUD · 장면 위 칸 · 노드 화면 | DB '열 씬'으로 저절로. 상태가 맞지 않으면 화면 코드가 스스로 숨긴다(테스트 씬은 여러 바탕이 함께 열린다) |
| 창(Window) | 메뉴 · 인벤토리 · 지도 · 편성 | 뒤로(Esc)로 닫힘. **플레이 중 핸드와 함께 쓰는 창은 '아래 입력 막기'를 끈다** |
| 팝업(Popup) | 결과 · 확인 · 상세 | 아래를 막는다. 뒷배경은 3-1의 3가지 중 하나(블러는 알림만). 화면을 거의 꽉 채우지 않는다 |
| 알림(Toast) | 실패·알림 | 기본 화면 |

### 1-8. 월드와 UI를 나누기

- **장면에 놓이는 것**(배경 층 · 걷는 캐릭터 · 움직이는 조각)은 월드(SpriteRenderer·프리팹 — `GameView`·`ViewList`). 그리기 순서는 다이얼로그 배경(-100)보다 뒤 — 이벤트가 고정 일러를 띄우면 장면을 덮어야 한다.
- **HUD·글·메뉴**는 UI Toolkit. 움직이지 않는 카드형 조각(보드 위 유닛 카드)은 UI여도 된다.
- 월드 오브젝트에 붙는 칸(이름·체력 막대·누름 자리)은 `Tick`에서 `RuntimePanelUtils.CameraTransformWorldToPanel`로 위치를 맞춘다. 월드 쪽은 발 위치·키를 내주는 static 함수 하나(`TryGetUnit`)로 연다.
- 월드 오브젝트를 누르는 대신 그 위에 투명한 UI 누름 자리를 두면 레이캐스트·충돌체가 필요 없다(UI 칸 위 판정은 관례 21절).

### 1-9. 그림 자리

- 그림 칸은 `background-image` + `-unity-background-scale-mode`(일러 `scale-to-fit`, 카드·칸 `scale-and-crop`). USS에 색 상자를 두고, 코드가 DB 원본의 그림 칸(`Sprite`)을 넣는다 — 비어 있으면 색 상자 그대로.
- 화면 고정 그림(로비 배경 등)은 반영 스크립트의 `AssetRequests.Sprite`로 임시 그림을 만들고 USS가 그 경로를 바로 쓴다(`url("/Assets/Dev/Art/…")`) — 개발자가 같은 자리에 진짜 그림을 넣으면 바로 바뀐다.
- 캐릭터가 서는 큰 자리(거점의 캐릭터 · 정비의 큰 일러)는 DB 원본에 그림이 없어도 비지 않게 USS 기본값으로 임시 그림을 둔다(코드가 원본 그림을 넣으면 그것이 덮는다).
- 아이콘 자리(타일·버튼)는 `KitIcon.Fill(칸, 그림, ID)` — 그림이 없으면 단색 샘플 아이콘(3-6).

### 1-10. 다이얼로그 화면

- 모듈의 UI 템플릿(`Assets/MomoiProject/Data/DialogueUI/`)을 반영 스크립트에서 한 번 만든다(메뉴 '다이얼로그 시스템 › UI 템플릿 만들기'와 같음 — `EditorApplication.ExecuteMenuItem`). 요소 이름은 지키고 USS를 이 문서의 재질·크기로 고친다(템플릿 USS 끝에 프로젝트 절을 덧붙인다).
- 다이얼로그는 자기 Panel Settings를 쓴다 — 프로젝트 테마 변수가 닿지 않으므로 색은 값으로 적는다(테마와 같은 값).

## 2. 레이아웃

### 2-1. 기준

- 1920×1080(16:9) px. 화면 가장자리 여백 16~24. 간격은 4 · 6 · 8 · 12 · 16 · 24 중에서.
- **PC 기준, 모바일처럼 크게 하지 않는다**(명세서가 모바일이면 그 절대값만 키운다).

### 2-2. 플레이 화면의 자리

| 자리 | 놓는 것 |
|---|---|
| 위 띠(0~70) 왼쪽 | 상태 — 남은 시간·자원·턴 |
| 위 띠 가운데 | 진행 — 길·웨이브·단계 |
| 위 띠 오른쪽 | 작은 시스템 버튼 가로줄 — 지도·가방·일시정지·설정 |
| 가운데 | 장면(월드) · 보드. 오브젝트 자기 칸(체력·이름)은 오브젝트에 붙인다 |
| 아래 띠 가운데 | 주된 조작 — 핸드·행동 막대. 그 아래 가운데에 주 자원(마나) |
| 아래 띠 양옆 | 보조 — 덱·버린 더미·빠른 칸 |
| 오른쪽 아래(아래 띠 위) | 그때만 쓰는 버튼의 작은 세로 줄 — 취소·도주·멈추기 |

- 주된 조작(아래 띠)은 플레이 중 다른 창이 가리지 않는다. 창은 아래 띠 위에서 끝난다.

### 2-3. 화면의 짜임 — 뒷배경으로 고른다

화면 전체의 짜임은 **뒷배경 셋**(3-1) 가운데 하나에서 시작한다 — DB › 화면의 '뒷배경' 칸을 고르고, UI 키트의 견본(`Templates/UI/Samples/`)을 바탕으로 짠다. 참고 그림이 있으면 가장 가까운 짜임을, 없으면 정보의 양으로 고른다.

| 짜임 | 뒷배경 | 쓰는 곳 | 견본 |
|---|---|---|---|
| 작은 팝업 | 일반 배경(장면이 그대로) | 정보가 적어 화면 일부만 — 보상 미리보기 · 의뢰 · 교환 · 결과 · 고르기 | `PopupPlain` |
| 알림 | 블러 | 알림성 정보만 — 새로 얻음 · 해금 · 확인 창 | `NoticeBlur` |
| 나눈 화면 | UI 배경 | 정보가 많은 정보형 — 인벤토리 · 도감 · 캐릭터 정보 · 편성 · 설정(목록 \| 칸 \| 상세처럼 영역을 꽉 채운다) | `SplitScreen` |
| 플레이 화면(HUD) · 거점 · 이벤트 | 없음(바탕 층 — 월드 장면 위) | 런 · 전투 · 로비 · 조우 | 새 견본 없음 — 2-2 자리 · 3절로 짜고 견본으로 올린다 |

- 화면을 거의 꽉 채우는 팝업은 쓰지 않는다 — 그 정보량이면 나눈 화면(UI 배경)으로. UI 배경 위에 가운데 팝업 하나만 두지 않는다.
- 거점(로비)은 배경 일러가 화면을 채우고 메뉴는 **옆에 작은 세로 버튼 줄** — 메뉴를 열면 그 화면의 짜임으로.
- **두 패널이 서로 주고받는 메뉴**(창고↔가방 · 장비↔창고)는 가운데 캐릭터(또는 왼쪽 큰 일러)를 왼쪽으로 비우고(자리 옮김 0.3초 — 3-5) 가운데 · 오른쪽에 패널을 나란히.
- **이벤트는 모두 선택지가 있다**(전투 이벤트도 선택지 뒤 전투). 만나면 걷던 캐릭터는 멈춰 서고(아이들), 글 띠 + 오른쪽 선택지 줄. 풀일러 이벤트는 그림이 화면을 채우고 대사가 있으면 대사 뒤에 설명 · 선택지. 선택지는 캐릭터 · 핸드를 가리지 않는 오른쪽에.
- **대상을 고르는 행동**(아이템을 캐릭터에게)을 창에서 시작하면 그 창을 닫는다 — 대상(캐릭터 · 보드)이 보여야 한다. HUD의 상태 알약이 '무엇을 누구에게', 오른쪽 아래가 취소, 고를 수 있는 대상은 물든 면.
- 패널 하나가 쓸 곳이 없으면(전투 중 컨테이너) 빈 판을 두지 않고 숨긴다.
- 같은 종류의 화면은 프로젝트 안에서 같은 짜임 · 같은 변칙(자름 · 잎 중 하나)을 쓴다.

## 3. 디자인 — 차가운 검정 + 종이 흰색, 정돈된 판

개발자 참고(2026-10-12, D-195·D-196과 그 뒤 참고 그림 · Astrae Oratio 풍 견본): 여백·글 크기·디자인·색만 참고하고, 모양은 더 단순하게 가도 된다.

### 3-1. 원칙

- **심플하고 깔끔하게. 매트·플랫.** 패널 자체는 불투명하고 평평하다 — 그라데이션·빛남·패널 그림자 없음. 패널 자체를 반투명 유리처럼 만들지 않는다.
- **UI는 늘 정돈되어 보인다**(개발자 2026-10-12) — 메인 패널을 **기울이지 않는다**(절대). 그래서 메모·쪽지처럼 기운 디자인도 쓰지 않는다. 클립·테이프 같은 **물건 소품은 쓰지 않는다**(깔끔함과 거리가 멀다). 책갈피를 정적인 폴리곤으로 그리는 것도 싸 보인다.
- **패널 모양은 4가지**(개발자 2026-10-12) — **직각 · 약간 둥근 · 모서리 자름 · 알약**(끝이 반원). 둥글기·자름은 모서리마다 고를 수 있다(예: 오른쪽 위·왼쪽 아래만 자름, 오른쪽 아래만 둥글게). 작은 요소(버튼·꼬리표·재화)는 알약·원.
- **모양의 변칙은 간단한 선 · 둥글기 · 각의 조합으로만.** 선 포인트 규칙(개발자 2026-10-12):
  - **선 포인트는 한 화면에 하나** — 포인트를 준 패널은 한 화면에 하나뿐이고, 나머지 패널은 순수 정보성에 가깝게 깔끔하게(선 장식 없음). 포인트는 **A 패널에만**, 패널 하나에 **한 종류만**.
  - 선 디자인이 주인공이 되어 시선을 과하게 끌면 안 된다 — 화려하지 않게, 심플하게. 선 수 · 겹 · 선끼리 교차를 아낀다. **앞 · 뒤 각각 나란한 2선이 마지노선**(개발자 2026-10-13).
  - **선 한 흐름은 최소한 한쪽 면의 끝에서 끝까지** — 면의 반만 잇는 짧은 선은 힘이 없다. 끊을 때도 끊긴 흐름마다 한 면 이상을 잇는다. 모서리의 짧은 ㄱ은 선이 아니라 점 · 별빛과 같은 **표시**로 본다(된다 — 표시처럼 아껴서).
  - 두께는 둘 — **두꺼운 선 1px · 얇은 선 0.5px**. 그보다 굵게 쓰지 않는다.
  - **안쪽 패널이 있는 자리는 선이 지나갈 수 없는 통로**(개발자 2026-10-12) — 바깥 선을 넣으려고 안쪽 패널을 좁히지 않는다. 선은 안쪽 패널이 없는 위 · 아래 자리(머리 띠 · 발 띠 — 예: 제목 끝에서 쪽수 앞까지)에만, 또는 안쪽 패널의 끝에서 시작하는 모양으로.
  - **요소를 촘촘히 붙이지 않는다**(개발자 2026-10-12) — 선 · 점과 다른 요소(패널 가장자리 · 안쪽 패널 · 글) 사이는 최소 8px(개발자 2026-10-13 확정). 틈이 그보다 좁으면 그 틈에 선을 넣지 않는다 — 틀 띠를 넓히거나(틀 24px에 선은 가운데) 다른 자리로.
  - **반대로 멀리 떼지도 않는다** — 패널 밖의 선은 앞 선 10px · 뒤 선 8px(요소 규격 세부, 개발자 2026-10-13), 뒤에 덧댄 판은 6px 안팎(개발자 2026-10-13 확정). 멀면 따로 논다.
  - **끝 점의 자리** — 두 면에서 같은 거리(자른 모서리면 직선 면과 45° 면에서 같은 거리 = 안으로 들어온 윤곽이 꺾이는 점)에 두고, 선은 점 앞에서 끊는다.
  - 선의 흐름은 **직선 · 대각선(45°) · 원(원호)** 셋뿐. 애매한 각도 · 애매한 곡률은 쓰지 않는다.
  - 선 끊기 · 점 · 십자(+) · X형 별빛 아이콘은 된다. 한 자리에 아이콘 여럿을 모으지 않는다 — 이것도 아껴서.
  - 테두리를 다 두르지 않아도 된다 — 두 면만 · 한쪽 면만 · 바깥 옆선처럼 다양하게.
  - 모서리를 자른 패널에서는 선이 직선 면의 끝에서 멈추고, 지나가는 모서리에서는 그 45°를 따라 이어 간다(자른 모서리 하나만 짧게 따라 긋지 않는다).
  - 나눔은 옅은 실선 · 점선이나 면 색의 차이로. 빛나는 테두리 강조는 쓰지 않는다.
  - **흰색(종이) 패널은 안쪽 왼쪽에 한해 세로 안내선을 둘 수 있다**(개발자 2026-10-13) — 내용을 조금 들여 쓰고, 그 왼쪽에서 섹션 머리의 아이콘(예: 돋보기)과 장식(별)을 세로로 잇는다(아이콘 → 선 → 별 → 아이콘). 선은 실선 · 점선 · 짧은 선으로 된 점선 중 하나, 장식을 더할 수 있다. 오른쪽 · 위 · 아래에는 두지 않는다. 이 안내선은 '한 화면에 선 포인트 하나'에 세지 않는다(정보 구조 — 개발자 2026-10-13).
  - 견본(실험실 `KitAccent`): 네 모서리 ㄱ · 두 모서리 ㄱ(표시) · 두 면 · 마주 보는 ㄱ · 끊긴 테두리 · 원호 모서리 · 뒤 상자(패널 뒤로 6px 밀린 선 상자 — 옆 · 아래 두 면과 직각 꺾임, 바깥 모서리에 십자). 한쪽 면 선 하나 · 한쪽 면 나란한 2선 · 위아래 선은 밋밋하고 뜻이 없어 쓰지 않는다(개발자 2026-10-12). 패널 바깥의 선은 패널이 아니라 뒤 배경에 맞는 색으로.
- **패널은 2중첩까지**(개발자 2026-10-12) — 배경 위 **A 패널, 그 안의 B 패널까지**. C(3중첩)부터는 쓰지 않는다.
  - UI 배경은 패널이 아니라 배경이라 세지 않는다.
  - 그림(이미지)은 패널이 아니라 정보(글과 같다)라 B 패널 위에 놓아도 된다.
  - 버튼 · 꼬리표 · 제목 막대도 패널이 아니라 정보 · 조작 요소라 세지 않는다 — 다른 내용을 담는 판만 패널로 센다(개발자 2026-10-13).
  - 디자인을 위해 여러 겹 덧댄 것(뒤에 덧댄 판 · 틀 안의 머리 띠와 판을 한 덩어리로 짠 것 · 패널 위에 패널을 둔 액자형 · 베젤 없이 덮는 판)은 디자인의 일부로 하나로 센다(애매하면 일단 하나 — 개발자 2026-10-13).
  - 틀(A) 안에 안판(B)이 있으면 그 안의 묶음(스탯 상자 등)은 면을 칠하지 않고 줄·간격으로만 나눈다.
- **뒷배경은 3가지**(개발자 2026-10-12):

  | 뒷배경 | 언제 | 모양 |
  |---|---|---|
  | **일반 배경** 앞 팝업 | 정보가 많지 않아 화면 일부만 차지할 때. 일반 배경이 그대로 보여 몰입감(현장감)이 오른다 | 흐림·어둡게 없음 |
  | **블러 배경** 앞 팝업 | **알림성 정보 전달만** — 뒤의 시야를 흐려 가운데 패널로 시선을 모은다 | 흐림 + 아주 옅은 어둡게 |
  | **UI 배경** 앞 나눈 화면 | 정보가 많고 UI에만 집중해야 할 때 — **화면을 나눠 영역을 꽉 채우는 정보형 UI에만**(캐릭터 정보 + 풀일러, 인벤토리 채우기 …) | 화면 전체를 덮는 UI 배경(단색 + 옅은 조각) 위에 영역을 나눈 판들 |

  - **일반 UI에는 블러를 절대 쓰지 않는다**(블러는 알림만).
  - **UI 배경 위에 가운데 팝업 하나만 덩그러니 띄우지 않는다**(개발자 2026-10-12) — UI 배경은 화면을 나눠 영역을 꽉 채울 때만 쓴다. 정보가 적어 팝업 하나면 되는 화면은 일반 배경 앞 팝업으로.
  - **화면을 거의 꽉 채우는 팝업은 쓰지 않는다** — 그럴 정보량이면 3번째(UI 배경)로 바꿔 팝업을 배경으로 치환한다.
  - **지바이블 기본 화면의 뒷배경**(개발자 2026-10-13, 일단) — 확인 창 블러(알림성) · 보상 고르기 일반 배경 · 일시정지 일반 배경 · 설정 · 세이브 슬롯은 화면을 나누는 배치(왼쪽 목록 · 오른쪽 내용) + UI 배경. 키트를 지바이블로 옮길 때 화면 항목의 '뒷배경' 칸 기본값으로 쓴다.
- **한 화면에 여럿 늘어서는 요소(아이템 슬롯 · 목록 칸 · 카드 칸 …)는 단순하게**(개발자 2026-10-13) — 중첩을 최소로, 선도 최소로. 액자형보다 베젤 없는 판을 쓰고, 라인 디자인은 쓰지 않는다. 꾸밈은 그 칸들을 담는 판이나 화면의 포인트 패널 하나에만.
- **따로 말이 없으면 일관되게 맞춘다**(개발자 2026-10-13) — 손그림·참고 그림의 어긋남을 그대로 옮기지 않는다. 같은 종류의 요소는 정렬을 맞추고(예: 아이콘 칸끼리 같은 줄), 같은 종류의 값은 하나로 쓴다(예: 한 패널의 둥근 모서리 크기). 다르게 하라는 전달이 있을 때만 다르게.
- **UI 요소는 최소 단위로 쪼개 조합하는 규격으로 정한다**(개발자 2026-10-13):
  - 메인 패널 — 모양(꼭짓점 마감: 모서리마다 직각 · 둥근 · 자름과 그 크기) · 가로세로 비율.
  - 라인 디자인 — 기본은 패널의 **앞**(패널 안쪽에서 외곽을 따라 두름) 또는 **뒤**(패널 바깥에서 외곽을 따라 두름), 정해진 간격. 여기에 옵션:
    - 8지점(꼭짓점 넷 · 변 중앙 넷)의 장식 — 선 위에, 또는 선을 끊고 그 자리에. 경로를 벗어나 꼭짓점 안쪽 · 바깥쪽에도 둘 수 있다. 종류는 점 · 십자(같은 두께 선의 +) · 별(두께감 있는 둥근 +).
    - 뒤 선의 치우침 — 사방을 두르지 않고 정해진 방향으로 밀린 상자처럼(예: 오른쪽 아래 · 왼쪽 위).
    - 선 끊기 — 변 단위로 빼기(예: 아래만 빼고 위 · 왼쪽 · 오른쪽만) 또는 불규칙 분할(예: 오른쪽 선을 0.1 : 30 : 15 : 7 : 나머지로).
    - 두 겹 · 두께 약 · 강.
  - 패널 방식 — 패널 위에 패널을 두는 액자형, 또는 베젤 없이 덮는 판(예: 뒷 패널 위로 위쪽을 다 덮는 포인트 색 판, 그 앞에 육각 글 판). 패널 색은 흰색 · 검정(패널 회색 톤) · 옅은 회색(비활성) · 포인트 색, 그라데이션도 된다(예: 아래만 포인트 색이고 위로 갈수록 원래 검정).
  - 버튼 — 흰색 · 노란색(갈색 계열) · 검정 세 색에 모양(동글이 · 알약 · 네모 · 변칙 패널)을 돌려 쓴다. **판 색과 같은 색의 면 버튼은 쓰지 않고**, 그 자리에는 판 색에 따라 **글자만 버튼**이나 **반전색 아웃라인 버튼**(면 없이 판과 반대 색 선 두 겹 — 바깥 굵게 1px · 안쪽 얇게 0.5px, 사이 3px)을 쓴다(개발자 2026-10-13). 끔은 옅은 회색. 견본 실험실 `showcaseO`.
  - **변칙 모양(모서리 자름 · 잎)** — 둘 다 쓰되 **한 화면에서는 한 가지만**(개발자 2026-10-13). 그 화면의 버튼 · **토글 메뉴 막대(안쪽 판까지) · 제목 막대**에 같은 변칙을 그대로 쓴다. 자름은 자른 모서리 패널과, 잎은 둥근 패널과 어울린다. 견본 실험실 `showcaseP`.
  - 토글 메뉴 — 가로 메뉴 방식 가운데 하나를 프로젝트에서 고정해 돌려쓴다. **기본은 B3(긴 막대 + 고른 것만 안쪽 판), 안쪽 판은 흰색**(모래색 아님 — 개발자 2026-10-13).
  - 실험실 구현: `KitPanel`(shape · `corners="tr:24 bl:72"` 모서리마다 크기 · 색 · 조각) · `KitOutline`(layer 앞·뒤 · gap · skew 치우침 · weight 약·강 · doubled 두 겹 · cut 변 빼기 · split 불규칙 분할 · marks 8지점 장식) · 그라데이션 판(아래에서 위로 옅어지는 텍스처에 포인트 색을 입힘). 견본 `showcaseN`(개발자 그림판 재현 — 흰 메인 패널 · 아래 20% 주황 그라데이션 · 검은 육각 제목 · 아이콘 칸 둘).
  - 정한 세부(개발자 2026-10-13):
    - 간격 — 앞 선 10px · 뒤 선 8px.
    - 장식 — 점 · 십자 · 별 · X 별 · 모서리 짧은 ㄱ. 한 자리에 하나.
    - 불규칙 분할 — 느낌으로 받아들인다: 값은 선들의 길이이고, 사이는 적당히 끊는다.
    - 선 수 — 앞 · 뒤 각각 2선까지(앞 두 겹 + 뒤 두 겹도 된다).
    - 포인트 색 — 빨주노초파남보 등 무엇이든(프로젝트가 고른다). 기본 UI의 노란색(버튼 등)은 이전에 정한 갈색 계열(모래색)이다.
    - 그라데이션 — 예: 위쪽 덮는 판의 아래 0~20%만 포인트 색, 불투명도 40% → 0%(위로 갈수록 원래 패널 색).
    - 아이콘 칸 — 원 도형(아이콘이 들어갈 자리)은 장식의 점과 다르다. 정보 요소이고, 선은 그 둘레 8px를 비켜 간다.
- **가로로 긴 메뉴(탭)는 두 방식**(개발자 2026-10-13):
  - A · 글만 나열하고 **고른 것에 패널**을 둔다(왼쪽 세로 목록과 같은 방식).
  - B · 전체를 **긴 막대 패널 위**에 두고 **고른 것에만 무언가를 더한다** — 그 자리의 막대를 비우기(패널을 숨김) · 막대 위에 작은 표시 · 안쪽 판(B 패널) · 짧은 밑줄처럼 심플하게.
  - 견본: 실험실 `showcaseM`(A · B1 비우기 · B2 위 표시 · B3 안쪽 판(기본 · 흰색) · B4 밑줄).
- **색은 둘이 주인공** — 차가운 검정과 종이 흰색. 거기에 회색, 숯색 돌, 아주 적은 모래색 강조 하나. 순백·순흑을 피한다.
- **UI 배경은 둘 다 쓴다** — 어두운 UI 배경(검정 + 옅은 조각)과 밝은 UI 배경(종이 흰색 + 옅은 조각). 검정만 쓰지 않는다.
- **같은 패널도 여러 형식** — 팝업 머리·팝업 틀·카드·상세·목록·버튼·탭은 가족마다 형식이 있다(키트 README). 한 화면 안에서는 가족마다 한 형식, 같은 종류의 화면끼리는 같은 형식.

### 3-2. 패널 면 — 단색 + 아주 옅은 조각

패널은 **단색 위에 명도가 아주 조금 다른 폴리곤 조각을 불규칙하게** 둔다(깨진 유리 같은 느낌, 개발자 2026-10-12). 텍스처 그림이 아니라 코드로 그린다(`KitPanel`) — 패널 크기와 상관없이 반복이 생기지 않는다.

- 조각은 **n각형이 꼭짓점마다 아무 각도로 만나는 모양**(개발자 2026-10-12) — 한 직선이 가운데서 길게 이어지는 거미줄형은 쓰지 않는다. 조각마다 크기 · 꼭짓점 수가 제각각이고, 수는 적게(15개 안팎 — 다각형이 많으면 예쁘지 않다). 조각 경계에 선을 긋지 않는다(밝은 외곽선이 생기면 가독성을 해친다).
- 명암 차(면 색에 더하고 빼는 밝기, 0~1)는 **0.014가 최대** — 더 옅어도 된다(0.005 안팎까지). 글을 읽을 때 무늬가 앞으로 나오지 않게. **기본값은 패널 0.009 · 화면 전체를 덮는 UI 배경 0.005**(넓은 면일수록 같은 값도 더 보인다 — 개발자 2026-10-13). 작은 칸(버튼 · 꼬리표 · 스탯 상자)은 조각 없이 단색.
- 같은 화면의 패널끼리는 씨앗(seed)을 달리해 무늬가 겹쳐 보이지 않게.

| 면 색 | 쓰는 곳 |
|---|---|
| 종이 흰색 | 팝업 몸 · 안판 · 밝은 UI 배경 · 대사 상자 · 알림 |
| 회색 | 머리 띠 · 탭 · 보조 판 |
| 검정 | 팝업 틀 · 어두운 UI 배경 · 그림 칸 · 꼬리표 · 고른 목록 막대 · 기본 버튼 |
| 숯색 돌 | 덧댄 판 · 재화 알약 · 레벨 띠 · 보드 칸 |
| 모래색 | 강조 하나 — 머리 띠 · 검정 판 위의 주 버튼 · 등급 |

- 값(면 색 · 명암 차 · 모서리 크기 · 선)은 테마 변수로 두고, 프로젝트는 색만 바꾼다(키트 `Kit.uss`의 `kit-pn-*` 클래스 — 커스텀 속성).

### 3-3. 상태

| 상태 | 표현(테두리 대신 면) |
|---|---|
| 올려 둠(hover) | 면을 조금 밝게(검정은 `--momoi-button-hover`) · 카드는 살짝 들림 |
| 고름·켜짐 | 탭 = 종이로 채움 · 타일 = 돌 색 + 들림 · 세로 카드 = 아래 띠 강조색 · 칸 = 강조색 밑 띠 3px |
| 받음·가짐 | 반투명 검정 + ✓ |
| 대상 표시 | 면을 강조색으로 옅게 물들임 |
| 끔 | `opacity: 0.4` |
| 위험·적 | 채도를 낮춘 붉은 면 |

- 상태가 바뀌는 움직임(올려 둠·고름)은 0.1초 안팎, `translate`·`scale`·`opacity`·`background-color`만. 튀기·빛남 없음. 나타나고 사라지는 움직임은 3-5.

- 검정 판 위의 칸(타일)은 한 단계 밝은 돌 면 — 같은 검정이면 칸이 보이지 않는다.
- 면 색이 겹치면(검정 틀 안의 종이 안판) **가장 가까운 면이 이긴다** — 면 색에 기대는 규칙을 더할 때 안쪽 면의 짝도 함께 적는다.

### 3-4. 색 정하기

- 키트 색 변수(`Kit.uss` 맨 위 `--kit-…`) + 테마 변수(기본 화면) + 글 + 강조색이면 화면 전체가 맞는다. 프로젝트 USS에 색 값을 직접 적지 않는다(변수로). 다이얼로그 USS만 예외(1-10 — 테마 변수가 닿지 않는다).
- 프로젝트 분위기에 맞춰 바꾸는 것은 강조색과 표지·종이의 미세한 색조 정도 — 차가운 검정·종이 흰색의 틀은 지킨다. 고른 색은 가안으로 승인받는다.

### 3-5. 움직임 — 짧고 하나로

씬 전환을 뺀 **모든 움직임은 아주 짧고 간결하게** 한 모양으로 통일한다(개발자 결정, 2026-10-12).

| 무엇 | 모양 |
|---|---|
| 화면(창·팝업·바탕)이 열리고 닫힘 | 투명도 0↔100% — 나타남 **0.189초** ease-out-sine, 사라짐 **0.135초** ease-in-sine(개발자 2026-10-13 — 0.14초는 짧고 1.5배는 과해 1.35배). GBible이 저절로(`ScreenMotion.Enter`·`Leave` — `GameScreens.Open`·`Close`) |
| 화면 안의 패널 | 위와 함께 **나타날 때만 옆·아래에서 14px쯤 제자리로**, 사라질 때는 미끄러지지 않고 투명도만(클래스 `momoi-motion` + 오는 쪽 `--left`·`--right`·`--down`, 없으면 아래에서). 열린 화면 안에서 패널 하나를 보이고 숨길 때는 `ScreenMotion.Show(요소, 참거짓)` |
| 자리 옮김(거점 캐릭터가 비킴) | `translate` 0.3초 안팎 ease-out — 움직이는 것이 보여야 하는 것만 |
| 올려 둠·고름 | 0.1초(3-3) |
| 씬 전환 | **풀 패널 연출을 따로 둔다(아직 없음)** — 만들 때까지 Bootstrap 씬 흐름의 기본 페이드(`GameScenes.Transition`). 화면 쪽에서 따로 만들지 않는다 |

- `translate`로 가운데 맞춘 요소에는 `momoi-motion`을 붙이지 않는다(움직이는 동안 translate를 덮는다 — margin으로 맞춘다).
- 카드 움직임(뽑기·쓰기·버리기)은 이 규칙 밖의 연출로 따로 만든다(`GameView.Present`·`Play`).
- **순간 연출**(획득 · 공개 · 강화 · 숫자 · 누름 — 펑 · 불티 · 빛 고리 · 빛살 · 훑는 빛 · 빛 번짐)도 이 규칙 밖이다(개발자 2026-10-13 — UI 애니메이션의 핵심). 패널 자체는 매트 그대로, 빛 · 파티클은 그 순간에만. 방식은 **UI Toolkit만**(개발자 2026-10-13 승인 — 메시로 그린 불티 · 고리 · 빛살 + filter drop-shadow 빛, 그림 파일 · 셰이더 · 패키지 없이), 빛 색 기본은 **따뜻한 금빛 · 프로젝트마다 바꾼다**(승인). 키트 `KitFx`(연출 층 `kit-fx` · `KitGlow` · `KitSheen` · `KitTween`, 묶음 Reward · Reveal · Buff · NumberPop · Tap — 견본 `Samples/Effects.uxml` · `EffectsSample.cs.txt`). 연출은 행동이 끝난 뒤(`SubscribeAfterAction`)에 부른다. **자체 발광 아이콘 · 이펙트**(개발자 2026-10-13 — 참고: Wildfrost 공격 버프, 네온 로고): 흰 면 · 흰 선(빛의 가운데) + 색 빛 두 겹(`KitGlow.Neon` — 가까운 빛 진하게 + 넓은 번짐 옅게). 버프는 채운 실루엣(`KitGlyph`)이 0.1초에 떠오르고 · 두 겹 빛이 번지고 · 납작한 빛 고리(타원)가 퍼지고 · 위로 오르며 사라진 뒤(0.85초) 수치가 펑. 메시는 시계 방향 삼각형만 그려진다. 더 필요하면 Unity 6.6 UI Toolkit의 요소별 머티리얼(`-unity-material`, Shader Graph)과 사용자 필터(FilterFunctionDefinition)로 넓힌다.
- 시간·거리는 `ScreenMotion`의 값과 Screens.uss의 움직임 클래스가 같다. 바꿀 때는 둘을 함께.
- **목록이 칸마다 차례로 나타나기** — 보상 · 결과를 공개할 때만 칸마다 **0.06초** 늦춘다(최대 5칸 — 0.03초는 동시로 보이고 0.1초는 길다, 개발자 2026-10-13). 평소 목록은 한꺼번에. **USS `transition-delay`로 늦추지 않는다** — 지연 중인 칸이 페이드 없이 바로 떠 버린다(Unity 6.6). 칸마다 '나타나기 전' 클래스를 떼는 때를 미룬다(`schedule.Execute(…).StartingIn`).
- 움직임은 실험실 견본(`lab.motion` — 팝업 · 패널 · 올림 · 누름 · 고름 · 탭 · 도움말 · 알림 · 값 변화 · 끌어 놓기 · 같은 층 교차 · 자리 옮김 · 차례로 나타나기)에서 개발자가 보고 정했다(2026-10-13 — 모두 좋음, 팝업은 1.35배, 차례는 0.06초). 나머지 값: 올림 면 색 0.08초 · 누름 0.97배 0.06초(놓으면 0.1초) · 탭은 옛 내용 바로 숨김 + 새 내용 탭 쪽에서 18px · 도움말 0.3초 머문 뒤 투명도만 · 알림 위에서 14px, 2.5초 뒤 사라짐 · 값 변화는 숫자 색 0.2초 반짝 · 끌어 놓기 놓으면 0.1초 · 못 놓으면 0.14초 제자리 · 같은 층 화면 바꾸기는 사라짐과 나타남을 겹침 · 자리 옮김 0.3초 ease-out. USS 곡선에는 quad가 없다(`ease-out-quad`는 경고와 함께 무시) — 쓸 수 있는 것은 ease · ease-in · ease-out · ease-in-out · linear와 sine · cubic · circ · back · elastic · bounce의 in · out · in-out.

### 3-6. 아이콘 — 단색 벡터

- 아이콘은 **단색 벡터**: 글 색(`color`)을 따르고 크기는 USS `width`·`height`. 그림자·그라데이션·여러 색 없음.
- 프로토타입에서는 키트의 샘플 `KitIcon`(코드로 그림 — 닫기·뒤로·집·메뉴·설정·지도·가방·멈춤·재생·별·방패·칼·하트·동전·보석·더하기·확인·새로 고침·정보·도움말·카드 21개)을 **뜻과 상관없이 돌려쓴다** — 씬의 디자인 완결성만 챙긴다. UXML `<MomoiProject.KitIcon glyph="Map" class="kit-icon" />`, 데이터 칸은 `KitIcon.Fill(칸, 그림, ID)`.
- 진짜 아이콘·캐릭터 SD·일러는 **개발자가 준 링크 안의 것**을 쓴다(받기 전에는 샘플·임시 그림). 받으면 같은 자리를 그림(`background-image`)으로 바꾼다.

## 4. 진행(단계 2의 화면 부분)

1. 화면 목록(명세서 7절) · 결정 기록의 화면 결정 · **참고 그림**(화면마다 전체 레이아웃 하나 — 없으면 화면 목록과 함께 요청한다).
2. **UI 키트를 들인다**(`Templates/UI/README.md` 설치 1~2): `Kit.uss`(+ 그라데이션을 쓰면 `Textures/`) · 코드 `KitPanel` · `KitOutline` · `KitAccent` · `KitLine` · `KitIcon`. 글꼴 에셋(한글 고딕 — 굵기 표)을 화면 설정에.
3. 화면마다 **짜임**(2-3 — 뒷배경)과 **변칙**(자름 · 잎 — 한 화면에 한 가지), 프로젝트의 **가로 메뉴 방식**(기본 B3)을 정한 표를 만든다. 참고 그림이 있는 화면은 그 그림에 가까운 짜임, 없는 화면만 묻는다(추천: 비슷한 화면의 짜임을 따름).
4. 테마 변수(색 · 강조색) → 프로젝트 USS(`@import` 키트 + 프로젝트 클래스) → UXML(견본을 바탕으로) → 반영 스크립트(DB › 화면 — 층 · 뒷배경) → 새로 읽기 → 화면 코드 → 다이얼로그 USS → 넣을 에셋.
5. 세부 배치(버튼 자리·크기·순서)는 묻지 않는다. 짜임 · 변칙 표와 참고를 해석한 곳만 '확인 기다리는 것'에 가안으로.
6. **AI가 플레이로 확인한다**(매뉴얼 38장 플레이 요청): `Logs/MomoiProject/Play.request`에 화면을 차례로 여는 둘러보기(열기 · 누르기 · 테스트 명령 · 찍기)를 적고, `PlayResults.txt`(단계마다 결과 · 콘솔 오류 · 새로 읽을 때 오류)와 찍은 그림(`Captures/*.png`)을 읽는다. 겹침 · 빈 자리 · 잘림 · 글 대비 · 오류를 고치고 다시 돌린다 — 개발자에게 넘기기 전에 둘러보기가 오류 없이 끝나고 그림이 이 문서대로일 때까지.
   - 둘러보기에는 화면마다 한 장, 상호작용마다(고르기 → 쓰기 → 대상) 앞뒤 한 장씩.
   - 움직임(3-5)은 `record <이름> 1.0`으로 찍는다: AI는 모음 그림(칸 16개 — 칸마다 시각)으로 나타나기 0.189초 · 사라지기 0.135초 · 오는 쪽을 확인한다. 영상(`.mp4`)은 개발자가 요청할 때만 보낸다(매뉴얼 38장 2-5 '영상 요청').
   - 플레이 요청은 창을 띄우지 않는다: DB의 '적용 전' 변경은 묻지 않고 적용된 데이터로 돈다(결과 첫머리에 건수). 열린 씬에 저장 안 한 변경이 있으면 시작하지 않는다.
7. 보고: 화면마다 배치·형식(짧게) · 넣을 에셋 · 플레이로 확인한 것과 개발자가 볼 것.

## 5. 보내기 전 확인

- [ ] 글은 모두 텍스트 키, 코드가 쓰는 Label에 `binding-path` 없음
- [ ] 모양은 클래스로만(키트 `kit-` + 프로젝트 접두어), 블록-부분--상태 이름
- [ ] 화면마다 짜임 하나(2-3 — DB › 화면의 '뒷배경' 칸), 같은 종류의 화면끼리 같게 · 변칙은 한 화면에 한 가지
- [ ] 창은 `전체 + 가운데` 감싸개 안, 장식·감싸개는 `picking-mode="Ignore"`
- [ ] 위 띠 · 아래 띠 · 오른쪽 아래 자리(2-2), 핸드가 가려지지 않음
- [ ] 크기 표(2-4) 안 — 모바일처럼 크지 않음
- [ ] 패널 그림자·빛남·그라데이션·두꺼운 테두리 없음 · 기울인 패널·물건 소품 없음 · 패널 모양 4가지 · 패널 2중첩까지 · 선 포인트는 한 화면에 하나(A 패널, 한 종류, 선은 한 면 끝에서 끝까지, 1px·0.5px) · 여럿 늘어서는 칸(슬롯·목록)은 베젤 없는 판에 중첩·선 최소, 라인 디자인 없음 · 요소 사이 최소 8px · 바깥 선 앞 10px·뒤 8px, 덧댄 판 6px 안팎 · 뒷배경 3가지(블러는 알림만, 꽉 찬 팝업 대신 UI 배경)
- [ ] 패널 면은 KitPanel(단색 + 옅은 조각), 색은 키트 클래스 · 변수, 검정 · 종이 둘 다 쓸 곳에 맞게 · 판과 같은 색 면 버튼 없음
- [ ] 상태는 면(채움·띠·들림·✓)으로, 강조색 하나
- [ ] 월드 장면은 다이얼로그 배경보다 뒤, 따라가는 칸은 `Tick`
- [ ] 목록 칸의 절대 위치는 TemplateContainer에
- [ ] `GameIds.Screen` 상수는 새로 읽기 뒤에 쓰기
- [ ] UXML 주석에 `--` 없음, 쓰는 클래스가 모두 USS에 있음
- [ ] 패널 움직임은 `momoi-motion`(+ 오는 쪽), 보이고 숨기기는 `ScreenMotion.Show`
- [ ] 아이콘은 단색 벡터(샘플 `KitIcon`), 빈 칸에는 샘플 없음
- [ ] 두 패널 메뉴는 가운데·오른쪽 나란히, 대상 고르기는 창을 닫고, 선택지는 캐릭터·핸드를 가리지 않음
- [ ] 플레이 둘러보기가 오류 없이 끝났고 찍은 그림을 모두 봄

# 프로젝트 진행 매뉴얼 (AI용)

GBible로 게임 하나를 **자료를 받은 날부터 출시까지** 진행하는 순서다. 단계마다 들어가는 조건, 할 일, 질문 양식, 나가는 조건이 있다. 질문·답은 결정 기록에 쌓아 다시 묻지 않는다.

- 어떻게 쓰나: `ProjectConventions.md`(관례). 무엇이 있나: `Reference.md`(참조). 기믹을 무엇으로 만드나: `GimmickCatalog.md`(기믹 목록). 명세서 칸 → GBible: `PlanningSpecGuide.md`(읽는 법).
- 스킬 `/think-momoi`가 이 문서를 따른다.

---

## 0. 누가 무엇을 하나

| 누가 | 하는 일 |
|---|---|
| **AI** | 로직·데이터 구조·규칙 함수·행동·Block·DB 종류·DB 항목(DB 반영 스크립트)·화면·연출 연결·테스트 씬·테스트 명령·테스트 상황 — 모두 코드와 파일로 |
| **개발자** | 자료(기획·콘텐츠 구조)를 넘기고, 질문에 답하고, 에디터에서 **읽고**(DB·모니터), **밸런싱 값을 바꾸고**(숫자·고르는 값·참조), **다이얼로그 그래프를 만들고**, **레벨을 배치하고**, **에셋을 가져오고**, **테스트한다**. AI가 만든 DB 항목을 읽어 보고 적용(Ctrl+S)한다 |

- 개발자는 에디터에서 로직을 만들거나 로직 쪽 DB 항목(능력·패시브·상태 효과·도전과제·가중치 표 …)을 추가·삭제하지 않는다. 그런 요청은 AI에게 말로 한다.
- 그래서 AI가 만드는 것은 모두 **개발자가 에디터에서 읽고 숫자·참조를 바꿀 수 있는 모양**이어야 한다(관례 18절). 테스트할 수 있는 모양이어야 한다(관례 19절).

## 1. 목표 — 예외를 첫 단계에서 막는다

가장 비싼 실패는 이것이다: 기획을 대충 흡수한 채 시스템을 세웠다가, 콘텐츠·레벨 디자인 단계에서 나온 기상천외한 기믹 때문에 시스템을 갈아엎는다.

- 그래서 **단계 0(흡수)에 시간을 쓴다.** 개발자 자료를 끝까지 읽고, 명세서를 질문으로 채우고, '예외 사냥'(5-3)으로 나중에 나올 기믹을 미리 끌어낸다.
- 이후 단계는 처음에 정한 틀 안에서 움직인다. 정해지지 않은 작은 것은 추천값으로 진행하고, 기록하고, 단계가 끝날 때 보여 준다.
- 예외 코드로 덧붙이지 않는다. 틀에 맞지 않는 것이 나오면 틀(메인 룰)을 고치는 쪽을 먼저 본다(12절).

## 2. 결정 기록 — `Docs/Decisions.md`

프로젝트를 열면 GBible이 빈 양식을 만들어 둔다(없을 때만).

- **세션을 시작하면 먼저 읽는다.** '지금 단계'와 '다음에 할 것'으로 이어 간다. 표에 있는 것은 다시 묻지 않는다.
- **답을 받으면 바로 적는다**(번호 `D-n` · 단계 · 정한 것 · 답 · 누가 · 이유 · 뒤집기 비용). 그리고 **같은 내용을 채팅 답에도 짧게** 적는다: "기록: D-12 보드는 열 우선(개발자)".
- **추천값으로 정한 것**은 '아직 보여 주지 않은 추천값'에 쌓았다가, 단계가 끝날 때 한 번에 보여 준다. 개발자가 바꾸라고 하면 그 줄을 고치고 '바뀐 것'에 남긴 뒤, 영향받는 코드·DB·문서를 고친다.
- **명세서는 살아 있는 문서다.** 답이 명세서 칸을 바꾸면 명세서도 고치고, 고친 칸 끝에 `(D-12)`를 붙인다.
- 사람이 결정 기록을 직접 고쳤으면 그것을 따른다(바뀐 줄이 코드와 다르면 그 차이를 알리고 맞춘다).

## 3. 질문 규칙(모든 단계)

- **한 번에 모아서, 번호 목록으로.** 질문마다 이 여섯 가지를 붙인다:

  > **3. 보드 순서** — 정할 것: 유닛이 발동하는 순서 / 선택지: (가) 줄마다 앞에서 뒤로 (나) 앞 칸 위·아래 → 다음 칸 / 추천: (나) / 이유: 자료의 그림 1·2·3이 열 우선 / 답이 없으면: (나)로 진행 / 뒤집기 비용: 높음(보드 데이터·패시브 순서·테스트)

- **묻는 것 = 뒤집기 비용이 큰 것**: 데이터 구조, 메인 룰(조각·자리·순서), 진행 흐름, 핵심 동사, 저장 모양, 멀티, 문법 밖 기믹, 개발자 몫의 범위(무엇을 에디터에서 바꾸나).
- **묻지 않는 것 = 되돌리기 쉬운 것**: 이름, 수치, 화면 배치, 연출 세부 → 추천값으로 정하고 기록(2절).
- **개수**: 단계 0은 필요한 만큼 하되 20개 안팎으로 묶는다. 이후 단계는 한 번에 10개 이하.
- **순서**: 비싼 것부터(멀티 → 시간 → 메인 룰·자리 → 데이터·흐름 → 동사 → 메인 룰 구조 → 갈래 → 문법 밖 → 나머지).
- 자료의 빈칸·모르는 말은 먼저 문맥으로 풀고, 그래도 갈리면 묻는다. 두 답이 부딪히면 둘을 함께 다시 묻는다.
- 개발자가 "알아서"라고 하면 추천값으로 정하고 기록한다.
- 질문만 하고 멈추지 않는다: 질문과 상관없는 일은 계속하고, 답에 달린 일만 기다린다. 답이 없으면 '답이 없으면'대로 가되, 뒤집기 비용이 높은 것은 기다린다.

| **5 밸런싱·테스트** | 2 끝 | 테스트 상황·명령 늘리기 · 자동 시뮬레이션 · 버그 고치기 · 바꿀 숫자 드러내기 | 알려진 버그 0 · 바꾸고 싶은 숫자가 모두 에디터에 | 값 바꾸기 · 버그 보고 |

## 5. 단계 0 — 흡수(가장 중요)

### 5-1. 자료 받기

받을 것(있는 만큼): 기획서 · 콘텐츠 구조(카드·적·유물 목록, 시트) · 레퍼런스 게임 · 그림·화면 스케치 · 꼭 넣고 싶은 기믹. 없다고 멈추지 않는다 — 한 문단 아이디어만 와도 명세서를 질문으로 채워 간다.

- 받은 자료는 **끝까지** 읽는다. 시트는 모든 줄의 효과 문장까지 본다(콘텐츠가 기믹의 폭을 정한다).
- 받은 파일은 `Docs/Source/`에 두라고 권한다(다음 세션이 다시 읽는다).

### 5-2. 명세서 채우기

`Docs/PlanningSpec.md`를 AI가 자료로 채운다. 칸마다 출처를 붙인다: `(자료)` · `(질문 D-n)` · `(추천)`. [필수] 칸이 자료로 안 채워지면 질문 목록에 넣는다. 칸 → GBible은 읽는 법 2절.

### 5-3. 예외 사냥

나중에 나오면 시스템을 갈아엎게 만드는 것을 지금 끌어낸다. 네 가지를 한다.

1. **메인 룰을 기믹 목록 1절 모양으로 써 본다**(조각 → 자리 → 순서). 안 써지는 곳은 질문.
2. **자료의 효과 문장을 모두 갈래로 나눠 본다**(기믹 목록 2절). 갈래가 없는 문장 · 메인 룰 자리(기믹 목록 3절)가 필요한 문장을 모은다.
3. **아래 표를 개발자에게 예/아니오로 묻는다.** 자료로 답이 나온 줄은 빼고 묻는다. "예"면 그 줄의 '그러면'을 하고, 자세한 것을 더 묻는다.
4. **개발자 몫의 범위를 묻는다**(5-4).

| 나중에 나올 수 있나? | 그러면 |
|---|---|
| 조각이 다른 조각을 만들거나·없애거나·바꾸나(소환·복제·변신·진화) | 조각 = 객체 목록(고유 id), 만들기는 `Game.NewId` · 원본 인스턴스. 바뀌면 원본 ID 필드 |
| 조각이 다른 조각의 효과를 빌려 쓰거나 흉내 내나 | 명세서 4-2 '빌려 쓴다' |
| 놓인 위치·순서가 효과를 바꾸나 — 순서가 목록 순서와 다르나(열 우선 등) | 4-2 '놓인 순서·위치' · 목록을 그 순서로 담는다 |
| 한 조각이 여러 칸을 차지하나 | 4-2 '여러 칸' |
| 태그·속성이 위치·상황으로 바뀌나 | 4-2 '태그가 바뀐다' |
| 자원을 다른 곳에서 내나 · 빚을 지나 · 여럿이 나눠 쓰나 | 4-2 '자원' |
| 효과가 반복되나 · 수치가 배율로 커지나 | 4-2 '반복' · 효과 배율 의도 |
| 판정 규칙(족보·승리 조건·대상 규칙)이 바뀌나 | 4-2 '판정 규칙' |
| 반응이 다른 효과가 끝난 뒤에 와야 하나 | 4-2 '반응을 미룬다' |
| 조각을 잠시 끄나(침묵·봉인·제약) | 상태 효과 '패시브를 끔' · 레벨 0 |
| 플레이어가 효과 도중에 고르나(한 번에 여럿 · 연달아) | 선택 대기(`Game.Ask`) — 이어서 할 행동 구조 |
| 시간을 멈추나 · 되감나 · 건너뛰나 · 턴을 더 얻나 | 시계 · `UndoTo` · 턴 흐름에 '한 턴 더' 자리. 저장을 넘는 되감기면 문법 밖 |
| 무작위를 다시 굴리나 · 확률을 바꾸나 · 시드를 고르나 | 확률 의도 · 다시 뽑기 · 시드 새 판 |
| 판이 끝나도 남는 것이 규칙을 바꾸나(영구 강화 · 해금 · 다음 판에 가져감) | 프로필 구역 · 판 시작 행동이 읽는다 |
| 다른 플레이어의 조각·자원을 건드리나(멀티) | 플레이어마다 칸 `players[].…` · 주인 id |
| 화면이 정하는 판정(충돌·조준·타이밍)이 규칙 값에 들어가나 | 판정 보고 행동 — 무엇을 보고하나 |
| 대화·컷신이 규칙 값을 바꾸거나 규칙이 대화를 여나 | 다이얼로그 값 바꾸기·신호·조건 연결 |
| 맵·적 배치에 규칙을 바꾸는 특수 칸·사건이 있나(함정 · 스위치 · 무작위 방) | 레벨 데이터 모양(단계 3)에 그 자리를 지금 둔다 |
| 수가 아주 커지나(1e308 넘음) | `BigNumber` |
| 하루·현실 시간이 규칙에 들어가나 | `Game.Now` · 날짜 |

### 5-4. 개발자 몫 묻기

- **밸런싱 범위**: 에디터에서 바꾸고 싶은 숫자·선택값·참조는 무엇인가(예: 적 체력·보상으로 줄 아이템·드롭 확률·카드 비용). 답이 없으면 "기획자가 바꿀 만한 숫자는 모두"로 간다(관례 18절).
- **레벨 배치**: 무엇을 개발자가 배치하나(맵·적·보상·사건) · 어디에서(Unity 씬·타일맵 / DB의 레벨 항목) · 한 레벨의 단위(층·방·스테이지·웨이브).
- **대사**: 다이얼로그 그래프로 쓰나 · 대사가 규칙 값을 바꾸나.
- **테스트**: 꼭 시험해 보고 싶은 상황(보스 직전 · 유물 다섯 개 든 덱 …) — 테스트 씬·상황에 미리 둔다.

### 5-5. 질문 → 답 → 시스템 목록

질문을 보내고(3절), 답을 결정 기록·명세서에 적고, **시스템 목록**(읽는 법 5절)을 한 페이지로 보여 확인을 한 번 받는다.

**나가는 조건** — 모두 참이어야 단계 1로 간다:
- 명세서 [필수] 칸이 다 차 있다(출처 표시).
- 메인 룰이 조각·자리·순서로 쓰여 있다.
- 예외 사냥 표의 줄마다 답(예/아니오)이 있고, "예"는 4-2·갈래·부가 기능으로 옮겨졌다.
- 자료의 효과 문장 중 갈래가 없는 것 = 0, 또는 만드는 법을 정했다.
- 문법 밖 기믹 = 0, 또는 개발자 답이 있다.
- 개발자 몫(밸런싱 범위·레벨 배치·대사·테스트)이 정해졌다.
- 시스템 목록을 개발자가 확인했다.

## 6. 단계 1 — 시스템층

순서는 관례 16절. 그 위에 이 단계에서 반드시 함께 만든다:

- **밸런싱이 될 숫자는 처음부터 에디터에** — 코드에 숫자를 적지 않는다(밸런스 값 · DB 칸 · 인스턴스 필드, 관례 18절).
- **테스트 씬과 기본 테스트 명령**(관례 19절): 판 시작 · 자원 주기 · 조각 얻기 · 적 만들기 · 상태 효과 걸기 · 다음 단계로.
- **레벨 데이터의 자리**(단계 3이 쓸 모양 — 예외 사냥에서 나온 특수 칸 포함).

질문 양식(필요할 때만, 10개 이하): 시스템 목록에 없던 구조가 필요해짐 · 명세서끼리 부딪힘 · 문법 밖이 새로 보임.

**나가는 조건**: 판 하나가 행동만으로 끝까지 돈다(규칙 테스트) · 테스트 씬에서 기본 테스트 명령이 돈다 · 화면 뼈대(기본 화면 + 핵심 HUD) · 결정 기록 갱신 · 보여 줄 추천값을 보여 줌.

## 7. 단계 2 — 콘텐츠

1. **목록 받기**: 개발자 목록(시트·문장)을 받는다. 일부만 있으면 방향과 대표 몇 개로 AI가 나머지를 제안하고 승인받는다.
2. **문장 쪼개기**: 문장마다 기믹 목록 2절의 갈래 → 부품. 관례 0절 순서(DB 조합 → 재사용 Block → `[BindTo]` → 중간층).
3. **DB 반영 스크립트**로 넣는다(관례 15절). 숫자가 많으면 CSV.
4. **조각마다 테스트 명령**(얻기 · 쓰기 · 걸기)을 만든다.

콘텐츠 질문 양식(묶음마다 한 번):

| 무엇 | 질문에 붙일 것 |
|---|---|
| 갈래에 맞지 않는 효과 | 문장 · 왜 안 맞나 · 만드는 법 후보 둘 · 추천 |
| 메인 룰을 고쳐야 하는 효과 | 영향 범위(코드·DB·저장) · 비용 · 대안(효과를 바꾸는 쪽) |
| 문장이 두 가지로 읽히는 효과 | 두 해석 · 결과가 어떻게 다른가 · 추천 |
| 숫자·이름·글이 빠진 것 | 묻지 않는다 — 추천값으로 넣고 기록 |

**나가는 조건**: 받은 목록 전부가 DB에 있다 · 조각마다 테스트 명령이 돈다 · 갈래 밖 = 0.

## 8. 단계 3 — 레벨 디자인(개발자가 배치한다)

AI는 배치하지 않는다. 개발자가 배치·대사를 넣을 수 있게 만든다.

- **레벨 데이터 모양**: 레벨 하나 = 무엇의 목록인가(웨이브 · 방 · 층 · 맵). 개발자가 DB에서 레벨을 더하고 빼려면 그 종류에 `[Database(…, DeveloperAuthored = true)]`(관례 18절). 고르는 것(적·보상)은 드롭다운(`[DataRef]`), 맵 모양은 Unity 씬·타일맵으로.
- **배치 도구**: 씬에 놓는 컴포넌트(스폰 지점·사건 칸)가 규칙 데이터로 읽히게, 또는 DB의 레벨 항목(인스턴스)에서 고르게.
- **대사 ↔ 규칙**: 다이얼로그의 값 바꾸기·신호·조건이 닿는 플레이어 데이터·이벤트를 정해 두고 목록을 알린다(매뉴얼 24장).
- **검증**: 빠진 참조 · 도달할 수 없는 레벨 · 쓰이지 않는 콘텐츠를 DB 검증이나 테스트로 알린다.

질문 양식: 레벨 단위 · 배치를 어디서 하나(씬 / DB) · 레벨마다 다른 규칙(특수 칸·사건) · 진행 조건(다음 레벨이 열리는 조건) · 대사가 바꾸는 값.

**나가는 조건**: 개발자가 레벨 하나를 처음부터 배치해 테스트 씬에서 돌려 볼 수 있다.

## 9. 단계 4 — 연출·UI·사운드

- 화면 목록 → 기본 화면으로 되는 것을 빼고 화면마다 UXML·USS + DB › 화면 + 화면 코드(매뉴얼 35장).
- **넣을 에셋 목록**: 경로 · 크기 · 쓰는 곳 · 지금 쓰는 임시 그림. 개발자는 밖에서 가져와 에셋 관리로 그 자리에 넣는다.
- 연출: 턴제는 연출 대기열, 실시간은 `GameView.Play`.

질문 양식: 화면마다 보여 줄 것·누르는 것 · 입력을 막을 연출 · 사운드 목록(배경음·효과음·목소리) · 글꼴·언어.

**나가는 조건**: 화면 목록 전부 · 임시 에셋 자리마다 '넣을 것' 목록.

## 10. 단계 5 — 밸런싱·테스트

- **테스트 상황**(관례 19절)을 늘린다: 개발자가 말한 상황 · 버그가 났던 상황 · 단계마다의 대표 상황.
- **자동 시뮬레이션**(턴제): 같은 상황을 시드만 바꿔 여러 번 돌려 승률·평균 턴·피해 표.
- **버그 보고 양식**(개발자 → AI): 테스트 상황 이름(또는 지금 상황 저장) · 한 일(명령·입력) · 기대 · 실제 · 모니터 타임라인·저널 한 줄. AI는 같은 상황으로 재현 테스트를 만들고 고친다.
- **"이 숫자를 바꾸고 싶다"**: 그 숫자를 밸런스 값·DB 칸으로 드러낸다(코드 숫자를 옮긴다).

**나가는 조건**: 알려진 버그 0 · 개발자가 바꾸고 싶은 숫자가 모두 에디터에 있다 · 테스트 상황으로 단계별 대표 장면을 다시 열 수 있다.

## 11. 단계 6 — 출시 준비

체크리스트(하나씩 확인하고 결정 기록에 적는다):

- Steam: 실제 App ID · 도전과제 API Name · 통계 · Cloud 경로(매뉴얼 34장).
- 저장: '출시됨' 켬(저장 호환) · 저장 변환 · 슬롯(매뉴얼 06·31장).
- 테스트 도구가 출시 빌드에 들어가지 않는다(개발 빌드에만).
- 텍스트: 출시 언어마다 빠진 키 0.
- 검증: DB "검증 통과" · 규칙 테스트 · 콘솔 오류 0.
- 성능: 가장 무거운 장면에서 행동 한 번의 시간(매뉴얼 33장 실시간 예산).

질문 양식: 출시 언어 · 저장을 어디까지 지킬지(체험판 → 정식) · 플랫폼 설정.

## 12. 변경 요청(어느 단계에서나)

개발자가 기획을 바꾸거나 새 기믹을 넣으려 할 때:

1. 결정 기록·명세서에서 무엇과 부딪히나 찾는다.
2. 갈래 안이면 그대로 만든다(질문 없음).
3. 메인 룰·데이터 구조를 바꿔야 하면 **영향 범위(코드·DB·저장·테스트)와 비용, 대안(기믹 쪽을 바꾸는 것)**을 붙여 묻는다.
4. 예외 코드로 덧붙여 때우지 않는다. 고치기로 하면 틀을 고치고, 같은 갈래의 다른 조각도 그 틀을 쓰게 한다.
5. 결정 기록의 '바뀐 것'과 명세서를 고친다.

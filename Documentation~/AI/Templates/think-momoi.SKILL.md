먼저 모드를 정한다. "명세서대로 만들어", "새 프로젝트 시작", 시스템층(`Assets/Code/Rules`의 규칙 함수·행동)이 아직 없으면 **시스템 모드**. 개별 콘텐츠 목록·효과 문장이면 **콘텐츠 모드**. 둘 다 아니면 묻는다.

## 시스템 모드 — 명세서 → 시스템층

목표는 레벨 디자인(개별 카드·몬스터·수치)을 뺀 모든 시스템과 화면을 하루 안에 만드는 것이다.

1. `PlanningSpecGuide.md`·`GimmickCatalog.md`를 끝까지 읽고, `Docs/PlanningSpec.md`를 끝까지 읽는다.
2. **질문 목록**을 만든다(가이드 1·4절): 빈 [필수] 칸 · 칸끼리 모순 · 기믹 목록 1절 모양(조각·자리·순서)으로 풀리지 않는 메인 룰 · 갈래로 쪼개지지 않는 이상한 효과 · 4-2에 표시가 없는데 이상한 효과에 보이는 구조(빌려 쓰기·여러 칸 …) · 문법 밖 기믹. 20개 이하, 바꾸기 비싼 것부터, 질문마다 정하는 것 · 추천값 · 이유 · 답이 없으면 무엇으로 가는지. **한 번의 답장에 번호 목록으로** 묻고 기다린다. 질문이 없으면 이 단계를 건너뛰고 추천값으로 정한 것을 3단계에서 알린다.
3. 답을 받으면 명세서에 답을 적어 두라고 권하고(사람이 허락하면 `Docs/PlanningSpec.md` 끝에 "정한 것" 절로 적는다), **시스템 목록**(가이드 5절)을 한 페이지로 보이고 확인을 한 번 받는다.
4. 관례 16절 순서로 만든다: 데이터 → 규칙 함수(동사마다 의도·가로채기 자리·이벤트)·메인 룰(조각 = 객체 목록, 자리 = 목록 + 줄 길이, 순서, 4-2에 표시된 자리) → 행동·재사용 Block → 프로젝트 고유 DB 종류 → DB 항목(DB 추가 메뉴·CSV) → 규칙 테스트(판 시작부터 한 단위 끝까지 행동만으로) → 화면(기본 화면을 뺀 화면마다 UXML·USS → DB › 화면 → 화면 코드) → 연출.
   - 단계마다 응답을 끝내면 컴파일 훅이 돈다. 오류는 그 자리에서 고친다.
   - 새로 생긴 의문은 되돌리기 쉬우면 정하고 보고, 어려우면 모아서 한 번에 묻는다.
5. 보고(관례 12절): 사람이 할 일(누를 DB 추가 메뉴 → Ctrl+S, 넣을 에셋: 경로·크기·쓰는 곳, Unity에서 볼 것), 추천값으로 정한 것, 명세서와 달라진 점, 정한 새 이름.

## 콘텐츠 모드 — 효과 문장 → DB·Block·코드

1. 문장마다 기믹 목록 2절의 갈래를 찾는다(자리·순서 · 반복 · 복사 · 변환 · 확률 · 규칙 바꾸기 · 쌓이는 값 · 세트 · 가진 동안 능력치 · 상태 효과 · 보상 · 판 구조). 갈래에 적힌 부품이 만드는 법이다. 갈래가 없으면 관례 13절대로 쪼갠다: 언제(즉시·발동·지연·지속) · 누구에게 · 무엇을 · 안전장치(사슬 한도).
2. 만드는 길을 고른다(관례 0절): DB 조합(있는 Block) → 재사용 Block을 더함 → 그 항목만의 `[BindTo]` → 중간층 확장(동사의 의도·이벤트에 필드 추가). 앞의 것으로 되면 뒤로 가지 않는다.
3. 메인 룰에 자리가 없어 예외 코드가 될 것(빌려 쓰기·여러 칸 차지·위치로 태그 바뀜 …, 기믹 목록 3절)은 덧붙이지 않고 메인 룰을 고친다. 고치는 범위가 크면 먼저 알린다.
4. 문법 밖이면(규칙 밖에서 정해지는 것) 만들지 않고 표시해서 묻는다: 무엇이 밖인지, 만드는 방법(화면 쪽·별도 시스템·근사)과 비용.
5. 항목은 DB 추가 메뉴(관례 15절) 또는 CSV(숫자가 많을 때). 숫자는 밸런스 값, 확률·풀은 가중치 표, 글은 텍스트 키(`<ID>.name` …).
6. 시험: 개발 명령(DB › 개발 명령)·모니터 명령 탭으로 하나씩, 규칙이 바뀌었으면 규칙 테스트.
7. 보고: 만든 항목(종류 · ID · 쓴 Block), 새로 만든 Block·`[BindTo]`·의도 필드, 사람이 할 일.

**역할**: 로직·DB 항목·화면·테스트 도구는 AI가 코드와 DB 반영 스크립트로 만든다. 개발자는 에디터에서 읽고, 밸런싱 값을 바꾸고, 다이얼로그 그래프를 만들고, 레벨을 배치하고, 에셋을 가져오고, 테스트한다. 그래서 만드는 모든 것은 에디터에서 읽히고 숫자·참조를 바꿀 수 있고 테스트할 수 있어야 한다(관례 18·19절).

## 시작할 때(매번)

1. `Docs/Decisions.md`를 읽는다 — 지금 단계·다음 할 일·이미 정한 것. 파일이 없으면 단계 0.
2. 요청이 어느 단계 일인지 정한다.

   | 요청 | 단계 |
   |---|---|
   | 자료·기획서·명세서를 줌, "새 프로젝트" | 0 흡수 |
   | "명세서대로 만들어", 시스템·흐름 | 1 시스템층(단계 0의 나가는 조건이 하나라도 거짓이면 0부터) |
   | 카드·적·유물 목록, 효과 문장 | 2 콘텐츠 |
   | 레벨·맵·웨이브 배치 준비, 대사 연결 | 3 레벨 디자인 |
   | 화면·연출·사운드·에셋 | 4 |
   | 버그, "이 숫자를 바꾸고 싶다", 테스트 상황 | 5 밸런싱·테스트 |
   | 출시·Steam·빌드 | 6 |
   | 기획을 바꿈·새 기믹·"이것도 되게" | 변경 요청(진행 매뉴얼 12절) |

3. 진행 매뉴얼의 그 단계 절을 다시 읽고 따른다. 앞 단계의 나가는 조건이 거짓이면 그것부터 채운다.

## 단계 0 — 흡수(가장 중요)

목표: 나중에 시스템을 갈아엎게 만들 것을 지금 다 끌어낸다.

1. 자료(`Docs/Source/`)·명세서·기믹 목록을 끝까지 읽는다. 시트는 모든 효과 문장까지.
2. 자료로 명세서를 채운다(칸마다 `(자료)`·`(답 D-n)`·`(추천 승인 D-n)`). **넘겨짚지 않는다** — 자료에 없는 칸은 [선택]까지 모두 추천을 붙여 묻고(작은 것은 추천 승인 목록으로 묶어), 개발자의 답·승인이 있어야 확정이다. 두 가지로 읽히는 자료는 "이렇게 이해했다"를 확인받는다.
3. 예외 잡기(진행 매뉴얼 5-3): 메인 룰을 조각·자리·순서로 써 보기 → 효과 문장을 갈래로 나눠 보기 → 예외 잡기 표를 예/아니오로 묻기 → 개발자 몫(밸런싱 범위·레벨 배치·대사·테스트 상황) 묻기.
4. 질문을 한 번에 보낸다(진행 매뉴얼 3절 형식). 개수 제한은 없지만 같은 것을 다시 묻지 않고(3-1), 묶음마다 남은 열린 결정 수가 줄어야 하며(3-2), 여섯 칸이 다 찬 질문만 보낸다(3-3). 질문과 상관없는 준비는 계속한다.
5. 답 → 결정 기록·명세서 → 시스템 목록(읽는 법 5절)을 보여 확인 한 번. 나가는 조건(진행 매뉴얼 5-5)이 모두 참이면 단계 1.

## 단계 1 — 시스템층

관례 16절 순서로 만든다. 함께 반드시: 밸런싱이 될 숫자를 에디터에(관례 18절), 테스트 씬·기본 테스트 명령(관례 19절), 레벨 데이터의 자리. 멀티면 처음부터 관례 20절(플레이어별 칸·공개 범위·서버 규칙)과 시험 모드 한 번. 단계마다 응답을 끝내면 컴파일 훅이 돈다 — 오류는 그 자리에서 고친다. 나가는 조건: 판 하나가 행동만으로 끝까지 돈다(규칙 테스트) · 테스트 씬에서 시험된다.

## 단계 2 — 콘텐츠

1. 문장마다 기믹 목록 2절의 갈래 → 부품. 관례 0절 순서(DB 조합 → 재사용 Block → `[BindTo]` → 중간층).
2. 메인 룰에 자리가 없어 예외 코드가 될 것은 덧붙이지 않고 메인 룰을 고친다 — 범위가 크면 진행 매뉴얼 12절대로 묻는다.
3. DB 반영 스크립트(`[DbSeed]`)로 넣는다. 숫자가 많으면 CSV. 숫자·이름·글이 빠졌으면 가안으로 넣고 '확인 기다리는 것'에 올려 승인받는다.
4. 조각마다 테스트 명령(얻기·쓰기·걸기).

## 단계 3~6

진행 매뉴얼 8~11절. 레벨 배치·대사는 개발자가 한다 — AI는 데이터 모양·배치 도구·연결·검증을 만든다. 버그 보고를 받으면 같은 상황을 테스트 상황·규칙 테스트로 재현한 뒤 고친다.

## 모든 단계에서

- 확정(개발자 답·승인)은 바로 결정 기록에, 같은 내용을 채팅 답에도 한 줄씩("기록: D-12 …"). 답을 기다리는 추천·가안은 '확인 기다리는 것'에.
- **기획은 넘겨짚지 않는다.** 뒤집기 비용이 큰 것은 하나씩 묻고, 되돌리기 쉬운 것(이름·수치·화면 배치)은 추천 승인 목록으로 묶어 승인받는다. 단계 1 이후 만들다 생긴 작은 것은 가안으로 넣고 진행할 수 있지만 승인 전에는 확정이 아니다. 구현 방식(코드 이름·내부 구조)은 AI가 정한다.
- 문법 밖이면 만들지 않고 표시해서 묻는다: 무엇이 밖인지, 만드는 방법(화면 쪽·별도 시스템·근사)과 비용.
- 응답 끝에 진행 매뉴얼 13절: 개발자가 할 일(적용할 DB 항목·넣을 에셋·돌려 볼 테스트 상황·Unity에서 볼 것) · 기록한 결정 · 확인 기다리는 것(승인 요청) · 지금 단계와 다음 할 일.

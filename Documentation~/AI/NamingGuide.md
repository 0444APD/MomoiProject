# 명명 가이드라인 (AI용)

개발자에게 보이는 이름을 **처음부터 개발자 말투로** 짓기 위한 규칙이다. 프로젝트마다 개발자가 바로잡은 이름을 4절 표에 모아, 다음 프로젝트에서는 같은 것을 다시 바로잡지 않게 한다.

- 이름을 새로 지을 때는 먼저 **4절 표**를 본다. 표에 있는 말은 바꾼 이름을 쓴다.
- 개발자가 이름을 바로잡으면 그 자리에서: ① 그 프로젝트의 화면 글·DB 이름·문서·코드 주석을 모두 바꾸고, ② 결정 기록에 적고, ③ **이 문서 4절 표에 한 줄 더한다**(라이브러리 커밋).

## 1. 이름의 세 종류

| 종류 | 예 | 누가 정하나 |
|---|---|---|
| 코드 이름 | 클래스·필드·함수·DB ID(`manaMax`)·이벤트 클래스 | AI — 영어, 관례 2절. 개발자 확인 없이 정하고 보고에 목록만 |
| **개발자 화면 이름** | DB 종류·탭 이름, 칸 이름표(`[FieldLabel]`), Block·이벤트·행동 직전 이벤트의 표시 이름, enum의 `[InspectorName]`, 키워드 그룹 이름, 밸런스 값의 표시 이름, 메뉴 | AI가 이 문서대로 짓고, 새 개념이면 개발자에게 확인(관례 2절) |
| 플레이어에게 보일 글 | 텍스트 키의 원문(`hud.gold`) | 기획 — 명세서·개발자 |

## 2. 개발자 화면 이름의 규칙

1. **게임을 만드는 사람이 평소 쓰는 말**로 짓는다. 우리말로 옮긴 말보다 업계에서 흔히 쓰는 외래어가 자연스러우면 그것을 쓴다(사건 → **이벤트**). 단, 4절 표에서 다른 말로 정해진 것은 그 말(예: 능력치 — Stat은 '로그'가 쓴다).
2. **기술 용어는 원어 그대로** 쓰고 처음 쓸 때 뜻을 한 줄 붙인다(Mirror, ChangeSet, Sync, 컨텍스트 …). 억지로 한글로 옮기지 않는다.
3. **한 개념에 한 이름.** 같은 것을 두 이름으로 부르지 않는다(동의어를 만들지 않는다). 다른 것에 같은 이름을 쓰지 않는다 — 겹치면 앞에 꾸밈말을 붙인다(이벤트 / 행동 직전 이벤트).
4. **짧게, 뜻이 드러나게.** 칸 이름은 무엇인지만(단위·형식은 주석으로 — 3절). 동작은 동사(걸기·풀기·옮기기), 상태·물건은 명사.
5. **이벤트 표현**: 이벤트는 '쏜다'(알린다)와 '받는다'(신호를 받고 값을 읽는다). '발생시킨다·구독한다'는 쓰지 않는다.
6. **번호·결정 근거는 이름에 넣지 않는다**(메모·주석에). 이름은 개발자가 화면에서 읽는 말이다.

## 3. 밸런스 값 만들기 — 표시 이름 · 메모 · 입력 칸 주석 · 묶음

밸런스 값(DB › 밸런스 값)을 DB 반영 스크립트로 만들 때는 값과 함께 넷을 꼭 채운다. 개발자는 DB의 밸런스 값 탭에서 이 넷으로 읽고, ✎로 언제든 고친다.

| 칸 | 무엇을 | 예 |
|---|---|---|
| 표시 이름(`label`) | 한글로 짧게, 무엇의 숫자인지. 같은 묶음 안에서 앞말을 맞춘다 | `마나 최대치` · `이동 이벤트 — 기본 확률` |
| 메모(`note`) | 무엇에 쓰는지 · 어디에 곱하는지 · 0이나 끝값이면 어떻게 되는지 · 근거 결정 번호 | `시간 1마다 차는 마나.` · `다 되면 런 실패(D-74).` |
| 입력 칸 주석(`hint`) | **형식이 필요한 값만**: 단위(`초` · `걸음` · `초당`), 범위(`% (0~100)`), 뜻(`1 = 그대로, 0 = 멈춤` · `0.5 = 가격의 절반`). 그냥 개수면 비운다 | `초(2400 = 40분)` |
| 묶음(폴더) | 주제별 머리글(개발자가 찾는 단위): 시간 · 마나·카드 · 배고픔·제한 시간 · 지도·걷기 · 이동 이벤트 · 도주 · 칸·경제 · 성장 … | — |

- 확률은 개발자가 읽기 쉬운 **%(0~100)**로 두고 규칙 코드가 100으로 나눈다. 배율은 `1 = 그대로`를 기준으로.
- 곡선은 단계에 따라 바뀌는 값에만 켠다(밸런스 값 탭은 곡선을 쓰는 값에만 곡선 칸을 보인다). 메모에 단계가 무엇인지(깊이 · 레벨 · 층) 적는다.
- 반영 스크립트는 값을 한 표(id · 값 · 표시 이름 · 묶음 · 주석 · 메모 · 곡선)로 두고, 새 항목을 만들 때 넷을 함께 넣는다. 이미 있는 항목은 비어 있는 칸만 채운다(개발자가 고친 것을 덮지 않는다).

## 4. 바로잡은 이름 (모은 것)

개발자가 바로잡은 이름이다. 위가 최근. 표에 있는 왼쪽 말은 쓰지 않는다.

| 쓰지 않는 말 | 쓰는 말 | 어디 | 언제 · 프로젝트 |
|---|---|---|---|
| 사건(노드 종류·이동 중에 뜨는 것) | **이벤트** — 이동 사건 → 이동 이벤트 | 게임 화면 이름·밸런스 값·문서 | 2026-10-11 · 보드 런 |
| 가로채기 · 의도 | **행동 직전 이벤트**(받기 · 고치기) | GBible 트리거·결과·문서 | 2026-10-11 · GBible |
| 예외 사냥 | **예외 잡기** | 진행 매뉴얼 | 2026-10-06 · GBible |
| 방장·방 열기 / 들어가기 / 되감기 지점 | **방 생성** / **방 참가** / **Undo 지점** | 멀티 화면 | 2026-10-06 · GBible |
| 씨앗 | **DB 반영 스크립트**(메뉴는 처음에 'DB 추가 메뉴') | 에디터 | 2026-10-04 · GBible |
| 드롭 표 | **가중치 표** | DB 종류 | 2026-10-04 · GBible |
| 도감 · 데이터베이스 창 | **DB** · DB 창 | 에디터 | 2026-10-03 · GBible |
| 이벤트 쏘기(모니터 도구) | **이벤트 호출** | 모니터 | 2026-10-02 · GBible |
| 맥락 | **컨텍스트**(`TriggerContext`) | 문서·화면 | 2026-10-02 · GBible |
| 템플릿(DB 원본) | **인스턴스** | DB 종류 | 2026-10-02 · GBible |
| 수치 / 상태 키 / 선택지 목록 | **로그** / **플레이어 데이터** / **키워드** | DB 탭 | GBible 초기 |

# 명명 가이드라인 (AI용)

개발자에게 보이는 이름을 **처음부터 개발자 말투로** 짓기 위한 규칙이다. 프로젝트마다 개발자가 바로잡은 이름을 4절 표에 모아, 다음 프로젝트에서는 같은 것을 다시 바로잡지 않게 한다.

- [필수] 이름을 새로 지을 때는 먼저 **4절 표**를 본다. 표에 있는 말은 바꾼 이름을 쓴다.
- [필수] 개발자가 이름을 바로잡으면 그 자리에서: ① 그 프로젝트의 화면 글·DB 이름·문서·코드 주석을 모두 바꾸고, ② 결정 기록에 적고, ③ **이 문서 4절 표에 한 줄 더한다**(라이브러리 커밋).

## 0. 개발자와 함께 쓰는 말(2026-10-12 개발자 정의)

| 말 | 뜻 | 헷갈리지 말 것 |
|---|---|---|
| **메뉴얼** | AI가 프로젝트를 진행할 때 필요한 모든 양식·규칙·단계·지침, 그리고 GBible 기능과 개발자와 협업하는 데 필요한 지식을 담은 **문서 전체**(`Documentation~/AI/` 전부 · 기능 장 `Manual/` · 사람용 `Guide/` · CLAUDE·스킬 틀). 개발자가 "메뉴얼을 업데이트해라"라고 하면 알맞은 문서들을 고쳐 **지금 프로젝트와 앞으로의 모든 프로젝트**가 따르게 한다 — 어디를 고치나는 `ManualMap.md` 끝 절 | 문서 안의 '매뉴얼 NN장'은 그중 기능 장(`Manual/`), '진행 매뉴얼'은 `ProjectFlow.md` |
| **밸런싱 값** | 개발자가 프로젝트에서 직접 건드리는 데이터 전부 — 숫자(DB › 밸런싱 값 탭) · DB 칸 · 인스턴스 필드 · 고르는 값 · 참조(드롭다운). DB 탭 이름도 '밸런싱 값' | 같은 말이다('밸런스 값'은 쓰지 않는다) |
| **지바이블(GBible)** | 모니터링 · 값 바꾸기 · 테스트를 위한 **개발자 도구**(이 패키지) | 시스템이 아니다 |
| **시스템** | 지금 진행하는 프로젝트의 **코어 스크립트들**(규칙·행동·이벤트 — 단계 1 '시스템층'이 만드는 것) | 지바이블과 섞어 부르지 않는다 |

## 1. 이름의 세 종류

| 종류 | 예 | 누가 정하나 |
|---|---|---|
| 코드 이름 | 클래스·필드·함수·DB ID(`manaMax`)·이벤트 클래스 | AI — 영어, 관례 2절. 개발자 확인 없이 정하고 보고에 목록만 |
| **개발자 화면 이름** | DB 종류·탭 이름, 칸 이름표(`[FieldLabel]`), Block·이벤트·행동 직전 이벤트의 표시 이름, enum의 `[InspectorName]`, 키워드 그룹 이름, 밸런싱 값의 표시 이름, 메뉴 | AI가 이 문서대로 짓고, 새 개념이면 개발자에게 확인(관례 2절) |
| 플레이어에게 보일 글 | 텍스트 키의 원문(`hud.gold`) | 기획 — 명세서·개발자 |

### 1-1. DB ID — 같은 개념이 여러 DB 종류로 나뉠 때

DB ID는 **모든 DB 종류를 통틀어 하나**다(인스턴스 `sword`와 패시브 효과 `sword`를 함께 둘 수 없다). 한 개념(아이템 하나 · 캐릭터 하나)이 여러 종류의 항목으로 나뉘면:

- **대표 항목**(원본 인스턴스 · 캐릭터)이 짧은 이름을 갖는다: `sword`, `seoa`. 인스턴스 ID는 lowerCamelCase 이름 하나다(`ironSword`, `potion`) — 종류 이름(`instance.`)을 앞에 붙이지 않는다.
- **딸린 항목**은 `대표.갈래`: `sword.fx`(그 아이템의 패시브 효과) · `seoa.profile`(스탠딩 프로필) · `seoa.talk1`(다이얼로그) · `seoa.date1`(이벤트 표 줄). 텍스트 키 `<id>.name`도 항목마다 따로 생긴다(`seoa.name` · `seoa.profile.name`).
- 원본이 DB 항목이 아니고 판 데이터에만 있는 조각(조커처럼 원본 ID가 곧 패시브 효과를 가리키는 것)은 패시브 효과 ID를 원본 ID로 쓴다(기믹 목록 1절).
- **ID를 종류 이름과 같게 짓지 않는다.** `GameIds`는 종류마다 안쪽 클래스(`GameIds.RunSettings`)를 두고 상수 이름을 ID에서 만들므로, ID가 종류 이름과 같으면(`runSettings` 종류 `RunSettingsData`) 상수가 클래스 이름과 겹쳐 `_2`가 붙는다(`GameIds.RunSettings.RunSettings_2`). 하나만 두는 설정 종류도 종류 이름과 다른 말로 짓는다(예: `RunSettingsData`면 `runConfig`). 라이브러리가 만드는 `screenSettings`(`GameIds.ScreenSettings.ScreenSettings_2`) · `steam`(`Steam_2`)은 알려진 예외다(고치지 않는다).
- **키워드 ID도 모든 그룹을 통틀어 하나**다(아이템 종류 `weapon`과 피해 종류 `weapon`이 겹친다). 겹칠 수 있는 그룹은 값에 그룹 앞말을 붙인다(`dmgPhysical` · `itemWeapon` — 키워드 ID는 lowerCamelCase라 점을 쓰지 않는다, 매뉴얼 05장). 겹쳐도 경고가 없으니 더하기 전에 DB 키워드 탭에서 찾아본다.

## 2. 개발자 화면 이름의 규칙

1. **게임을 만드는 사람이 평소 쓰는 말**로 짓는다. 우리말로 옮긴 말보다 업계에서 흔히 쓰는 외래어가 자연스러우면 그것을 쓴다(사건 → **이벤트**). 단, 4절 표에서 다른 말로 정해진 것은 그 말(예: 로그 — 코드 이름은 Stat이지만 DB 탭은 '로그', 캐릭터 수치는 **스탯**).
2. **기술 용어는 원어 그대로** 쓰고 처음 쓸 때 뜻을 한 줄 붙인다(Mirror, ChangeSet, Sync, 컨텍스트 …). 억지로 한글로 옮기지 않는다.
3. **한 개념에 한 이름.** 같은 것을 두 이름으로 부르지 않는다(동의어를 만들지 않는다). 다른 것에 같은 이름을 쓰지 않는다 — 겹치면 앞에 꾸밈말을 붙인다(이벤트 / 행동 직전 이벤트).
4. **짧게, 뜻이 드러나게.** 칸 이름은 무엇인지만(단위·형식은 주석으로 — 3절). 동작은 동사(걸기·풀기·옮기기), 상태·물건은 명사.
5. [필수] **이벤트 표현**: 이벤트는 '쏜다'(알린다)와 '받는다'(신호를 받고 값을 읽는다). '발생시킨다·구독한다'는 쓰지 않는다.
6. **번호·결정 근거는 이름에 넣지 않는다**(메모·주석에). 이름은 개발자가 화면에서 읽는 말이다.

## 3. 밸런싱 값 만들기 — 표시 이름 · 메모 · 입력 칸 주석 · 묶음

밸런싱 값(DB › 밸런싱 값의 숫자)을 DB 반영 스크립트로 만들 때는 값과 함께 넷을 채운다(입력 칸 주석은 형식이 필요한 값만). 개발자는 DB의 밸런싱 값 탭에서 이 넷으로 읽고, ✎로 언제든 고친다.

| 칸 | 무엇을 | 예 |
|---|---|---|
| 표시 이름(`label`) | 한글로 짧게, 무엇의 숫자인지. 같은 묶음 안에서 앞말을 맞춘다 | `최대 마나` · `이동 이벤트 — 기본 확률` |
| 메모(`note`) | 무엇에 쓰는지 · 어디에 곱하는지 · 0이나 끝값이면 어떻게 되는지 · 근거 결정 번호 | `시간 1마다 차는 마나.` · `다 되면 런 실패(D-74).` |
| 입력 칸 주석(`hint`) | **형식이 필요한 값만**: 단위(`초` · `걸음` · `초당`), 범위(`% (0~100)`), 뜻(`1 = 그대로, 0 = 멈춤` · `0.5 = 가격의 절반`). 그냥 개수면 비운다 | `초(2400 = 40분)` |
| 묶음(폴더 — `EditorAssignFolder`) | 주제별 머리글(개발자가 찾는 단위) — 예: 시간 · 마나·카드 · 포만감·제한 시간 · 지도·걷기 · 이동 이벤트 · 도주 · 칸·경제 · 성장 … | `item.EditorAssignFolder("시간")` · 아래 단계는 `"전투/보스"` |

- 확률은 개발자가 읽기 쉬운 **%(0~100)**로 두고 규칙 코드가 100으로 나눈다. 배율은 `1 = 그대로`를 기준으로.
- 곡선은 단계에 따라 바뀌는 값에만 켠다(밸런싱 값 탭은 곡선을 쓰는 값에만 곡선 칸을 보인다). 메모에 단계가 무엇인지(깊이 · 레벨 · 층) 적는다.
- 반영 스크립트는 보통 값을 한 표(id · 값 · 표시 이름 · 묶음 · 주석 · 메모 · 곡선)로 두고, 새 항목을 만들 때 넷을 함께 넣는다. [필수] 이미 있는 항목은 비어 있는 칸만 채운다(개발자가 고친 것을 덮지 않는다).

## 5. 게임 이름의 기본(모든 프로젝트 — 2026-10-12 개발자)

프로젝트를 진행하며 개발자와 소통하고 지바이블에 보일 이름이다. 코드 이름(영어 필드·클래스)은 AI가 알아서 짓는다(개발자가 직접 건드릴 일이 없다). 프로젝트가 다르게 정한 것만 그 프로젝트를 따르고, 결정 기록에 적는다.

### 5-1. 이벤트

- 코드의 알림(Action 콜백·`GameEvent`)과 게임 안의 사건·트리거를 **모두 '이벤트'**라 한다. 히든 이벤트 · 보스 조우 이벤트 · 이동 중 이벤트 · 아이템 사용 이벤트.
- 이미 있는 꾸밈말은 그대로: 행동 직전 이벤트(`Intent`). 쏜다·받는다(2절 5).
- **행동**(`GameAction` — 플레이어 입력 하나, Undo 한 단위)은 이벤트라 부르지 않고 '행동' 그대로(개발자 승인 2026-10-12): 행동은 일어나게 하는 명령, 이벤트는 그 결과 일어난 일이다. 지바이블 타임라인은 '행동 하나 → 그 안에서 쏜 이벤트들'로 보인다.

### 5-2. 스탯

- 이름의 출처 순서: ① **리그 오브 레전드(롤) 한국어**(공격력 · 이동 속도 …) ② 없으면 **세피리아** ③ 고유 키워드는 **와일드프로스트**의 패시브 키워드(이 감성의 말이 좋다). 모은 목록은 6절 — 매번 찾지 않고 6절을 본다.
- 속성: `~ 속성` — 번개 속성 · 불 속성 · 얼음 속성.
- 최대값: `최대 ~` — 최대 체력 · 최대 마나 · 최대 핸드 수. 지금 값은 `현재 ~`, 줄어든 만큼은 `잃은 ~` — 현재 체력 · 잃은 체력.
- **고유 개념**(포만감처럼 그 게임만의 것)은 최대값을 `최대 ~`로 하지 않고 이름 그대로 — '포만감'. 지금 값·줄어든 만큼은 그대로 `현재 포만감` · `잃은 포만감`.
- 스킬에 붙는 비율은 **계수**: `0.3 계수` · `1.0 공격력 계수`(= 1.0 AD 계수).

### 5-3. 카드 덱

- **덱**(카드 전체 — 뽑을 카드가 쌓인 곳도 덱) · **핸드** · **버려진 덱**.

### 5-4. 유물 · 효과 · 스킬

- 패시브 효과를 주는 물건은 **유물**(기본). 개발자가 프로젝트마다 "유물을 아티팩트로" 식으로 바꿀 수 있다 — 바꾸면 그 프로젝트 전체를 바꾸고 결정 기록에.
- 무언가의 결과 로직은 **효과**: 패시브 효과 · 액티브 효과 · 아이템 효과 · 고유 효과. 지바이블 DB 탭도 **상태 효과 · 패시브 효과 · 액티브 효과**.
- **스킬**은 비교적 플레이어가 직접 쓰는 액티브 쪽, **효과**는 로직 그 자체. 개발자는 둘을 섞어 쓸 수 있다 — 문맥으로 알아듣는다.

### 5-5. 아이템

- **장비**: 유닛이 장착하는 아이템. **소비 아이템**: 사용하는 아이템. **기타 아이템**: 둘 다 아닌 것(대체로 팔기 위한 것).
- 필요할 때만 더 나눈다: **귀중품**(기타와 돈벌이용을 나눌 때) · **자재**(제작이 있을 때).

### 5-6. 유닛

- 조종하는 게임의 각 객체는 **유닛**. 내 쪽은 **아군**, 상대는 **적**.
- 펫 개념이 있으면 메인 아군은 **플레이어블**, 펫 같은 것은 **하수인**(게임 분위기에 따라 소환수).

### 5-7. 아이템 컨테이너

- 아이템을 담는 묶음 = **아이템 컨테이너**(추상 — 부모 같은 개념, 직접 부를 일은 적다). 목적에 따라:
  - **창고** — 플레이어의 로비 아이템 컨테이너(플레이어블에 딸리지 않음).
  - **인벤토리** — 플레이어(플레이어블)가 들고 다니는 아이템 컨테이너.
  - **전리품** — 쓰러뜨린 것이 가진 아이템 컨테이너(개발자는 '시체'라고도 함).
  - **주머니** — 인벤토리와 비슷하지만 퀵슬롯 같은 따로 쓰는 기능이 있을 때.
  - **상자**(또는 컨테이너) — 아이템 컨테이너 안에 아이템으로 든 아이템 컨테이너(인벤토리 안의 인벤토리).
- 한 칸 = **슬롯**(아이템 슬롯).

### 6-4. 겹칠 때 정한 것

- **같은 말, 다른 뜻**은 출처 순서(롤 먼저)를 따르고 뒤의 것은 다른 이름으로: 강인함 = 롤(군중 제어 시간 감소) — 세피리아의 '받는 피해 고정 감소'는 `피해 감소`. 고정 피해 = 롤(방어 무시) — 세피리아의 '계산 뒤 더하는 피해'는 `추가 피해`. 이동 불가 = 롤(군중 제어) — 와일드프로스트의 '옮길 수 없는 카드'는 `고정`(추정, 개발자 확인).
- **체력·마나**로 쓴다(세피리아의 HP·MP 줄임말은 쓰지 않는다). 피해는 '피해'(대미지 아님). 치명타 피해는 `치명타 피해량`.
- **비슷한 것끼리 섞지 않는다**: 보호막(롤) · 껍질 · 방어벽 / 가시(되돌리는 %) · 이빨(되돌리는 고정값) / 치명타(확률) · 치명(자리 키워드) / 격노(연속 발동) · 분노(공격 +X) / 카운터(카운트다운) · 반격 · 반응 / 생명력 흡수 · 흡수(아군을 먹음).
- **일반 말과 같은 키워드**(무작위 · 봄 · 불꽃)는 쓸 때 키워드임을 드러낸다(지바이블 Block '무작위 n개'와 섞이지 않게).

# 구현 가이드 (AI용)

게임 하나(카드 던전)를 처음부터 끝까지 만들어 보이며 **장르별 조립 · 습관 · 흐름**을 안내한다. 장마다 "지금 무엇을 정하고, 무엇을 만드는가"를 짧은 본문과 코드로 보이고, 이유·세부는 접힌 칸에 둔다.

다른 문서와의 몫:

- 진행 순서·질문·결정 기록 → [진행 매뉴얼](../ProjectFlow.md). 이 가이드보다 먼저다.
- 지킬 규칙 → [프로젝트 관례](../ProjectConventions.md) · 무엇이 있나 → [참조](../Reference.md) · 기능 하나의 문법·옵션 전부 → [기능 장](../../Manual/00-Index.md).
- 이 가이드 → 그 기능들을 어떤 순서로 엮고 무엇을 기준으로 고르나. API 설명은 한두 줄만 두고 기능 장을 가리킨다(장 끝 '더 보기').

**역할**(관례 첫머리): 로직·DB 항목·화면·테스트 도구는 AI가 코드와 **DB 반영 스크립트**(`Assets/MomoiProject/Code/Editor/Seeds`의 `[DbSeed]` 함수, 관례 15절)로 만든다. 개발자는 에디터에서 읽고(DB·모니터), 밸런싱 값을 바꾸고, 다이얼로그 그래프·레벨·에셋을 넣고, 테스트한다. 그래서 이 가이드에서 "DB › X에 항목을 만든다"는 반영 스크립트로 만든다는 뜻이다 — 개발자의 DB 창은 로직 쪽 항목의 추가·삭제·ID 바꾸기와 Block 조립을 잠그고 값만 연다(`EditorPolicy`). '프로그래머 실수'는 코드 실수(없는 ID 등)를 뜻하는 말이다로 읽는다.

기믹(조각의 효과 규칙)의 범위는 네 게임(발라트로·와일드프로스트·매지크래프트·세피리아)의 다양성이다. 장르·화면·싱글/멀티는 자유다. 갈래마다 무엇으로 만드나는 [기믹 목록](../GimmickCatalog.md).

## 예시 게임: 카드 던전

모든 장이 같은 게임 하나를 조금씩 키워 가며 설명한다. 턴제 덱빌딩 로그라이크다.

- 판(런)을 시작하면 주인공이 시작 덱·유물·물약을 가지고 1층 전투에 들어간다.
- 전투는 턴제다. 턴마다 에너지를 받아 핸드의 카드를 내고(피해·방어도·화상), 턴을 끝내면 적이 공격 패턴대로 행동한다.
- 이기면 골드를 받고 다음 층으로, 상점에서 카드를 사고 상점 주인과 대화한다. 쓰러지면 판이 끝나고 기록이 프로필에 남는다.
- 도전과제(첫 승리, 한 턴 30 피해), 로그(처치 수, 한 턴 최대 피해, 번 골드), 유물(전투 첫 턴 방어도, 승리 때 회복)이 붙는다.

쓰는 것: 플레이어 데이터(판 `run` = 세션 구역, 프로필 `profile` = 메타 구역), 인스턴스(카드·몬스터·물약 원본), 키워드, 이벤트, 행동과 Undo, 비용(`Game.Pay`)·플레이어용 실패(`Game.Fail`), 효과·대상 Block, `[BindTo]`, 상태 효과(화상), 패시브 효과(유물), 도전과제·로그, 인벤토리(물약 슬롯), 화면(DB › 화면)·연출 대기열·미리보기, 다이얼로그, 텍스트, 오디오, 필드 규칙, 개발 명령, 저장과 이어 하기. 덱빌딩에 맞지 않는 것은 [07장](07-GenreRecipes.md)과 장마다 '다른 장르라면' 접힌 칸에서 다룬다.

## 장 구성

01–11장은 같은 모양이다.

1. **첫 문단** — 이 장에서 하는 일, 한두 문장
2. **이 장에서 쓰는 말** — 접힌 칸(그 장에서 처음 나오는 말)
3. **번호 붙은 절** — 할 일과 핵심 코드만 짧게
4. **체크리스트** — 마지막 절
5. **더 보기(매뉴얼)** — 접힌 칸

**본문은 흐름, 접힌 칸은 세부다.** `> [!note]- 제목` 모양의 칸은 Obsidian에서 접힌 채 보인다(다른 Markdown 뷰어에서는 인용문). 이유·표·긴 코드·'다른 장르라면'이 여기 있다.

다른 장의 절은 "NN장 N절"로 가리킨다.

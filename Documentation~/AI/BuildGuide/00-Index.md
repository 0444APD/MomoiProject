# 구현 가이드 (AI용)

> 이 문서는 예전 '프로그래머 가이드'다. 2026-10-05부터 코드는 AI가 쓰므로 AI용 참고로 옮겼다(사람용은 `Documentation~/Guide/`의 운영 가이드). 진행 순서·질문·결정 기록은 [진행 매뉴얼](../ProjectFlow.md)이 우선한다. 이 문서는 "카드 던전 하나를 처음부터 끝까지 코드로 만들면 이렇게 된다"는 예시로 읽는다. 본문의 '프로그래머'는 AI, '기획자'는 개발자다. DB 항목을 메뉴로 만드는 곳은 지금은 DB 반영 스크립트(`[DbSeed]`, 관례 15절)로 읽는다.

Momoi Project(코드 이름 `GBible`)로 **프로젝트를 시작해서 출시할 때까지 코드를 쓰는 쪽이 하는 일**을 순서대로 안내한다. 장마다 "지금 무엇을 정하고, 무엇을 만드는가"를 짧은 본문과 코드로 보이고, 이유·자세한 설명은 접힌 칸에 둔다.

[매뉴얼](../../Manual/00-Index.md)과의 관계: 매뉴얼은 기능별 사전(모든 문법과 옵션)이고, 이 가이드는 진행 순서와 판단 기준이다. 가이드에서 처음 나오는 기능은 장 끝 '더 보기'에서 매뉴얼의 해당 장으로 잇는다.

기믹(조각의 효과 규칙)의 범위는 네 게임(발라트로·와일드프로스트·매지크래프트·세피리아)의 다양성으로 본다. 장르·화면·싱글/멀티는 자유다. 기믹 갈래마다 무엇으로 만드나는 AI 문서 [기믹 목록](../GimmickCatalog.md)에 있다.

## 예시 게임: 카드 던전

모든 장이 같은 게임 하나를 조금씩 키워 가며 설명한다. 턴제 덱빌딩 로그라이크다.

- 판(런)을 시작하면 주인공이 시작 덱·유물·물약을 가지고 1층 전투에 들어간다.
- 전투는 턴제다. 턴마다 에너지를 받아 손패의 카드를 내고(피해·방어도·화상), 턴을 끝내면 적이 공격 패턴대로 행동한다.
- 이기면 골드를 받고 다음 층으로, 상점에서 카드를 사고 상점 주인과 대화한다. 쓰러지면 판이 끝나고 기록이 프로필에 남는다.
- 도전과제(첫 승리, 한 턴 30 피해), 로그(처치 수, 한 턴 최대 피해, 번 골드), 유물(전투 첫 턴 방어도, 승리 때 회복)이 붙는다.

이 게임이 쓰는 것: 플레이어 데이터(판 `run` = 세션 구역, 프로필 `profile` = 메타 구역), 인스턴스(카드·몬스터·물약 원본), 키워드(등급·속성·카드 종류), 이벤트, 행동과 Undo, 비용(`Game.Pay`)과 플레이어용 실패(`Game.Fail`), 효과·대상 Block, `[BindTo]`, 상태 효과(화상), 도전과제·로그, 프로젝트 고유 기능(유물), 인벤토리(물약 칸), 연출 대기열(`GameView.Present`)·미리보기(`Game.Preview`), 다이얼로그, 텍스트·현지화, 오디오, 필드 규칙, 모니터·개발 명령(DB › 개발), 저장과 이어 하기. 덱빌딩에 맞지 않는 것(실시간 스냅샷 되감기 등)은 [07장](07-GenreRecipes.md)과 여러 장의 '다른 장르라면' 접힌 칸에서 다룬다.

## 장 구성

01–11장은 같은 모양이다.

1. **첫 문단** — 이 장에서 하는 일, 한두 문장
2. **이 장에서 쓰는 말** — 접힌 칸
3. **번호 붙은 절** — 할 일과 핵심 코드만 짧게
4. **체크리스트** — 마지막 절
5. **더 보기(매뉴얼)** — 접힌 칸

**본문은 흐름, 접힌 칸은 세부다.** `> [!note]- 제목` 모양의 칸은 Obsidian에서 접힌 채 보이고, 눌러 펼친다(다른 Markdown 뷰어에서는 인용문으로 보인다). 이유·표·긴 코드·'다른 장르라면'이 여기 들어 있다. 처음에는 본문만 읽고, 필요할 때 펼친다.

다른 장의 절은 "NN장 N절"로 가리킨다. 부록의 기능 사용 표는 "03 §6"(3장 6절)처럼 줄여 쓴다.

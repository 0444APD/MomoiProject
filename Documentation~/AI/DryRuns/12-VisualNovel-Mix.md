## 1. 한 줄 결론

기믹 21개는 문법 밖·예외가 0이다(메인 룰 10 · DB 4 · Block 5 · BindTo 1 · 화면 1). 예외 6·문법 밖 1은 모두 비주얼 노벨의 부가 기능과 다이얼로그 연결에서 나왔다. **가장 큰 빈틈: 다이얼로그 진행(대사 넘김·선택·되감기)이 행동 밖에서 돌아 Undo·판 저장·선택 대기와 따로 논다.** 그래서 "이전 대사로 되감기", "세이브 30칸(프로필 공유)", "대사만 넘긴 진행의 저장"을 프로젝트 코드로 이어 붙여야 한다.

## 2. 기획 명세서 — 기억서랍

`PlanningSpec.md` 양식을 기획자처럼 채운 것이다. 몇 칸은 일부러 비우거나 서로 어긋나게 두었다(AI가 물을지 보려고).

### 0. 한 줄 소개

- [필수] 장르·참고 게임: 비주얼 노벨(대화 중심). 기믹은 세피리아(가방 격자·석판·콤보), 매지크래프트(지팡이 칸 연계·Mimicry Cube), 발라트로(Oops! All 6s).
- [필수] 한 문장 소개: 잃어버린 기억을 읽는 '서랍지기'가 대화로 기억 조각을 모아 마음 격자에 정리하고, 장면 끝에 대사 카드를 이어 말해 상대의 마음을 연다.
- [필수] 멀티플레이: 없음.
- [선택] 한 판의 길이: 회차 하나 180~240분.

### 1. 한 판의 흐름

- [필수] 시간: 턴제(클릭으로 대사를 넘긴다). 실시간은 고백 직전 미니게임 '떨리는 손' 하나뿐.
- [필수] 한 판: 새 회차(시작 대사 카드 3장 + 지난 회차에서 해금한 카드) → 프롤로그 → 1장(미나) → 2장(세오) → 3장(하루) → 마지막 장(호감도가 가장 높은 인물) → 엔딩(인물마다 좋은·나쁜 엔딩, 진엔딩 하나) → 타이틀. 장마다 장면 3~4개.
- [필수] 반복 단위: 장면. 대화(선택지로 기억 조각·대사 카드를 얻고, 중요한 선택지에서 호감도 판정) → 장면 끝 '대사 칸'에 카드를 놓고 "말하기" → 연계 대사 → 상대의 반응 대화. 장면 사이에 마음 격자를 정리한다.
- [필수] 판이 끝나는 때: 엔딩에 닿으면 끝(나쁜 엔딩 포함). 게임 오버는 없다.
- [필수] 판이 끝나도 남는 것: 본 엔딩, 갤러리(CG), 읽은 대사, 엔딩마다 해금되는 시작 대사 카드, 회차 수.
- [선택] 되돌리기: 이전 대사로 되감기(휠 위로·대사 로그에서 고르기). 되감으면 그 사이에 얻은 조각·호감도도 돌아간다.
- [선택] 이어 하기: 끄고 켜면 보던 대사부터. 세이브 30칸 + 자동 저장(장면 시작마다) + 빠른 저장.

### 4. 메인 룰과 기믹

#### 4-1. 메인 룰

"마음 격자에 기억 조각과 감정 석판을 놓으면 석판이 무늬대로 옆 칸 조각의 레벨을 올린다(돌릴 수 있다). 레벨·자리로 조각이 켜지고 태그가 정해지며, 같은 태그(신뢰·의심·애정) 개수로 콤보 단계(2/4/6개 → 1/2/3단계)가 열린다. 콤보 단계가 오르면 대화에 새 선택지가 해금된다. 장면 끝에는 대사 칸을 왼쪽부터 읽는다: 강화 카드는 다음 발화에 붙고, 연계 카드는 왼쪽 대사가 끝나 상대에게 닿으면 오른쪽 카드를 발동하고, 흉내 카드는 오른쪽 카드를 따라 한다. 카드마다 용기를 내고, 모자라면 거기서 멈춘다. 중요한 선택지에서는 호감도 판정을 굴린다(기본 30% + 호감도 × 1%, 최대 90%)."

- 이상한 효과 세 개:
  1. **거울 대사**(대사 카드): 오른쪽 칸의 대사 카드를 자기 레벨까지 흉내 내 한 번 더 말한다. 오른쪽이 연계면 연계까지 따라 하고, 오른쪽도 거울이면 아무것도 하지 않는다.
  2. **첫사랑의 기억**(기억 조각): 마음 격자 가로 2칸을 차지한다(돌리면 세로). 가장자리에 닿아 있으면 태그가 애정에서 의심으로 바뀐다.
  3. **운명의 실**(아이템, 1회용): 다음 호감도 판정 확률이 2배. 대신 그 판정이 실패하면 대사 칸 맨 오른쪽 카드가 사라진다.

### 묻지 않고 정해 알릴 것(추천값)

- 멀티 없음 → 세션 하나. 턴제 → 고정 틱 0. Undo 행동 단위 200, 끊는 이벤트 없음. 판 저장 행동마다, 판 끝 이벤트 `EndingReached`, 시작할 때 이어 하기 끔(타이틀이 있음). 프로필도 행동마다 저장 켬(갤러리·엔딩).
- **대사만 넘긴 진행의 저장**: 진행 기록이 행동 밖에서 바뀌어 판 저장 설정으로는 끌 때만 저장된다(6절 13번). 화면이 대사 20줄마다·선택지를 고를 때마다 `GBibleRuntime.SaveRun`을 부른다.
- **그래프와 규칙의 몫**: 기믹을 거는 곳은 그래프의 '값 바꾸기' + 프로젝트 Reward(행동 안에서 돈다). 신호는 쓰지 않거나 화면 일에만 쓴다. 플레이어 입력을 기다려야 하는 곳(대사 칸·미니게임·보상 고르기)은 그래프를 끝내고, 규칙이 판 데이터에 "이어 갈 곳"을 적고, 화면이 일이 끝나면 그 시작 ID로 다시 연다.
- **그래프의 판정**: 값 바꾸기(Reward '호감도 판정') → 조건 분기(`run.lastCheck.success`). 조건 '확률'은 그래프에서 쓰지 않는다(늘 거짓, 6절 4번).
- **호감도는 동사로만**: 그래프에서 '플레이어 데이터에 주기'로 호감도를 직접 더하지 않고 Reward '호감도 바꾸기'를 쓴다. 직접 더하면 가로채기(질투·두 배)를 건너뛴다.
- **인물은 DB 항목 없이**: 판 데이터 `cast`의 런타임 id = 스탠딩 프로필 ID. 인물별 수치는 밸런스 값. DB ID는 종류를 넘어 하나라 스탠딩 프로필과 같은 ID의 인스턴스를 만들 수 없고, 규칙 어셈블리는 다이얼로그 모듈을 참조하지 않는다(코드 확인, 6절 17·18번).
- **기억 조각 원본 = 인스턴스**(`MemoryData`: 태그·크기·자리 규칙). 효과가 있는 조각만 패시브를 따로 두고 인스턴스의 `passive` 칸으로 잇는다(같은 ID를 쓸 수 없다).
- **콤보 단계·호감도 조건은 프로젝트 조건 Block**('콤보 단계', '호감도 검사'). DB 필드 고르기 창이 `comboTier[love]`·`cast[mina].affection` 같은 `[키]` 경로를 만들지 않는다(11장 3-1).
- 다이얼로그 재생기 `pauseGame` 끔: 비주얼 노벨은 게임 시간을 쓰지 않고, 켜 두면 대화 중 호감도 연출(`GameView.Wait`)이 멈춘다(가이드 06장 4절).
- 키 바꾸기 끔(마우스·클릭). Steam 켬(App ID 480으로 시작), 리치 프레즌스 = 장·대화 상대.
- 설정: 기본 5개(전체·브금·효과음 음량, 언어, 전체 화면) + 텍스트 속도·자동 진행 대기·읽은 대사만 건너뛰기·목소리 음량.
- 난수 흐름: `affinity`(호감도 판정) · `line`(대사 닿음) · 장면 보상 표는 표마다 자동(`table:…`).

## 4. 시스템 목록 (답을 받은 뒤 한 번 보여 줄 것 — 추천값으로 답했다고 본다)

### 4-1. 메인 룰 — GBible로 어떻게 세우나

메인 룰이 셋이다. 둘은 네 게임의 모양 그대로이고(세피리아형 계산, 매지크래프트형 해석기), 하나는 판정 동사다.

**A. 마음 격자(세피리아형, 계산형)**
- 조각 = `run.heart`의 객체(`HeartPiece { id, item, turns, head, chapters }`, `item` = 원본 인스턴스 ID). 자리 = 목록 + 줄 길이 5(처음 15칸, 빈 칸 `null`, 장이 바뀌면 행동이 `Add(null)` 5번).
- 순서 = 배치 행동(`PlacePiece`·`MovePiece`·`RotatePiece`·`StorePiece`) 끝의 계산 함수 `Heart.Recalculate(game)`:
  1. 차지 칸 표시(크기 2, 회전 → '차지됨' 조각 = `head`가 머리 id) — Q4 자리
  2. 석판 무늬 레벨 보너스(`Placement.Pattern`, 가장자리 조건은 `Placement.Is`)
  3. 조각 원본의 자리 규칙 레벨 보너스(`levelRules`: 양옆이 빈 칸 +2 …)
  4. **태그 정하기**(석판의 `setTag`, 조각의 `tagRules`: 가장자리면 의심) — 4-2 자리, 세기 전에
  5. `run.lit` 다시 쓰기(`LitMemory { id = 격자 조각 id, memory = 패시브 ID, level, tag }`, 격자 칸 순서)
  6. 태그 개수 → 단계(밸런스 `comboNeed`) → `run.comboTier`(태그 → 단계 딕셔너리). 단계가 바뀌면 이벤트 `ComboChanged`
- 조각 효과 = 패시브(가진 목록 `run › lit`, `matchField` `memory`, `perElement` 켬, `levelField` `level`). 콤보 효과 = 패시브 `trust`·`doubt`·`love`(가진 목록 `run › comboTier`, 레벨 = 단계).

**B. 대사 칸(매지크래프트형, 해석기)**
- 조각 = `run.lineSlots`의 객체(`OwnedCard { id, card, level }`). 자리 = 목록 + 줄 길이 0(고정 5칸).
- 순서 = 행동 `DeliverLines`(장면 끝 "말하기"):
  1. 해석기 `LineReader.Plan(game)`이 칸을 왼쪽부터 읽어 단계 목록을 만든다: 강화는 다음 발화에 배율을 쌓고, 연계는 다음 단계를 "왼쪽이 닿았을 때만"으로 표시하고, **거울은 오른쪽 칸 카드를 한 번 더 읽는다(레벨 한도 = 거울 레벨, 오른쪽이 거울이면 읽지 않음 = 고리 끊기 — 4-2 빌려 쓰기 자리)**, 메아리는 왼쪽 단계의 `times` +1(4-2 반복 자리).
  2. 단계마다 용기를 낸다: 저장점 `Data.Mark()` → `Game.Pay(…"hero.courage"…)` → 모자라면(`GameFailure`) `Data.RollbackTo`로 그 지불만 되돌리고 거기서 멈춘다(02장 2.7).
  3. `Rules.Speak(game, step)`: 의도 `SpeakIntent`를 가로채기에 통과 → 닿음 `Game.Chance(accuracy, "line")` → `Rules.ChangeAffection` → 이벤트 `LineSpoken`. 연계 단계는 왼쪽이 닿았을 때만 돌고 연계 보너스(밸런스 `linkBonus`)를 받는다.
  4. 결과를 `run.chain`(단계·닿음·호감도 변화)에 쓰고 `ChainResolved`, `SceneEnded`를 쏜다.
- 카드의 특수 효과 = 패시브(가진 목록 `run › lineSlots`, `matchField` `card`, `perElement`) — `LineSpoken`(가진 쪽 필드 `cardId`)·`SpeakIntent` 가로채기로.
- 자리 순서가 결과를 바꾸는 예: "떨리는 목소리 · 발화 A · 발화 B"는 A가 2배, "발화 A · 떨리는 목소리 · 발화 B"는 B가 2배.

**C. 호감도 판정(동사 + 판정 스위치)**
- `Rules.AffinityCheck(game, who, basePercent, sourceId)`: 확률 p = (기본 + 호감도 × 계수, 상한) → `Game.Chance(p, "affinity", source, user: 인물)`(기본 의도 '확률'을 거친다 → 확률 2배가 붙는다) → **판정 결과 의도 `CheckResultIntent { characterId, success, probability, sourceId }`**(굴린 뒤 결과를 고치는 자리 — 4-2 '판정 규칙이 바뀐다') → `run.lastCheck` → 이벤트 `AffinityChecked`.

### 4-5. 진행 흐름

- 새 회차 `StartRun`(시작·해금 카드, 격자 15칸, 대사 칸 5칸) → 화면이 `Dialogues.Play(prologue)`.
- 그래프 안의 값 바꾸기(프로젝트 Reward, 각각 행동 하나): '장면 시작'(장면·상대 → 용기 3, `SceneStarted`) · '기억 조각 얻기' · '대사 카드 얻기' · '호감도 바꾸기' · '호감도 판정' · '아이템 쓰기' · '대사 칸 열기'(이어 갈 시작 ID → `phase` = 대사 칸, 장면 보상 `Game.Ask`) · '엔딩'(→ `ReachEnding`).
- 화면의 행동: `PlacePiece` · `MovePiece` · `RotatePiece` · `StorePiece` · `SetLineCard` · `ClearLineSlot` · `DeliverLines` · `UseItem` · `ReportMinigame { success }`(판정 보고 행동) · `TakeCard { [Chosen] card }`(보상 고르기의 이어서 할 행동) · `EndChapter`(장 끝: `ChapterEnded` → 격자 +5칸 → 계산).
- 반복 단위의 이벤트: `SceneStarted`·`SceneEnded`(상태 효과의 셀 이벤트 "이번 장면 동안"), `ChapterEnded`(진심의 반지 1회, 진화 횟수).
- 판 끝: `ReachEnding` → `EndingReached`(Bootstrap 판 끝 이벤트) → 프로필(엔딩·갤러리·해금 카드·회차).
- 장면 하나의 흐름:

```
Dialogues.Play(장 다이얼로그, 장면 시작 ID)
  값 바꾸기(장면 시작) → 대사 … → 선택지(보일 조건: 콤보 단계) → 값 바꾸기(기억 조각 얻기) …
  값 바꾸기(호감도 판정) → 조건 분기(run.lastCheck.success) → 성공·실패 대사
  값 바꾸기(대사 칸 열기, 이어 갈 곳 = "scene2After") → 끝
화면: 다이얼로그가 끝났고 run.phase == 대사 칸 → 대사 칸 화면(고르기 창: 장면 보상) → [말하기] DeliverLines
  → 연계 연출(GameView.Present) → Dialogues.Play(run.resumeDialogue, run.resumeEntry)
  반응: 조건 분기(run.chain.hits ≥ 3) …
```

- 씬 흐름: 씬 둘(Title·Story), Bootstrap 씬 흐름 = `run.scene`(비면 Title).

## 6. 다이얼로그 연결 점검

다이얼로그와 기믹 시스템이 만나는 곳마다 되는지 본다. "코드 확인"은 문서에 없어 코드를 본 곳이다.

| # | 연결 | 되나 | 어떻게 · 빈틈 |
|---|---|---|---|
| 1 | 조건 분기가 판 데이터(호감도·콤보·판정 결과)를 읽기 | 됨 | 조건 '플레이어 데이터 검사'. 클래스 필드(`run.lastCheck.success`)는 DB 창에서 고른다. 딕셔너리·id 목록의 `[키]`(`comboTier[love]`·`cast[mina].affection`)는 DB 창이 만들지 않아(11장 3-1) 조건 Block '콤보 단계'·'호감도 검사'로 |
| 2 | 콤보 단계로 선택지 해금 | 됨(조건 있음) | 선택지의 보일 조건 + 흐리게 보여 주기. 단 **선택지가 뜨는 순간 한 번만** 평가한다(코드 확인: `BuildChoices`는 글이 다 나온 때만 부름). 떠 있는 동안 격자를 고쳐도 바뀌지 않음 → Q7 |
| 3 | 사용자·이벤트 기준 조건 | 맞지 않음 | 그래프의 조건은 트리거 순간 없이 `condition.Evaluate(Session)`으로 돈다(코드 확인). '상태 효과 검사(사용자)'는 대상이 없어 0으로 본다(≤ 0이면 늘 참), '자리 검사(사용자)'는 늘 거짓. → 조건 Block '주인공 상태 효과'처럼 대상을 직접 찾는 Block |
| 4 | 그래프 안의 확률 판정 | 조건 '확률'은 안 됨 | 행동 밖·순간 없음이라 늘 거짓(코드 확인: `ChanceCondition`). → 값 바꾸기(Reward가 행동 안에서 `Game.Chance`) + 조건 분기. 확률 2배(가로채기 '확률')가 그대로 붙고, 이어 하기 때 분기는 기록된 결과로 다시 밟는다(다시 굴리지 않음) |
| 5 | 값 바꾸기에 넣을 수 있는 결과 | 일부 | `rewards`는 `List<Reward>`라 '플레이어 데이터에 주기'·'다이얼로그 재생'·프로젝트 Reward만 고른다(코드 확인). '가중치 표에서 주기/고르기'·'비용 내기'·'대상에게 효과'·'이벤트 쏘기'·'선택 요구'·'로그에 기록'은 없다 → 필요하면 프로젝트 Reward로 감싼다 |
| 6 | 그래프에서 조각 얻기 | Block 필요 | 조각 목록은 객체 목록(고유 id)인데 '플레이어 데이터에 주기'의 인스턴스 사본은 id를 새로 주지 않는다(코드 확인: `CopyInstance`) → Reward '기억 조각 얻기' |
| 7 | 신호 → 게임 코드 | 됨(한계) | 화면이 `Dialogues.Signaled`를 받아 `Game.Do`. 신호는 이름뿐(값 없음)이고, 행동이 실패해도 대화는 이어지고, 대화는 응답을 기다리지 않고 다음 노드로 간다(코드 확인). 기믹 거는 데는 쓰지 않는다 |
| 8 | 게임 입력 기다리기(대사 칸·미니게임·보상 고르기) | 노드 없음 | 기다리는 흐름 노드가 없고, 그래프 안에서 `Game.Ask`(장면 보상)를 해도 다이얼로그는 `Game.IsWaiting`을 보지 않아 계속 진행한다(코드 확인). → 그래프를 끝내고 규칙이 `run.resumeDialogue/Entry`에 이어 갈 곳을 적고, 화면이 일이 끝나면 다시 `Play`. 진행 기록·지나온 줄이 거기서 끊긴다(7절 E6) |

## 7. 예외·문법 밖 목록

기믹 21개에는 없다. 아래는 부가 기능·대화 연결에서 나온 것이다. 각 줄 끝이 해결 가능 여부·방식이다.

**E1. 세이브 30칸(프로필 공유) — 예외**
- 왜: 슬롯은 프로필 + 판 묶음이다(31장 2-1). 30칸을 슬롯으로 하면 갤러리·엔딩·읽은 대사가 칸마다 갈린다. 기본 슬롯 화면도 슬롯용이다.
- 우회: 기본 슬롯 하나 + 프로젝트 `SaveBook`. 저장 = `SaveRun` 뒤 `RunSavePath` 파일을 `saves/NN.json`으로 복사 + 요약(장·상대·시각)·썸네일 파일. 불러오기 = 그 파일을 `RunSavePath`로 복사 → `LoadRun` → `Dialogues.ResumeSaved()`. 자동·빠른 저장 칸도 같은 방식. 플레이 시간은 슬롯 하나라 칸마다 저장 시점의 값을 요약에 적는다.
- 라이브러리에 있으면 없어지는 것: 프로필을 함께 쓰는 "판 저장 칸"(요약·지우기·복사·기본 화면). 요약 보류 목록의 "슬롯을 넘는 저장"과 같은 것.
- 해결: 가능(프로젝트 코드), 라이브러리에 넣으면 기본 화면까지.

**E2. 이전 대사로 되감기 — 예외**
- 왜: 다이얼로그의 되감기(`Resume(snapshot)`)는 화면만이고 진행 기록을 어긋나게 한다. 판 데이터의 되감기(`UndoTo`)는 다이얼로그 위치를 모른다(6절 14번).
- 우회: 프로젝트 `DialogueRewind`: `Runner.LineEntered`마다 (`HistoryMark`, `Runner.Progress` 사본)을 쌓는다. n줄 되감기 = `UndoTo(그 지점)` + `Runner.Restore(그 진행 기록)`(값 바꾸기·신호를 다시 하지 않고 같은 길을 밟는다, 분기는 기록대로). 다이얼로그를 새로 열면 목록을 비운다(Q10). 되감은 판정은 난수도 돌아가 같은 결과(명세서 5절과 맞음).
- 라이브러리에 있으면 없어지는 것: 다이얼로그 되감기 API(줄마다 지점을 함께 기록하고 `Rewind(n)`이 판 데이터·진행 기록·화면을 함께 돌림).
- 해결: 가능.

**E3. 연계 대사를 다이얼로그로 차례 재생 — 예외(Q2 추천이면 생기지 않음)**
- 왜: 다이얼로그에 대기열이 없고, 여러 다이얼로그 사이의 위치를 저장하지 않는다.
- 우회: `run.chainCursor` + 화면 대기열 + 한 장이 끝날 때마다 커서를 넘기는 행동, 불러오면 커서부터.
- 라이브러리: "규칙이 정한 다이얼로그 목록 재생"(진행 기록에 목록·위치).
- 해결: 가능. 추천은 연출로 피하기.

**E4. 그래프 안 확률 분기 — 예외**
- 왜: 조건 '확률'은 행동 안·순간이 있을 때만 굴린다. 그래프 조건은 둘 다 없어 늘 거짓.
- 우회: 값 바꾸기(Reward '호감도 판정') + 조건 분기(이미 이 게임의 표준 모양).
- 라이브러리: 그래프 '확률 분기' 노드(행동 하나로 굴리고 결과를 진행 기록에).
- 해결: 가능.

**E5. 떠 있는 선택지 다시 보기 — 예외**
- 왜: 보일 조건은 뜰 때 한 번만 본다.
- 우회: 대화 중 격자 편집을 막는다(Q7).
- 라이브러리: `DialogueRunner.RefreshChoices()` 또는 플레이어 데이터가 바뀌면 떠 있는 선택지 조건을 다시 봄.
- 해결: 가능(설계로 피함).

**E6. 대화 안에서 게임 입력·선택 대기 기다리기 — 예외**
- 왜: 신호는 기다리지 않고, 다이얼로그는 `Game.IsWaiting`을 보지 않는다.
- 우회: 그래프를 끝내고 규칙이 이어 갈 곳을 적은 뒤 다시 `Play`. 되감기는 그 앞으로 가지 않는다(Q10과 맞음).
- 라이브러리: '게임 기다리기' 흐름 노드(신호를 보내고 선택 대기·지정 플래그가 풀릴 때까지 멈춤, 진행 기록에 남김).
- 해결: 가능.

**X1. 불러온 세이브의 앞으로 되감기 — 문법 밖**
- 판 저장에 Undo 이력이 없다(저장을 넘는 되감기). Q9로 물었다. 추천: 불러온 지점까지만.
- 해결: (가) 범위 제한 — 가능, 추천 / (나) 대사만 되감기 근사 — 값 어긋남 / (다) 대사마다 판 사본을 세이브에 묶는 별도 시스템 — 가능하나 GBible 판 저장 밖.

**GBible에 없음 — 읽은 대사 기록·"읽은 대사만 건너뛰기"**
- 우회: Q11(프로필 목록 + 저장 직전 행동 하나 + 화면이 줄 키를 보고 빨리 넘김).
- 해결: 가능. 라이브러리의 다이얼로그 모듈에 읽음 기록이 있으면 없어진다.

**기능 빈틈 — 대사만 넘긴 진행의 저장**
- 우회: 화면이 N줄마다 `SaveRun`(6절 13번).
- 해결: 가능. 라이브러리가 진행 기록이 바뀔 때 판 저장 표시를 하면 없어진다.

## 보강 뒤(2026-10-05)

- 기믹 쪽은 예외·문법 밖 0 그대로. '자리로 고르기'에 기준 '없음'(목록 전체의 맨 처음·맨 끝)이 생겼다. "모자라면 그 카드부터 멈춤"은 `Game.TryPay`(저장점이 필요 없다).
- 다이얼로그 쪽 예외 6·문법 밖 1은 **보류**(다이얼로그 모듈 후보): 대사 진행이 행동 밖 · 세이브 수십 칸(슬롯을 넘는 저장) · 이전 대사로 되감기 · 대화 대기열 · 신호 노드·`Game.Ask`가 대화를 멈추지 않음 · 선택지 조건 한 번 평가 · 읽은 대사 기록. 지금 동작은 매뉴얼 24장 주의 절에 적었고, 명세서 6절 대화 줄과 읽는 법의 부가 기능 표가 이것을 질문 거리로 둔다.
- 다이얼로그 코드 버그 셋은 고쳤다: 받은 '값 바꾸기' 행동이 DB의 노드에서 값을 다시 찾음(예전에는 아무것도 안 바뀜) · 값 바꾸기의 '다이얼로그 재생'·신호가 연 새 다이얼로그가 곧바로 끝나던 것 · 스냅샷으로 이어 간 대화가 이전 재생의 진행 기록을 이어 쓰던 것.

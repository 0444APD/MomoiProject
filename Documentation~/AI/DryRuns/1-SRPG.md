# 장르 시험 1 — 턴제 전술 SRPG(잿불 전선)

GBible 문서·규칙과 기획 명세서만 받은 AI가 새 프로젝트의 시스템층과 화면(레벨 디자인 제외)을 하루 안에, 질문 20개 이하로 만들 수 있는지 SRPG 하나로 시험한 기록이다.

- 1절은 기획자가 쓴 것처럼 채운 명세서다(가상의 게임). [선택] 칸 몇 개는 일부러 비웠다: 1절 이어 하기, 4절 고리, 6절 가방, 9절 저장 시점.
- 2~4절은 AI가 그 명세서를 `PlanningSpecGuide.md` 1·4·5·7절대로 읽고 내놓는 것: 질문 목록 → 시스템 목록 → 효과 쪼개기.
- 5절은 빈틈, 6절은 하루 안에 되는지의 판단이다.
- 판정 글자: **A** = DB만 · **B** = 코드 한 단위(재사용 Block·`[BindTo]`) · **C** = 중간층 확장(동사·행동 직전 이벤트 필드·새 이벤트) · **D** = 문법 밖.
- 코드로 확인하지 못한 것은 "가정"이라 적었다. 문서와 코드가 다르면 코드를 따랐고, 그 차이는 5-2에 적었다.

확인한 코드: `Runtime/Core/GameSession.cs`(Undo·스냅샷·판 저장), `PlayerDataStore.cs`(Permanent·UndoLast), `Actions.cs`(Preview), `GameApi.cs`(Find·Use·Intercept), `Attributes.cs`, `Statuses.cs`, `EventBus.cs`, `Triggers.cs`(구독 순서·예외), `Random.cs`, `Runtime/Unity/GameDatabase.cs`·`RunSaver.cs`·`UndoBoundary.cs`·`StatusData.cs`·`AbilityData.cs`·`GameData.cs`, `Optional/Inventory/Runtime/Inventory.cs`.

## 1. 기획 명세서 — 잿불 전선

> `PlanningSpec.md` 양식. 기획자가 쓴 글이라 GBible 용어를 쓰지 않는다.

### 0. 한 줄 소개

- [필수] 장르·참고 게임: 턴제 전술 SRPG. 파이어 엠블렘(격자·직업·영구 사망·캠페인) + Into the Breach(밀치기·충돌).
- [필수] 한 문장 소개: 국경 수비대장 레아가 용병을 모아 불타는 변경을 되찾는다.
- [필수] 멀티플레이: 없음
- [선택] 한 판의 길이: 전투 하나 20~40분, 캠페인 전체 15장(약 15시간)

### 1. 한 판의 흐름

- [필수] 시간: 턴제
- [필수] 한 판: 새 캠페인(난이도 고르기) → [장 시작 대화 → 출격 준비(나갈 동료 고르기 · 출격 칸에 배치 · 장비 바꾸기) → 전투 → 결과(경험치 · 떨어진 아이템 · 골드 · 보상 상자) → 막사(영입 · 장비 사기/팔기 · 전직 · 대화) → 다음 장] × 15 → 마지막 장 승리 → 엔딩.
- [필수] 반복 단위: 라운드. 아군 페이즈(아군마다 이동 1번 + 행동 1번: 공격 · 기술 · 아이템 · 경계 · 대기. 순서 자유. 모두 행동하거나 '턴 끝'을 누르면 끝) → 적 페이즈(적이 하나씩 움직인다) → 라운드 끝(불이 번지고 꺼진다).
- [필수] 판이 끝나는 때: 장마다 승리 조건이 다르다(적 전멸 / 두목 격파 / N라운드 버티기 / 레아가 목표 칸에 도착). 패배: 레아가 쓰러지거나 아군 전멸 → 그 장의 출격 준비부터 다시.
- [필수] 판이 끝나도 남는 것: 장 사이에는 동료(레벨·스탯·직업·장비)·창고·골드, 영구 사망한 동료는 떠난 채로. 캠페인을 끝내면 클리어 기록이 남고 '하드' 난이도가 열린다. 하드는 **모든 세이브 슬롯에서** 열려야 한다.
- [선택] 되돌리기: 없음(대신 5절의 되감기). 단, 이동한 뒤 행동을 고르기 전에는 이동을 물릴 수 있다.
- [선택] 이어 하기: (비움)

### 2. 다루는 것들

#### 2-1. 주인공·유닛

- [필수] 아군(동료)·적·적 두목. 숫자: 체력·최대 체력·힘·마력·기술·속도·행운·수비·마방·이동력·시야(칸)·레벨·경험치. 동료와 직업마다 성장률(스탯마다 %)이 있다.
- 이동 종류: 보병·기마·비행·중장. 비행은 지형 비용과 지대 통제를 무시하고 구덩이에 떨어지지 않는다. 중장은 밀리지 않는다.
- [선택] 피해 공식: 물리 = 힘 + 무기 위력 − 상대 수비, 마법 = 마력 + 위력 − 상대 마방(0 아래면 0). 명중 = 기술×2 + 무기 명중 − (상대 속도×2 + 지형 회피). 치명 = 기술÷2 + 무기 치명 − 상대 행운, 치명은 피해 ×3. 속도가 4 이상 빠르면 한 번 더 친다(추격).
- 적의 행동: 돌격(가장 쉽게 쓰러뜨릴 수 있는 대상에게), 대기(누가 사거리에 들어오면 돌격으로 바뀜), 고정(움직이지 않고 사거리 안만 공격). 두목은 고정. 대상 고르기: 쓰러뜨릴 수 있는 대상 > 예상 피해가 큰 대상 > 가까운 대상.

### 4. 효과의 폭

- [필수] 언제: [x] 즉시 · [x] 발동(맞으면·공격받으면·죽으면·칸에 들어오면·유닛 턴 시작/끝·라운드 끝) · [x] 지연(N라운드 뒤 증원) · [x] 지속(독 3턴, 경계 다음 내 차례까지, 불 3라운드)
- [필수] 누구에게: [x] 자신 · [x] 고른 대상(유닛 또는 칸) · [x] 무작위(불 번짐) · [x] 전체 · [x] 조건으로 거른 대상(범위 안·옆 칸·보이는 적)
- [필수] 무엇을: [x] 숫자 바꾸기 · [x] 스탯 보정 · [x] 만들기·없애기·바꾸기(칸 불태우기·증원·전직) · [x] 다른 효과 고치기 · [ ] 효과 도중 고르기 · [x] 비용 바꾸기(쿨다운)
- [필수] 가장 이상한 효과(셋보다 많지만 다 넣을 것):
  1. 밀치기: 맞은 유닛이 뒤로 1칸 밀리고, 벽이나 다른 유닛에 부딪히면 추가 피해 3. 구덩이로 밀리면 떨어져 죽는다.
  2. 반격: 근접 공격을 받으면 살아 있을 때 공격자에게 반격한다. 반격은 반격을 부르지 않는다.
  3. 협동 공격: 대상 옆에 다른 아군이 있으면 그 아군도 피해 50%로 함께 공격한다.
  4. 지형 효과: 숲 칸에 있으면 회피 +20%. 불타는 칸은 그 칸 유닛의 턴 시작마다 피해 2. 숲이 불타면 라운드 끝에 옆 숲으로 50% 확률로 번지고, 불은 3라운드 뒤 꺼진다.
  5. 경계 사격: '경계'로 대기한 궁수는 적이 사거리 안 칸에 들어오는 순간 한 번 쏜다. 그 적이 쓰러지면 이동도 거기서 끝.
- [선택] 효과끼리 서로 부르는 고리: (비움)

### 5. 문법에 안 맞는 기믹

- 시야(안개): 아군 시야 밖의 적은 보이지 않고 대상으로 고를 수 없다.
- 되감기 3회: 한 전투에 3번까지, 아무 때나 내 턴의 시작으로 되돌린다.

### 6. 진행·화면

- [필수] 씬: 타이틀 → 막사 → 전투 → 막사 → … → 엔딩. 전투에 지면 같은 장의 출격 준비로.
- [선택] 화면: 타이틀(이어 하기·새 캠페인·슬롯·설정·종료), 막사(동료·장비·상점·영입·전직·출격), 출격 준비, 전투 HUD(라운드·되감기 남은 수·턴 끝), 유닛 정보, 행동 메뉴, 전투 예측(양쪽 피해·명중·치명·반격·협동), 레벨업, 전투 결과, 게임 오버.
- [선택] 연출이 끝날 때까지 입력을 막는 곳: 이동, 공격(명중·빗나감·피해 숫자·치명), 밀리기와 충돌, 레벨업, 적 페이즈 전체(설정에서 빨리 감기).
- [선택] 효과 도중 고르기 창: 승리 보상 상자 셋 중 하나.

- [선택] 칸이 있는 가방: (비움)

### 7. 성장·밸런스

- 경험치: 공격 10 + 처치 30 + (적 레벨 − 내 레벨)×3, 회복 지팡이 10. 100마다 레벨업, 최대 20.
- 적 레벨: 1장 2레벨, 장마다 +1. 하드는 +3.
- 무게로 뽑는 표: 승리 보상 상자(골드 60%·무기 30%·희귀 무기 10%), 셋을 보여 주고 하나 고름, 이미 가진 희귀 무기는 나오지 않음.
- 자주 바꿀 숫자: 되감기 횟수 3, 충돌 피해 3, 숲 회피 20, 불 피해 2, 불 번짐 50%, 협동 비율 50%, 추격 속도 차 4, 무기 상성(검 > 도끼 > 창 > 검) 명중 15·피해 1, 시작 골드.

### 8. 기록·도전과제

- 도전과제(Steam에도): 첫 승리, 되감기 없이 한 장 클리어, 영구 사망 없이 캠페인 클리어, 밀치기로 구덩이에 3명 떨어뜨리기.
- 기록: 처치 수, 충돌 수, 쓴 되감기 수.

### 9. 저장·기기

- 저장 시점: (비움)

- 키 바꾸기: 필요 없음(마우스). 패드는 나중.
- Steam: 클라우드 저장 예. 리치 프레즌스 "n장 · 라운드 m".

**데이터 구조·한 판의 흐름**

1. **'판'이 무엇인가(저장 단위)**
   - 정하는 것: 세션 구역(`run`)에 무엇을 두나. (가) 판 = 전투 하나, 캠페인은 프로필(`profile`, 메타 구역, 슬롯마다). (나) 판 = 캠페인 전체, 전투는 그 안의 값.
   - 추천: (가).
   - 이유: 지면 "이 장 출격 준비부터 다시"가 `GBibleRuntime.NewRun`(세션 구역만 처음으로) + `StartBattle`로 끝난다. 되감기(Undo)는 전투 안의 변경만 건드린다. 전투에만 걸린 상태 효과·Modifier가 새 판에 저절로 비워진다(29장 2-4). (나)는 패배 뒤 장 시작으로 돌아갈 지점이 없다(5-1 G3). 대신 (가)는 동료를 전투로 **복사**해야 하고, 복사본 id를 동료 id와 다르게 두어야 한다(`Game.Use`·상태 효과·Modifier가 형식 없이 id로 찾는다, 5-2 E5).
   - 답이 없으면: 추천값으로 진행.

2. **'하드는 모든 슬롯에서' — 슬롯을 넘는 값**
   - 정하는 것: 하드 해금을 어디에 두나. GBible의 프로필·도전과제 달성은 슬롯마다 따로이고, 슬롯을 넘는 저장 구역이 없다(5-1 G5).
   - 추천: 기기 설정 파일의 원시 값(`GameSettings.SetRaw("hardUnlocked", "1")`, 화면 쪽이 `CampaignCleared`를 받아 적는다). 대안: 하드를 슬롯마다로 바꾼다(기획 변경).
   - 이유: 지금 GBible로 슬롯을 넘는 유일한 곳이다. 다만 기기마다이고 플레이어 데이터가 아니다(Steam Cloud에 실리는지는 확인하지 않음 — 가정).
   - 답이 없으면: 추천값으로 진행하고, 전역 구역이 생기면 옮긴다.

3. **끄고 켜면 어디서 이어 하나(1절 '이어 하기'·9절 '저장 시점'이 비었음)**
   - 정하는 것: 판 저장 시점. Undo 이력은 판 저장에 들어가지 않아(`GameSession.ExportRun`, 불러오면 `ClearUndo`) 턴 중간에 끄고 켜면 그 턴의 되감기가 턴 시작으로 가지 못한다.
   - 추천: 전투 중에는 **아군 턴 시작(과 되감기 직후)에만** 판을 저장한다. 막사(프로필)는 행동마다 저장.
   - 이유: 이어 하는 지점 = 되감기 지점이라 어긋남이 없다. 잃는 것은 끈 턴의 진행뿐이다. 대안 '행동마다 저장'은 불러온 턴에는 되감기를 못 쓰게 막아야 한다.
   - 답이 없으면: 추천값으로 진행.

**핵심 동사**

4. **공격 한 번의 처리 순서(3절 '순서는 잘 모르겠음')**
   - 정하는 것: 규칙 함수 `Rules.Attack`의 단계 순서. 예측 창도 같은 순서로 계산한다.
   - 추천: ① 본 공격(명중·치명·피해) → ② 협동 공격(밀리기 전 자리에서, 대상과 붙은 다른 아군 각자) → ③ 밀치기(본 공격이 명중했고 대상이 살아 있을 때) → ④ 반격(대상이 살아 있고, 밀린 뒤에도 공격자가 대상 무기의 사거리 안일 때) → ⑤ 추격(속도가 4 이상 빠른 쪽이 한 번 더. 추격에는 협동·밀치기 없음).
   - 이유: 밀치기를 앞에 두면 협동·반격 자격이 공격마다 흔들려 예측 창을 믿기 어렵다. 이 순서면 "밀어서 반격을 피한다"는 전술이 하나 생긴다.
   - 답이 없으면: 추천값으로 진행.

5. **연쇄와 협동 자격**
   - 정하는 것: 반격·협동·추격이 서로를 부르나, 누가 협동하나.
   - 추천: 반격·협동·추격·경계 사격은 반격·협동·밀치기를 부르지 않는다(공격 한 번에 한 단계). 협동은 대상과 붙어 있는 아군(근접 자리)만, 이미 행동한 유닛도 참여, 무기 사용 횟수는 쓰지 않음, 명중 판정 있음·치명 없음.
   - 이유: 4절 '고리'가 비었고, 반격이 협동을 부르면 공격 한 번에 연쇄가 끝없이 커진다.
   - 답이 없으면: 추천값으로 진행.

6. **밀치기는 모든 공격인가**
   - 정하는 것: 4절 1번 "맞은 유닛이 뒤로 1칸"이 모든 공격인지, 밀치기가 붙은 무기·기술만인지(2-2 무기의 '밀치기 여부' 칸과 엇갈린다).
   - 추천: 밀치기가 붙은 무기·기술만(DB의 효과 Block).
   - 이유: 모든 공격이 밀면 근접 반격이 거의 사라지고 협동 자리가 매번 깨진다.
   - 답이 없으면: 추천값으로 진행.

**문법 밖(5절)**

7. **적도 시야를 따르나**
   - 추천: 적은 모두 본다(시야는 플레이어 쪽 규칙).
   - 이유: 적 AI가 안개를 다루려면 기억·수색 행동이 더 필요하다.
   - 답이 없으면: 추천값으로 진행.

8. **안 보이는 적과 범위·무작위 효과**
   - 정하는 것: 칸을 고르는 범위 기술(화염구), 무작위 대상, 충돌이 안 보이는 적에게 닿나.
   - 추천: 칸 단위 범위 효과·충돌은 닿는다(닿은 순간 드러난다). 유닛을 고르는 공격·기술·무작위 대상은 보이는 적만.
   - 이유: "대상으로 고를 수 없다"는 고르기의 규칙이고, 칸을 치는 효과까지 막으면 안개 속을 불태우는 전술이 사라진다.
   - 답이 없으면: 추천값으로 진행.

9. **숨은 적이 길을 막거나 지대 통제를 걸면**
   - 정하는 것: 이동 동사의 규칙. 이동 범위는 보이는 것만으로 계산되므로, 경로 위에 숨은 적이 있으면?
   - 추천: 경로를 따라가다 숨은 적 바로 앞(또는 숨은 적의 지대 통제 칸)에서 멈추고, 그 유닛은 행동을 할 수 없이 차례가 끝난다(매복). 실패가 아니라 멈춤이다.
   - 이유: 길찾기·이동 행동 직전 이벤트의 모양이 이것으로 정해진다(경로를 칸마다 따라가야 한다 — 경계 사격과 같은 바탕).
   - 답이 없으면: 추천값으로 진행.

10. **되감기가 갈 수 있는 곳**
    - 정하는 것: "내 턴의 시작"이 지금 아군 턴의 시작뿐인지, 적 페이즈에 맞은 것까지 되돌리는 바로 전 아군 턴의 시작도 되는지. "아무 때나"에 적 페이즈 연출 중도 드는지.
    - 추천: 지금 아군 턴 시작 / 바로 전 아군 턴 시작 둘 중 고른다. 적 페이즈 연출 중에 누르면 연출을 건너뛰고 고르기를 띄운다.
    - 이유: 지금 턴 시작만이면 적에게 맞은 결과는 되돌릴 수 없어 되감기가 '내 실수 물리기'가 될 뿐이다. 둘까지면 Undo 이력을 전투 동안 쌓아 두는 것으로 된다(전투가 끝나면 새 판이 비운다). 끄고 켠 뒤에는 '바로 전 턴'은 없다(3번 답).
    - 답이 없으면: 추천값으로 진행.

11. **되감은 뒤 같은 공격은 같은 결과인가**
    - 정하는 것: 명중·치명·성장률이 되감기 전과 같은가.
    - 추천: 같다. GBible의 Undo는 난수도 되돌린다(02장 2.8).
    - 이유: 되감기가 운을 다시 굴리는 버튼이 되지 않고 "다른 선택을 해 보는" 기능이 된다. 다른 결과를 원하면 문법 밖이다(난수를 Undo 밖에서 바꿀 규칙이 없다).
    - 답이 없으면: 추천값으로 진행.

**나머지**

12. **맵을 무엇으로 그리나**
    - 정하는 것: 전투 맵의 칸을 기획자가 만드는 도구. GBible에는 격자 맵 편집이 없다(5-1 G1).
    - 추천: DB 종류 '전투 맵'의 글자 줄(한 줄 = 한 행, 글자 = 지형, 예 `..FF#..`) + 범례(글자 → 지형) + 적 배치·출격 칸 목록. Tilemap에 칠해 DB로 굽는 도구는 나중.
    - 이유: 글자 줄이면 CSV·시트로도 고칠 수 있고 시스템층이 바로 읽는다.
    - 답이 없으면: 추천값으로 진행.

> 명세서에 답을 적어 두기를 권한다(다음 세션이 다시 묻지 않게).

### 묻지 않고 정해 알릴 것(추천값)

- **Undo 방식은 행동 단위**(보관 수 0 = 전투 동안 무제한, Undo 끊는 이벤트 비움). 1절 되돌리기는 '없음'이지만 되감기가 Undo를 쓴다. 플레이어에게 Undo 버튼은 두지 않는다.
- **이동 물리기**: 이동과 행동을 행동 하나(`Act { unit, path, command, target }`)로 보낸다. 화면이 경로를 미리 보여 주다가 행동을 고르면 보낸다. Undo를 열지 않으니 되감기 횟수가 의미를 잃지 않는다.
- **가방(6절 비움)**: 유닛마다 5칸 + 창고. 무기마다 사용 횟수가 있어 개체(`OwnedItem { id, item, uses }`)로 둔다. 선택 기능 인벤토리는 개수만 다뤄 쓰지 않는다.
- **고리(4절 비움)**: 사슬 한도 16 + 5번 답의 "한 단계" 규칙.
- **불타는 칸의 '턴 시작'**: 그 칸 위 유닛의 진영 페이즈 시작(유닛마다 `UnitTurnStarted`).
- **협동 피해**: 협동하는 아군의 보통 공격 예상 피해 × 0.5, 내림. 협동 경험치 5.
- **반격 조건**: 대상이 든 무기의 사거리에 거리 1이 들 때. 반격도 명중·치명 판정.
- **충돌**: 밀린 쪽만 3. 벽·맵 밖·유닛·들어갈 수 없는 지형이 막힘. 구덩이는 떨어져 죽음, 물은 막힘(둘 다 비행 제외).
- **시야 선**: 벽만 시야를 가린다. 시야는 스탯 `vision`(기본 3).
- **지대 통제**: 비행과 '잠입' 특성은 무시. 시작 칸이 적 옆이어도 한 칸은 나갈 수 있다.
- **경계**: 한 번 쏘면 풀리고, 쏘지 않았으면 그 유닛의 다음 턴 시작에 풀린다.
- **예측 창**: 난수를 쓰지 않는 예측 행동을 `Game.Preview`로 돌린다(5-2 E1 — 실제 공격을 미리보기하면 명중 결과가 새어 나간다).
- **난수 흐름**: `hit`·`crit`·`growth`·`ai`·`fire`·`loot`.
- **씬**: Camp·Battle 둘. 타이틀은 Camp 씬 위의 화면(씬 흐름이 키 하나만 따른다).
- **설정**: 기본 5개 + 6절의 셋. Steam 켬(App ID 480으로 시작, 사람이 바꾼다).

## 3. 시스템 목록

> 2절에 추천값으로 답했다고 보고 만든 목록이다(`PlanningSpecGuide.md` 5절).

### 3-1. 데이터

- **`profile`**(메타 구역, 슬롯마다) = `Campaign`: `chapter` · `gold` · `difficulty` · `List<Member> roster` · `List<OwnedItem> convoy` · `List<string> fallen` · `List<string> clearedChapters`.
  - `Member { id(= 동료 ID, "lea"), [DataRef] character, [DataRef] unitClass, level, exp, hp, str, mag, skl, spd, lck, def, res, mov, vision, List<OwnedItem> items, equipped }` — 숫자 필드가 스탯.
  - `OwnedItem { id(Game.NewId("item")), [DataRef] item, uses }`.
- **`run`**(세션 구역 = 전투 하나) = `BattleState`: `mapId` · `phase`(Deploy·Ally·Enemy·Ended) · `round` · `phaseActions` · `List<BattleUnit> units` · `List<Tile> tiles` · `rewindsLeft` · `rewindsUsed` · `List<string> firedEvents` · `scene` · `won`.
  - `BattleUnit { id("b." + memberId / Game.NewId("e")), memberId, team, [DataRef] unitClass, [Keyword(typeof(MoveType))] moveType, x, y, hp, maxHp, str … vision, level, exp, items, equipped, moved, acted, [Keyword(typeof(AiKind))] ai, Dictionary<string,int> cooldowns, isLeader, isBoss }` — 동료의 사본. id를 동료와 다르게 둔다.
  - `Tile { id("t.x.y"), x, y, [DataRef(typeof(Terrain))] terrain }` — 상태 효과(불)를 걸 수 있게 id가 있다.
- **슬롯 밖**: `hardUnlocked` = 기기 설정 원시 값(2번 답).

### 3-2. 원본 종류

- DB › 인스턴스: `UnitClass`(이동 종류·이동력·기본 스탯·성장률·무기 종류 목록·`[DataRef(typeof(StatusData))] passive`·전직처) · `Character`(시작 직업·레벨·개인 성장률·passive) · `Weapon`(종류·위력·명중·치명·사거리·사용 횟수·마법 여부·`push`·passive·가격) · `Consumable`(사용 횟수·`[SerializeReference] Usable usable`·가격) · `Skill`(사거리·범위 모양·크기·대상 종류·쿨다운·`Usable usable`) · `Terrain`(evasion·defense·이동 종류마다 비용·blocksSight·passable·deadly) · `EnemyTemplate`(직업·레벨·장비·ai·떨굼).
- 프로젝트 DB 종류: **전투 맵**(`[Database("전투 맵", Group = "콘텐츠")] BattleMapData : GameData` — 크기·글자 줄·범례·출격 칸·적 배치·`[TriggerSlot] Trigger victory/defeat`·`List<TriggerRule> events`).
- DB › 상태 효과: `poison` · `burning` · `fireSpread` · `overwatch` · 직업·무기 패시브 효과(영구).
- 키워드: `WeaponType` · `MoveType` · `Team` · `AiKind` · `AreaShape` · `TargetKind` · `Rarity`.

### 3-3. 핵심 동사

| 동사 | 규칙 함수 | 행동 직전 이벤트(`[Intent]`, 필드) | 끝난 뒤 이벤트(`[GameEvent]`) |
|---|---|---|---|
| 이동 | `Rules.Move(game, unit, path, MoveKind)` — 칸마다 따라간다 | `MoveIntent`(unitId·path·toX·toY·kind·cancelled) | `UnitStepped`(칸마다: unitId·tileId·x·y·visible) · `UnitMoved` |
| 밀치기 | `Rules.Push(game, source, target, distance)` | `MoveIntent`(kind Push) | `UnitPushed` · `UnitCollided`(unitId·otherId·wall) |
| 공격 | `Rules.Attack(game, attacker, target, AttackKind)` · 예측 `Rules.Forecast`(순수, 난수 없음) | `AttackIntent`(attackerId·targetId·kind·hit·crit·scale·push·cancelled) · `CounterIntent`(defenderId·attackerId·cancelled) | `AttackResolved`(kind·hit·crit·damage·visible) |
| 피해 | `Rules.Damage(game, source, target, amount, DamageKind)` | `DamageIntent`(sourceId·targetId·amount·kind·attackKind·targetMoveType·forecast·cancelled) | `DamageDealt` |
| 회복 | `Rules.Heal` | `HealIntent` | `Healed` |
| 죽음 | `Rules.Kill` | `DeathIntent`(unitId·killerId·surviveHp·cancelled) | `UnitKilled`(unitId·killerId·team·isLeader·isBoss) |
| 기술·아이템 | `Rules.UseSkill` → `Game.Use(기술 ID, 사용자, 대상)` | `CastIntent`(unitId·skill·times·cooldown·cancelled) | `AbilityUsed`(기본 제공) |

### 3-4. 진행 흐름(행동)

- 막사(프로필을 바꾼다): `StartCampaign { difficulty }` · `Recruit` · `Equip`/`Unequip` · `BuyItem`/`SellItem` · `ChangeClass` · `StoreItem`.

## 4. 기믹·효과 쪼개기

`PlanningSpecGuide.md` 7절처럼 언제 · 누구에게 · 무엇을 · 안전장치로 쪼개고 GBible 부품에 붙였다. 판정은 "이 효과를 이 프로젝트에 처음 넣을 때 필요한 가장 깊은 층"이다.

### 4-1. 먼저 따질 것 — 격자

모든 동사가 칸 위에서 돈다. GBible에는 칸·좌표·길찾기·사거리·범위 모양·시야 선 긋기·방향이 없다(03장 2.15에 거리와 `At` 예가 있을 뿐). 그래서 아래 표의 "길찾기" "범위 칸" "옆 칸" "시야"는 모두 프로젝트가 `Rules` 안에 만드는 것이다(5-1 G1). 칸은 `Tile { id }` 객체 목록으로 판 데이터에 두고, 지형 같은 고정 값은 원본 ID로만 든다.

## 5. 빈틈 목록

### 5-1. GBible에 없는 것

**G1. 격자(칸·길찾기·범위·시야)**
- 무엇: 칸 데이터, 좌표 → 칸 찾기, 이웃·거리, 이동 비용이 있는 길찾기(막힘·지대 통제·멈출 칸·경로), 사거리·범위 모양(십자·마름모·직선), 시야와 선 긋기, 방향(밀치기), 맵 그리기 도구, 화면의 칸 집기·범위 칠하기·경로 화살표.
- 왜: 이 장르의 동사 전부(이동·공격·기술·시야·밀치기·AI)가 이 위에 선다. 지금은 프로젝트마다 AI가 처음부터 만들고, 질문 9·12번도 여기서 나온다. 화면 쪽(맵 위 입력 흐름)도 기본으로 되는 것이 없다.
- 다른 장르: 전략·퍼즐(칸 밀기)·로그라이크·보드게임·칸 있는 카드 전술·타워 디펜스·농장 시뮬(밭 칸).
- 제안: 선택 기능 '격자'.
  - Core(Rules에서 쓴다): 상속해 쓰는 칸 `[Serializable] public class GridCell { public string id; public int x, y; }`, `GridIndex.Of(cells)`(좌표 → 칸 사전, 행동마다 새로), `Grid.Neighbors(x, y, Adjacency.Four)`, `Grid.Distance`, `Grid.Reachable(start, budget, cost: (from, to) => …, passable, stopAt)` → `Reach { Cells, PathTo(x, y) }`, `Grid.Line(a, b)`, `Grid.Visible(from, range, blocksSight)`, `Grid.Shape(center, AreaShape, size, dir)`, `Grid.Direction(from, to)`·`Grid.Step`.
  - 기본 Block: 대상 `범위 칸`·`칸 위의 개체`·`인접 개체`, 조건 `사거리 안`.
  - DB: 종류 '격자 맵'(지형 팔레트로 칠하는 편집 화면, 글자 줄 CSV 가져오기), 칸마다 지형 원본 ID.
  - Unity: `GridView`(Tilemap 또는 프리팹으로 칸 그리기, `PickCell(마우스)`, `Paint(cells, 색)`, `Path(cells)`).
- 3요소: ① 평범한 static 함수와 상속할 데이터 클래스(감싸는 형식 없음) ② 지형은 칸에 원본 ID만 두어 변경이 적다 — 바뀌는 것(불)만 전송 ③ 리플렉션 없음.

**G2. 행동 안의 미리보기 · 부수 효과 없는 행동 직전 이벤트**
- 무엇: `Game.Preview`는 행동 밖에서만 되고(`Actions.Preview`), `Data.Mark/RollbackTo`는 난수와 이벤트를 되돌리지 않는다. 적 AI(행동 안)가 행동 직전 이벤트("받는 피해 −2", 특효 ×2)까지 반영한 예상 피해를 보려면 순수 예측 함수가 `Game.Intercept`를 직접 부르는 수밖에 없고, 행동 직전 이벤트 밖 값을 바꾸는 행동 직전 이벤트(28장 5-7 메아리의 `PlayerDataReward`)는 예측만으로도 돈다. Journal에 예측마다 "결과: 행동 직전 이벤트 amount -2"가 쌓인다.
- 왜: 적 페이즈마다 수십~수백 번.
- 다른 장르: 카드 게임 AI, 오토배틀러, 보드게임 AI, 행동 안에서 "이렇게 하면" 값을 미리 따지는 모든 규칙.
- 제안: (가) `Game.Simulate(() => 읽기)` — 행동 안에서도 되는 미리보기(저장점 + 난수 상태 보관 + 그 안의 행동 뒤 받는 쪽·Journal 버림 → 되돌림). (나) 가벼운 쪽: `Game.Intercept(intent, dryRun: true)` + `TriggerContext.IsDryRun` + 조건 Block `미리 따지는 중`(DB에서 부수 효과 결과를 거른다) + dryRun이면 Journal 줄 생략.
- 3요소: ① 함수 하나 ② 되돌린 변경은 전송하지 않음 ③ 없음. 성능: (가)는 저장점마다 Sync라 AI가 칸마다 부르면 무겁다(가정) → AI에는 (나).

**G3. 되감기 지점(이름 붙인 Undo 지점·저장되는 체크포인트)**
- 무엇: "여기까지 되돌리기" API가 없어 화면 쪽이 `while (UndoCount > 0 && !도착) Undo()`를 돈다. Undo 이력이 판 저장에 들어가지 않아(`GameSession.ExportRun` 주석, `ImportRun`이 `ClearUndo`) 끄고 켜면 되감기 지점이 사라진다. 되감아도 남을 값(횟수)은 AI가 `Permanent()`를 알아야 한다. 28장 1절·관례 13절은 되감기를 문법 밖으로만 적어 AI가 이 길을 찾지 못할 수 있다(5-2 E3).
- 왜: 기믹 6번 그대로.
- 다른 장르: 퍼즐·Into the Breach의 '이 턴 다시', 카드 게임 '턴 다시', 로그라이크 '방 다시', 액션의 체크포인트, 패배 뒤 '장 시작부터'(판 = 캠페인일 때).
- 제안: `session.MarkPoint(이름)`(행동 밖, 지금 이력 위치에 이름) · `session.UndoTo(이름)` · `session.Points`. 저장을 넘으려면 `session.Checkpoint(이름)`(세션 구역 + 난수 + 시계를 판 저장 안에 함께, 개수 한도) · `RestoreCheckpoint(이름)`(메타 구역은 두므로 횟수는 메타나 Permanent에). 가이드 07장 턴제 전술 칸에 "턴 시작으로 되감기" 예.
- 3요소: ① 함수 둘 ② 복원은 스냅샷 되감기처럼 한 묶음으로 보냄, 체크포인트는 판 저장 파일만 키움 ③ 없음.

**G4. 판 저장 시점 '이 이벤트를 받을 때'**
- 무엇: Bootstrap 판 저장은 행동마다 · 끌 때 · 저장 안 함뿐(`RunSaveMode`). 이 게임은 "아군 턴 시작에만"(3번 답)이라 화면 쪽이 아군 `PhaseStarted`를 받아 프레임 끝에 `GBibleRuntime.SaveRun`을 직접 부른다.
- 다른 장르: 로그라이크(방에 들어갈 때), 액션(체크포인트), RPG(마을 도착).
- 제안: 판 저장 방식 '이 이벤트를 받을 때' + 이벤트 칸(여럿). `RunSaver`가 그 이벤트를 쏜 바깥 행동이 끝날 때만 저장 표시를 세운다(Undo 끊는 이벤트와 같은 모양).
- 3요소: 문제 없음.

**G5. 슬롯을 넘는 저장**
- 무엇: 프로필·도전과제 달성(`achievement:<ID>`, 메타 구역 — `Achievements.cs`)·영구 Modifier가 모두 슬롯마다. "하드는 모든 슬롯에서", 도감·갤러리·클리어 특전을 둘 곳이 없다. 기기 설정 원시 값(`GameSettings.SetRaw`)은 모듈용이고 플레이어 데이터가 아니다.
- 다른 장르: RPG·비주얼 노벨(갤러리), 슬롯이 있는 로그라이크의 해금, 수집형.
- 제안: 구역 `DataZone.Global`(`MomoiProject/global.json`, 슬롯 폴더 밖, 프로필과 같은 때 저장), DB › 플레이어 데이터 구역 칸에 '전역', 도전과제에 '모든 슬롯' 칸. Steam 도전과제는 원래 전역이라 게임 안 목록과도 맞는다(34장의 동기화는 확인하지 않음 — 가정).
- 3요소: 문제 없음.

**G6. 상태 효과 '가진 쪽 필드'의 한계**
- 무엇: 이벤트·행동 직전 이벤트의 필드 하나가 가진 쪽 id와 같은지만 본다(`Statuses.HoldersFor`·`OnEvent`). ① 진영 페이즈 턴제는 "내 턴이 끝날 때"를 위해 유닛마다 `UnitTurnEnded`를 쏘아야 한다. ② 상태 효과 하나에 트리거 하나·가진 쪽 필드 하나라, 한 칸의 불이 "그 칸 유닛의 턴 시작(tileId)"과 "라운드 끝(필드 없음)"에 함께 반응하려면 상태 효과를 둘로 나눠 같이 건다(4-2 #5). ③ "가진 쪽의 적일 때"는 조건 Block을 따로 만든다.
- 왜: 이 장르 상태 효과(독·경계·불·패시브 효과) 거의 전부.
- 다른 장르: 팀 단위 턴 게임 전부(보드·2인 카드), 오라.
- 제안: 가진 쪽 필드 옆에 '가진 쪽의 이 필드와 같을 때'(예: 이벤트 `team` = 가진 쪽 `team`) 칸, 걸려 있는 동안 규칙을 `List<TriggerRule>` 모양으로(줄마다 가진 쪽 필드). 가이드 07장 6절에 "진영 페이즈면 유닛마다 턴 이벤트를 쏜다" 한 줄.
- 3요소: 생성 필드 읽기(`FieldAccess`)라 리플렉션 없음.

**G7. 같은 셀 이벤트에서 걸린 상태 효과가 그 이벤트에 바로 줄어든다**
- 무엇: 세션 생성자에서 `TriggerSystem`이 `StatusSystem`보다 먼저 만들어지고 먼저 `Events.SubscribeAll`한다(`GameSession.cs` 124·131줄, `Triggers.cs` 524줄, `Statuses.cs` 106줄). `EventBus.PublishObject`는 `SubscribeAll` 받는 쪽을 등록 순서대로 부른다. 그래서 `RoundEnded`를 받은 결과가 새로 건 '3라운드 불'은 같은 `RoundEnded`의 지속 줄이기(`StatusSystem.OnEvent`가 그 뒤에 목록을 찍는다)에 들어가 곧바로 2가 된다. 29장 2-2 "결과가 먼저다"는 같은 상태 효과 안의 순서만 말한다(코드로 본 것, 실행해 보지는 않음).
- 다른 장르: "턴 끝에 다음 턴까지 버프" 류 전부.
- 제안: 걸린 순간의 이벤트는 세지 않는다(걸린 것에 걸린 이벤트 번호를 적어 두고 그 이벤트는 건너뜀). 아니면 29장에 주의 한 줄.
- 3요소: 문제 없음.

**G8. '조건이 참인 동안' 지속·보정**
- 무엇: 상태 효과 지속은 영구·이벤트 횟수·시간, Modifier는 붙였다 떼기뿐. "숲 위에 있는 동안 회피", "옆 아군마다 공격 +1", "체력 절반 이하인 동안"은 규칙 함수가 계산하거나 이동마다 붙였다 떼야 한다(이 게임은 규칙 함수 계산으로 피했다, 4-2 #3).
- 다른 장르: 오라(MOBA·ARPG·오토배틀러), 카드 "필드에 있는 동안".
- 제안: 상태 효과 지속 '조건이 참인 동안'(조건 Block, 행동 끝에 평가) 또는 Modifier 줄의 '계산값'(조건 Block·대상 Block을 `Game.Attribute`가 읽을 때 평가 — 저장되지 않음).
- 3요소: ② 계산값이면 전송할 것이 없다. 읽을 때 비용은 가정.

**G9. 범용 대상 Block**
- 무엇: 기본 대상 Block은 `사용자 자신` 하나다. '이벤트·행동 직전 이벤트의 id 필드로 찾기'(때린 쪽·맞은 쪽·들어온 유닛), '조건으로 거르기', '무작위 n(흐름 이름)'은 장르마다 같은 것을 다시 만든다(이 게임만 해도 #4·#10·#13).
- 제안: `이벤트의 개체`(`[FieldPath]`로 이벤트·행동 직전 이벤트 필드를 고름 → `Game.Find`), `조건으로 거르기`(후보마다 `Context.User`를 그 후보로 두고 조건 Block 평가), `무작위`(개수·흐름 이름).
- 3요소: 생성 필드 읽기라 문제 없음.

**G10. 상태 효과·액티브 효과의 아이콘·숨김·설명 칸**
- 무엇: `StatusData`·`AbilityData`에 아이콘이 없다(도전과제에는 `icon`이 있다, 14장). 유닛 정보의 상태 아이콘 줄·기술 버튼 아이콘을 그리려면 프로젝트가 따로 짝(인스턴스나 이름 규칙)을 만든다. 출격 때 거는 패시브 효과(영구 상태 효과)를 아이콘 줄에서 숨길 칸도 없다. 두 클래스는 `sealed`라 프로젝트가 칸을 더할 수 없다.
- 다른 장르: 상태 효과가 보이는 모든 게임.
- 제안: `icon`(Sprite) · `hidden`(화면 목록에서 빼기) · 설명 텍스트 키 규칙 `<id>.desc`(DB 이름 키 채우기 메뉴가 함께 만든다).
- 3요소: 문제 없음(에셋은 DB에 남고 판 데이터에는 ID만).

**G11. 고르기 창 하나·'저절로'는 전부 켜기/끄기**
- 무엇: 맵 위에서 칸·유닛을 고르는 선택과 팝업 목록 선택이 섞이면 선택마다 화면을 고를 길이 없다. 이 게임은 대상을 행동 전에 고르므로 드물다(보상 셋 중 하나만 팝업).
- 제안: `Game.Ask(…, kind: "map")` 같은 선택 종류 → DB › 화면 설정에 '선택 종류 → 화면' 줄.
- 3요소: 문제 없음. 급하지 않다.

**G12. 이벤트로 발동한 결과의 예외는 행동을 취소하지 않는다**
- 무엇: `EventBus.Invoke`가 받는 쪽의 예외를 잡아 Journal에 "구독자 오류"로 남기고 계속한다(`EventBus.cs` 132~143줄). 트리거 감시(`TriggerSystem.OnEvent`)와 상태 효과 지속도 `SubscribeAll` 받는 쪽이라, 이벤트 받기로 발동한 결과·`[BindTo]`·상태 효과 결과 안에서 `Game.Fail`이나 예외가 나도 행동은 실패하지 않고, 던지기 전에 바꾼 값은 남는다. 관례 3절 "안 되는 순간 던진다(바꾼 것이 모두 취소된다)"를 이 자리에서 따르면 반쯤 바뀐 상태가 된다. 행동 직전 이벤트로 발동한 결과는 `Game.Intercept`를 부른 규칙 함수로 그대로 올라와 행동이 취소된다(이벤트와 다르다). 10장은 "다른 받는 쪽은 계속 불린다"만 적는다.
- 왜: 이 게임은 이벤트로 도는 규칙이 많다(경계 사격 `UnitStepped`, 불 `UnitTurnStarted`, 맵 이벤트·증원, 승패 조건).
- 다른 장르: 이벤트 받기 트리거를 쓰는 모든 게임(유물·퀘스트·로그).
- 제안: 행동 안에서 이벤트로 발동한 결과를 돌릴 때 이벤트 예약처럼 저장점을 두고(29장 2-5 "그 예약이 바꾼 것만 되돌린다"와 같은 `Data.Mark`/`RollbackTo`) 실패하면 그 결과가 바꾼 것만 되돌린 뒤 경고. `GameFailure`는 바깥 행동까지 올려 보낼지 정하는 칸. 최소한 관례 3절·10장에 "이벤트로 발동한 결과 안에서는 던지지 말고 조건으로 거르거나 return" 한 줄.
- 3요소: ① 쓰는 법은 그대로 ② 되돌린 변경은 전송하지 않음 ③ 없음. 저장점마다 Sync가 한 번 돈다(비용).

### 5-2. 문서가 틀리거나 모자란 것

- **E1. 가이드 07장 6절(턴제 전술)** "공격 전에 보이는 예상 피해·명중은 미리보기(`Game.Preview(new Attack …)`)로" — 미리보기는 난수를 실제로 굴린 결과를 보여 준다(33장 2-2 표 "실제로 하면 미리본 값과 같다", 5-3). 명중률이 아니라 이번 공격이 맞는지가 새어 나간다. 고칠 글: "명중·치명 확률은 난수를 쓰지 않는 예측 함수(`Rules.Forecast`)로 계산하고, 화면은 그것을 감싼 예측 행동을 미리보기한다(5-4 F3). 실제 공격 행동은 미리보기하지 않는다."
- **E2. `PlanningSpecGuide.md` 2절 '1 되돌리기 — 없음: Undo 방식 없음'** — 되감기·'이 턴 다시' 같은 기믹이 있으면 틀린 안내다. 고칠 글: "없음 = 플레이어 Undo 버튼을 두지 않는다. Undo로 만드는 기믹이 없으면 Undo 방식 '없음'."
- **E3. 28장 1절 "문법 밖: 게임 상태를 통째로 되감는 효과('3턴 전으로')" · 관례 13절 "게임 전체를 과거로 되감기"** — 같은 세션 안이면 행동 단위 Undo로 몇 턴 전 시작까지 되감긴다(4-2 #8). 문법 밖은 "저장을 넘는 되감기", "되감은 뒤 난수를 다시 굴리는 되감기"다.
- **E4. `PlanningSpecGuide.md` 2절 '1 한 판' vs 가이드 07장 1절 표 '턴제 전술: 전장 = Session, 캠페인 진행 = Meta'** — 캠페인형 게임에서 '판'이 무엇인지 두 문서가 다르게 이끈다(질문 1번이 생긴 까닭). 양식 1절에 "[필수] 저장 단위: 한 판 = ? (캠페인형이면 전투 하나 / 캠페인 전체)" 칸, Guide 2절에 "캠페인형: 판 = 전투(세션), 캠페인 = 프로필(메타). 동료 → 전투 사본은 id를 다르게, 장비 보정·패시브 효과는 전투 시작에 다시 붙인다" 줄을 더한다.
- **E5. 02장 2.2 "같은 형식 안에서 id가 겹치지 않는다"** — 코드로는 형식 없이 id로 찾는 곳이 많다: `Game.Use`의 사용자·대상(`Abilities.cs` 189줄, 16장 4절에 한 줄), 상태 효과의 가진 쪽(`Statuses.cs` 234·253줄), Modifier 대상(`Attributes.cs` — id 글자만), 선택의 후보(`Choices.cs`), 사라진 개체 정리(`PruneMissing`). 형식이 달라도 같은 id면 먼저 찾은 것(데이터 키 이름순)이 쓰인다. 동료(`profile`)와 전투 사본(`run`)이 같은 id면 `Game.Use(skill, "lea")`가 프로필의 동료를 사용자로 잡는다. 고칠 글: "id는 플레이어 데이터 전체에서 하나로 둔다(형식이 달라도)."
- **E6. 03장 2.15 `Grid.At` 예** — 칸마다 `game.All<Unit>()`를 부른다. 같은 장 3절은 `All`·`Find`가 그 키를 Sync하고 사본 나무를 처음부터 훑는다고 적는다. 길찾기가 이 예를 따르면 행동 하나에 수백 번 Sync가 돈다(5-3 P1). 예를 "전투 객체를 한 번 꺼내 좌표 사전을 만든다"로.
- **E7. 가이드 07장 6절 "독·기절 … 지속 = 유닛 턴 끝 N회, 가진 쪽 필드로"** — 진영 페이즈(아군 전체 → 적 전체)면 유닛마다 턴 이벤트를 쏘아야 한다는 말이 빠졌다(G6).
- **E8. Reference 6절 "Undo 보관 수(행동 단위) 200(Bootstrap)"** — 코드 기본값은 0(무제한)이다(`GameDatabase.historyLimit`, `SessionOptions.HistoryLimit`). 200은 Guide 3절의 추천값이다. "정해진 숫자" 표에서 빼거나 "추천 200, 기본 0"으로.
- **E9. 양식에 적 AI 칸이 없다** — 상대가 스스로 움직이는 게임(전술·카드·전략·보드)에서 큰 시스템인데 `PlanningSpec.md`에 칸이 없고 Guide 2절에도 줄이 없다. 이 명세서는 2-1에 자유 글로 넣었다. 제안: 양식 2-1에 "[필수, 상대가 스스로 움직이면] 적 행동 방식(종류·대상 고르는 기준·난이도 차이)", Guide 2절에 "적 AI → 진영 페이즈 행동 안의 규칙 함수, 난수 흐름 `ai`, 예측은 순수 함수(G2), AI 종류는 키워드 + 인스턴스 칸".
- **E10. 관례 3절 "안 되는 순간 던진다" · 02장 2.7 "예외가 나면 전부 취소"** — 이벤트로 발동한 결과 안의 예외는 `EventBus`가 잡아 기록만 하고 행동은 계속된다(G12). 두 곳 모두 "행동 직전 이벤트·행동 본문 안에서만 그렇다"는 단서가 빠졌다.

### 5-3. 성능·3요소

- **P1. `Find`·`All`의 비용**: 부를 때마다 그 키를 Sync하고 사본 나무를 처음부터 훑는다(`GameApi.Find`, `Mirror.FindById`에 id 색인 없음). 상태 효과의 가진 쪽 찾기·정리도 줄마다 `Game.Find`다. 칸 120개 + 유닛 30 + 칸 상태 효과가 있는 이 게임에서 길찾기·AI가 칸마다 찾으면 행동 하나에 Sync가 수백 번 돈다(측정하지 않음, 가정). 제안: E6 문서 수정 + `Find(id)` 색인(Sync가 만드는 id → 노드 사전) 검토. 3요소 ②와는 상관없고 CPU 쪽이다.
- **P2. 적 AI 예측**: G2. 예측을 순수 함수로 두면 Sync가 없어 가볍다.
- **P3. 되감기**: Undo마다 Sync·`Synced` 알림이 나가지만 다시 그리기는 프레임 끝 한 번이라 화면 비용은 작다. Undo 이력이 전투 내내 쌓이지만(보관 수 0) 전투가 끝나면 새 판이 비운다(가정: 전투 하나의 이력 메모리는 문제 없음).
- **3요소를 어기는 것은 없었다.** 제안한 기능도 모두 ① 함수·어트리뷰트·상속할 데이터 클래스 ② 되돌림·파생 값은 전송 없음 ③ 생성 코드 읽기다. 단 시야를 멀티 대전에 쓰면 ②에서 숨은 정보를 보내지 않는 필터가 필요하다(`Architecture.md`에 설계 한 줄만 있음).

### 5-4. 문서에서 찾기 어려움(기능은 있다)

- **F1. 칸·카드처럼 싸우지 않는 객체에도 상태 효과를 건다**(29장 2-1 끝) — 불타는 칸에 딱 맞다. Reference 2-2의 상태 효과 줄은 "독·화상·보호막·분노"만 적는다.
- **F2. 유닛마다 다른 패시브 효과(직업·무기·동료 특성) = 출격 때 거는 영구 상태 효과** — 가진 쪽 필드·행동 직전 이벤트·스탯 보정이 이미 다 있다. Guide 2절 '2-2 지니면 발동 = 프로젝트 고유 기능(17장)'만 보면 유물처럼 DB 종류를 새로 만들게 된다(그건 플레이어 하나가 가진 것에 맞다).
- **F3. 예측 창 모양**: `Game.Preview`는 넘긴 행동 객체를 그대로 실행한다(`Actions.Preview`). 그래서 `var f = new ForecastAttack { attacker, target, fromX, fromY }; Game.Preview(f, _ => f.result)`처럼 `Run`이 행동 필드에 적은 예측을 읽기에서 꺼낼 수 있다. 예측 행동이 난수를 쓰지 않으면 결과가 새지 않고, 공격자를 옮겨 둔 것도 되돌아간다. 문서에 이 모양이 없다(33장 5-3은 실제 행동을 미리본다).
- **F4. 패배 뒤 '이 장 다시'** = 판을 전투로 두면 `GBibleRuntime.NewRun` + `StartBattle`(06장). 판 = 캠페인이면 길이 없다(G3).
- **F5. 막사(프로필)를 행동마다 저장** = Bootstrap '프로필도 행동마다 저장'. 가이드 07장에는 수집형·방치형 쪽에만 있다.
- **F6. 이동 물리기**: 이동과 행동을 행동 하나로 보내고 화면이 경로를 미리 보여 주면 Undo를 열지 않고 된다. 02장 4.1 예는 `Move`·`Attack`을 따로 두고 Undo 버튼을 단다.

## 6. 하루 안에 되나

**판단: 질문은 12개로 20개 안에 든다. 시스템층과 화면을 함께 하루 안에 끝내기는 어렵다. 시스템층만이라면 들어간다.**

GBible이 이 장르에서 바로 해 주는 것:
- 저장·슬롯·설정·Steam·대화 — 거의 DB 설정과 기본 화면(슬롯·설정·일시정지·확인·알림·고르기 창)으로 끝난다.
- 상태 효과(독·불·경계·패시브 효과), 행동 직전 이벤트(감쇠·특효·면역·협동 100%), 가중치 표(보상 셋 중 하나), 밸런싱 값 — 대표 효과 20개 중 11개가 A·B다.
- 되감기의 바탕(행동 단위 Undo가 난수까지 되돌림 + `Permanent`), 패배 뒤 다시 하기(`NewRun`), 예측 창의 바탕(`Game.Preview`).
- HUD의 값 칸(binding-path)과 버튼 → 행동(`OnClick`).

하루를 넘기게 하는 것:
- **격자가 없다**(G1). 칸 데이터·길찾기(이동 종류별 비용·지대 통제·숨은 적에서 멈춤)·사거리·범위 모양·시야 선 긋기·밀치기 방향을 규칙 쪽에서, 칸 그리기·마우스로 칸 집기·범위 칠하기·경로 표시를 화면 쪽에서 처음부터 만든다. 맵 작성 도구도 없다.
- **맵 위 입력 흐름**(유닛 고르기 → 이동 범위 → 칸 → 행동 메뉴 → 대상 → 예측 → 확정 → 물리기)은 UI Toolkit 화면이 아니라 씬 쪽이라 기본 화면·binding-path가 닿지 않는다.
- **공격 처리 순서와 예측 창이 같은 계산을 해야 한다.** 추격·반격·협동·밀치기·상성·지형·행동 직전 이벤트를 한 함수(`Rules.Forecast`)에 모아 실제 공격과 예측 창과 AI가 함께 써야 하는데, 이 모양을 문서가 알려 주지 않는다(E1·F3).
- **적 AI**: 행동 안에서 쓸 미리보기가 없어 예측 함수 + 행동 직전 이벤트 약속을 직접 세운다(G2).
- **연출**: 적 페이즈 한 행동 안의 이동(칸마다)·공격·반격·협동·밀치기·레벨업을 연출 대기열에 차례로 넣고 안개 속 보임을 이벤트 값으로 맞춘다. 대기열은 GBible이 주지만 장면마다의 연출 코드는 프로젝트 몫이다.

하루 안에 들어가게 하려면:
- GBible에 선택 기능 '격자'(G1: Core 길찾기·범위·시야 + `GridView` + 격자 맵 DB)가 있으면 가장 큰 덩어리가 빠진다.
- 가이드 07장 턴제 전술 칸에 "공격 한 함수 + 예측 행동 + 유닛마다 턴 이벤트 + 턴 시작 되감기" 예가 있으면 AI가 구조를 정하는 데서 헤매지 않는다(E1·E3·E7·F3).
- 그 둘이 없으면 첫날은 시스템층(규칙·DB·저장·되감기)과 HUD·막사까지로 끊고, 맵 위 입력과 연출은 다음 날로 넘기는 것이 현실적이다.

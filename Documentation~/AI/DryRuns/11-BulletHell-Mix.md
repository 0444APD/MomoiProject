## 2. 기획 명세서(채운 것)

### 0. 한 줄 소개

- 장르·참고 게임: 종스크롤 탄막 피하기 아케이드 + 빌드 로그라이트.
  - 동방 프로젝트: 탄막·스침·저속 이동.
  - 발라트로: 부적 칸 점수.
  - 와일드프로스트: 카운터·Snow.
- 한 문장 소개: 둘이 함께 탄막을 피하는 동안 무기는 카운터대로 저절로 쏘고, 웨이브가 끝나면 부적 칸이 왼쪽부터 점수 배수를 더하고 곱한다.
- 멀티플레이: 있음 — 온라인 협동 2인(Steam 친구). 혼자도 할 수 있다.
- 플레이 한 판의 길이: 25분.

### 1. 한 판의 흐름

- 시간: 섞임.
  - 웨이브는 실시간이다.
  - 웨이브 사이(보상·상점)는 둘 다 '준비'를 누를 때까지 기다린다.
- 한 판은 이 순서다.
  1. 로비에서 캐릭터를 고른다(각자 시작 무기 1개).
  2. 웨이브 1~15를 치른다.
  3. 웨이브마다 끝에 정산한다(부적 발동).
  4. 각자 보상을 받는다(부적·무기 셋 중 하나).
  5. 3웨이브마다 상점이 열린다(공용 코인).
  6. 5·10·15웨이브는 보스다. 15웨이브 보스를 잡으면 끝이다.
- 반복 단위: 웨이브.
  - 40초가 지나거나 적을 모두 잡으면 끝난다. 보스 웨이브는 보스를 잡으면 끝난다.
  - 플레이어는 8방향으로 움직이고, Shift로 저속 이동한다.
  - 폭탄은 웨이브마다 1개이고, 화면의 탄을 지운다.
  - 무기는 저절로 쏜다.
  - 탄이 히트박스 가까이 지나가면 '스침'이다(칩 +1).
- 판이 끝나는 때:
  - 승리: 15웨이브 보스 처치.
  - 패배: 둘 다 쓰러짐.
  - 쓰러진 사람은 파트너가 곁에 3초 서 있으면 체력 1로 일어난다.
  - 웨이브 점수가 목표 점수보다 낮으면 둘 다 체력 −1.
- 판이 끝나도 남는 것: 해금(부적·무기·캐릭터), 최고 점수, 별가루(해금에 쓴다).
- 되돌리기: 없음.
- 이어 하기: 없음(아케이드라 끄면 그 판은 끝난다).

### 2. 다루는 것들

#### 2-1. 주인공·유닛

- 플레이어 캐릭터(둘): 체력 3·최대 체력·폭탄 수·이동 속도·히트박스 크기·스침 반경·무기 피해 보정을 가진다. 상태 효과가 걸린다.
- 적: 체력·칩(잡으면)·코인·탄 종류·탄 패턴을 가진다.
- 보스: 체력·패턴 단계를 가진다. 체력 66%·33%에서 패턴이 바뀐다.
- 피해 공식:
  - 플레이어 탄 → 적: 무기 피해 × (1 + 피해 보정).
  - 적 탄 → 플레이어: 늘 1(방어 없음). 탄 종류마다 상태 효과가 붙는다.

### 4. 메인 룰과 기믹

#### 4-1. 메인 룰

웨이브 동안 무기 칸의 무기는 0.5초 박자마다 카운터가 1씩 준다. 0이 되면 그 무기가 탄 패턴을 쏘고 카운터가 돌아온다. 얼음에 걸린 사람의 무기는 카운터가 멈춘다.

적을 잡거나 탄을 스치면 칩이 쌓인다.

웨이브가 끝나면 부적 칸을 왼쪽부터 발동해 배수(처음 1)에 더하고 곱한다. +4 다음 ×2면 10, 순서가 반대면 6이다. 점수 = 칩 × 배수다. 목표 점수보다 낮으면 둘 다 체력 −1이다.

#### 4-2. 메인 룰 구조

- [x] 다른 것의 액티브 효과를 빌려 쓴다(거울 부적)
- [x] 놓인 순서·위치가 효과를 바꾼다(부적 왼쪽부터, 충전포의 오른쪽)
- [ ] 한 조각이 여러 칸을 차지한다
- [ ] 위치·조건에 따라 조각의 태그·속성이 바뀐다
- [x] 자원을 다른 곳에서 내거나 여럿이 나눠 쓴다(공용 코인, 빚)
- [ ] 효과가 반복 발동한다
- [ ] 판정 규칙이 바뀐다

#### 4-3. 기믹 갈래

- [x] 다른 효과 고치기 · [x] 자리·순서 · [x] 반복·배율 · [x] 복사·흉내 · [x] 변환 · [x] 확률·운 · [x] 규칙 바꾸기(빚·보스 패턴 끄기) · [x] 쌓이는 값·카운터 · [ ] 세트·콤보 · [x] 가진 동안 스탯 · [x] 상태 효과 · [x] 보상·선택·경제 · [ ] 판 구조·소환·시드(일일 탄막은 6절)
- [x] 대상: 자신 · 무작위 · 전체 · 조건으로 거른 대상 · 자리(옆·파트너 칸). 고른 대상은 없다.
- 이상한 효과 세 개:
  1. **거울 부적**: 오른쪽 부적을 따라 한다. 맨 오른쪽 칸이면 파트너 부적 칸의 같은 칸을 따라 한다.
  2. **얼음 탄(Snow)**: 맞은 사람의 무기 카운터가 3초 멈춘다. 해동 부적을 가진 사람은 그 대신 자기 무기 카운터가 모두 −2가 된다(0이 되면 바로 쏜다).
  3. **메아리 부적**: 파트너의 무기가 쏠 때마다 내 무기 칸 맨 왼쪽 무기가 한 번 더 쏜다(한 웨이브 10번까지).
- 고리: 생길 수 있다. 둘 다 메아리 부적이면 서로의 발사가 서로를 부른다. 10번 제한으로 막을 생각이다.

### 5. 문법에 안 맞는 기믹

- 보스의 '되감기': 화면의 탄막과 두 캐릭터를 3초 전 자리로 되돌린다.
- 온라인의 두 사람이 같은 탄막을 봐야 한다(누가 맞았는지 어긋나면 안 된다).

### 7. 진행·화면

- 씬: 타이틀 → 로비(방 만들기·들어가기·캐릭터·해금) → 전투 → 결과 → 로비. 웨이브·보상·상점은 전투 씬 안의 화면이다.
- 화면:
  - HUD: 둘의 체력·폭탄, 공용 코인, 칩 × 배수, 목표 점수, 남은 시간, 각자의 무기 칸(카운터 원)·부적 칸.
  - 보상 창: 각자.
  - 상점: 사기·다시 뽑기·칸 늘리기·준비.
  - 결과: 점수·별가루·해금.
  - 로비.
- 연출이 끝날 때까지 입력을 막는 곳: 웨이브 끝 정산 연출(부적이 왼쪽부터 하나씩 빛나며 배수가 바뀐다)이 끝날 때까지 보상 창을 열지 않는다. 웨이브 중에는 막지 않는다.
- 효과 도중 고르기 창: 웨이브 끝 보상(둘이 각자, 동시에).

### 8. 성장·밸런스

- 커지는 숫자:
  - 목표 점수: 1웨이브 300, 웨이브마다 ×1.6.
  - 적 체력: 웨이브마다 +10%.
  - 다시 뽑기 비용: 1회 2, 회마다 +1.
- 뽑는 표:
  - 부적 보상: 일반 70 · 희귀 25 · 전설 5. 해금한 것만 나오고, 둘이 가진 것은 빠진다. 셋 중 하나를 고른다.

  - 상점 진열: 부적 3·무기 2.
  - 웨이브 적 조합: 웨이브 번호에 따라.

### 9. 기록·도전과제

- 기록: 처치 수, 스침 수, 한 웨이브 최고 점수.

### 10. 저장·설정

- 출시 언어: 한국어·영어·일본어.

- 웨이브가 끝나면 플레이어의 상태 효과를 모두 푼다.
- 맞은 뒤 무적은 규칙의 상태 효과다(화면은 깜빡임만).
- 부적·무기 원본은 인스턴스이고, 그 패시브 효과 ID를 칸으로 가리킨다(DB ID가 종류를 넘어 하나뿐이라서, 9절).
- 조각에 `ownerId`를 둔다.
- 파트너에게 건네기는 행동 하나다.
- 공용 지갑은 먼저 산 쪽이 가져간다.
- 설정 8개, 슬롯 1개, 출시 언어, 이름(가칭).

## 4. 시스템 목록(질문에 추천값으로 답을 받았다고 본다)

### 4-1. 메인 룰 — GBible로 세우는 법

**조각 → 자리**

| 조각(판 데이터의 객체) | 자리 | 원본 ID 필드 |
|---|---|---|
| `Charm { id, card, charm, kind, ownerId, stack, uses, level }` | `run › players[i].charms`(`List<Charm>`, 5칸, 빈 칸 `null`, 줄 길이 0) | `card` = 부적 원본(인스턴스), `charm` = 그 원본이 가리키는 패시브 효과 ID(일치 필드) |
| `Weapon { id, weapon, reaction, ownerId, counter, level }` | `run › players[i].weapons`(3칸) | `weapon` = 무기 원본(인스턴스, 사용 기능), `reaction` = 반응 패시브 효과 ID(일치 필드, 비면 반응 없음) |

**순서 — 세 갈래**

1. **박자(실시간)**
   - `BulletRules.Register(session)`이 `session.Ticked`에 건다(33장 5-1).
   - 틱마다 하는 일: `phase == Wave`이고 `Clock.Time >= wave.nextBeatAt`이면 `session.Do(new Beat())`.

   ```csharp
   // Beat.Run (요지) — 와일드프로스트 턴 행동과 같은 모양
   var run = Game.Data().Run;
   run.wave.nextBeatAt += Game.Balance(GameIds.Balance.BeatSeconds);
   foreach (var p in run.players)                                              // 1P 먼저
   {
       if (p.downed || Game.HasStatus(p, GameIds.Status.Snow)) continue;       // 얼음 = 그 사람 무기 카운터 멈춤
       for (int i = 0; i < p.weapons.Count; i++)                               // 칸 번호 순서, 그 순간의 칸
           if (p.weapons[i] is Weapon w) Rules.ChangeCounter(Game, w, -1);     // 0이 되면 안에서 되돌리고 Game.TryUse(w.weapon, w)
   }
   ```

   - 무기 원본의 사용 기능 결과 = 효과 `발사`. `Rules.Fire`가 `FireIntent`를 거쳐 `WeaponFired`를 쏜다. 화면이 받아 탄을 만든다.
2. **판정 보고**
   - 화면이 틱마다 모은 맞음을 행동 하나로 보낸다: `ReportHits { enemyHits(enemyId·weaponId), playerHits(playerId·bullet), grazes(playerId·count) }`.
   - 규칙은 `Rules.Damage`·`Rules.HitPlayer`·`Rules.Graze`로만 바꾼다.
3. **웨이브 끝**
   - 틱에서 `Clock.Time >= wave.endsAt`이거나 적이 비면 `session.Do(new EndWave())`를 부른다.

   ```csharp
   // EndWave.Run (요지)
   var hidden = Rules.HideSealed(Game, run);                                   // 꺼진 조각 자리: 봉인된 칸을 잠시 null로(8절 예외)
   var settle = Game.Intercept(new SettleIntent { wave = run.wave.number, times = 1 });   // 반복 발동 자리
   for (int t = 0; t < settle.times; t++)
   {
       var s = Game.Intercept(new ScoreIntent { wave = run.wave.number, chips = run.wave.chips, mult = 1 });
       // 부적 = '놓인 것마다' 패시브 효과: 1P 줄 왼쪽→오른쪽, 이어서 2P 줄 순서로 mult를 더하고 곱한다
       if (!s.cancelled) run.score += s.chips * s.mult;
   }
   Rules.RestoreSealed(Game, run, hidden);
   // → WaveScored(통과 여부) → 미달이면 Rules.HitPlayer(둘, kind penalty) → 상태 효과 풀기 → 보상 요구(각자) → 3웨이브마다 상점
   ```

**4-2에서 만들 자리**

| 표시 | 만들 것 |
|---|---|
| 빌려 쓰기 | 조각이 패시브 효과라 결과 '빌려 쓰기'가 이미 된다. 각자 칸이라 대상은 `내 줄 자리로 고르기`(아래 Block)로 고른다 |
| 놓인 순서·위치 | 조각 = 객체 목록(고유 id + 원본 ID 필드). 정산 부적은 패시브 효과 `perElement`(놓인 것마다) + `matchField`(일치 필드) `charm`. 모든 정산 부적의 가진 목록을 똑같이 `run › players[].charms`로 적는다(같은 줄로 서는 조건) |
| 자원 나눔·빚 | 모든 지불을 `Game.Pay(run, "coins", …)` 하나로. 빚은 행동 직전 이벤트 '비용 지불' 받기 `floor` |
| 반복 발동(Q10) | 발사는 `TryUse`(행동 직전 이벤트 '사용'의 `times`). 정산은 `SettleIntent { times }` |

## 5. 기믹 분류

가진 목록 표기:
- **부적 줄**: `run › players[].charms`, `matchField` `charm`.
- **무기 줄**: `run › players[].weapons`, `matchField` `reaction`.

'놓인 것마다'를 켠 것은 *놓인 것마다*, 끈 것(가진 쪽 = 플레이어)은 *플레이어마다*로 적는다.

| # | 조각 | 분류 | 만드는 법 |
|---|---|---|---|
| 1 | 붉은 부적(+4 배수) · 금 부적(×2 배수) | DB | 패시브 효과, 부적 줄, *놓인 것마다*. 발동 `행동 직전 이벤트 받기` → `점수`. 결과 `행동 직전 이벤트 고치기` `mult` 더하기 4 / 곱하기 2. 1P 줄 왼쪽부터, 이어서 2P 줄. 연출용 결과 `발동 알리기`를 같이 둔다 |
| 2 | 행운 부적(1/4 확률로 ×3) | DB | 1번 + 발동에 `AND 확률`(25, 흐름 `luckyCharm`) |
| 3 | 거울 부적(오른쪽을 따라 함, 맨 오른쪽이면 파트너 줄 같은 칸) — 이상한 효과 1 | Block | *놓인 것마다*. 결과 `빌려 쓰기` → 빌릴 조각 `내 줄 자리로 고르기`(오른쪽, 없으면 파트너 줄 같은 칸) → `조건으로 거르기`(`kind` 일치 정산·반응, Q13). 발동은 따라 할 순간을 `OR`로 묶는다(행동 직전 이벤트 점수 · 받기 적 처치 · 받기 스침 · 받기 발사). 기본 `자리로 고르기`(`list` `run › players[].charms`)는 첫 플레이어 줄만 봐 2P 줄에서 아무것도 못 고른다(코드 확인) |

## 6. 화면과 규칙의 경계

탄막 피하기는 대부분이 화면 쪽이다. GBible은 판정의 **결과**와 **규칙 값**만 맡는다(관례 3절 판정 보고 행동, 33장 5-7).

| 무엇 | 화면(Client) | 규칙(Rules) | 잇는 것 |
|---|---|---|---|
| 이동·저속·히트박스 위치 | 전부 | — | 크기·속도는 규칙 스탯 `Game.Attribute(player, "hitbox"·"moveSpeed")`를 화면이 읽는다(깃털 부적이 바꾼다) |
| 플레이어 탄 | 생성·궤도·오브젝트 풀 | 언제·몇 발 쏘나(`Beat` → `WeaponFired`) | `SubscribeAfterAction<WeaponFired>` → `GameView.Play`(입력을 막지 않음)로 패턴 생성 |
| 적 탄 | 생성·궤도·풀, 적 원본의 `pattern` | 탄 수를 모른다. 보스 패턴 단계만 고른다 | 적 그리기 `ViewList<Enemy>`, `BossPhaseChanged` |
| 충돌·스침 판정 | 판정하고 모은다 | 결과로만 바꾼다(피해 양·상태 효과·무적·칩) | `ReportHits { enemyHits, playerHits, grazes }` 틱마다 하나. 화면은 양을 넣지 않는다 |
| 카운터 | 카운터 원(`GameScreen.Tick`) | 값과 발사 시점 | `Beat`, `CounterChanged` |
| 적 이동 | 전부 | 적 목록·체력·처치 | `EnemyKilled` → 사라지는 연출 |
| 폭탄 | 탄 지우기 | 폭탄 수(`Game.Pay`)·적 피해·무적 | `UseBomb` → `BombUsed` |
| 부활 | 곁에 선 시간 3초를 잰다 | 자격(쓰러짐·파트너가 서 있음)·체력 | `Revive { target, by }` |
| 되감기 탄 | 3초 위치 기록·되돌림 | 하지 않는다 | `BossPhaseChanged` |
| 남은 시간 | 막대(`TickAlpha` 보간) | `wave.endsAt` | — |
| 정산 연출 | 부적이 하나씩 빛남(`GameView.Present`, 웨이브 사이라 막아도 된다) | 정산 | 부적마다 `CharmFired`(Block `발동 알리기`). '놓인 것마다' 패시브 효과가 발동했다는 기본 이벤트가 없어서 Block을 둔다(9절) |

- **실시간 예산**:
  - 행동은 이것만 돈다: 박자 2/초 · 판정 보고 ≤ 30/초 · 상태 효과 주기·만료.
  - 탄 수백과 위치는 판 데이터에 넣지 않는다.
  - 저장은 하지 않고, Undo는 끈다.
- **같은 컴퓨터 2인**: 기기 → 플레이어 나누기(Unity의 기기별 입력)는 화면 쪽이다. 화면이 보내는 행동에 `actorId`를 채운다.

## 7. 멀티플레이(2인 온라인 협동)

**네트워크층은 아직 없다.** 서버·접속·매칭·중개 층은 보류 중이다(가이드 11장, `TestMultiplayer.md`). Steam 로비·P2P도 없다(34장). 그래서 이 시험은 그 층을 지어내지 않는다. 지금 있는 것으로 무엇이 따라오고, 무엇이 비는지만 적는다.

| 지금 있음(지키면 따라온다) | 없음(보류·범위 밖) |
|---|---|
| 행동이 데이터다: `Game.Do`·`actorId`·`Visibility`. 행동 끝 Sync → ChangeSet·Snapshot·`MirrorReceiver` | 서버·접속·중개 층, 실시간 틱마다 ChangeSet 묶어 보내기(설계만) |
| 고정 틱(만료·예약·주기가 기기마다 같은 틱) | Steam 로비·초대·P2P·SDR(유형 B 설계만) |
| 결정론 난수(시드·흐름) | **위치·탄막 동기화** — 가이드 11장은 "별도 동기화(보간)"라고만 하고 도구가 없다 |
| `Game.Ask`의 `player`(기록만) | 답할 플레이어 검사(화면·서버 몫), 동시 선택 창 |
| static 없는 세션 | 플레이어마다의 메타 구역(프로필) |
| — | 멀티 Undo 정책(미정), 온라인 일시정지(`GameTime.Pause`는 그 기기만) |
| — | 행동 예측(맞는 순간의 반응을 왕복 전에 보이기, 00-Summary 보류 목록) |

**이 게임이 지금 만드는 모양**:
- 한 세션에 `run.players` 둘을 둔다. 입력 행동마다 `actorId`를 채운다.
- 행동 안에서 "그 플레이어가 그 행동을 할 수 있나"를 검사한다(자기 캐릭터의 판정·자기 칸만).
- 같은 컴퓨터 2인과 혼자로 시험한다.

**온라인이 붙을 때 이 게임에 걸리는 것**(표시만, 만들지 않는다):
1. **권한**: 유형 B(방장 권한)다. 방장 세션이 체력·점수·카운터·부적·정산을 계산한다.
2. **판정 보고의 출처**(Q2):
   - 피격·스침은 맞는 사람 화면이 판정해 `ReportHits`를 방장에게 보낸다.
   - 방장 행동은 `actorId`로 "자기 캐릭터 것만" 받아들인다.
   - 적 피격은 방장 화면이 판정한다.
3. **지연**: 체력 감소·무적이 방장 왕복 뒤에 데이터로 온다. 화면이 먼저 깜빡이고 값은 나중에 맞춘다. GBible에 예측이 없어 화면 쪽 꾸밈이다.
4. **탄막 일치**: 패턴 난수를 시드 + 틱 + 적 id로 정한다. 화면 쪽 결정론이고 GBible 밖이다. 발사는 방장의 `WeaponFired`를 받아 양쪽이 같은 패턴을 만든다(이벤트 전달은 설계에 있다).
5. **성능**(3요소): 화면 판정 결과만 행동으로 가고, 탄·위치는 데이터에 없다. 그래서 ChangeSet은 체력·칩·카운터 정도다. 박자 2/초 + 판정 보고는 서버 틱 묶음(설계) 안에 든다.
6. **동시 보상**: 같은 ID 고르기 창이 `player`로 거른다. 방장은 `actorId`로 답한 사람을 확인한다.
7. **멈춤**: 둘이면 멈추지 않는다(Q4).
8. **프로필**: 각자 받는 해금·별가루는 메타 구역 설계가 필요하다(Q3, 보류).
9. **저장·Undo**: 판 저장 안 함, Undo 끔이라 영향이 없다.

## 9. 문서 빈틈

**문서만으로 판단이 안 돼 코드를 본 곳**

1. **'놓인 것마다' + `[]` 가진 목록의 순서**
   - 17장 0-1·37장 2-6·11장 6-1은 "같은 목록(같은 `ownerKey`·`ownerPath`)이면 목록 순서"라고만 한다.
   - `players[].charms`처럼 가진 쪽이 여럿일 때의 순서는 `Passives.cs`의 주석과 코드에만 있다: "가진 쪽이 여럿이면 그 순서대로 이어서 센다" = 1P 줄 전부 → 2P 줄.
   - 협동 게임의 정산 순서(Q6)를 문서로는 정할 수 없었다.
2. **자리 Block의 `list`에 `[]` 경로를 주면 첫 목록만 본다**(`PlacementBlocks.cs`). 37장 3-1은 "`key` › `path`(필드(목록))"라고만 한다. 실패가 조용해서(아무도 안 고름·거짓) 찾기 어렵다. 6절 '주의할 점' 표에도 없다.
3. **'놓인 것마다'가 아닌 패시브 효과를 빌려 쓰면 결과의 사용자 = 원본 조각이다**. 그 패시브 효과의 가진 쪽(플레이어)이 아니다(`Passives.Borrow`).
   - 17장 0-1·12장 2-4e는 "결과의 사용자 = 원본 조각"만 말하고, 가진 쪽이 조각이 아닌 패시브 효과(`players[].charms`의 *플레이어마다*)를 빌릴 때 `{user}`·가진 쪽 필드가 어긋난다는 말이 없다.
   - "가진 목록이 글자 목록·딕셔너리면 빌릴 수 없다"만 있다.
4. **이벤트 쏘기의 값에 틀(`{user}` 등)이 되는지**: 12장 2-4b에 말이 없다. 코드에서 틀을 펴지 않는 것을 확인했다(`PublishEventOutcome.cs`).
5. **뺄 목록 경로에 `[]`와 객체 필드(`players[].charms[].card`)를 쓸 수 있는지**: 30장은 `run › relics`·`run › seenEvents`만 보인다. 코드(`WeightTables.IdsAt`)는 경로를 풀어 글자·객체 id를 모은다. 그래서 된다.

**문서끼리·문서와 이 게임이 어긋난 곳**

6. **기믹 목록 2-7 "실시간 'N초마다'는 상태 효과의 주기"** — 카운터를 멈추거나(Snow) 앞당기는(Sun Rod) 기믹이 같은 갈래(2-7 '카운터 조작')에 있다. 그런데 주기는 멈출 수 없고, `상태 효과 줄이기`는 남은 지속을 줄일 뿐 다음 주기를 당기지 않는다(29장 2-1·2-3). 실시간 카운터 조각은 "박자 행동 + 숫자 필드"(와일드프로스트 모양)가 맞다. 2-7이 둘 중 무엇을 고를지 말하지 않는다.
7. **기믹 목록 1절 와일드프로스트 줄 "반응 = 패시브 효과 '놓인 것마다' + 가진 쪽 필드"**
   - 조각의 원본이 인스턴스(유닛·무기)일 때 반응 패시브 효과를 어떻게 잇는지 말이 없다.
   - DB ID는 종류를 넘어 하나뿐이라(17장 1절) 인스턴스 `chainGun`과 패시브 효과 `chainGun`을 같은 ID로 둘 수 없다.
   - 그래서 조각에 패시브 효과 ID 칸(`reaction`)을 따로 두고 `matchField`로 본다. 이 모양이 예시에 없다. 반응이 둘인 조각은 칸이 둘이어야 한다.
8. **패시브 효과 하나 = 발동 하나 + 결과 목록 하나**: 쌓고(이벤트 A)·쓰고(행동 직전 이벤트 B)·초기화(이벤트 C)하는 조각(스침 부적, 발라트로 Ride the Bus의 초기화)은 `[BindTo]`가 된다. 기믹 목록 2-7 '조각마다 쌓임'·'줄어듦'은 한 순간짜리 예만 있어 이 경계를 말하지 않는다. 프로젝트 DB 종류에는 `List<TriggerRule>`(17장 2-4)가 있지만 패시브 효과에는 없다.
9. **사용자(가진 쪽)의 필드를 보는 조건**: 기믹 목록 2-7 '카운터·충전'(Loyalty Card 6번째마다)은 "숫자 필드 + 필드 바꾸기 + 조건"이라고 한다. 그러나 기본 조건 중 사용자의 필드를 보는 것이 없다(11장 2-4 표). 29장 4-3의 코드 조건 예로만 된다.
10. **조각 끄기(봉인·디버프된 조커)** 가 기믹 목록 2절 갈래·3절 자리·명세서 4-2 어디에도 없다(8절 예외). 네 게임 범위 안의 기믹이다(발라트로 보스 블라인드).

**멀티·협동**

11. **명세서 읽는 법 2절 '0 멀티플레이' 줄**은 "보류 중이라고 알린다. 단일로 만든다"뿐이다. 협동 게임이 지금 무엇을 해 두어야 하는지 가리키지 않는다: 플레이어 목록, `actorId`, 조각의 주인, 각자 줄과 자리 Block의 관계, 동시 선택, 일시정지. 가이드 11장(`actorId`·키 나누기)으로 가는 연결도 없다.
12. **동시 선택**: 29장 2-6은 "`player`는 기록만", 35장은 "기본 고르기 창은 `Game.Choice`(맨 앞)". 둘을 합쳐야 "둘이 동시에 고르면 기본 창으로 안 된다"를 안다. 30장 '가중치 표에서 고르기'에 답할 플레이어 칸이 없다는 것도 따로 적혀 있지 않다.
13. **일시정지·'고르는 동안 시간 멈춤'이 `Time.timeScale`(그 기기만)** 이라는 것은 35장에 있다. 그러나 가이드 11장(멀티 대비)에 온라인에서 멈추면 안 된다는 말이 없다.
14. **같은 컴퓨터 2인 입력**: 선택 기능 입력(31장)은 한 벌의 동작·바인딩이다. 기기마다 플레이어를 나누는 것(그리고 키 바꾸기를 플레이어마다 저장하는 것)이 화면 쪽인지 말이 없다.
15. **Steam 리더보드**: 34장에 있다/없다는 말 자체가 없다(로비·P2P만 "아직 없다"). 아케이드 장르는 흔히 쓰므로 명세서 6절 Steam 줄에 적을 칸·답이 필요하다.

**이름이 헷갈린 곳**

16. **패시브 효과 칸 `holderField`(가진 쪽 필드)와 상태 효과 지속의 `holderField`**: 같은 이름이 '발동 거르기'와 '셀 이벤트 거르기' 두 곳에 있다. 상태 효과 하나 안에 둘 다 있어 DB 화면에서 헷갈린다(29장 3-1 표에 둘 다 나온다).
17. **조각과 원본의 ID 필드 이름**: 조커 예는 `joker` = 패시브 효과 ID다(원본이 곧 패시브 효과). 와일드프로스트·이 게임처럼 원본이 인스턴스면 '원본 ID 필드'(인스턴스)와 '일치 필드'(패시브 효과)가 둘이 된다. 37장 용어 '원본 ID 필드 = 패시브 효과의 일치 필드가 보는 것'이 이 경우에 맞지 않는다.

# 기획 명세서를 읽는 법 (AI용)

기획 명세서(`PlanningSpec.md` 양식, 채운 예시 `PlanningSpec-CardDungeon.md`)를 받아 시스템층을 만들 때 AI가 따르는 절차다. 목표는 **질문 20개 이하**로 정할 것을 다 정하고, 새 프로젝트의 기반을 하루(약 12시간) 안에 닦는 것이다. 어떻게 쓰나는 `ProjectConventions.md`(프로젝트 관례), 무엇이 있나는 GBible 참조 문서를 따른다.

---

## 1. 순서

1. 명세서를 끝까지 읽는다. 모르는 말은 질문에 넣지 말고 문맥으로 먼저 푼다.
2. **질문 목록**을 만든다: 빈 [필수] 칸, 칸끼리 모순, 4절의 이상한 효과 중 문법으로 쪼개지지 않는 것, 5절의 문법 밖 기믹. 한 번에 보낸다(4절 규칙).
3. 답을 받으면 **시스템 목록**(5절)을 만들어 사람에게 한 번 보여 준다(확인 질문 하나).
4. 관례 16절 순서로 만든다. 만드는 동안 새로 생긴 의문은 되돌리기 쉬우면 정하고 보고, 어려우면 모아서 한 번에 묻는다.

## 2. 칸 → GBible

| 0 멀티플레이 | 세션 구조 | 없음: 세션 하나(`GBibleRuntime.Session`). 있음: 멀티 구현은 보류 중이라 알리고, 모든 변경을 행동으로·static 상태 없음(관례)만 지켜 단일로 만든다 | 질문 |
| 1 시간 | 시계·Undo 방식 | 턴제: 고정 틱 0, Undo 행동 단위. 실시간: 고정 틱 30(DB › Bootstrap), Undo 스냅샷 | 질문 |
| 1 한 판 | 행동 목록·씬 흐름 | 판 시작·단계마다 행동(`StartRun`·`StartBattle`·`EndRun` …), 판 끝 이벤트(Bootstrap '판 끝 이벤트'), 씬 흐름(판 데이터의 씬 필드) | 질문 |

| 1 판이 끝나는 때 | 승패 행동 | 승리·패배 행동과 판 끝 이벤트 | 질문 |
| 1 남는 것 | 프로필 | `profile`(Meta 구역) 필드. 해금은 프로필 목록 또는 도전과제 보상 | 질문 |
| 1 되돌리기 | Undo 범위 | 마음대로: 행동 단위·보관 200. 이번 턴만: Undo 끊는 이벤트 = 턴 끝 이벤트. 없음: Undo 방식 '없음' | 장르 추천값(3절) |
| 1 이어 하기 | 판 저장 | 행동마다 저장 / 끌 때 / 저장하지 않음(Bootstrap '판 저장'), 타이틀이 없으면 '시작할 때 이어 하기' | 장르 추천값 |
| 2-1 유닛 | 데이터 클래스·능력치 | `id`가 있는 `[Serializable]` 클래스, 숫자 필드 = 능력치(Modifier 대상, `Game.Attribute`) | 질문(숫자 목록) |
| 2-1 피해 공식 | 규칙 함수 안 계산 | `Rules.Damage`: 스탯 → 계수 → 증폭 합 → 추가 피해, 방어 100/(100+방어), 가로채기 자리(관례 4절) | 기본 공식. 유닛에 공격력·방어 숫자가 없으면 양을 그대로(방어도처럼 기획에 적힌 막기만) |
| 2-2 원본 종류 | 클래스·DB | 원본 클래스 + DB › 인스턴스(또는 능력·상태 효과). 판 데이터에는 원본 ID + 바뀌는 값(`DeckCard { id, card, upgraded }`). "쓰기" = 사용 기능 필드(`Usable`) + `Game.Use`. "장착" = Modifier(출처 = 장비 ID). "지니면 발동" = 프로젝트 고유 기능(DB 종류 + 트리거 감시, 매뉴얼 17장) | 질문(종류 목록) |
| 2-2 키워드 | 고르는 값 | `[KeywordGroup]` 클래스 + `[Keyword(typeof(그룹))]` 필드 | 쓰지 않음 |
| 2-3 자원 | 필드·비용 | 판 자원은 RunState, 남는 자원은 Profile 필드. 쓰는 곳은 `Game.Pay(키, 경로, 양, what: "자원.name")` | 질문 |
| 2-4 슬롯 | 세이브 칸 | 1개: 기본 슬롯. 여러 개: 기본 슬롯 화면(`GameScreens.Slots`, `SlotsRequest { count }`) + `GBibleRuntime.SlotSummary` | 1개 |
| 3 핵심 동사 | 규칙 함수 | 동사마다 `Rules` 함수 + 의도(`~Intent`, 필드는 주체·대상 id·양·종류·횟수·`cancelled`) + 끝난 뒤 이벤트. "고칠 수 있어야 하나"가 아니어도 핵심 동사는 모두 가로채기 자리를 둔다 | 장르의 기본 동사(3절) |
| 4 언제 | 트리거·지속 | 발동 = 트리거(이벤트 받기·조건·가로채기). 지연 = 상태 효과의 끝날 때 결과(DB) / `ScheduleOn`·`ScheduleAfter`(코드). 지속 = 상태 효과(턴제는 이벤트 횟수, 실시간은 게임 시간) + 중첩당 Modifier | 표시한 것만 준비 |
| 4 누구에게 | 대상 Block | 자신(`SelfTarget`), 고른 대상(사용 때 넘긴 대상), 무작위(난수 흐름 하나), 전체, 조건 거르기 — 표시한 것을 재사용 대상 Block으로. 사용자가 없는 결과(유물·도전과제)가 주인공을 고를 대상 Block(`주인공`)도 | 3절 대상 Block 기본 |
| 4 무엇을 | 효과 Block·중간층 | 숫자 바꾸기 = 효과 Block(동사 함수를 부름). 능력치 보정 = '능력치 보정'. 만들기·없애기·바꾸기 = 규칙 함수(`Spawn`·`Remove` …, 새 id는 `Game.NewId`) + Block. 다른 효과 고치기 = 가로채기 + '의도 고치기'. 고르기 = 선택 대기('선택 요구'). 비용 바꾸기 = `CostIntent` 가로채기 | 표시한 것만 준비 |
| 4 이상한 효과 3개 | 의도 필드·Block 범위 | 관례 13절로 쪼갠다. 쪼갠 부품이 지금 동사·의도 필드·Block으로 다 만들어지는지 보고, 모자란 필드·Block을 시스템층에서 미리 만든다 | — |

## 3. 비었을 때의 추천값

장르별 기본은 가이드 7장 1절 표(Undo 방식·판 저장·구역·난수 흐름·더 쓰는 부품)를 따른다. 그 밖의 기본값:

- 고정 틱: 턴제 0, 실시간 30.
- Undo 보관 수 200. 사슬 한도 16.
- 피해 공식: 스탯 → 스킬 계수 → 피해 증폭(합) → 추가 피해, 방어 100/(100+방어), 같은 칸은 더하고 칸끼리는 곱한다.
- 기본 동사(3절이 비었을 때): 피해·회복·죽음·사용(카드·스킬·아이템)·비용·획득(보상). 카드 게임이면 뽑기·버리기, 이동이 있으면 이동.
- 슬롯 1개. 기본 설정 5개: 전체 음량·브금 음량·효과음 음량·언어·전체 화면.
- 대상 Block 기본: 자신·고른 대상, 적이 여럿이면 전체 적·무작위 적, 지니면 발동하는 종류가 있으면 주인공.
- 선택 기능: Steam 켬, 다이얼로그·인벤토리는 6절에 있을 때만, 입력은 실시간일 때.

## 4. 질문 규칙

- **한 번에 모아서, 20개 이하.** 질문마다: 무엇을 정하는지 · 추천값 · 이유 · 답이 없으면 무엇으로 가는지.
- **순서는 바꾸기 비싼 것부터**: 멀티 → 시간(턴제·실시간) → 데이터 구조·한 판의 흐름 → 핵심 동사 → 효과의 폭 → 문법 밖 → 나머지.
- 묻지 않는 것: 이름·수치·화면 배치·개별 콘텐츠(레벨 디자인). 되돌리기 쉬운 것은 정하고 보고한다.
- 추천값으로 가도 되는 질문은 "답이 없으면 추천값으로 진행"이라고 붙인다.
- 같은 것을 두 번 묻지 않는다. 답을 명세서에 적어 두라고 사람에게 권한다(다음 사람·다음 세션이 읽는다).

## 5. 시스템 목록(답을 받은 뒤 한 번 보여 줄 것)

한 페이지로:

1. 데이터: 판(RunState)·프로필(Profile)의 필드, 유닛 클래스.
2. 원본 종류: 클래스·DB 종류·판 데이터 모양, 기능 필드.
3. 핵심 동사: 함수 이름 · 의도(필드) · 이벤트.
4. 진행 흐름: 행동 목록(판 시작 → … → 판 끝), 반복 단위의 행동, 씬 흐름.
5. 프로젝트 고유 기능(유물처럼 DB에서 조립할 종류)과 감시.
6. 재사용 Block: 효과·대상·조건.
7. DB 설정: Bootstrap(Undo·판 저장·Undo 끊는 이벤트·고정 틱·씬 흐름), 설정 항목, Steam.
8. 선택 기능.
9. 밸런스 값·가중치 표 이름.
10. 질문으로 정한 것과 추천값으로 정한 것.

확인을 받으면 관례 16절 순서로 만들고, 끝에 관례 12절대로 보고한다.

## 6. 나중: 레벨 디자인 단계

시스템층이 끝난 뒤 기획자가 효과 문장(카드·스킬·유물 하나하나)을 보내면 관례 0절 순서(DB 조합 → 재사용 Block → `[BindTo]` → 중간층 확장)로 만든다. 문법 밖이면 표시하고 묻는다. 기획 단계에서 모든 기믹을 나열할 필요가 없는 이유는 4절 "효과의 폭"과 핵심 동사마다의 가로채기 자리다.

## 7. 효과를 쪼개는 예(효과 문법)

관례 13절의 "언제 + 누구에게 + 무엇을 + 안전장치"로 쪼갠 예다. 4절의 이상한 효과는 이렇게 쪼개 보고, 마지막 칸의 부품이 시스템층에 있는지 확인한다. 부품 이름은 DB에 보이는 Block 이름이다.

| 효과 | 언제 | 누구에게 | 무엇을 | 시스템층에 있어야 할 것 |
|---|---|---|---|---|
| 받는 피해 −5 | 가로채기(피해 의도) + 대상이 가진 쪽인지 조건 | — | 의도 고치기 `amount` 더하기 −5 | 피해 의도(`targetId`·`amount`) |
| 불 피해 면역 | 가로채기(피해 의도) + `element` 필드 검사 | — | 의도 고치기 막기 | 피해 의도에 `element` 필드 |
| 다음 공격 두 배(한 번) | 상태 효과(지속 = 셀 이벤트 '피해' 1번, 가진 쪽 필드 `sourceId`) | — | 걸려 있는 동안 트리거 가로채기(피해 의도, `sourceId`가 가진 쪽) → 의도 고치기 `amount` 곱하기 2 | 피해 이벤트에 `sourceId`(때린 뒤 세어 끝난다) |
| 대신 맞기 | 가로채기(피해 의도, 대상이 동료) | — | 의도 고치기 `targetId` 값으로 바꾸기(자기 id) | 피해 의도의 `targetId`가 문자열 id |
| 반사(받은 만큼 돌려주기) | 이벤트 받기(피해 이벤트) + 대상이 가진 쪽 | 대상 Block '때린 쪽'(프로젝트, `Use.Context.Event`의 `sourceId`) | 대상에게 효과 → 피해 | 피해 이벤트에 `sourceId`·`amount`. 반사가 반사를 부르면 사슬 한도 16 |

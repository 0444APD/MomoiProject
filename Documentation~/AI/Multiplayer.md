# 멀티플레이에서 처음부터 지킬 것 (AI용)

명세서 0절이 '있음'인 프로젝트에서 읽는다(관례 20절 · 기능 장 40).

구조는 4블록 하나다(매뉴얼 40장 1-1): 화면(클라이언트)은 행동만 보내고, 판정하는 쪽(매칭큐 = 서버, 친구 방 = 방장)이 실행해 바뀐 곳·이벤트를 돌려준다. 게임 코드는 싱글과 같게 짜되 아래를 처음부터 지킨다(나중에 고치면 데이터 구조부터 바뀐다).

- **판정은 행동 안에서만.** 화면·연출 코드는 플레이어 데이터를 바꾸지 않는다(클라이언트에서 바꾸면 어긋난다). 화면은 `Do` 직후 결과를 읽지 않고 바뀐 곳 알림·`SubscribeAfterAction`으로 그린다. 실패는 `GameScreens.Do`가 알림으로 띄운다(멀티 거절도 같다).
- **플레이어마다 칸.** 사람마다 따로인 데이터(핸드·편성·지갑)는 DB › 플레이어 데이터의 '플레이어마다'(`perPlayer`)로 둔다 — 실제 키는 `hand:1`·`hand:2`, 코드·DB Block은 `hand` 그대로 쓴다(행동을 한 플레이어의 몫). 남에게 숨길 것은 '그 사람에게만 보임'(`ownerOnly`). 한 키 안의 일부만 숨길 것(안개 속 유닛·덮인 카드)은 서버 규칙 자리에서 투영 `server.Project` + `HideStatuses`(매뉴얼 40장 1-2). 판(Session) 구역만 된다. 몫은 들어온 뒤에 채운다(`RoomReady`·판 시작 행동). 시스템 행동·서버 쪽 코드는 몫을 적는다(`PlayerDataStore.KeyFor("hand", 번호)`·`KeysOfAllPlayers`) — `Validate` 안의 `hand`는 보낸 사람의 몫, 패시브 효과의 결과는 그 가진 쪽 플레이어의 몫이다. 판에 하나인 것(차례·보드)은 보통 키다. 숨길 이벤트(카드를 뽑음)는 `IOwnedEvent`(주인만 받음), 서버 규칙끼리만 쓰는 이벤트는 `[GameEvent(ServerOnly = true)]`.
- **게임 규칙 등록은 `Bootstrap.RegisterRules` 한 곳.** 행동 처리기·고유 기능 감시·규칙이 받는 이벤트·틱 규칙은 `Client/Bootstrap.cs`의 `RegisterRules`(`GBibleRuntime.SessionCreated`)에서 Rules의 등록 함수를 부른다 — 화면 세션·방장·시험 모드의 서버와 봇·매칭 방·서버 빌드까지 **모든 세션**에 온다. `Started`는 화면 세션에만 오므로 연출 받기 같은 화면 연결만 둔다(매뉴얼 20장 4절).
- **서버 규칙은 서버가 준비될 때 건다.** 서버 객체가 필요한 것만: 친구 방·시험 모드 `GameNet.ServerStarted += server => …`, 매칭큐 `GameNet.RoomStarting += room => …`(투영·`Validate`), 첫 턴은 `GameNet.RoomReady`. 여기서 게임 규칙 등록 함수를 또 부르지 않는다(`RegisterRules`가 이미 불렀다 — 두 번 발동). `Validate`는 차례·주인(남의 유닛을 움직이려 함)을 거절 글로 막는다. 행동의 참조 필드는 서버 데이터의 진짜 객체로 바뀐 뒤 `Validate`에 온다 — 필드를 그대로 읽는다: `server.Validate = (player, action) => action is MoveUnit m && m.unit.owner != player.Id ? "내 유닛이 아닙니다." : null;`(보낸 사이 사라진 대상은 거절 글 "대상이 이미 없습니다.", 안에서 던진 `Game.Fail`도 거절 글). `actorId`는 서버가 보낸 사람 번호로 덮으므로 규칙은 `actorId`를 믿고 쓴다.
- **매칭큐 결과**: 승패를 정한 규칙이 `GameNet.Hub.EndMatch(room, NetMatchResult[])`를 부른다(다음 틱에 점수·전적 저장 후 로비로). 재화·해금·로스터처럼 매치가 끝나도 남는 값은 DB '매칭 계정에 남김'(플레이어마다 데이터) — 방이 열릴 때 계정에서 읽고 매치가 끝나면 계정에 쓴다(40장 1-6). 클라이언트의 프로필에 두지 않는다(조작된다).
- **비동기 대전(고스트)**: 남이 남긴 보드·덱과 겨루는 것은 서버 중개가 아니라 `Ghosts.Store`(40장 1-13) — 받은 글을 행동 필드로 넘긴다.
- **실시간 협동의 움직임**: 내 캐릭터·탄환처럼 매 순간 움직이는 것은 규칙 데이터가 아니라 `NetTransformSync`(entityId를 모든 프로그램에서 같게, owner = 플레이어 번호). 맞힘·피해는 방장의 규칙이 판정한다(클라이언트는 판정 보고 행동, 방장이 확인).
- **친구 방 화면**: 방 만들기·초대·참가 버튼은 `GameNet.CreateRoom`·`InviteToRoom`·`JoinRoom`만 부른다(Steam이 준비되면 Steam 로비, 아니면 직접 접속 — 화면 코드는 같다). 방장이 나가면 판이 끝난다(이어받기 없음) — `GameNet.Closed`에서 메뉴로 돌아간다. **친구 방은 방장 프로그램이 서버라 방장이 모든 데이터를 본다**(Owner 키도 방장 메모리에 있다). 숨길 정보(핸드·안개)가 있는 대전을 친구끼리 하게 하려면 친구 방 대신 매칭큐 서버에서 같은 종류 글자로 줄을 선다(`GameNet.Client.Queue("friend:" + 코드)` — 같은 종류끼리만 묶인다). `EndMatch`는 결과가 있으면 종류와 상관없이 점수를 바꾸므로, 친구 대전(`room.Mode`)은 빈 결과로 닫는다. 어느 쪽인지는 기획 질문이다(명세서 0절).
- **끊김**: 다시 접속은 저절로 된다(`GameNet.AutoReconnect`). 화면은 `GameNet.Reconnecting`에서 '다시 접속하는 중'을 보이고 `Reconnected`에서 거둔다. `Joined`는 처음 한 번만 온다 — 다시 들어온 뒤에도 화면은 바뀐 곳 알림으로 저절로 맞는다.
- **끊긴 채 돌아오지 않는 플레이어**: 다시 접속은 저절로지만 기권은 저절로가 아니다. 차례가 있는 게임은 턴 타이머를 둔다 — 턴을 여는 행동에서 `Game.ScheduleAfter(턴 시간(밸런싱 값), new TurnTimeout { … })`, 턴을 넘기면 `Game.CancelSchedule(id)`. `TurnTimeout`처럼 시스템이 실행하는 프로젝트 행동에는 `[SystemAction]`을 붙인다(클라이언트가 보내면 서버가 거절한다). 시간 초과가 이어지면 기권 → 결과(매칭큐면 `EndMatch`) — 몇 번인지는 기획 질문. 끊김을 바로 알아야 하면 `server.PlayerLeft`(다시 들어오면 `PlayerJoined`) — 행동 밖이라 값은 `server.Session.Do(행동)`으로 바꾼다.
- **되감기 기믹**: 턴 시작 행동에서 `Game.MarkRewind()`, 기믹은 `Game.Rewind`·`RewindKey`·`RewindEntity`(행동 안). 멀티에서 플레이어의 일반 무르기는 없다.
- **주고받는 클래스**: `[Serializable]`(생성 코드), `#if UNITY_EDITOR` 필드를 두지 않는다. 이벤트는 `[GameEvent]` 클래스(구조체 이벤트는 보낼 수 없다).
- **시험**: 단계 1에서 시험 모드로 한 번 돌려 본다 — AI는 플레이 요청(`Logs/MomoiProject/Play.request`)의 첫 단계를 `net test 0.1`로(매뉴얼 38장 2-5 — 이 화면이 같은 프로그램 안 서버의 클라이언트가 되고 메시지가 0.1초 늦게 오간다), 이어서 평소 단계(명령 · 누르기 · 찍기)로 화면이 결과를 기다리는지 본다. 개발자는 컴포넌트 `TestScene`의 `multiplayer` = 시험 모드(`TestNetMode.TestMode`), `latency` 0.1 이상(기본 0.08)으로 같은 것을 켠다. 매칭큐는 `GameNet.StartMatchServer` + 테스트 패널의 매칭 찾기로 로컬에서 끝까지(줄 → 수락 → 방 → `EndMatch` → 로비) 확인한다. **2인 경기를 혼자 끝까지**: 시험 모드에 봇을 둔다(`TestScene`의 `extraClients` · 플레이 요청 `net test 0.1 1`). 봇은 화면 없는 클라이언트라 스스로 두지 않으므로, 봇 차례는 개발 명령으로 보낸다 — `Bootstrap.Started`에서 `session.Debug.Register("멀티", "봇 1: 턴 끝", () => GameNet.ExtraClients[0].Session.Do(new EndTurn()))`. 봇 세션의 `Do`는 봇의 번호로 서버에 가서 `Validate`·차례 검사를 그대로 거친다. 규칙 테스트는 코어에서 `NetServer`·`NetClient`·`MemoryNetwork`(Manual)로 서버 하나·클라이언트 둘을 띄워 단언할 수 있다(`Tests/Editor/NetTests.cs`가 본보기).

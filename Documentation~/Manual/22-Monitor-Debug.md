# 22. 모니터와 디버깅

`MomoiProject → 모니터`는 플레이 중인 세션을 들여다보고 조작하는 창이다. 무엇이 왜 바뀌었는지(통합 기록), 지금 값이 무엇인지(데이터), 도전과제·로그를 테스트로 움직이기, 이벤트 쏘기, 행동 되돌리기, 개발 명령(DB › 개발 › 개발 명령), 게임 시간 조절을 한곳에서 한다.

## 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| 통합 기록(Journal) | 세션에서 일어난 모든 일(행동·이벤트·값 변경·달성·보상·경고)을 한 줄씩 남기는 기록. 줄마다 원인 줄의 번호(`CauseId`)가 있어 "무엇 때문에 일어났는가"를 거슬러 올라갈 수 있다. 이름 그대로 Journal이라고도 쓴다. |
| 행동 | `Game.Do(행동)`으로 실행한 플레이어 입력 하나. Undo 한 단위다. |
| Undo | 마지막 행동을 되돌리는 것. 스냅샷 방식이면 마지막 스냅샷으로 되감는다. |
| Sync | 시스템이 들고 있는 플레이어 데이터의 사본(Mirror)과 지금 값을 비교해 바뀐 곳만 기록하는 동작. 행동 시작·끝, Modify 끝, 매 프레임 끝에 일어난다. |
| 행동 밖 변경 | 행동 안이 아닌 곳(씬 코드·코루틴 …)에서 바뀐 값. 기록에는 남지만 어느 행동의 Undo 단위에도 들어가지 않는다. |
| 이벤트를 쏜다 / 받는다 | 게임 코드·도구가 이벤트를 알리는 것을 "쏜다", 트리거·로그가 그것을 처리하는 것을 "받는다"고 한다. |

## 1. 창 열기와 화면 구성

**한 줄 요약.** 플레이 중에 열면 실시간 값이 보이고(0.25초마다 새로 고침), 플레이 중이 아니면 "플레이 모드에서 실시간 값이 표시됩니다"만 보인다.

### 에디터에서

1. 메뉴 `MomoiProject → 모니터`(우선순위 1). 창 이름 "모니터".
2. **사이드바**: 위에 세션 상태("실행 중"/"대기"), 아래 탭 7개 — **타임라인 · 데이터 · 도전과제 · 로그 · 이벤트 · 행동 · 명령**.
3. **머리**: 탭 이름, 그 아래 세션 정보 한 줄 — "시드 n · 틱 n · n초 · Undo할 수 있는 행동 n · 기록 n/4096"(스냅샷 방식이면 "되감기 스냅샷 n (n초 간격)", 되돌리기 없음이면 "되돌리기 없음"). 필드 규칙의 필수 값이 비어 있으면 "필수 값 비어 있음 n"이 붙는다.
4. **머리 오른쪽**: 게임 시간 조절(**일시정지/재개**, **1프레임**, 배속 **0.25× · 0.5× · 1× · 2× · 4×**)과 **Undo** 버튼.
5. **아래 줄(작업 줄)**: 도전과제·로그·이벤트 탭에서 고른 것을 조작하는 버튼이 오른쪽 아래 같은 자리에 뜬다. 결과는 본문 위에 알림으로 4초 동안 보인다.

### 주의할 점

- 입력 중인 칸이 있으면 화면을 다시 그리지 않는다(입력값이 날아가지 않게).
- 시간 조절은 `GameTime`(Unity `Time.timeScale`)을 바꾼다. 물리·애니메이션·파티클·게임 시계가 함께 멈추거나 빨라진다. 오디오·UI 연출처럼 `unscaledDeltaTime`을 쓰는 것은 영향을 받지 않는다.

## 2. 타임라인 (통합 기록)

**한 줄 요약.** 세션의 모든 기록을 원인별로 묶어 보거나 시간순으로 본다. 한 줄을 고르면 원인과 결과를 오른쪽 "인과 관계"에 따라 보여 준다.

**언제.** "골드가 왜 줄었지?", "이 도전과제는 어떤 이벤트로 달성됐지?"를 거슬러 찾을 때.

### 에디터에서

1. **기록 검색** 칸: 메시지·코드식 문장·키에 글자가 들어간 줄만. 묶어 보기에서는 맞은 줄의 원인 줄도 함께 펼쳐 보인다.
2. **모든 값 ▾**: 플레이어 데이터 하나를 고르면 그 값이 바뀐 기록만 본다.
3. 종류 칩 **행동 · 이벤트 · 데이터 · 스냅샷 · Undo · 도전과제 · 보상 · 시스템 · 경고 · 오류**: 눌러서 보이기/숨기기.
4. **묶어 보기 / 시간순**: 묶어 보기는 원인이 없는 줄(행동·Undo·되감기·시스템)을 한 줄로 두고, 그 때문에 일어난 줄을 아래에 접어 둔다(행동 → 이벤트 → 값 변경 → 달성 → 보상처럼 여러 단계). 접힌 줄 옆에 "하위 12 · 데이터 8 · 이벤트 2 · 보상 1" 같은 요약이 붙는다. 시간순은 최신순으로 평평하게.
5. 줄 왼쪽 ▸/▾를 누르면 펼치기·접기, **Shift+클릭**은 아래 단계까지 모두. 줄을 두 번 누르거나 Enter도 펼치기·접기. **모두 펼치기 / 모두 접기**.
6. **일시정지 / 재개**(본문 오른쪽): 타임라인 새로 고침만 멈춘다(게임은 계속).
7. 줄 오른쪽 "#번호 · 틱 n", 담긴 내용(이벤트·행동·값 사본)이 있으면 **열기**(탐색기, 읽기 전용).
8. 줄을 고르면 오른쪽 **인과 관계**에 뿌리 원인부터 그 줄까지, 그리고 그 줄이 일으킨 줄들이 들여쓰기로 보이고, 목록에서 관련 없는 줄은 흐려진다.
9. 문장은 자연어로 보이고, **Alt**를 누르고 있으면 코드식 문장이 보인다.

### 코드로 쓰는 법

**`session.Journal.Append(종류, 시스템 이름, 메시지)`** — 기록에 직접 한 줄 남긴다. `JournalKind.Warning`·`Error`는 콘솔에도 "[MomoiProject] …"로 나간다.

```csharp
using GBible;

GBibleRuntime.Session.Journal.Append(JournalKind.System, "Quest", "퀘스트 '숲의 정령' 시작");
```

**`using (journal.Cause(id))`** — 이 범위에서 남기는 줄의 원인을 `id` 줄로 잇는다.

```csharp
var journal = GBibleRuntime.Session.Journal;
var root = journal.Append(JournalKind.System, "Quest", "보스 등장 연출");
using (journal.Cause(root.Id))
{
    journal.Append(JournalKind.System, "Quest", "BGM 교체");   // 타임라인에서 '보스 등장 연출' 아래로 묶인다
}
```

**읽기**: `Entries`(오래된 것부터), `Find(id)`, `CauseChain(id)`(뿌리 원인 → 자신), `Consequences(id)`(이 줄이 일으킨 줄), `LastId`, `Count`, `Capacity`, `Appended` 이벤트(줄이 더해질 때).

```csharp
foreach (var entry in GBibleRuntime.Session.Journal.Entries)
    if (entry.Kind == JournalKind.Warning) UnityEngine.Debug.Log(entry.Message);
```

### 상황별 예제

**골드가 왜 줄었는지 찾기.** 모든 값 ▾에서 골드를 고르고 묶어 보기를 켠다. 맨 위 줄(행동)을 펼치면 행동 → 이벤트 → 데이터 변경 순서가 보이고, 데이터 줄을 고르면 인과 관계에 뿌리 행동이 보인다.

**기록 용량 늘리기.** 긴 세션에서 앞부분이 밀려나면 `SessionOptions.JournalCapacity`를 키운다(`20-Setup.md` 3절).

### 주의할 점

- 기록은 고리 버퍼라 용량(기본 4096줄)을 넘으면 가장 오래된 줄부터 사라진다. 원인 줄이 밀려나면 묶어 보기에서 뿌리로 올라온다.

## 3. 데이터

**한 줄 요약.** 지금 세션의 모든 값을 폴더형 탐색기로 본다. 값을 고치면 게임 코드와 같은 통로(`Set`·`Modify`)로 기록된다.

### 에디터에서

맨 위 "데이터" 아래 폴더:

| 폴더 | 내용 |
|---|---|
| 필수 값 비어 있음 (n) | 필드 규칙에서 필수로 정한 값이 빈 곳(빈 동안만 맨 위에 보인다). 값 = "비어 있음". |
| 판 데이터 | 세션 구역 플레이어 데이터. 판 저장에 들어간다. |
| 프로필 데이터 | 메타 구역 플레이어 데이터. 프로필 저장에 들어간다. |
| 로그 | 로그 값(`stat:` 키). |
| 도전과제 달성 | 도전과제마다 참/거짓. 참으로 바꾸면 달성(이유 "모니터에서 직접 달성"), 거짓이면 달성 표시 초기화. |

클래스·리스트 값은 폴더처럼 들어가 안쪽 필드를 본다. 값을 고치면 바로 적용되고 타임라인에 데이터 줄이 남는다. 들어가 있는 폴더는 값이 바뀌어도 유지된다.

### 주의할 점

- 모니터에서 고친 값은 **행동 하나**(행동 탭의 "[개발] 모니터에서 … 고침", 공개 범위 "개발자")로 기록된다. Undo 버튼으로 되돌릴 수 있다. 저장·네트워크로 보내는 행동은 아니다(개발용).

## 4. 도전과제 · 로그 테스트 (시뮬레이션)

**한 줄 요약.** 값을 덮어쓰지 않고 **실제 이벤트를 쏴서** 게임과 같은 경로(행동 → 이벤트 → 로그 → 도전과제 → 보상)로 움직인다. 쏜 이벤트 묶음은 행동 하나로 기록되어 Undo된다.

**언제.** "처치 100회 도전과제"를 실제로 100번 잡지 않고 확인할 때, 보상이 제대로 들어가는지 볼 때.

### 에디터에서 — 도전과제 탭

1. 도전과제가 카드로 보인다: 이름, 트리거 문장, "달성" / "진행 중" 배지, 진행 중이면 진행 막대와 "현재 / 목표".
2. 카드를 누르면 아래 작업 줄에 버튼이 뜬다.
   - **트리거로 달성**(진행 중일 때): 트리거를 따라가 부족한 로그를 이벤트로 채우고, 트리거의 이벤트(값 조건을 맞춘 것)를 쏜다. 모두 행동 하나("[테스트] … — '이름' 트리거 발동"). Undo하면 로그는 돌아가고 달성은 유지된다.
   - **강제 달성**: 조건·이벤트 없이 달성 처리만.
   - **초기화**(달성했을 때): 달성 표시만 지운다(로그는 그대로).
3. 자동으로 못 채우는 트리거는 이유를 알린다: "'사용'은 테스트 이벤트로 재현할 수 없음(게임 코드의 Game.Use)", NOT, 값을 늘려 채울 수 없는 비교, "서로 다른 이벤트를 AND로 묶어 같은 순간을 만들 수 없음", "OR의 어느 갈래도 자동으로 채울 수 없음", 값 조건을 맞출 수 없는 경우("이벤트 탭에서 값을 채워 직접 쏘세요"). 이때는 강제 달성을 쓴다.

### 에디터에서 — 로그 탭

1. 표: 로그 · 범위 · 집계 · 현재 값. 행을 누르면 아래 작업 줄이 뜬다.
2. 왼쪽 숫자 칸 + **직접 수정**: 값만 덮어쓴다(이벤트·다른 로그·도전과제는 반응하지 않고 기록에만 남는다).
3. 오른쪽 숫자 칸 + **이벤트로 더하기**(합계형) / **이벤트로 기록**(최고·최저·마지막 값형): 반영 규칙을 거꾸로 따라가 실제 이벤트를 쏜다. 버튼에 마우스를 올리면 "쏠 이벤트: 적 처치 ×10" 같은 계획이 보인다. 같은 이벤트를 받는 다른 로그·도전과제도 함께 반응한다.
4. 이벤트로 바꿀 수 없으면 이유를 알린다: 반영 규칙이 없음("직접 수정을 쓰세요"), 횟수 규칙은 합계형에서 1~1000 사이 정수 배만, 중첩 필드(`a.b`)는 자동 생성하지 않음, 배수가 0인 규칙.

### 코드로 쓰는 법

**`session.SimulateEvents(이벤트들, 이유)`** — 이벤트 목록을 행동 하나로 쏜다(`ActionRecord`를 돌려준다).

```csharp
using GBible;

[GameEvent("적 처치")]
public class EnemyKilled { public string enemy; public int combo; }

public static class Tests
{
    public static void KillTen(GameSession session)
    {
        var events = new System.Collections.Generic.List<object>();
        for (int i = 0; i < 10; i++) events.Add(new EnemyKilled { enemy = "goblin" });
        session.SimulateEvents(events, "테스트 처치 10회");
    }
}
```

**`session.TrySimulateStat(로그 ID, 양, out 설명, out 오류)`** — 로그 탭의 "이벤트로 더하기"와 같다.

```csharp
if (!session.TrySimulateStat("killsTotal", 100, out var plan, out var error))
    UnityEngine.Debug.LogWarning(error);
```

**`session.TrySimulateAchievement(도전과제 ID, out 오류)`** — 도전과제 탭의 "트리거로 달성"과 같다. 이미 조건을 만족하면 "이미 조건을 만족합니다."

**`EventSimulator.Create(형식, 이름→값)`** — 이벤트 객체를 필드 이름으로 만든다(값은 필드 형식으로 바뀐다).

```csharp
var evt = EventSimulator.Create(typeof(EnemyKilled), new System.Collections.Generic.Dictionary<string, object> { ["enemy"] = "orc", ["combo"] = 3 });
```

### 주의할 점

- 테스트로 쏜 행동은 "개발자에게만 보이는" 행동이다(행동 탭의 공개 범위 "개발자").
- 도전과제 달성·보상은 Undo해도 유지된다(시스템 규칙).

## 5. 이벤트 호출

**한 줄 요약.** 모니터의 **이벤트** 탭은 `[GameEvent]` 이벤트의 값을 채워 직접 쏘는 도구(이벤트 호출)다.

**언제.** 게임 코드가 아직 그 이벤트를 쏘지 않을 때, 특정 값(콤보 50, 보스 태그)으로 반응을 볼 때.

### 에디터에서

1. 왼쪽 목록에 이벤트(표시 이름, 이름순)가 있다. 내 코드의 이벤트와 라이브러리 기본 이벤트가 나온다. 이 이벤트를 받는 코드가 있으면 오른쪽에 "받는 곳 n"이 보인다.
2. 이벤트를 고르면 오른쪽 패널에 그 이벤트 객체 하나가 탐색기로 열린다. 필드 값을 채운다(중첩 클래스·리스트 필드도 같은 화면에서). 키워드가 연결된 필드는 목록에서 고른다.
3. 패널 아래 "반응하는 로그: 처치 수 ← 횟수 · …"로 이 이벤트를 받는 로그를 미리 본다.
4. 아래 작업 줄의 숫자 칸(1~1000)에 횟수를 넣고 **이벤트 호출**을 누른다. 쏠 때마다 사본을 만들어 쏘므로, 이후에 값을 고쳐도 이미 쏜 기록은 바뀌지 않는다. 알림 "적 처치 ×3 쐈습니다".
5. 쏜 이벤트 묶음은 행동 하나("[테스트] … — 모니터 이벤트 호출")라 Undo된다.

### 코드로 쓰는 법

게임 코드에서는 `Game.Events.Publish(이벤트)`로 쏜다. 연출·UI는 `SubscribeAfterAction<T>`로 받는다(성공한 행동의 이벤트만, 행동이 끝난 뒤 쏜 순서대로. 반환값을 `Dispose`하면 그만 받는다. `10-Events.md`). 같은 쏘기를 버튼으로 저장해 두려면 DB › 개발 명령의 **이벤트 쏘기** Block을 쓴다(7절).

```csharp
using GBible;
using UnityEngine;

public sealed class KillPopup : MonoBehaviour
{
    System.IDisposable _sub;

    void OnEnable() => _sub = GBibleRuntime.Game.Events.SubscribeAfterAction<EnemyKilled>(e => Debug.Log($"{e.enemy} 처치!"));
    void OnDisable() => _sub?.Dispose();
}
```

### 주의할 점

- 매개변수 없는 생성자가 없는 이벤트 클래스는 만들 수 없다: "이벤트 '…'에 매개변수 없는 생성자가 없어 테스트로 만들 수 없습니다."
- 이벤트를 받는 쪽에서는 플레이어 데이터를 바꾸지 않는다(연출·UI만). 값 변경은 행동·효과·결과에서.

## 6. 행동 · Undo

**한 줄 요약.** 행동 탭은 `Game.Do`로 실행한 행동 로그, 머리의 **Undo**는 마지막 행동을 되돌린다.

### 에디터에서

1. **행동** 탭: "행동 로그 n개 · Undo할 수 있는 행동 n". 최신순으로 줄마다 상태 배지(**실행** / **Undo됨** / **실패**), 행동 문장(`Describe()`), 공개 범위(공개 / 본인만 / 개발자), "틱 n". 실패한 행동은 마우스를 올리면 오류가 보인다. 줄을 누르면 행동 내용을 탐색기로 본다.
2. 머리의 **Undo**: 행동 방식이면 마지막 행동을, 스냅샷 방식이면 마지막 스냅샷으로 되감는다. 알림 "Undo됨: 행동 이름 · 행동이 바꾼 값은 돌아가고 달성한 도전과제·보상은 유지". 되돌릴 것이 없으면 "되돌릴 행동이 없습니다.", 되돌리기 없음 방식이면 버튼이 꺼진다.

### 코드로 쓰는 법

```csharp
var session = GBibleRuntime.Session;
if (session.UndoCount > 0) session.Undo();   // 성공하면 true
```

### Undo 관련 경고 (타임라인 · 콘솔)

| 경고 | 뜻 | 대처 |
|---|---|---|
| Undo '행동'가 행동 밖에서 바뀐 값을 덮었습니다: 경로들 | 그 행동이 바꾼 곳을 행동 밖(씬 코드·모니터)에서 또 바꿨는데, Undo가 행동 전 값으로 되돌렸다. | 되돌릴 수 있어야 하는 변경은 행동 안에서 한다. |
| '이름'이(가) Modify를 거치지 않고 바뀌었습니다(경로). Undo와 원인 기록에서 빠집니다. | 예전 방식(리플렉션 비교) 데이터를 Modify 밖에서 고쳤다(`DetectUntrackedChanges`가 켜졌을 때). | 행동 안에서 고치거나 `Modify`를 쓴다. 클래스에 `[Serializable]`을 붙여 Mirror 방식으로 바꾼다. |
| '이름'은(는) 예전 방식(리플렉션)으로 비교합니다: 이유 | 그 값 형식에 Mirror 비교 코드가 없다. | 클래스·구조체에 `[Serializable]`, `com.unity.nuget.mono-cecil` 확인. |
| '이름' 값이 큽니다(요소 n개) … | 예전 방식 값이 커서 수정마다 전체 복제·비교한다. | 자주 바뀌는 부분을 별도 키로 나눈다. |

### 주의할 점

- 행동 안에서 다른 행동을 `Do`하면 바깥 행동의 일부로 실행된다(행동 탭에는 둘 다 보이지만 Undo는 바깥 행동 하나).
- 스냅샷 방식에서는 찍은 뒤 아무 일도 없었으면 한 칸 더 뒤로 되감는다.

## 7. 명령

**한 줄 요약.** 개발 명령을 분류별 버튼으로 보여 준다. 마우스를 올리면 설명. 명령은 **DB › 개발 › 개발 명령**에서 결과 Block으로 조립하는 것이 기본이고, 코드가 필요한 것만 `[BindTo]`나 `session.Debug.Register`로 쓴다.

### 에디터에서 — 명령 탭

기본 명령:

| 분류 | 명령 |
|---|---|
| 세션 | **Undo (Undo)**, **이번 판 수치 초기화** |
| 저장 | **프로필 저장**, **프로필 삭제**, **판 저장**, **판 불러오기**, **새 판**(`GBibleRuntime.NewRun`: 이번 판 값을 처음 값으로 + 판 저장 삭제) |
| 시간 | **일시정지 / 재개**, **1프레임 진행**, **배속 0.25**, **배속 1**, **배속 2** |

DB › 개발 명령의 항목이 그 분류(기본 "개발")로 더해지고, 샘플을 켜면 "샘플" 분류(고블린 공격, 오크 공격 ×10, 상자 열기 …)가 더해진다.

**선택 대기 패널** — 플레이어의 답을 기다리는 선택(`Game.Ask`·결과 `선택 요구`, `29-Statuses-Schedules-Choices.md`)이 있으면 명령 탭 **맨 위**에 선택마다 패널이 생긴다. 게임 화면(고르기 창)이 아직 없어도 여기서 고르고 답할 수 있다.

| 부분 | 내용 |
|---|---|
| 제목 | "선택 대기 · (안내 글)"(안내 글이 없으면 선택 id). 오른쪽에 "1개 고르기" / "1~2개 고르기" |
| 후보 버튼 | 후보마다 하나. 글자는 후보 이름(텍스트 표의 `<id>.name`, 없으면 id). 누르면 앞에 ✓가 붙고 다시 누르면 빠진다. 하나만 고르는 선택은 다른 버튼을 누르면 바꿔 고른다 |
| **답하기** | `Game.Answer`와 같다. 행동 "선택: …"(공개)으로 타임라인·행동 탭에 남고 Undo된다. 개수가 틀리면 "1개를 골라야 합니다(고른 것 0개)." 같은 알림이 뜨고 아무것도 바뀌지 않는다 |

기다리는 선택이 여럿이면 패널도 여럿이다(먼저 요구한 것이 위). 답하거나 Undo해서 선택이 바뀌면 패널도 다시 그려진다.

### 에디터에서 — DB › 개발 › 개발 명령 (`DebugCommandData`)

항목 하나 = 명령 탭의 버튼 하나. DB 사이드바 그룹 **개발**에 있다(`21-Editor-Database.md`).

| 칸 | 뜻 |
|---|---|
| 버튼 이름 | 명령 탭에 보이는 이름. 비우면 ID |
| 분류 | 명령 탭에서 묶이는 이름(기본 "개발") |
| 설명 | 버튼에 마우스를 올리면 보이는 글 |
| 결과 | 결과 Block 목록: **플레이어 데이터에 주기 · 이벤트 쏘기 · 로그에 기록 · 대상에게 효과 · 코딩한 결과** 등(`12-Outcomes.md`) |

버튼을 누르면 결과 전체가 **행동 하나**(`DeveloperEditAction`, 타임라인에 "[개발] 버튼 이름")로 실행된다. 게임 행동처럼 기록되고 머리의 Undo로 되돌린다. 결과가 하나도 없고 `[BindTo]`도 없으면 검사가 "결과가 없습니다(무엇을 할지)."를 알린다.

예(카드 던전):

| ID | 버튼 이름 | 결과 |
|---|---|---|
| `goldPlus100` | 골드 +100 | 플레이어 데이터에 주기: run › gold +100 |
| `turnDamage30` | 한 턴 30 피해 | 이벤트 쏘기: `TurnEnded` (turn = 1, damage = 30) — 그 이벤트를 받는 로그·도전과제·트리거가 반응 |
| `killAll` | 적 모두 처치 | 코드(`[BindTo]`, 아래) |

> [!note]- 이벤트 쏘기 Block
> - 칸: **이벤트**(고르기) · **값**(줄마다 필드 경로 = 값) · **횟수**(1 이상).
> - 값은 숫자·글자·참거짓·enum 필드만. 경로 `a.b`로 안쪽 필드도 적는다. 적지 않은 필드는 이벤트 클래스의 기본값이다.
> - 모니터 이벤트 탭(5절)이 손으로 한 번 쏘는 것이라면, 이 Block은 같은 쏘기를 버튼으로 저장해 두는 것이다.
> - 개발 명령 말고 도전과제 보상처럼 종류 제한이 '모두'인 결과 칸에서도 쓸 수 있다(`12-Outcomes.md`).

### 코드로 쓰는 법

**코드가 필요한 명령 — DB 항목 + `[BindTo]`.** 규칙 함수를 거쳐야 하는 명령(예: 적 모두 처치 — 피해 규칙을 거쳐야 처치 이벤트·로그가 게임과 같게 돈다)은 DB 항목을 만들고 그 ID에 `[BindTo]`를 붙인다. 결과 칸은 잠기고 이 함수가 결과가 된다. 실행은 똑같이 행동 하나라 Undo된다(`13-BindTo.md`).

```csharp
using System.Linq;
using GBible;
using GBible.Ids;

public static class DebugCode
{
    [BindTo(GameIds.DebugCommand.KillAll)]
    static void KillAll(TriggerContext c)
    {
        var game = c.Game;
        foreach (var enemy in Rules.LivingEnemies(game).ToArray()) Rules.Damage(game, game.Data().Run.hero, enemy, 9999);
    }
}
```

**`session.Debug.Register(분류, 이름, 동작, 설명)`** — 코드로 직접 버튼을 더한다. 같은 분류·이름이면 덮어쓴다. 보통 `GBibleRuntime.Started`에서 등록한다(`20-Setup.md` 4절). 동작은 그대로 불리므로, 값을 바꾸는 명령은 안에서 `session.Do(행동)`을 불러야 기록·Undo된다(DB 항목은 이것을 저절로 한다).

```csharp
using GBible;
using UnityEngine;

public static class DebugMenu
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
    static void Hook() => GBibleRuntime.Started += session =>
    {
        session.Debug.Register("시간", "배속 4", () => GameTime.SetSpeed(4f));
    };
}
```

**출시 빌드.** `session.Debug.Enabled`가 거짓이면 `Register`는 아무것도 하지 않는다. 런타임이 `Debug.isDebugBuild`로 이 값을 넣으므로, 출시 빌드에서는 DB 항목·코드 등록 모두 버튼이 생기지 않는다. 그래서 개발 명령 코드를 `if (Debug.isDebugBuild)`로 감싸지 않는다. 직접 만든 세션(테스트·서버)은 기본값 참이다.

### 주의할 점

- 명령에서 난 예외는 콘솔에 찍히고 창은 계속 동작한다.
- 명령은 세션마다 등록된다. 플레이를 다시 시작하면 DB 항목과 `Started`에서 다시 등록된다.
- 시드는 모니터 머리에 늘 보이므로 시드를 기록하는 명령은 따로 만들지 않는다. 도전과제를 트리거로 달성하는 것은 도전과제 탭의 **트리거로 달성**(4절)을 쓴다.

## 8. 게임 시간 (`GameTime`)

**한 줄 요약.** 일시정지(이유별로 겹침), 배속, 프레임 넘기기. 모니터 머리의 시간 조절과 명령 탭의 시간 명령이 이것을 쓴다. 게임 시계·난수와 함께 `07-Random-Time.md`에서 자세히 다룬다.

### 코드로 쓰는 법

```csharp
using GBible;

GameTime.Pause("메뉴");          // 이유별로 겹친다
GameTime.Pause("다이얼로그");
GameTime.Resume("메뉴");         // 다이얼로그가 남아 있어 계속 멈춤
bool paused = GameTime.IsPaused; // true
GameTime.Resume("다이얼로그");

GameTime.SetSpeed(0.5f);         // 0.05~16 사이로 잘린다
GameTime.StepFrame();            // 일시정지 중에만, 한 프레임 진행
```

`GameTime.Changed`(상태가 바뀔 때), `PausedBy`(멈춘 이유들), `Speed`, `ResumeAll()`(모든 이유 해제).

### 주의할 점

- 일시정지 중에는 게임 시계가 멈추지만, 프레임 끝의 Sync와 도전과제 확인은 계속된다.
- 다이얼로그 재생기는 기본으로 다이얼로그 동안 "다이얼로그" 이유로 멈춘다(`24-Dialogue.md`).

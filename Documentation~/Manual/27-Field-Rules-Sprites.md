# 27. 필드 규칙과 스프라이트 규격

코드에는 빈 필드만 두고, "이 필드는 어디서 고르는가, 비면 안 되는가, 이 그림은 어떤 크기로 잘라 쓰는가"는 에디터에서 정한다. 그 설정을 담는 것이 **필드 규칙**이고, 그림 크기 쪽은 **스프라이트 규격**이다.

## 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| 필드 규칙(`FieldRuleData`) | 클래스의 필드 하나에 붙는 에디터 설정: 값 출처, 필수, 스프라이트 규격 그룹, 미리보기 규격. 도감 종류지만 사이드바에 숨겨져 있고 클래스 상세에서 정한다. |
| 클래스 상세 | 도감 › 클래스에서 클래스를 누르면(또는 도감 탭 머리의 **필드 연결**) 상세 창에 열리는 화면(`21-Editor-Database.md` 6.2). |
| 스프라이트 규격(`SpritePresetData`) | 출력 크기 하나(가로×세로 픽셀). 예: `icon` 128×128. |
| 규격 그룹(`SpritePresetGroupData`) | 한 용도의 규격 모음. 예: `character` = standingA · standingB · icon. |
| 맞춤 | 원본 그림에서 어디를 중심으로 얼마나 확대해 자를지 정하는 것(중심 · 배율). 원본마다 한 번 정하면 그룹의 모든 규격에 쓰인다. |
| 베이크 | 맞춤대로 잘라 규격 크기의 PNG를 실제로 만드는 것. |
| 예외 촬영 | 특정 규격만 따로 잡은 맞춤. 규격이 바뀌면 '확인 필요'로 표시된다. |

## 1. 필드 규칙

**한 줄 요약.** 필드마다 "필수", "스프라이트 규격 그룹", "미리보기 규격"을 에디터에서 정한다. 키워드 그룹 연결은 이제 코드의 `[Keyword(typeof(그룹))]`로 쓰고, 클래스 상세에서 고르면 저장할 때 그 어트리뷰트를 코드에 써 준다.

**언제.** 아이템의 등급처럼 비면 안 되는 값을 막을 때, 일러 필드를 규격대로 잘라 쓸 때.

### 에디터에서

1. `MomoiProject → 도감` → **클래스** 탭 → 클래스를 누른다(라이브러리·선택 기능의 종류는 그 탭 머리의 **필드 연결**).
2. 필드 줄에서 정한다.
   - **키워드 그룹**(string·string 목록 필드): 값을 누르면 **연결 없음** / 그룹들 / **+ 새 그룹 만들어 연결**. 오른쪽에 "하나 고름" 또는 "여러 개 고름".
   - **스프라이트 규격 그룹** / **미리보기 규격**(`Sprite` 필드): 2절.
   - **필수 (비어 있으면 도감 검증 오류)** 체크.
3. 저장(Ctrl+S). 필드 규칙 에셋이 만들어지거나 바뀐다(키워드 그룹은 코드에 `[Keyword]`).

필드 규칙 에셋의 칸(직접 볼 일은 드물다. `Create → MomoiProject → 필드 규칙`으로도 만들 수 있다):

| 칸 | 뜻 |
|---|---|
| targetType · field | 규칙을 붙일 클래스(전체 이름)와 필드 이름 |
| source | 값 출처: 키워드 / 도감 항목 / 플레이어 데이터 / 자유 입력 |
| dataType | 출처가 '도감 항목'일 때 그 도감 종류 |
| required | 필수 |
| spriteGroup · previewPreset | 스프라이트 규격 그룹 · 미리보기 규격 |

값 출처가 '도감 항목'·'플레이어 데이터'인 예전 규칙은 클래스 상세에 "도감 항목에서 고름" / "플레이어 데이터에서 고름"으로 보인다. 클래스 상세에서 출처를 새로 정하는 칸은 없다. 새로 정할 때는 코드 어트리뷰트를 쓴다(아래).

### 코드로 쓰는 법

필드 규칙 대신 코드 어트리뷰트로 같은 일을 하는 것들(어트리뷰트가 있으면 칸이 바로 그 목록에서 고르는 드롭다운이 된다):

**`[Keyword(typeof(그룹))]`** — 키워드 그룹에서 고르기.

```csharp
using System;
using GBible;

[Serializable]
public class Equipment
{
    [Keyword(typeof(Rarity))] public string rarity = "";
}

[KeywordGroup("등급")]
public static class Rarity
{
    public const string Common = "common";
    public const string Rare = "rare";
}
```

**`[DataRef(typeof(도감 종류))]`** — 도감 항목에서 고르기(ID가 바뀌면 따라간다).

```csharp
[GBible.Data.DataRef(typeof(GBible.Data.InstanceData))] public string dropItem = "";
```

**`[PlayerDataRef]`** — 플레이어 데이터 목록에서 고르기. **`[StatRef]`** — 로그 목록. **`[AchievementRef]`** — 도전과제 목록. **`[EventTypeRef]`** — `[GameEvent]` 이벤트 형식 목록.

```csharp
[GBible.PlayerDataRef] public string targetKey = "";
[GBible.StatRef] public string stat = "";
```

**필수 값의 런타임 감시** — 런타임은 시작할 때 '필수'인 필드 규칙을 모두 플레이어 데이터 저장소에 등록한다(`session.Data.Require(형식, 필드)`). 플레이어 데이터 안의 그 형식 객체에서 필드가 비면 기록에 경고 "필수 값이 비어 있습니다: 이름 › 경로"를 남기고, 채워질 때까지 모니터 › 데이터 맨 위 "필수 값 비어 있음 (n)"에 보인다. 코드에서 직접 더할 수도 있다.

```csharp
using GBible;

GBibleRuntime.Session.Data.Require(typeof(Equipment), nameof(Equipment.rarity));
foreach (var (key, where) in GBibleRuntime.Session.Data.MissingRequired)
    UnityEngine.Debug.Log($"{key} › {where} 비어 있음");
```

### 상황별 예제

**등급 필수.** `Equipment.rarity`에 키워드 그룹 "등급"을 연결하고 필수를 켠다. 도감 › 인스턴스에서 등급을 비운 장비는 검증 오류 "필수 값 'Rarity'(value.rarity)이 비어 있습니다."(이름표는 Unity가 다듬은 필드 이름, 괄호 안은 경로)가 뜨고 빌드가 막힌다. 게임 중에 코드가 빈 등급의 장비를 만들면 모니터에 "필수 값 비어 있음"이 뜬다.

**드롭 아이템 고르기.** `MonsterData.dropItem`에 `[DataRef(typeof(InstanceData))]` → 칸이 인스턴스 목록이 된다. 그 인스턴스를 지우려 하면 "삭제할 수 없습니다"(사용처 목록)로 막힌다.

### 주의할 점

- 필수 검사는 빈 글자·빈 오브젝트 참조·비어 있는 `[SerializeReference]`·빈 목록을 "비었음"으로 본다(숫자 0은 비었음이 아니다).
- 필드 규칙 탭은 숨겨져 있다. 규칙 에셋을 손으로 고치기보다 클래스 상세를 쓴다.
- 검증: 클래스·필드를 찾을 수 없으면 "클래스 '…'를 찾을 수 없습니다.", "'형식'에 '필드' 필드가 없습니다(이름이 바뀌었는지 확인)." — 코드에서 필드 이름을 바꿨으면 규칙도 다시 정한다.

## 2. 스프라이트 규격

**한 줄 요약.** 원본 일러를 필드에 넣는 순간 맞춤 창이 열리고, 중심·배율을 한 번 정하면 그룹의 모든 규격 크기 이미지가 GPU로 만들어진다(베이크). 게임 코드는 `SpriteSpecs.Get(원본, 규격 ID)`로 꺼낸다.

**언제.** 캐릭터 일러 하나에서 스탠딩·초상화·아이콘을 잘라 쓰는 게임, 아이템 아이콘 크기를 프로젝트 단위로 맞출 때. 이미지 크기 관리가 필요 없으면 쓰지 않아도 된다.

### 에디터에서

**1) 그룹과 규격 만들기** — 도감 › **스프라이트 규격** 탭(사이드바 "이미지" 그룹).

1. 머리의 **+ 새 그룹**(또는 맨 위 줄 **+ 그룹**) → "새 규격 그룹" 창의 **그룹 ID**(예: `character`, `itemImages`).
2. 그룹 줄의 **+ 규격** → "'그룹'에 규격 추가" 창: **ID**(예: `icon`, `standingA`), **x (가로 px)**, **y (세로 px)**(8~8192, 기본 256), 왼쪽 체크박스는 종횡비 고정(한쪽을 바꾸면 다른 쪽이 같은 비율로 따라간다) → **추가**.
3. 그룹 줄의 **+ 하위 그룹**, **↗**(새 창), **⋯ → 그룹 편집**(ID 바꾸기·삭제). 규격 줄을 누르면 상세(`group`·`width`·`height`)와 **규격 사용 현황**(베이크된 이미지 수, 예외 촬영 목록과 **맞추기**). 규격·그룹을 끌어 다른 그룹에 놓아 옮긴다.
4. 그룹 아래 "쓰는 필드"에 이 그룹으로 베이크하는 필드가 보인다.
5. 저장(Ctrl+S).

**2) 필드에 연결** — 도감 › 클래스 → 클래스 → `Sprite` 필드 줄의 **스프라이트 규격 그룹**을 고르고(그룹이 없으면 "도감 › 스프라이트 규격에서 그룹을 먼저 만드세요"), **미리보기 규격**(목록·카드에 보일 규격, 기본 "원본 그대로")을 고른다. 저장.

**3) 원본 넣기 → 맞춤 창** — 연결된 스프라이트 필드(도감 상세·인스턴스 탐색기 어디서든)에 원본을 넣으면 "스프라이트 맞춤 · 원본 이름" 창이 열린다.

- 설명: "그룹 이름 그룹 · 규격 n개. 클릭: 중심 · 휠: 배율". 그림 위에 규격마다 색 테두리, 옆에 규격별 미리보기("이름  가로×세로", 예외면 "· 예외", 다시 봐야 하면 "· 확인 필요").
- 클릭 = 중심, 휠 = 배율(1~12, 1 = 규격 비율로 원본에 꽉 차게).
- 위의 **공통** 버튼: 예외가 없는 규격 모두를 함께 맞춘다. 규격 이름 버튼: 그 규격만 따로 잡는다(예외 촬영으로 영구 기록). **예외 해제**: 고른 규격을 공통 맞춤으로 되돌린다.
- **적용 (베이크)** → 콘솔 "[MomoiProject] '원본'을(를) 규격 n개로 베이크했습니다." / **취소**.
- 결과 PNG는 `Assets/MomoiProjectData/Sprites/<그룹>/<규격>/<원본>_<규격>.png`, 맞춤 기록은 `Assets/MomoiProjectData/Resources/MomoiProject/SpriteSpecs.asset`(게임 중에도 읽는다).

**4) 다시 맞추기·다시 베이크**

- 연결된 칸 옆 **맞추기** 버튼, 또는 규격 항목의 **규격 사용 현황 › 맞추기**.
- 규격 크기를 바꾸거나 그룹에 규격을 더하면(저장 뒤) 자동으로 다시 베이크한다. 콘솔 "[MomoiProject] 바뀐 스프라이트 규격으로 n개를 다시 베이크했습니다." 예외 촬영이 걸린 규격이 바뀌면 '확인 필요'가 되고 경고가 남는다(검증 경고 "규격이 바뀌어 예외 촬영을 확인해야 합니다: …").
- 전체 다시 베이크: 메뉴 `MomoiProject → 스프라이트 규격 다시 베이크`.

### 코드로 쓰는 법

**`SpriteSpecs.Get(원본, 규격 ID)`** — 베이크본. 없으면 원본을 돌려준다(그래서 베이크 전에도 화면이 깨지지 않는다).

```csharp
using GBible.Data;
using UnityEngine;

public sealed class ItemIcon : MonoBehaviour
{
    [SerializeField] SpriteRenderer target;

    public void Show(Sprite original) => target.sprite = SpriteSpecs.Get(original, "icon");
}
```

**`GameIds.SpritePreset.X`** — 규격 ID 상수(도감 저장 뒤 생성). 문자열 대신 쓴다.

```csharp
image.sprite = SpriteSpecs.Get(item.icon, GameIds.SpritePreset.Icon);   // using GBible.Ids;   // 'icon' 규격이 있을 때
```

**`SpriteSpecs.Has(원본, 규격 ID)`** — 베이크본이 있는지.

**`SpriteSpecs.ClearCache()`** — 맞춤 기록을 다시 읽게 한다(에디터가 새로 베이크하면 부른다).

### 상황별 예제

**캐릭터 일러 하나로 세 가지.** 그룹 `character`: `standingA` 600×900, `standingB` 400×900, `icon` 128×128. `CharacterInfo.portrait`(Sprite)에 그룹 `character`, 미리보기 `icon`을 연결. 일러를 넣고 얼굴을 클릭해 중심, 휠로 배율을 맞춘 뒤, `icon`만 얼굴에 더 가깝게 예외로 잡고 **적용 (베이크)**. 코드는 `SpriteSpecs.Get(info.portrait, "standingA")`, `SpriteSpecs.Get(info.portrait, "icon")`.

**아이콘 크기를 나중에 바꿈.** `icon`을 128 → 160으로 고치고 저장 → 모든 아이콘이 자동으로 다시 베이크된다. 예외로 잡은 아이콘은 '확인 필요'가 되어 규격 사용 현황에서 **맞추기**로 다시 본다.

### 주의할 점

- 같은 원본은 어디에 쓰든 맞춤이 하나다(원본 기준). 필드마다 다르게 자를 수 없다. 다른 크기가 필요하면 규격을 더한다.
- 규격 ID와 그룹 ID는 같을 수 없다("ID: 그룹 ID와 규격 ID가 같을 수 없습니다.").
- 베이크·맞춤은 작업본을 거치지 않고 바로 에셋에 쓴다. 다만 규격 크기 변경은 도감 저장(Ctrl+S) 뒤에 다시 베이크된다.
- 그룹에 규격이 하나도 없으면 맞춤 창이 "'그룹' 그룹에 규격이 없습니다. 도감 › 스프라이트 규격에서 먼저 만드세요."만 보여 준다.
- 검증: 규격의 그룹이 비면 "그룹이 정해지지 않았습니다.", 크기가 범위를 벗어나면 "크기는 8~8192px 사이여야 합니다."

# 27. 필드 규칙과 스프라이트 틀

코드에는 빈 필드만 두고, "이 필드는 어디서 고르는가, 비면 안 되는가, 이 그림은 어떤 크기로 잘라 쓰는가"는 에디터에서 정한다. 그 설정을 담는 것이 **필드 규칙**이고, 그림 크기 쪽은 **스프라이트 틀**이다.

## 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| 필드 규칙(`FieldRuleData`) | 클래스의 필드 하나에 붙는 에디터 설정: 값 출처, 필수, 스프라이트 틀, 미리보기 크기. DB 종류지만 사이드바에 숨겨져 있고 클래스 상세에서 정한다. |
| 클래스 상세 | DB › 클래스에서 클래스를 누르면(또는 DB 탭 머리의 **필드 연결**) 상세 창에 열리는 화면(`21-Editor-Database.md` 6.2). |
| 스프라이트 틀(`SpriteFrameData`) | 한 용도의 원본을 잘라 둘 크기 목록. 파일 하나 = 틀 하나, 인스펙터의 표에 크기(이름·가로·세로 px)를 적는다. 예: `character` = standing 600×900 · portrait 400×400 · icon 128×128. |
| 크기 | 틀의 표 한 줄(이름 + 가로×세로 픽셀). 이름은 영문 소문자로 시작(예: `icon`, `cardFront`). |
| 맞춤 | 원본 그림에서 어디를 중심으로 얼마나 확대해 자를지 정하는 것(중심 · 배율). 원본마다 한 번 정하면 틀의 모든 크기에 쓰인다. |
| 굽기 | 맞춤대로 잘라 크기마다 PNG를 실제로 만드는 것(틀의 모든 크기를 한꺼번에). |
| 예외 촬영 | 특정 크기만 따로 잡은 맞춤. 그 크기가 바뀌면 '확인 필요'로 표시된다. |

---

## 1. 필드 규칙

**한 줄 요약.** 필드마다 "필수", "스프라이트 틀", "미리보기 크기"를 에디터에서 정한다. 키워드 그룹 연결은 코드의 `[Keyword(typeof(그룹))]`다(AI가 쓰고, 클래스 상세에서는 보기만).

**언제.** 아이템의 등급처럼 비면 안 되는 값을 막을 때, 일러 필드를 틀의 크기대로 잘라 쓸 때.

### 에디터에서

1. `MomoiProject → DB` → **클래스** 탭 → 클래스를 누른다(라이브러리·선택 기능의 종류는 그 탭 머리의 **필드 연결**).
2. 필드 줄에서 정한다.
   - **키워드 그룹**(string·string 목록 필드): 보기만 — 코드의 `[Keyword(typeof(그룹))]`(AI가 쓴다). 오른쪽에 "하나 고름" 또는 "여러 개 고름".
   - **스프라이트 틀** / **미리보기 크기**(`Sprite` 필드): 2절.
   - **필수 (비어 있으면 DB 검증 오류)** 체크.
3. 저장(Ctrl+S). 필드 규칙 에셋이 만들어지거나 바뀐다.

필드 규칙 에셋의 칸(직접 볼 일은 드물다. `Create → MomoiProject → 필드 규칙`으로도 만들 수 있다):

| 칸 | 뜻 |
|---|---|
| targetType · field | 규칙을 붙일 클래스(전체 이름)와 필드 이름 |
| source | 값 출처: 키워드 / DB 항목 / 플레이어 데이터 / 자유 입력 |
| dataType | 출처가 'DB 항목'일 때 그 DB 종류 |
| required | 필수 |
| spriteFrame · previewSize | 스프라이트 틀 · 미리보기 크기(틀의 크기 이름) |

값 출처가 'DB 항목'·'플레이어 데이터'인 예전 규칙은 클래스 상세에 "DB 항목에서 고름" / "플레이어 데이터에서 고름"으로 보인다. 클래스 상세에서 출처를 새로 정하는 칸은 없다. 새로 정할 때는 코드 어트리뷰트를 쓴다(아래).

### 코드로 쓰는 법

필드 규칙 대신 코드 어트리뷰트로 같은 일을 하는 것들(어트리뷰트가 있으면 칸이 바로 그 목록에서 고르는 드롭다운이 된다):

**`[Keyword(typeof(그룹))]`** — 키워드 그룹에서 고르기.

```csharp
using System;
using GBible;

[Serializable]
public class Equipment
{
    [Keyword(typeof(Rarity))] public string rarity = "";
}

[KeywordGroup("등급")]
public static class Rarity
{
    public const string Common = "common";
    public const string Rare = "rare";
}
```

**`[DataRef(typeof(DB 종류))]`** — DB 항목에서 고르기(ID가 바뀌면 따라간다).

```csharp
[GBible.Data.DataRef(typeof(GBible.Data.InstanceData))] public string dropItem = "";
```

**`[PlayerDataRef]`** — 플레이어 데이터 목록에서 고르기. **`[StatRef]`** — 로그 목록. **`[AchievementRef]`** — 도전과제 목록. **`[EventTypeRef]`** — `[GameEvent]` 이벤트 형식 목록.

```csharp
[GBible.PlayerDataRef] public string targetKey = "";
[GBible.StatRef] public string stat = "";
```

**필수 값의 런타임 감시** — 런타임은 시작할 때 '필수'인 필드 규칙을 모두 플레이어 데이터 저장소에 등록한다(`session.Data.Require(형식, 필드)`). 플레이어 데이터 안의 그 형식 객체에서 필드가 비면 기록에 경고 "필수 값이 비어 있습니다: 이름 › 경로"를 남기고, 채워질 때까지 모니터 › 데이터 맨 위 "필수 값 비어 있음 (n)"에 보인다. 코드에서 직접 더할 수도 있다.

```csharp
using GBible;

GBibleRuntime.Session.Data.Require(typeof(Equipment), nameof(Equipment.rarity));
foreach (var (key, where) in GBibleRuntime.Session.Data.MissingRequired)
    UnityEngine.Debug.Log($"{key} › {where} 비어 있음");
```

### 상황별 예제

**등급 필수.** `Equipment.rarity`에 키워드 그룹 "등급"을 연결하고 필수를 켠다. DB › 인스턴스에서 등급을 비운 장비는 검증 오류 "필수 값 'Rarity'(value.rarity)이 비어 있습니다."(이름표는 Unity가 다듬은 필드 이름, 괄호 안은 경로)가 뜨고 빌드가 막힌다. 게임 중에 코드가 빈 등급의 장비를 만들면 모니터에 "필수 값 비어 있음"이 뜬다.

**드롭 아이템 고르기.** `MonsterData.dropItem`에 `[DataRef(typeof(InstanceData))]` → 칸이 인스턴스 목록이 된다. 그 인스턴스를 지우려 하면 "삭제할 수 없습니다"(사용처 목록)로 막힌다.

### 주의할 점

- 필수 검사는 빈 글자·빈 오브젝트 참조·비어 있는 `[SerializeReference]`·빈 목록을 "비었음"으로 본다(숫자 0은 비었음이 아니다).
- 필드 규칙 탭은 숨겨져 있다. 규칙 에셋을 손으로 고치기보다 클래스 상세를 쓴다.
- 검증: 클래스·필드를 찾을 수 없으면 "클래스 '…'를 찾을 수 없습니다.", "'형식'에 '필드' 필드가 없습니다(이름이 바뀌었는지 확인)." — 코드에서 필드 이름을 바꿨으면 규칙도 다시 정한다.

## 2. 스프라이트 틀

**한 줄 요약.** 용도마다 틀 파일 하나에 필요한 크기를 표로 적는다. 원본 일러를 틀에 넣으면 맞춤 창이 열리고, 중심·배율을 한 번 정하면 표의 모든 크기가 한꺼번에 구워진다(GPU로 잘라 PNG). 크기마다 따로 잡을 수도 있다(예외 촬영). 게임 코드는 `SpriteSpecs.Get(원본, 크기 이름)`으로 꺼낸다.

**언제.** 캐릭터 일러 하나에서 스탠딩·초상화·아이콘을 잘라 쓰는 게임, 아이템 아이콘 크기를 프로젝트 단위로 맞출 때. 프로젝트마다 필요한 틀만 만든다(캐릭터만 쓰면 `character` 하나, 배경도 쓰면 `background`를 더). 이미지 크기 관리가 필요 없으면 쓰지 않아도 된다.

### 에디터에서

**1) 틀 만들기** — Project 창(보통 `Assets/Dev` 아래 아무 폴더)에서 우클릭 › **Create › MomoiProject › 스프라이트 틀**. 파일 이름이 ID가 된다(예: `Character` → `character`, 영어로). 인스펙터(전용 화면)에서 채운다.

1. **ID** — **바꾸기**(쓰는 곳도 함께 고침). 파일 이름과 ID가 다르면 "ID를 '…'로" 버튼이 보인다.
2. **크기** 표 — 줄마다 이름 · 가로(px) · **↔**(가로세로 바꾸기) · 세로(px) · **▾**(빠른 크기: 64~2048 정사각형, 1920×1080 등) · **✕**(빼기). **+ 크기 더하기**로 줄을 더한다. 아래에 크기별 비율 미리보기.
   - 칸을 벗어나거나 Enter를 누르면 바로 저장되고, 이 틀로 자른 원본이 바뀐 크기로 다시 구워진다.
   - 크기 이름을 바꾸면 자른 기록·예외 촬영·필드 규칙의 미리보기 크기가 따라간다. 크기를 빼면 그 크기로 구운 이미지는 `MomoiProjectBackups/<시각>-sprites/`로 옮겨진다(지우지 않음).
   - 이름이 틀리거나 겹치거나 크기가 8~8192px 밖이면 표 아래에 빨간 안내가 뜨고, 고칠 때까지 굽지 않는다.
3. 틀 파일은 Dev 폴더 탭(DB 사이드바 'Dev')에도 보인다. DB에 따로 스프라이트 틀 탭은 없다.

**2) 원본 넣기** — 두 길이 있다. 어느 쪽이든 결과는 같다.

- **틀 인스펙터의 원본 넣기**: 칸에 원본 스프라이트(또는 스프라이트로 가져온 텍스처)를 끌어 놓는다. 하나면 맞춤 창이 열리고, 여럿이면 지금 맞춤(처음이면 가운데·배율 1)으로 모두 한꺼번에 굽는다 — 그 뒤 위치를 바꿀 것만 아래 목록의 **맞추기**로 다시 잡는다. **원본 고르기** 칸으로 하나를 골라도 된다. 필드에 연결하기 전에도 미리 잘라 둘 수 있다.
- **틀을 쓰는 스프라이트 필드에 넣기**: AI가 필드 규칙으로 필드에 틀을 연결해 두면(아래 3), 그 필드(DB 상세·인스턴스 탐색기 어디서든)에 원본을 넣는 순간 맞춤 창이 열린다.

**맞춤 창** "스프라이트 맞춤 · 원본 이름"

- 설명: "틀 이름 · 크기 n개. 클릭: 중심 · 휠: 배율 · 크기 단추: 그 크기만 따로 잡기(예외 촬영)". 그림 위에 크기마다 색 테두리, 옆에 크기별 미리보기("이름  가로×세로", 예외면 "· 예외", 다시 봐야 하면 "· 확인 필요").
- 클릭 = 중심, 휠 = 배율(1~12, 1 = 크기 비율로 원본에 꽉 차게).
- **공통** 단추: 예외가 없는 크기 모두를 함께 맞춘다. 크기 이름 단추: 그 크기만 따로 잡는다(예외 촬영으로 영구 기록). **예외 해제**: 고른 크기를 공통 맞춤으로 되돌린다.
- **적용 (모든 크기 굽기)** → 콘솔 "[MomoiProject] '원본'을(를) 틀 character의 크기 n개로 구웠습니다." / **취소**.
- 결과 PNG는 `Assets/MomoiProject/Data/Sprites/<틀>/<크기>/<원본>_<GUID 앞 8자>_<크기>.png`, 맞춤 기록은 `Assets/MomoiProject/Data/Resources/MomoiProject/SpriteSpecs.asset`(게임 중에도 읽는다).

**3) 필드에 연결** — DB › 클래스 → 클래스 → `Sprite` 필드 줄의 **스프라이트 틀**을 고르고, **미리보기 크기**(목록·카드에 보일 크기, 기본 "원본 그대로")를 고른다. 저장. 보통 AI가 한다.

**4) 다시 맞추기·다시 굽기**

- 틀 인스펙터의 **이 틀로 자른 원본** 목록: 원본마다 **맞추기**(맞춤 창) · **원본**(Project 창에서 보기). 표시: "예외 n"(따로 잡은 크기), "확인 필요 n"(크기가 바뀌어 다시 봐야 하는 예외), "구울 것 n"(아직 굽지 않았거나 크기가 바뀐 크기). 위의 **모두 다시 굽기**는 이 틀로 자른 원본을 지금 맞춤 그대로 다시 굽는다.
- 연결된 칸 옆 **맞추기** 버튼으로도 연다.
- 예외 촬영이 걸린 크기가 바뀌면 '확인 필요'가 되고 경고가 남는다(검증 경고 "크기가 바뀌어 예외 촬영을 확인해야 합니다(…): 원본 · 크기").
- 전체 다시 굽기: 메뉴 `MomoiProject → 스프라이트 틀 모두 다시 굽기`.

### 코드로 쓰는 법

**`SpriteSpecs.Get(원본, 크기 이름)`** — 구운 이미지. 없으면 원본을 돌려준다(그래서 굽기 전에도 화면이 깨지지 않는다).

```csharp
using GBible.Data;
using UnityEngine;

public sealed class ItemIcon : MonoBehaviour
{
    [SerializeField] SpriteRenderer target;

    public void Show(Sprite original) => target.sprite = SpriteSpecs.Get(original, "icon");
}
```

**`GameIds.SpriteSize.틀.크기`** — 크기 이름 상수(틀을 저장하면 다시 만들어진다). 문자열 대신 쓴다. 틀 ID 자체는 `GameIds.SpriteFrame.틀`.

```csharp
image.sprite = SpriteSpecs.Get(item.icon, GameIds.SpriteSize.Character.Icon);   // using GBible.Ids;   // 틀 'character'에 크기 'icon'이 있을 때
```

**`SpriteSpecs.Has(원본, 크기 이름)`** — 구운 이미지가 있는지.

**`SpriteSpecs.ClearCache()`** — 맞춤 기록을 다시 읽게 한다(에디터가 새로 구우면 부른다).

### 상황별 예제

**캐릭터 일러 하나로 세 가지.** 틀 `character`의 표: `standing` 600×900, `portrait` 400×400, `icon` 128×128. 일러를 틀 인스펙터의 원본 넣기에 끌어 놓고, 얼굴을 클릭해 중심, 휠로 배율을 맞춘 뒤, `icon` 단추를 눌러 얼굴에 더 가깝게 따로 잡고(예외 촬영) **적용 (모든 크기 굽기)**. 코드는 `SpriteSpecs.Get(info.portrait, GameIds.SpriteSize.Character.Standing)`. 캐릭터가 서른 명이면 일러 서른 장을 한꺼번에 끌어 놓아 모두 구운 뒤, 얼굴 위치가 다른 것만 **맞추기**로 다시 잡는다.

**아이콘 크기를 나중에 바꿈.** 표의 `icon`을 128 → 160으로 고치고 Enter → 이 틀로 자른 원본의 아이콘이 모두 다시 구워진다. 예외로 잡은 아이콘은 '확인 필요'가 되어 목록에서 **맞추기**로 다시 본다.

### 주의할 점

- 같은 원본은 어디에 쓰든 맞춤이 하나이고 틀도 하나다(원본 기준). 다른 틀에 넣으면 그 틀로 옮겨 가고, 예전 틀로 구운 이미지는 백업 폴더로 옮겨진다. 다른 크기가 필요하면 지금 틀의 표에 크기를 더한다.
- 굽기·맞춤·틀의 표는 DB의 작업본을 거치지 않고 바로 에셋에 쓴다(Ctrl+S가 필요 없다).
- 틀에 크기가 하나도 없으면 맞춤 창이 "틀 '…'에 크기가 없습니다. 틀 파일을 골라 인스펙터의 표에 크기를 더하세요."만 보여 준다.
- 검증: 크기가 없으면 경고 "크기가 없습니다. …", 이름이 틀리거나 겹치면 오류, 크기가 범위를 벗어나면 "크기 '…': 8~8192px 사이여야 합니다(…)." 필드 규칙의 미리보기 크기가 그 틀에 없으면 경고.
- 예전 형식(2026-10-07 전, 크기마다 '스프라이트 규격' 파일)이 남아 있으면 에디터를 열 때 그 그룹(지금의 틀)의 표 한 줄로 옮기고, 원래 파일은 `MomoiProjectBackups/<시각>-sprites/`로 옮긴다. 자른 기록·예외 촬영·미리보기 크기는 그대로 이어진다.

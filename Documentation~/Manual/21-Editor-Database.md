# 21. DB 창

`MomoiProject → DB`은 게임 데이터를 만들고 고치는 창이다. 플레이어 데이터·로그·도전과제·액티브 효과·인스턴스 같은 데이터 에셋과, 코드로 정의한 클래스·이벤트·키워드를 한 창에서 본다. AI가 코드와 DB 반영 스크립트로 항목을 만들고, 개발자는 여기서 읽고 값(수치·고르는 값·참조)을 바꾼다(구조 잠금, 3-1).

## 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| DB 종류 | `GameData`를 상속한 ScriptableObject 클래스. 상속하기만 하면 코드 추가 없이 DB에 탭이 생긴다. |
| 항목 | DB 종류의 에셋 하나. **ID로만 식별**한다(표시 이름 필드가 없다). |
| 작업본 | DB에서 고친 내용을 Unity 에셋에 쓰기 전에 모아 두는 메모리 사본. 저장(Ctrl+S)할 때 한 번에 에셋에 쓴다(DB는 코드를 고치지 않는다). |
| 검증 | 끊긴 참조, 빈 필수 값, ID 형식 등을 검사하는 것(`DataValidator`). 오류가 있으면 빌드가 막힌다. |
| 상세 창 | 항목·클래스를 열면 뜨는 창. 탭이 크롬 브라우저처럼 쌓인다. |
| 트리거 · 결과 | "언제(트리거) → 무엇을(결과)" 칸. 로그·도전과제·액티브 효과·사용 기능·상태 효과·패시브 효과가 같은 편집 화면을 쓴다(`CodingSyntax.md` 2-1). |

## 1. 창의 구성

**한 줄 요약.** 왼쪽 사이드바에서 탭을 고르고, 오른쪽 본문의 폴더 목록에서 항목을 눌러 상세 창에서 고친다.

### 에디터에서

1. 메뉴 `MomoiProject → DB`(우선순위 0)을 연다. 창 이름은 "DB".
2. **사이드바**: 맨 위 "MomoiProject" 로고 아래에 그룹별 탭이 있다. 탭 오른쪽 숫자는 항목 수이고, 검증 오류가 있으면 "n · 오류 m"으로 보인다.
3. **머리**: 탭 이름(제목)과 한 줄 설명, 오른쪽에 검색 칸("ID 검색   invalid"), **필드 연결**(연결할 필드가 있는 종류만), **+ 새로 만들기**(탭마다 글자가 다르다).
4. **본문**: 폴더 목록(2절).
5. **사이드바 아래**: 저장 안 된 변경이 있으면 노란 알림 "저장 안 된 변경 n건"과 **저장  Ctrl+S** · **되돌리기** 버튼. 그 아래 검증 상태("검증 통과" / "경고 n건" / "검증 오류 n건 · 빌드가 막힙니다"). `GameData`를 상속하지 않은 ScriptableObject가 프로젝트에 있으면 "등록되지 않은 데이터 타입 n개"(마우스를 올리면 목록)가 보인다. 오류·경고가 있으면 그 알림에 마우스를 올려 목록을 보고, 누르면 목록 창이 열린다(줄을 누르면 그 항목으로 간다). 같은 내용(+ 적용 전 변경)이 파일 `Logs/MomoiProject/DbStatus.txt`에도 쓰인다 — AI가 읽는다(DB 창이 닫혀 있어도 컴파일 뒤·DB가 바뀔 때 다시 쓰인다).

### 코드로 쓰는 법 — DB 종류 만들기

**`GameData` 상속** — 이것만으로 "데이터" 그룹에 탭이 생긴다. 필드만 쓰면 된다.

```csharp
using GBible.Data;

public sealed class MonsterData : GameData
{
    public int hp = 100;
    public int attack = 10;
}
```

**`[Database(표시 이름, Group, Order, IdPrefix, Hidden, Page, DeveloperAuthored, Single, HideWhenEmpty)]`** — 탭 이름·그룹(비우면 "데이터". 기본 종류는 `요소`·`DB`·`개발`)·순서, 새 ID 제안 앞부분(없으면 클래스 이름에서: `MonsterData` → `monster`), 사이드바 숨김, 전용 화면 키, 개발자가 만드는 종류(추가·삭제·ID 바꾸기가 열린다, 3-1 — 레벨 배치 종류만 켠다), 하나만 두는 설정, 비면 탭 숨김(2-1).

```csharp
using GBible.Data;

[Database("몬스터", Group = "전투", Order = 10, IdPrefix = "monster")]
public sealed class MonsterData : GameData
{
    public int hp = 100;
}
```

**`[HideInDatabase]`** — `GameData`를 상속하지만 DB에 보이지 않아야 할 때.

**`[DataRef(typeof(X))]`** — string 필드(또는 `List<string>`)가 다른 DB 항목의 ID임을 표시한다. 칸이 그 종류의 목록에서 고르는 드롭다운이 되고, 검증이 없는 ID를 찾으며, ID를 바꾸면 값도 따라 바뀐다. 가리키는 곳이 있는 항목은 지울 수 없다.

```csharp
using GBible.Data;

[Database("스테이지", Group = "전투")]
public sealed class StageData : GameData
{
    [DataRef(typeof(MonsterData))] public string boss = "";
    [DataRef(typeof(MonsterData))] public System.Collections.Generic.List<string> mobs = new System.Collections.Generic.List<string>();
}
```

**`ValidateData(IValidationContext)`** — 항목 고유의 검증. `context.Error(...)`는 빌드를 막고, `context.Warning(...)`은 표시만 한다.

```csharp
using GBible;
using GBible.Data;

[Database("몬스터", Group = "전투")]
public sealed class MonsterData : GameData
{
    public int hp = 100;
    [DataRef(typeof(InstanceData))] public string dropItem = "";

    public override void ValidateData(IValidationContext context)
    {
        if (hp <= 0) context.Error("hp는 1 이상이어야 합니다.");
        if (string.IsNullOrEmpty(dropItem)) context.Warning("드롭 아이템이 없습니다.");
    }
}
```

### 주의할 점

- 칸의 이름표는 **코드의 변수 이름**이다. `[FieldLabel("설명")]`의 글은 마우스를 올리면 보이는 설명이 된다.
- 추상 클래스·제네릭 정의·테스트 어셈블리의 종류는 DB에 나오지 않는다.

## 2. 폴더 목록 (모든 탭 공용)

**한 줄 요약.** 모든 탭이 같은 모양의 목록을 쓴다: 폴더(중첩) 안에 항목, 한 폴더 안에서 폴더 먼저 → 항목, 각각 이름순.

### 에디터에서

- **폴더 줄**: 버튼을 뺀 아무 곳이나 누르면 접고 펼친다. 마우스를 올린 줄만 밝아지고 도구 버튼이 나타난다.
- **항목 줄**: 누르면 상세 창에서 연다. 오른쪽에 "오류"(검증 오류), "새 항목 · 적용 전" / "변경 · 적용 전"(저장 전 변경) 배지가 붙는다.
- **끌어 놓기**: 항목·폴더를 끌어 다른 폴더 위에 놓으면 그 안으로 옮긴다(놓을 폴더가 분홍으로 밝아진다). 자기 안쪽·지금 폴더에는 놓이지 않는다.
- **폴더 도구**(일반 DB 종류 탭): **+ (종류 이름)** — 그 폴더에 새 항목, **+ 하위 폴더**, **↗**(새 창에서 열기), **⋯** → **이름 바꾸기** / **폴더 지우기**(안의 항목·하위 폴더는 한 단계 위로 옮긴다). 맨 위 폴더 줄(종류 이름 줄)에는 **⋯** 대신 **CSV**가 있다(아래).
- **CSV**: 그 탭의 항목을 CSV로 내보내고 가져온다(구글 시트·엑셀에서 수치를 한꺼번에 고칠 때). 메뉴는 **CSV로 내보내기…** / **CSV 가져오기…**, 인스턴스 탭은 값의 클래스마다 **Card 내보내기…** / **Card 가져오기…**. 한 줄 = 항목 하나(첫 칸 `id`), 칸 = 단순 필드(묶음 필드 안쪽은 `curve.step`, 목록은 번호마다 `entries[0].weight`·`tags[1]`). Block 칸(트리거·조건·결과)은 빠진다. 가져온 것은 작업본(적용 전)으로 들어간다. 없는 id는 잠긴 종류(로직 쪽)면 건너뛰고("없는 id n개는 건너뜀 — 새 항목은 AI가 만든다"), 개발자가 만드는 종류면 새 항목이 된다 — 그래서 로직 쪽 새 항목은 CSV가 아니라 DB 반영 스크립트(3-1)로 만든다. UTF-8이 아닌 파일은 읽지 않고 알린다. 자세히는 `33-Tick-Preview-Csv.md` 2-3·3-2.
- **새 창(↗)**: 그 폴더(그룹)만 보이는 작은 창(`CodexGroupWindow`)을 연다. 여러 개 열 수 있고 Ctrl+S도 된다.

폴더의 뜻은 탭마다 다르다.

| 탭 | 폴더 |
|---|---|
| 클래스 · 이벤트 | 폴더 없음. `Assets/MomoiProject/Code` 안의 것을 이름순 한 목록으로 보인다(코드 폴더 경로는 보이지 않는다, 읽기 전용, 끌어 옮기기 없음). Code 밖의 스크립트는 보이지 않는다. 라이브러리가 기본으로 내는 것은 "자동" 배지가 붙은 묶음. |
| 키워드 | **그룹**. 그룹 안에 하위 그룹을 둔다. |
| 그 밖의 모든 종류 | **정리용**. 게임 동작·디스크 위치와 상관없다. 항목의 폴더는 항목 자신(숨은 칸)에, 빈 폴더 목록은 `ProjectSettings/MomoiProject/CodexFolders.json`에 남는다. |

### 검색

머리의 검색 칸에 글자를 넣으면 ID(키워드는 상수 이름도)에 그 글자가 들어간 항목만 보인다. 폴더 이름이 맞으면 그 안 전체가 보인다. **`invalid`** 를 넣으면 검증 오류가 있는 항목만 보인다(띄어 쓰고 다른 글자와 함께 쓸 수 있다).

### 주의할 점

- 정리용 폴더를 만들고·바꾸고·지우는 것도 저장(Ctrl+S)할 때 적용된다.

## 2-1. 사이드바 — 빈 탭 숨기기 · Dev 폴더 탭

- **빈 탭 숨기기**: 'DB' 그룹의 로직 종류(액티브 효과·상태 효과·패시브 효과·가중치 표·밸런싱 값·화면·인스턴스·프리팹)와 `[Database(HideWhenEmpty = true)]` 종류(도전과제·로그)는 항목이 없으면 탭이 숨는다 — 그 프로젝트가 쓰는 것만 보인다. AI가 항목을 만들면 나타난다. 개발자가 만드는 종류와 지금 연 탭은 비어도 보인다. 바닥의 "빈 탭 N개 숨김 · 보기"로 잠깐 모두 보인다.
- **선택 요소**(상태 효과·패시브 효과·액티브 효과): DB 종류를 GBible이 갖지 않고 프로젝트가 템플릿에서 들인다(AI 문서 Reference 4-1). 들인 클래스가 없으면 탭도, 그 요소의 기본 Block·행동 직전 이벤트·이벤트도 고르는 목록에 보이지 않는다.
- **Dev 폴더 탭**: `Assets/Dev` 바로 아래 폴더 하나 = 'Dev' 그룹의 탭 하나. 탭은 그 폴더 안(하위 포함)의 **모든 에셋**을 보이고, 더 깊은 폴더는 탭 안의 접는 묶음이다. 줄을 누르면 고르기(인스펙터), DB 항목이면 상세 창, '열기'는 씬·프리팹·스크립트를 연다. 정리(옮기기·이름 바꾸기·지우기)는 Project 창에서 한다 — 폴더를 만들거나 옮기면 탭·묶음이 바로 따라 바뀐다.
- **창이 낮을 때**: 탭 목록만 스크롤된다(항목 크기 그대로). 저장·검증 칸은 바닥에 늘 보인다.
- **하나만 두는 설정**(`[Database(Single = true)]` — 화면 설정·Steam): 그 종류가 켜져 있는데 항목이 없으면 에디터가 기본값으로 하나 만든다. 반영 스크립트는 새로 `Add`하지 않고 그 하나를 찾아 `Work`로 고친다(3-1).

## 3. 저장 흐름 (작업본)

**한 줄 요약.** DB에서 한 모든 변경은 작업본에 모아 두었다가 **Ctrl+S** 또는 사이드바의 **저장** 버튼으로 한 번에 에셋에 쓴다.

### 에디터에서

1. 상세 창에서 값을 고치면 바로 작업본에 반영되어 목록에도 보인다(상세 창 아래 "바꾼 값은 바로 반영 · Unity 적용은 저장(Ctrl+S)할 때"). 바뀐 칸은 이름표 색이 바뀐다.
2. 사이드바에 "저장 안 된 변경 n건"이 생긴다. 누르면 변경 목록 창("저장 안 된 변경")이 열리고 **닫기** / **되돌리기** / **저장**을 고른다.
3. **Ctrl+S**(DB·상세·그룹 창에 포커스가 있을 때)는 확인 없이 바로 저장한다. 콘솔에 "[MomoiProject] 저장했습니다: DB 항목 n건, …"이 찍힌다. 저장이 막히거나 일부가 실패해 변경이 남으면 대신 경고 "[MomoiProject] 저장하지 못한 DB 변경이 남아 있습니다 … — Console의 오류를 보고 고친 뒤 다시 저장(Ctrl+S)하세요."가 찍히고, 사이드바의 "저장 안 된 변경 n건"도 그대로 남는다. 단축키는 Unity Shortcuts 관리자의 "MomoiProject/DB 변경 저장 (DB 창)"·"(상세 창)"·"(그룹 창)"으로 바꿀 수 있다.
4. 저장하지 않은 채로 DB 창을 닫거나, 플레이를 시작하거나, Unity를 끄면 "DB에 저장 안 된 변경" 창이 **저장** / **취소** / **되돌리기**를 묻는다. **저장**을 골랐는데 저장이 막히면 "DB 저장 실패" 창이 저장하지 않은 채 **계속**할지 **취소**할지 다시 묻는다(남은 변경은 DB에 그대로 있다 — Unity를 닫으면 사라진다). 도메인 리로드(스크립트 다시 컴파일) 뒤에도 작업본은 남는다.

**저장할 때 일어나는 일**

1. **적용한 뒤의 모습을 먼저 본다.** 두 항목이 같은 ID(대소문자만 달라도)를 쓰게 되거나, 출시 뒤 예전 ID를 다른 항목이 다시 쓰게 되면(4절) **아무것도 적용하지 않는다** — 콘솔 오류 "[MomoiProject] 저장하지 못했습니다 — 아무것도 적용하지 않았고 변경은 그대로 남아 있습니다. …" 아래에 까닭이 항목마다 한 줄씩 보인다("… '(ID)'는 (다른 항목)도 쓰게 됩니다." 등). DB에서 고친 뒤 다시 저장한다.
2. 문제가 없으면 차례로 적용한다: 지운 항목을 휴지통으로 → 작업본의 내용(ID 포함)을 에셋에 → 에셋 파일 이름(서로 바꾸기도 겹치지 않게 두 단계) → 출시 이력·이름 텍스트(`<ID>.name`)·씬 흐름의 플레이어 데이터 키 → 새 항목 에셋(`Assets/MomoiProject/Data/<종류 폴더>/<ID>.asset` — 종류 폴더는 영어(`Ability`·`PlayerData` …)). 하나가 실패하면 그것만 남기고(다음 저장에 이어서 적용) 알린다.
3. 폴더 정리, 그리고 `GameDatabase`·`GameIds.cs` 갱신(`GameIds.cs`는 적용된 항목만으로 만든다. 내용이 바뀌면 Unity가 다시 컴파일하고, 새 상수는 그 뒤에 코드에서 쓸 수 있다 — 20장 7절).

**바로 적용되는 것**(작업본을 거치지 않음): 스프라이트 굽기·맞춤·틀의 크기 표, 프리팹 컴포넌트 수정, 선택 기능 켜고 끄기, 보기 설정·배치 같은 화면 설정, 다이얼로그 그래프·연출 프리셋 창의 편집.

### 주의할 점

- 저장 전 항목('적용 전')은 런타임(`GameDatabase`)과 `GameIds`에 없다. 플레이로 확인하기 전에 저장한다. 빌드에도 저장한 데이터만 들어간다(7절). DB 반영 스크립트가 만든 새 항목은 저절로 적용되지만, 고치기·지우기·ID 바꾸기는 이 저장을 기다린다(3-1).
- **저장(적용)은 Ctrl+Z로 되돌리지 않는다.** 파일 이름·이력·`GameIds`는 Unity의 Undo가 되돌리지 못하므로, 반쯤 되돌아가지 않게 적용한 에셋의 예전 Undo 기록도 지운다. 저장 전 변경은 사이드바의 **되돌리기**로 버린다.

## 3-1. 구조 잠금 · DB 반영 스크립트

**한 줄 요약.** 로직·DB 항목은 AI가 코드와 **DB 반영 스크립트**로 만들고, 개발자는 DB에서 **읽고 값을 바꾼다**. 그래서 DB 창은 기본으로 **구조를 잠근다**(`EditorPolicy`). 개발자가 만드는 종류는 잠그지 않는다(아래).

| 잠김(구조 — AI에게 요청) | 열림(값 — 개발자가 바꾼다) |
|---|---|
| 블록(트리거·조건·결과·효과·대상) 더하기·빼기·바꾸기·순서, 조건식 조립(AND/OR·괄호·NOT) | 문장 안의 값 칸: 숫자 · 고르는 값(enum·키워드) · 참조 드롭다운(보상으로 줄 아이템·걸 상태 효과) |
| 규칙 줄(`TriggerRule`·블록이 든 요소) 더하기·빼기 | 데이터 목록·딕셔너리의 줄(보상 아이템 목록·층마다 적 목록) 더하기·빼기. **데이터 줄**(`[DataRow]` — 가중치 표의 항목 줄·패시브 효과의 보정 줄)은 Block 칸을 품어도 줄 더하기·빼기가 열린다(줄 안의 Block 칸은 잠김) |
| 인스턴스의 기능 필드 붙이기·떼기 | 인스턴스·항목의 값 |
| 로직 쪽 DB 항목 추가·삭제·ID 바꾸기, 키워드 만들기·지우기, 코드를 고쳐야 하는 연결(`[Hide]`·키워드 그룹 연결) | 폴더 정리 · CSV 가져오기 · 스프라이트 틀 · 필수 |

- **개발자가 만드는 종류**(`[Database(…, DeveloperAuthored = true)]` — 다이얼로그·연출 프리셋·장소·스탠딩 프로필·스프라이트 틀, 프로젝트의 레벨 배치 종류)는 추가·삭제·ID 바꾸기가 열리고, **그 에셋 안의 구조도 개발자가 짠다**: Block·조건식·결과 목록·규칙 줄을 더하고 빼고 바꾸는 것이 구조 편집 열기 없이 된다(예: 다이얼로그 그래프의 선택지 줄 `+ 추가`). 그 밖의 종류의 에셋은 위 표대로 잠긴다(`EditorPolicy.CanEditStructureOf(에셋)`).
- 잠긴 종류의 헤더에는 "값을 바꿉니다(추가·삭제·구조는 AI에게)"가 보이고 **+ 새로 만들기**·**삭제**가 없다. 상세 창 제목(ID)은 고칠 수 없다.
- 라이브러리를 고치거나 급할 때: 메뉴 **MomoiProject › 개발 › 구조 편집 열기(라이브러리 개발용)**(이 컴퓨터에만, 기본 꺼짐).

**DB 반영 스크립트**(`[DbSeed("버전")]`, 네임스페이스 `GBible.EditorTools`): AI가 로직 쪽 항목을 만드는 길이다. 예와 쓰는 규칙(이미 있으면 건너뛰기 · 숫자 칸은 덮지 않기 · 밸런싱 값의 표시 이름·메모)은 AI 문서 `ProjectConventions.md` 15절.

- **함수**: `Assets/MomoiProject/Code/Editor`(에디터 어셈블리)의 매개변수 없는 static 함수(아니면 경고 "[DbSeed] '…'는 매개변수 없는 static 함수여야 합니다."). 내용을 바꾸면 버전 글자를 바꾼다(`"1"` → `"2"`) — 기록(`ProjectSettings/MomoiProject/DbSeeds.json`)과 버전이 다른 함수만 돈다.
- **함수 안에서 쓰는 것**(`EditorDatabase.Staging`):
  - `Add(typeof(종류), "id")` → 새 항목(메모리)을 돌려준다. 그 객체의 칸을 채운다. ID가 규칙에 어긋나거나 **어느 종류에서든** 이미 쓰는 ID면(4절) `ArgumentException`을 던진다 — 그래서 먼저 `EditorDatabase.Instance.FindById(id) == null`을 본다(적용 전 항목도 찾는다).
  - `Work(항목)` → **작업본(사본)을 돌려준다.** 돌려받은 객체의 칸을 고친다(넘긴 원본 에셋을 직접 고치지 않는다 — 작업본을 거치지 않아 '적용 전'으로 보이지 않고, 디스크에 남는다는 보장도 없다).
  - `Remove(항목)` 지우기 · `Rename(항목, 새 ID)` ID 바꾸기(가리키는 칸이 함께 바뀐다, 4절).
  - **하나만 두는 설정 종류**(`Single = true` — 화면 설정·Steam)는 에디터가 없으면 하나 만들어 두므로, 새로 `Add`하지 않고 그 종류의 하나를 찾아 `Work`로 고친다: `var one = EditorDatabase.Instance.OfType<ScreenSettingsData>().FirstOrDefault();` → 있으면 `Work(one)`, 없을 때만 `Add`(ID로 찾아 `Add`하면 ID가 다른 둘째가 생긴다).
- **언제 돌고 무엇이 생기나**(차례):
  1. 스크립트 파일을 쓰고 Unity가 그것을 컴파일한다(Unity가 파일 변경을 읽어야 시작된다 — AI는 `Logs/MomoiProject/RunTests.request`로 새로 읽기를 부른다, 38장 2-4). 컴파일 오류가 하나라도 있으면 새 함수가 읽히지 않아 돌지 않는다.
  2. 에디터가 한가해지면(컴파일·가져오기·플레이 중이 아닐 때) 돌 차례인 함수를 이름순으로 돌린다. 시작 설정 전(DB 에셋이 없을 때)에는 돌지 않는다. 에디터를 열 때도 같은 검사를 한다.
  3. **새 항목은 저절로 적용된다** — 에셋 파일이 생기고 `GameDatabase`가 맞춰지며 콘솔·DB 창에 "[MomoiProject] DB 반영 스크립트가 만든 새 항목 n개를 적용했습니다: …"가 뜬다. ID가 겹치는 등으로 적용하지 못한 새 항목은 '적용 전'으로 남는다.
  4. 적용된 새 항목으로 `GameIds.cs`가 다시 쓰이고 Unity가 한 번 더 컴파일한다. **그 상수를 쓰는 코드는 이 뒤에 쓴다**(`GameIds.cs`에 상수가 생긴 것을 파일로 확인한다 — 먼저 쓰면 컴파일 오류로 1단계가 막힌다, 20장 7절).
  5. **이미 있는 항목을 고치거나 지우거나 ID를 바꾼 것은 '적용 전'으로 남는다**(콘솔 "'적용 전'으로 남은 것(고치기·지우기 n개, 새 항목 n개)을 DB에서 보고 Ctrl+S로 적용하세요."). 개발자가 읽어 본 뒤 Ctrl+S로 적용해야 런타임·`GameIds`에 들어간다.
- **기록**: 남은 '적용 전' 변경이 없으면 바로 "이 버전은 돌았다"로 기록한다. 남았으면 Ctrl+S로 적용할 때 기록하고, 버리면(되돌리기) 다음 컴파일 뒤 다시 돈다. 함수가 예외를 던지면 오류 "[MomoiProject] DB 반영 스크립트 '…'(버전 n)가 실패했습니다: …"를 남기고 기록하지 않는다(다음 컴파일 뒤 다시 돈다). 던지기 전에 `Add`한 새 항목은 그대로 적용되므로, 다시 돌 때 '이미 있으면 건너뛰기'로 이어 간다.
- **메뉴**: **MomoiProject › 개발 › DB 반영 스크립트 — 새 항목은 바로 적용**(체크, 기본 켬)을 끄면 새 항목도 '적용 전'으로 둔다(`ProjectSettings/MomoiProject/DbSeedOptions.json`). **MomoiProject › 개발 › DB 반영 스크립트 모두 다시 돌리기**는 기록과 상관없이 모두 돌린다(이미 있으면 건너뛰는 스크립트라 안전하다).

## 4. 항목 만들기·이름(ID) 바꾸기·지우기

**한 줄 요약.** 이름(ID)은 만들 때 한 번 짓고, 이후 모든 곳에서는 목록에서 고른다. ID를 바꾸면 가리키는 곳이 모두 따라간다. **로직 쪽 종류는 구조 잠금(3-1) 때문에 이 절의 버튼이 보이지 않는다** — 개발자가 만드는 종류와 구조 편집을 열었을 때만.

### 에디터에서

**만들기**

1. 머리의 **+ 새로 만들기** 또는 폴더 줄의 **+ (종류 이름)** 을 누른다.
2. "새 (종류 이름)" 창의 **ID** 칸에 제안된 ID(접두어 + 번호, 예: `stat3`)를 고친다. 설명: "ID는 저장 파일·코드(GameIds)·조건이 함께 쓰는 식별자입니다. 나중에 바꿔도 참조가 모두 따라갑니다."
3. **만들기** → 상세 창이 열린다.

ID 규칙(`IdRules`): 영문 소문자로 시작, 영문·숫자만, 단어 사이는 대문자(lowerCamelCase), 분류는 점(.)으로. 64자 이하. **ID는 모든 종류를 통틀어 하나다**(퀘스트 `fireball`과 액티브 효과 `fireball`은 함께 있을 수 없다 — "'…'는 이미 '…'(종류)이(가) 쓰고 있습니다."). 대소문자만 다른 ID도 같은 ID로 본다. 같은 종류 안에서 점(.)·대문자 자리만 달라 생성 코드 이름이 같아지는 ID도 쓸 수 없다(`bossDragon`·`boss.dragon` → 둘 다 `GameIds`의 `BossDragon`). 예: `playerGold`, `player.inventory`, `ability.fireball`.

**ID 바꾸기**: 상세 창 제목(ID)을 눌러 고친다. 이 ID를 가리키는 참조 칸(`[DataRef]`·플레이어 데이터 키 칸 …)의 작업본이 함께 바뀌어 DB가 바로 새 ID로 보이고, 콘솔에 "ID를 …(으)로 바꿨습니다(참조 n곳 함께, 저장(Ctrl+S)할 때 적용)."이 찍힌다. **적용은 저장할 때**다: 에셋 파일 이름·`GameIds`·이름 텍스트(`<ID>.name`, 모든 언어 표)·씬 흐름의 플레이어 데이터 키가 함께 바뀐다. 저장할 때 참조를 다시 훑지 않으므로 서로 바꾸기(a ↔ b)도, 비운 ID를 다른 항목이 다시 쓰기도 그대로 맞다.

- **같은 ID를 쓰는 항목이 또 있으면**(Project 창에서 복제한 에셋) 참조는 옮기지 않는다. 어느 쪽을 가리키던 것인지 알 수 없어 남은 항목을 그대로 가리킨다(콘솔 "…참조는 옮기지 않았습니다 — 그 칸들은 남은 항목을 그대로 가리킵니다."). 바꾼 항목을 가리켜야 하는 칸은 다시 고른다.
- **출시 뒤**(`MomoiProject → 개발 → 출시됨 (저장 호환 유지)`)면 저장할 때 이름 바꾸기 이력이 남아 예전 이름으로 저장된 값을 이어받는다. 그래서 이력의 예전 ID와, 이번 저장에서 바꾸는 중인 항목의 예전 ID는 다른 항목이 쓸 수 없다(예전 저장의 그 ID가 불러올 때마다 바꾼 항목으로 이어지기 때문이다). 같은 항목이 예전 이름으로 돌아가는 것은 된다.

**지우기**: 상세 창 아래 **삭제** → 확인 창 "항목 삭제". 저장하면 에셋이 휴지통으로 간다. 어딘가에서 가리키고 있으면 "삭제할 수 없습니다" 창이 사용처(최대 10곳)를 보여 준다. 프리팹 항목은 DB에서 지우지 않는다(아래 6.9).

### 주의할 점

- 에셋을 프로젝트 창에서 복제하면 같은 ID가 둘이 된다. 검증 오류 "ID '…'가 n개 항목에서 중복됩니다(복제한 에셋일 수 있음). 하나를 'ID 바꾸기'로 고치세요 — …"가 뜬다. 바꾼 쪽을 가리켜야 하는 칸은 다시 고른다(위).
- `Create` 메뉴로 만든 에셋처럼 ID가 없는 항목은 저절로 ID가 붙는다(파일 이름을 ID로 쓸 수 있으면 그것, 아니면 접두어 + 번호).

## 5. 상세 창

**한 줄 요약.** 항목·클래스를 열면 뜨는 창. 메뉴는 없고 DB에서 열 때만 뜬다(도킹 가능).

### 에디터에서

- **탭**: 항목이 탭으로 쌓인다. 이미 열린 항목은 그 탭으로 간다. 항목 안의 클래스·배열·리스트 값을 누르면 바로 오른쪽에 안쪽 탭이 열리고(탭 앞에 › 표시), 탭을 닫으면(✕ 또는 가운데 버튼) 안쪽 탭도 함께 닫힌다.
- **머리**: 제목 = ID(눌러서 바꾸기), 부제 = 종류 이름(새 항목이면 "새 항목(적용 전)"). 도전과제·액티브 효과·로그는 제목 아래에 요약 줄이 붙는다(도전과제·액티브 효과: "트리거"·"결과", 로그: "방식"·"반영"). `[BindTo]`로 코드 결과가 연결된 항목은 결과가 "코드: 클래스·함수 이름"으로 보이고, 로그는 "결과" 줄이 더해진다("… (로그에 기록 대신)"). 자세히는 `13-BindTo.md`.
- **본문**: 칸마다 이름표(변수 이름) + 값. 검증 문제는 위에 알림으로, 문구에 필드 이름이 들어 있으면 그 칸도 빨간 이름표·밑줄로 보인다.
- **아래 줄**: 상태 글, **에셋 위치**(프로젝트 창에서 원본 에셋을 깜빡임), **삭제**(프리팹은 **프로젝트에서 보기**).
- 트리거·조건 칸은 한 줄 식 편집기(`+ 블럭` · `+ 논리 연산자` · `+ 괄호`), 결과 칸은 `+ 결과 추가`로 고친다. 문장은 자연어로 보이고 **Alt**를 누르고 있으면 코드식으로 보인다.
- `[ShowIf]` 칸은 형제 칸의 값에 따라 보이고 숨는다 — 상세 창 맨 위 칸, **묶음 필드**(곡선·지속 설정·설정 값처럼 칸 여러 개를 묶은 클래스 값) 안, 목록의 줄, 블록 안쪽 칸, 조건식 블럭, 값 탐색기 모두 같다. 조건 칸 자신이 숨어 있으면 그에 딸린 칸도 숨는다. 값을 바꾸면 바로 바뀐다(예: 곡선의 방식을 `표`로 바꾸면 시작 단계·더할 값 대신 점이 보이고, `최솟값으로 자르기`를 켜면 최솟값 칸이 나온다). `[ShowIf]`는 값을 여러 개 받는다: `[ShowIf(nameof(kind), CurveKind.Linear, CurveKind.Power)]` = 둘 중 하나일 때(`04-Instances.md` 2.4).
- 사이드바 머리의 **필드 연결**은 그 종류의 클래스 상세(아래 6.2)를 상세 창에 연다.

### 주의할 점

- 상세 창의 값은 작업본이다. 저장(Ctrl+S) 전에 플레이하면 반영되지 않는다(시작할 때 묻는다).

## 6. 탭별 설명

### 6.1 키워드

**한 줄 요약.** 등급·부위·태그처럼 "고르는 값"의 모음. 코드의 `[KeywordGroup] static class`가 원본이고(AI가 쓴다), 이 탭은 그 코드를 읽기만 한다.

**언제.** 아이템 등급, 장비 부위, 몬스터 태그처럼 정해진 값 중에서 고르는 string 필드가 필요할 때. enum은 저장값이 숫자라 쓰지 않는다.

**에디터에서**

1. 그룹 = 폴더(하위 그룹은 안쪽), 키워드 = 줄(왼쪽 ID, 오른쪽 코드 상수 이름). 그룹 줄의 **cs 열기**는 그룹 코드 파일을 연다. 만들기·이름 바꾸기·지우기 버튼은 없다 — 키워드가 더 필요하면 AI에게(새 그룹은 `Assets/MomoiProject/Code/Rules/Keywords/그룹이름.cs` — 규칙 어셈블리 안).
2. 그룹 아래 "연결된 필드"에 이 그룹을 쓰는 필드(`클래스.필드`)가 칩으로 보인다. 누르면 그 클래스 상세로 간다.

**코드로 쓰는 법**

`[KeywordGroup("표시 이름")]`을 static class에, 키워드는 `const string`으로.

```csharp
using GBible;

[KeywordGroup("등급")]
public static class Rarity
{
    public const string Common = "common";
    public const string Rare = "rare";
    public const string Legendary = "legendary";
}
```

하위 그룹은 안쪽 static class에 `[KeywordGroup]`.

```csharp
[KeywordGroup("장비 태그")]
public static class EquipTag
{
    [KeywordGroup("속성")]
    public static class Element
    {
        public const string Fire = "fire";
        public const string Ice = "ice";
    }
}
```

필드 연결은 `[Keyword(typeof(그룹))]`. `string` 필드는 하나, `string` 리스트·배열은 여러 개를 고른다.

```csharp
using System;
using System.Collections.Generic;
using GBible;

[Serializable]
public class Item
{
    public string id;
    [Keyword(typeof(Rarity))] public string rarity = "";
    [Keyword(typeof(EquipTag.Element))] public List<string> elements = new List<string>();
}
```

게임 코드는 상수로 비교한다: `if (item.rarity == Rarity.Legendary) …`

**주의할 점**

- 키워드 ID(상수 값)는 모든 그룹을 통틀어 겹치지 않게 짓는다.
- 그룹 클래스를 지우거나 이름을 바꾸면 그 그룹을 쓰는 필드의 `[Keyword(typeof(…))]`가 컴파일 오류를 낸다. 쓰는 곳은 그룹 아래 "연결된 필드"에 보인다 — 함께 고친다.
- 검증: 키워드 필드의 값이 그 그룹에 없으면 "필드: 값은(는) 키워드 그룹 이름에 없는 키워드입니다. 목록에서 다시 고르거나, 필요한 키워드면 코드에 더하세요(AI에게)."
- 문장 속 용어(`[[rare]]`)의 색·아이콘은 다국어 설정의 `termStyles`에서 정한다(`23-Text-Localization.md`).

### 6.2 클래스 (읽기 전용)

**한 줄 요약.** `Assets/MomoiProject/Code` 안에서 코드로 정의한 `[Serializable]` 클래스와 프로젝트의 DB 종류를 이름순 한 목록으로 본다(2절 표). 만들고 고치는 것은 코드에서 한다.

**에디터에서**

1. 목록에서 클래스를 누르면 상세 창에 **클래스 상세**가 열린다. 줄에는 이름·표시 이름·필드 수, DB 종류면 "DB 종류" 배지.
2. 클래스 상세 머리: 이름, 종류 배지, 전체 이름, "폴더: …", **cs 열기**, **프로젝트 창**, DB 종류면 **DB 탭 열기**.
3. **필드** 목록: 필드마다 이름·형식(`[FieldLabel]` 설명), 상속받은 필드는 "상속: 부모" 배지. 형식이 다른 클래스(또는 그 리스트·배열·딕셔너리)면 **→ 클래스이름** 버튼으로 바로 이동.
4. 필드마다 코드에서 정한 것(보기만):
   - **키워드 그룹**: string·string 목록 필드. 코드의 `[Keyword(typeof(그룹))]`(연결 없음 · 그룹 이름).
   - `[Hide]`(데이터 클래스): "DB › 인스턴스에서 보이지 않는 필드입니다 … [Hide]" 글. `[ShowIf]`가 있으면 조건이 글로 보인다. 기능 필드면 "기능 필드: 비어 있으면 그 기능이 없습니다. 인스턴스에서 '+ 기능'으로 붙입니다."
5. 필드마다 정하는 에디터 설정(저장할 때 적용):
   - **스프라이트 틀** / **미리보기 크기**: `Sprite` 필드(`27-Field-Rules-Sprites.md`).
   - **필수 (비어 있으면 DB 검증 오류)** 체크.

**코드로 쓰는 법**

클래스 탭에 나오는 조건: 내 코드(8절 — 기본은 Unity·패키지·이 라이브러리·Plugins 제외)의 `[Serializable]` 클래스 가운데 `Assets/MomoiProject/Code` 안의 것. 컴포넌트·행동·조건·결과 Block·이벤트는 빠진다.

```csharp
using System;

[Serializable]
public class Unit
{
    public string id;
    public int hp;
    public int x, y;
}
```

**주의할 점**

- 이 탭에서 클래스를 만들거나 필드를 더하거나 이름을 바꾸는 기능은 없다.
- 라이브러리·선택 기능의 클래스는 목록에 없다. 그 종류의 탭 머리 **필드 연결**로 클래스 상세를 연다(잠김 "시스템" 배지).

### 6.3 로그

**한 줄 요약.** 이벤트를 받아 숫자를 자동으로 모으는 기록(처치 수·획득 골드 총합·최고 콤보). 코드 형식 이름은 `StatData`.

**에디터에서**

1. 항목은 AI가 DB 반영 스크립트로 만든다(`Staging.Add(typeof(StatData), "killsTotal")`, 3-1).
2. 상세 칸: **scope**(범위: 이번 판 / 누적), **aggregate**(집계 방식: 합계·최고치·최저치·마지막 값), **triggers**(반영 규칙). 규칙마다 트리거는 "이벤트 받기"(+ 이벤트 값 조건)만, 결과는 "로그에 기록" 하나로 고정되어 반영할 값(이벤트의 숫자 필드, 비우면 횟수 1)과 배수만 고친다.
3. 요약 줄: "방식"(이번 판/누적 · 집계), "반영"(규칙 문장).

**코드로 쓰는 법** — 게임 코드는 이벤트만 쏜다. 로그가 받는다.

```csharp
using GBible;

[GameEvent("적 처치")]
public class EnemyKilled { public string enemy; public int combo; }

// 행동·효과 안에서
// Game.Events.Publish(new EnemyKilled { enemy = "goblin", combo = 3 });
```

읽기: `session.Stats.Get("killsTotal")`. 결과를 코드로 바꾸려면 `[BindTo("killsTotal")]`(그 칸은 잠기고 보기·cs 열기만).

**주의할 점** — 검증: 반영할 값이 트리거의 이벤트에 없으면 "로그에 기록의 반영할 값 '…'을 읽을 이벤트가 트리거에 없습니다(비우면 횟수 1)."

### 6.4 이벤트 (읽기 전용)

**한 줄 요약.** `[GameEvent]` 클래스 목록. 클래스 탭과 같은 모양(이름순 한 목록 + "자동" 묶음)이다. 코드에서 만든다.

**에디터에서** — 누르면 클래스 상세(필드 목록). 라이브러리 기본 이벤트(`AchievementUnlocked`·`AbilityUsed` 등)는 "자동" 배지 묶음에 보인다. 에디터에서 이벤트를 쏘는 곳은 모니터(플레이 중)의 **이벤트** 탭이다(`22-Monitor-Debug.md`).

**코드로 쓰는 법**

```csharp
using GBible;

[GameEvent("골드 획득")]
public class GoldEarned { public int amount; }
```

### 6.5 플레이어 데이터

**한 줄 요약.** 저장소에 담을 값 하나(골드·인벤토리·유닛 목록 …)의 ID·구역·값 형식을 정한다. 게임이 켜질 때 자동으로 등록된다.

**에디터에서**

1. 항목은 시작 설정(`run`·`profile`)이나 AI의 DB 반영 스크립트(`Staging.Add(typeof(PlayerDataEntry), "player.gold")`, 3-1)가 만든다.
2. **zone**(구역): `Session`(이번 판, 새 판에서 처음 값) / `Meta`(프로필, 판이 바뀌어도 유지).
3. **valueType**(값 형식): 숫자·글자·참거짓·enum 같은 단순 값, 또는 프로젝트의 클래스·리스트·딕셔너리. 목록에는 내 코드와 켜진 선택 기능의 데이터 클래스만 나온다.
4. **defaultValue**(기본값): 단순 값만(예: `100`, `true`). 클래스·컬렉션은 클래스의 초기값(필드 초기화·생성자)을 쓴다.

**코드로 쓰는 법** — `GameIds.PlayerData.X`(`PlayerDataKey<T>`) 또는 `Game.Data().X`(`20-Setup.md` 7절).

**주의할 점** — 검증: "값 형식이 선택되지 않았습니다.", "담을 수 없는 필드: …", "기본값 '…'을(를) …(으)로 읽을 수 없습니다.", 경고 "클래스·컬렉션 형식은 기본값 글자를 쓰지 않습니다", "비교 코드로 다룰 수 없어 예전 방식(리플렉션, 더 느림)으로 비교합니다: 이유".

### 6.6 도전과제

**한 줄 요약.** 트리거가 참이 되는 순간 달성하고 결과(보상)를 준다. 달성·보상은 Undo로 되돌리지 않는다.

**에디터에서** — 칸: **icon**, **trigger**(이벤트 받기 · 조건 충족, AND·OR·NOT·괄호로 중첩), **outcomes**(플레이어 데이터에 주기 · 대상에게 효과 · 코딩한 결과 · 다이얼로그 재생 등). 요약 줄 "트리거"·"결과".

**주의할 점** — 검증: 서로를 조건으로 보는 도전과제는 "도전과제 순환 참조: A → B → A" 오류. 트리거가 없으면 런타임 기록에 "트리거가 없어 달성될 수 없습니다." 경고.

### 6.7 액티브 효과

**한 줄 요약.** `Game.Use(액티브 효과 ID, 사용자, 대상들)`로 쓰는 효과 묶음(스킬·아이템 사용 효과·버프 발동).

**에디터에서** — **trigger**(기본 "사용", AND로 사용 조건을 더한다. 쿨다운은 조건 `상태 효과 검사`), **outcomes**(대상에게 효과 · 플레이어 데이터에 주기 · 코딩한 결과), **failText**(쓸 수 없을 때 글), **icon**(아이콘, 스킬 버튼 그림 — 화면 코드가 읽는다). 요약 줄 "트리거"(없으면 "사용할 때")·"결과".

### 6.8 인스턴스

**한 줄 요약.** 코드로 정의한 클래스의 원본 하나(몬스터 A, 아이템 A …). 게임은 원본의 깊은 사본을 쓴다(`session.CopyInstance(id)`).

**에디터에서**

1. 항목은 AI가 DB 반영 스크립트로 만든다(3-1). ID는 lowerCamelCase 이름 하나다(`potion`, `ironSword` — 종류 접두어 `instance.`를 붙이지 않는다. 접두어 `instance`는 DB 창이 제안하는 번호 ID `instance1`에만 쓰인다). DB ID는 모든 종류를 통틀어 하나이므로, 같은 대상에 딸린 다른 종류의 항목(그 아이템의 패시브 효과 등)은 `potion.fx`처럼 대표 ID 뒤에 갈래를 붙인다(AI 문서 `NamingGuide.md`). 레벨 배치처럼 개발자가 늘리고 줄일 데이터는 인스턴스가 아니라 `DeveloperAuthored` 종류로 둔다(관례 18절).
2. **instanceType**(형식)을 고르면 그 클래스의 빈 객체가 **value**(값)에 만들어진다. 값을 채운다.
3. 필드 보이기: 클래스의 `[Hide]`는 항상 숨김, `[ShowIf(필드[, 값…])]`은 조건부(값을 여러 개 적으면 그중 하나일 때).
4. 기능 필드(비어 있을 수 있는 `[SerializeReference]` 클래스 필드)는 비어 있으면 **+ 기능**으로 붙이고, 붙어 있으면 줄의 빼기로 뗀다 — 구조라 잠겨 있다(AI가 반영 스크립트로, 3-1). 개발자는 붙은 기능 안의 값을 바꾼다.

**코드로 쓰는 법**

```csharp
using System;
using GBible;
using UnityEngine;

[Serializable]
public class Item
{
    public string id;
    public int price;
    [Hide] public int internalVersion;
    [SerializeReference] public Usable usable;           // 기능 필드: null = 쓸 수 없는 아이템
    [ShowIf(nameof(usable))] public int charges = 1;      // usable이 붙어 있을 때만 보인다
}
```

**주의할 점** — 검증: "형식이 선택되지 않았습니다.", "값이 비어 있습니다. 형식을 다시 고르면 새로 만들어집니다.", "값의 형식(…)이 고른 형식(…)과 다릅니다."

### 6.9 프리팹

**한 줄 요약.** 프리팹을 DB에 등록해 컴포넌트 필드를 탐색기로 보고 고친다.

**에디터에서** — **prefab** 칸에 프리팹을 넣는다. 컴포넌트 수정은 바로 적용된다(작업본을 거치지 않음). DB에서 지우지 않는다: **삭제** 대신 **프로젝트에서 보기**로 가서 프로젝트 창에서 프리팹을 지우면 항목도 자동으로 정리된다("DB에서 지울 수 없습니다").

**주의할 점** — 프리팹이 없어져도 항목을 지우지 않고 두는 때가 있다: 다른 항목이 그 프리팹 항목을 가리킨다 · DB에서 고치는 중이다(저장 안 된 변경·상세 창에 열림) · 같은 때 다른 프리팹이 들어왔다(.meta 없이 옮긴 프리팹일 수 있다). 그때는 콘솔 경고 "프리팹이 없어진 DB 항목을 지우지 않고 두었습니다: …"와 검증 경고 "프리팹이 없습니다(…)"가 뜬다. 프리팹 칸에 다시 넣거나, 필요 없으면 Project 창에서 그 항목 에셋을 지운다.

### 6.10 스프라이트 틀

**한 줄 요약.** 원본 일러에서 잘라 낼 크기(스탠딩·아이콘 …)를 용도마다 틀 파일 하나의 크기 표로 정한다. DB에 따로 탭은 없다 — 틀 파일(Dev 폴더 탭에도 보인다)의 인스펙터에서 채운다. 자세히는 `27-Field-Rules-Sprites.md`.

**에디터에서** — Project 창 **Create › MomoiProject › 스프라이트 틀** → 인스펙터의 **크기** 표(이름 · 가로 · 세로, **+ 크기 더하기**), **원본 넣기**(하나 = 맞춤 창, 여럿 = 한꺼번에 굽기), **이 틀로 자른 원본**(맞추기 · 모두 다시 굽기), **쓰는 필드**. 필드 연결은 클래스 상세의 **스프라이트 틀** / **미리보기 크기**(6.2).

### 6.12 개발 (개발 명령 · 저장 변환)

**한 줄 요약.** 게임 내용이 아니라 개발·운영에 쓰는 항목. 개발 명령과 저장 변환을 코드 대신 표로 적는다.

**개발 명령**(`DebugCommandData`, ID 앞부분 `command`) — 항목 하나 = 모니터 › 명령 탭의 버튼 하나. 칸: `label`(버튼 이름, 비우면 ID) · `category`(분류, 기본 "개발") · `description`(설명) · `outcomes`(결과 — 결과 Block 목록: 플레이어 데이터에 주기 · 이벤트 쏘기 · 로그에 기록 · 대상에게 효과 · 코딩한 결과). 누르면 결과 전체가 행동 하나로 실행되어 Undo된다. 개발 빌드에서만 등록된다. 코드가 필요하면 그 ID에 `[BindTo]`를 붙이고 결과 칸은 잠긴다. 자세히는 `22-Monitor-Debug.md` 7절.

**저장 변환**(`SaveMigrationData`, ID 앞부분 `migration`) — 항목 하나 = 변환 한 단계. 칸: `version`(버전, 2부터) · `kind`(종류: 필드 옮김 / 키 이름 바꿈 / 키 삭제) · `key`(키) · `fromPath`·`toPath`(예전 경로·새 경로, 필드 옮김일 때만 보인다 — 리스트의 모든 요소는 `items[].power`, 키의 값이 리스트면 `[].power`) · `newKey`(새 키, 키 이름 바꿈일 때만). 게임이 켜질 때 버전 순서로 등록된다. 같은 버전이면 ID 글자 순서다(폴더로 나눈 DB 목록의 차례와 다를 수 있다) — 순서가 중요하면 버전을 나눈다. 자세히는 `06-SaveLoad.md` 1.4.

**주의할 점** — 검증: 개발 명령 "결과가 없습니다(무엇을 할지).", "비어 있는 결과 칸이 있습니다." / 저장 변환 "버전은 2부터입니다(버전 1이 처음 출시).", "키를 적으세요.", "키 앞뒤에 공백이 있습니다(저장 파일의 키와 맞지 않습니다).", "예전 경로와 새 경로를 적으세요.", 경로 모양(7절 표), "새 키를 적으세요.", "새 키 앞뒤에 공백이 있습니다.", "새 키가 키와 같습니다." 경로 모양이 맞아도 불러올 때 예전 경로를 찾지 못하면 기록(모니터 타임라인)에 경고 "저장 변환 '(ID) · …'(v1 → v2)을 적용하지 못했습니다: …"가 남는다.

## 7. 검증 메시지 모음

**한 줄 요약.** DB는 열 때·바뀔 때마다 전체를 검사한다(저장 안 된 변경까지 — 사이드바·목록의 오류 표시). 빌드할 때는 **저장(적용)한 데이터만** 검사하고, 오류가 하나라도 있으면 빌드가 막힌다("[MomoiProject] 데이터 검증 오류 n건으로 빌드를 중단합니다. DB 창에서 확인하세요.").

- 저장 안 된 변경이 있으면 빌드 전에 "DB에 저장 안 된 변경" 창이 **그대로 빌드** / **빌드 취소**를 묻는다. 빌드에는 저장한 데이터만 들어가므로, 넣으려면 취소하고 DB 창에서 저장(Ctrl+S)한 뒤 다시 빌드한다. 명령줄 빌드(배치 모드)는 묻지 않고 경고만 남긴다.

| 메시지(요약) | 뜻 | 고치는 법 |
|---|---|---|
| ID가 없습니다 / ID '…': 형식 오류 | ID 규칙 위반 | 상세 창 제목을 눌러 ID 바꾸기 |
| ID '…'가 n개 항목에서 중복됩니다 | 에셋 복제(글자까지 같음), 또는 대소문자만 다른 ID(같은 ID로 본다) | 하나의 ID 바꾸기. 글자까지 같으면 그 ID를 가리키던 칸은 남은 항목을 그대로 가리킨다 — 바꾼 쪽을 가리킬 칸은 다시 고른다(4절) |
| ID '…'는 같은 종류의 '…'와(과) 생성 코드 이름(GameIds의 …)이 같습니다 | 점(.)·대문자 자리만 다른 ID(`bossDragon`·`boss.dragon` → `BossDragon`) | 하나의 ID 바꾸기 |
| ID '…'는 출시 뒤 '…'(으)로 바꾼 예전 ID입니다 | 출시 뒤 이력의 예전 ID를 다른 항목이 쓴다. 예전 저장의 그 ID와 구분할 수 없다 | 이 항목의 ID 바꾸기(4절) |
| 필드: 없는 (종류) '…'를 가리킵니다 | `[DataRef]` 끊김 | 목록에서 다시 고르거나 그 항목을 먼저 만든다 |
| 필드: '…'은(는) (클래스) 인스턴스가 아닙니다 | `[DataRef(typeof(Card))]` 칸에 다른 클래스의 인스턴스를 골랐다 | 그 클래스의 인스턴스를 고른다 |
| 필드: 값 틀 '{balance:…}'의 밸런싱 값 '…'가 없습니다 — 이대로면 이 결과가 도는 행동이 실패합니다 | 틀 안의 ID는 ID 바꾸기가 따라가지 않는다. 실행하면 없는 밸런싱 값을 읽다가 그 행동 전체가 실패하므로 오류다 | 틀의 글자를 고친다 |
| 필드: 값 틀 '{data:…}'·'{count:…}'의 플레이어 데이터 '…'가 없습니다 (경고) | 틀 안의 ID는 ID 바꾸기가 따라가지 않는다(실행하면 빈 글 + 경고) | 틀의 글자를 고친다 |
| 필드: (종류)이(가) 선택되지 않았습니다 (경고) | 빈 참조. 숨은 칸(`[ShowIf]`)·Block 안의 칸·다른 칸의 `[ShowIf]` 스위치·필수 칸(필수 검사가 따로 본다)은 경고하지 않는다 | 고르거나 그대로 둔다 |
| 필수 값 '…'(경로)이 비어 있습니다 | 필드 규칙의 필수 | 값을 채운다 |
| 필드: 값은(는) 키워드 그룹 …에 없는 키워드입니다 | 키워드 목록 밖의 값 | 다시 고르거나, 필요한 키워드면 코드에 더한다(AI에게) |
| 이 칸에서는 '…' 트리거/결과를 쓸 수 없습니다 | 칸의 잠금 밖 블록 | 허용된 블록으로 바꾼다 |
| 조건이 아무 값도 관찰하지 않아 발동할 수 없습니다 | 조건 Block 계약 위반 | 조건 코드를 고친다 |
| 결과가 '…' 하나로 고정된 칸인데 n개입니다 | 로그 규칙 결과 개수 | 하나만 둔다 |
| 플레이어 데이터 검사/주기: 없는 플레이어 데이터 '…' | 끊긴 키 | 다시 고른다 |
| 플레이어 데이터에 주기: 없는 인스턴스 '…' / 인스턴스 형식이 다름 | 인스턴스 참조 | 맞는 인스턴스를 고른다 |
| 도전과제 순환 참조 | A·B가 서로를 조건으로 | 한쪽 조건을 바꾼다 |
| 크기가 바뀌어 예외 촬영을 확인해야 합니다 (경고) | 스프라이트 예외 맞춤 | 틀 인스펙터의 '이 틀로 자른 원본'에서 맞추기 |
| 미리보기 크기 '…'이(가) 틀 '…'에 없습니다 (경고) | 필드 규칙의 미리보기 크기가 그 스프라이트 틀에 없다(원본이 대신 보인다) | 클래스 상세에서 다시 고른다(6.2) |
| 프리팹이 없습니다(…) (경고) | 프리팹이 없어졌는데 지우지 않고 둔 프리팹 항목(6.9) | 프리팹 칸에 다시 넣거나 Project 창에서 그 항목 에셋을 지운다 |
| 이 항목에 [BindTo] 코드가 n개 연결되어 있습니다 (경고) | 같은 ID에 `[BindTo]`가 여럿이라 모두 돌고 순서가 정해지지 않는다 | 하나로 합친다(AI에게) |
| 예전 경로·새 경로 '…': …(빈 칸 · 공백 · 요소 번호 · 마지막 칸의 []) / '…' → '…'는 옮길 수 없습니다 / 예전 경로와 새 경로가 같습니다 | 저장 변환(6.12)의 경로 모양이 틀렸거나, 리스트 요소 안의 칸을 요소 밖으로 옮기려 했다 | 리스트의 모든 요소는 `items[].power`처럼 `[]`만, 마지막 칸은 옮길 필드 이름. 요소 밖으로 옮기는 변환은 코드(`Migrations.Add`, 06장)로 |
| 검증 중 오류: … / 참조 검사 중 오류: … | 그 항목의 검증 코드(`ValidateData`·Block의 `Validate`)가 예외를 냈다 | 메시지를 AI에게 보인다 |

- 참조 메시지의 '필드'는 `보이는이름(변수이름)`이다(예: `보상 아이템(rewardItem)`). `[FieldLabel]`이 없으면 변수 이름만.

코드로 만든 Block·DB 종류는 `Validate`·`ValidateData`에서 같은 방식으로 메시지를 낸다.

## 8. 그 밖의 메뉴

| 메뉴 | 내용 |
|---|---|
| `MomoiProject → 개발 → 창 탭 막대 숨기기` | MomoiProject 창을 탭 막대 없는 창(기본)으로 열지, 도킹되는 탭 창으로 열지. 바꾼 뒤 열린 창을 닫고 다시 연다. |

- 나머지 `MomoiProject → 개발 →` 메뉴는 그 기능의 절에 있다: DB 반영 스크립트 두 메뉴 · 구조 편집 열기 → 3-1, 출시됨 (저장 호환 유지) → 4절·20장 3절, 시작 설정 → 20장 1절, 처음 상태로 되돌리기… · 지금 상태를 처음 상태로 기록 → 20장 10절, Claude Code 파일 지금 맞추기 · 맞추지 않기 → 20장 11절.
- 메뉴 없이 코드로만 하는 것: 식별자 코드 다시 만들기 `GameIdsGenerator.Generate(force: true)`(DB를 저장하면 저절로, 20장 7절) · 화면 준비 `ScreenSetup.Ensure()`(35장) · 테스트 씬 `TestSceneSetup.Ensure(…)`(38장) — 모두 에디터 코드(DB 반영 스크립트 안)에서 부른다.

- 내 코드 범위(클래스를 고르는 목록 — 값 형식 · 인스턴스 형식 · 필드 규칙 · 키워드 연결 — 에 보일 범위)는 창이 없다. 기본 규칙(이 프로젝트의 코드, Unity · 패키지 · 라이브러리 · Plugins 제외)으로 충분하고, 바꿀 때는 `ProjectSettings/MomoiProject/ProjectCode.json`(쓸 폴더 · 뺄 폴더 · 뺄 네임스페이스)을 고친다.

# 29. 상태 효과·예약·선택 대기

**한 줄 요약**: **상태 효과**는 대상에게 걸려 있는 동안 효과가 나는 버프·디버프다(독·분노·보호막·"3턴 뒤 폭발"·쿨다운). DB › 상태 효과에서 중첩·지속(영구 / 이벤트 횟수 / 게임 시간)·능력치 보정·트리거와 결과(또는 N초마다 내는 **주기**)를 정하고, 효과 Block `상태 효과 걸기` 또는 `Game.ApplyStatus`로 건다. 걸기 직전에 의도 `상태 효과 걸기`를 거치므로 가로채기가 거는 상태 효과·중첩·길이·최대 중첩·주기를 바꾸거나 막는다(화상 → 푸른 화상, 면역). 상태 효과마다 **종류**(버프·디버프)를 정해 묶어서 풀거나(정화) 세고, 걸린 쪽의 패시브를 끄게(침묵) 할 수 있다. 걸리고 끝날 때 이벤트 `StatusApplied`·`StatusEnded`를 쏜다. **예약**은 행동 하나를 나중에(게임 시간 N초 뒤, 또는 이벤트를 N번 받은 순간) 실행한다(코드). **선택 대기**는 행동 안에서 플레이어에게 고르기를 요구하고(`Game.Ask`·결과 `선택 요구`), 답이 오면 이어서 할 행동을 실행한다. 셋 다 플레이어 데이터에 들어 있어 Undo·판 저장·멀티플레이가 그대로 따라온다.

**언제 쓰는가**

- "턴이 끝날 때마다 독 피해, 3턴", "공격력 +10%, 최대 3중첩"처럼 **몇 턴·몇 초 동안** 이어지는 효과(상태 효과).
- "받는 피해 반감, 3턴"처럼 **걸려 있는 동안만 켜지는 가로채기**(가로채기 트리거를 가진 상태 효과).
- "3턴 뒤 폭발"처럼 **늦게 터지는 효과**(상태 효과의 끝날 때 결과. 코드라면 예약).
- "0.5초마다 화상 피해 2, 3초"처럼 **실시간으로 N초마다** 나는 효과(상태 효과의 주기).
- "화염구: 쓰면 3턴 동안 다시 못 쓴다"처럼 **쿨다운**(화면에 숨긴 상태 효과 + 사용 조건 `상태 효과 검사`).
- "화상 → 푸른 화상", "독 중첩 ×2", "독 면역"처럼 **다른 효과가 거는 상태 효과를 바꾸거나 막을 때**(가로채기 `상태 효과 걸기`).
- "디버프를 모두 푼다", "디버프가 2가지 이상이면"처럼 **버프·디버프를 묶어서** 다룰 때(종류).
- "잉크: 걸린 유닛의 패시브가 꺼진다"처럼 **패시브를 끌 때**(`silencesPassives`), "독에 걸린 적 모두에게"처럼 **걸린 것으로 대상을 거를 때**(대상 `상태 효과로 거르기`).
- "카드 1장을 골라 버린다", "보상 3개 중 1개"처럼 **플레이어가 고르는 효과**(선택 대기). 보상 후보를 **다시 뽑기**도 여기다.

이 문서에서 쓰는 용어:

| 용어 | 뜻 |
|---|---|
| 상태 효과 (Status) | DB › 상태 효과의 항목 하나. 중첩·지속·능력치 보정·트리거·결과를 정한 **정의**다. 코드 형식은 `StatusData`(DB), `StatusDefinition`(실행 중의 정의). |
| 걸린 것 (`ActiveStatus`) | 상태 효과가 대상 하나에 걸린 기록 한 줄: 정의 ID · 가진 쪽 id · 중첩 · 남은 지속 · 출처 · 건 개체. 플레이어 데이터 `$statuses`에 있다. |
| 가진 쪽 (holder) | 상태 효과가 걸린 대상. `id`가 있는 플레이어 데이터 객체(`Fighter`·`DeckCard` …)다. |
| 중첩 (stacks) | 같은 상태 효과가 몇 겹 걸렸는지. 능력치 보정은 중첩 × 값으로 붙고, 결과는 중첩 수를 읽을 수 있다. |
| 지속 (duration) | 언제 끝나는지: 영구(풀 때까지) · 이벤트 횟수(셀 이벤트를 N번 받으면) · 게임 시간(N초 뒤). |
| 셀 이벤트 | 지속이 이벤트 횟수일 때 받을 때마다 남은 횟수를 하나 줄이는 이벤트(예: `턴 끝`). |
| 가진 쪽 필드 | 이벤트·의도의 필드 하나. 그 값이 가진 쪽 id일 때만 발동하거나 센다(예: 피해 의도의 `targetId` → "내가 맞을 때만"). |
| 주기 (pulse) | 걸려 있는 동안 게임 시간 N초마다 결과를 내는 칸. 트리거 없이 돈다(실시간 지속 피해·재생). |
| 줄이기 | 남은 지속을 줄이는 일(효과 `상태 효과 줄이기`·`Game.ShortenStatus`). 다 되면 지속이 다 된 것과 같다. |
| 쿨다운 | 다시 쓰기까지 기다리는 시간. 화면에 숨긴 상태 효과 하나 + 사용 조건 `상태 효과 검사`로 만든다(5-12). |
| 종류 (`StatusKind`) | 상태 효과의 갈래: `없음` · `버프` · `디버프`. 묶어서 풀기(정화)·세기·가로채기 조건에만 쓴다(2-1c). |
| 의도 `상태 효과 걸기` (`StatusIntent`) | 상태 효과를 걸기 직전에 지나는 기본 제공 의도. 의도는 "일어나기 직전의 일"을 담은 객체이고, 가로채기가 그 필드를 고치거나 막는다(28장 2-3). 여기서는 상태 효과·중첩·길이·대상·최대 중첩·주기를 바꾸거나 막는다(2-1b). |
| 건 개체 (`by`) | 상태 효과를 건 개체(사용자)의 id. 다시 걸면 마지막에 건 쪽으로 바뀐다. 처치 기여("마지막에 독을 건 쪽")에 쓴다. 출처(`source`, 건 항목 ID)와 다르다. |
| 예약 (Schedule) | 행동 하나를 나중에 실행하도록 맡겨 둔 기록. 플레이어 데이터 `$schedule`에 있다. |
| 선택 대기 (Choice) | 플레이어의 답을 기다리는 고르기 요구 하나(`PendingChoice`). 플레이어 데이터 `$choices`에 있다. |
| 이어서 할 행동 (then) | 고르기를 요구할 때 함께 맡기는 행동. 답이 오면 고른 것을 받아 실행된다. |
| `[Chosen]` | 이어서 할 행동의 필드에 붙이는 어트리뷰트. 고른 것이 그 필드에 들어간다. |
| 다시 뽑기 | 기다리는 선택의 후보를 같은 가중치 표에서 새로 뽑는 일(`Game.RerollChoice`). 결과 `가중치 표에서 고르기`로 만든 선택만 된다(4-10b). |
| 컨텍스트 (`TriggerContext`) | 결과가 도는 순간의 정보. 상태 효과의 결과에서는 `User`가 가진 쪽, `Owner`가 상태 효과 ID다. |

> **상태 효과와 키워드** — 화상·빙결 같은 상태는 키워드 목록(05장)에 글자로 두지 않고 이 장의 상태 효과(DB › 상태 효과, ID 상수는 `GameIds.Status`)로 만든다. 걸린 것은 대상의 필드가 아니라 플레이어 데이터 `$statuses`에 있다(2-4). 그래야 지속·중첩·턴마다의 효과·만료가 붙는다.

| "유물·특성: 가지고 있는 동안 늘" | 상태 효과가 아니라 DB › 패시브(17장 0절) |

> **규칙: 기획자가 DB에서 만드는 지연·지속 효과는 상태 효과로, 프로그래머가 코드에서 행동 하나를 나중에 돌릴 때는 예약으로.** 상태 효과는 걸린 것이 모니터에 보이고, 풀 수 있고, 중첩·갱신 규칙이 있다. 예약은 "이 행동을 그때 실행"만 한다.

> **규칙: "가지고 있으면 늘 켜진 규칙"(유물·특성·패시브 스킬·장비 효과)은 영구 상태 효과로 걸어 두지 않고 DB › 패시브로 만든다(17장 0절).** 상태 효과는 걸고 푸는 것(지속·중첩·만료)이고, 패시브는 가진 목록(유물 목록·특성 목록)에 그 ID가 있는 동안 발동한다.

> **규칙: 상태 효과 하나 = 트리거·결과 한 쌍.** 한 상태 효과가 서로 다른 두 순간에 반응해야 하면(턴 끝에 피해 + 맞을 때 반감) 상태 효과 둘로 나눠 함께 건다. **"턴마다 1씩 준다"는 지속이 아니라 트리거 + 결과 `상태 효과 풀기` 1**이다(지속 `영구`, 5-18). 지속(이벤트 횟수)은 중첩과 따로 세는 남은 횟수라 "중첩이 곧 남은 턴"인 상태 효과에 맞지 않는다.

> **규칙: 행동은 멈추지 않는다.** 행동 안에서 플레이어의 답을 기다리지 않는다(코루틴·`await` 없음). `Game.Ask`는 요구만 남기고 바로 돌아온다. 고른 뒤에 할 일은 모두 **이어서 할 행동**에 쓴다.

## 2. 동작 규칙

### 2-1. 걸기 · 다시 걸기 · 풀기

- 걸기 직전에 의도 `상태 효과 걸기`를 가로채기에 통과시킨다(2-1b). 아래 규칙은 고쳐진 의도(상태 효과·대상·중첩·길이)로 돈다. 막히면 아무것도 걸리지 않는다.
- 처음 걸면 걸린 것 한 줄이 생긴다(id `$status1`, `$status2` …). 중첩은 건 중첩과 최대 중첩(의도의 `maxStacks`, 처음은 정의의 값) 중 작은 값, 지속은 처음 길이로 시작한다. 능력치 보정이 붙고 **걸릴 때 결과**가 한 번 돈다.
- 같은 대상에 같은 상태 효과를 다시 걸면 새 줄이 생기지 않고 **다시 걸 때** 규칙을 따른다. 걸릴 때 결과는 다시 돌지 않는다. 최대 중첩은 이번 의도의 값으로 바뀌고, 건 개체(`by`)는 이번에 건 쪽으로 바뀐다(이번 건 쪽이 비었거나 `무시`면 그대로).

| 다시 걸 때 (`StatusReapply`) | 중첩 | 남은 지속 |
|---|---|---|
| 중첩 더하기 (`AddStacks`) | 더한다(최대 중첩에서 멈춘다) | 그대로 |
| 지속 갱신 (`Refresh`) | 그대로 | 처음 길이로 |
| 중첩 더하고 지속 갱신 (`AddStacksAndRefresh`, DB 기본) | 더한다 | 처음 길이로 |
| 무시 (`Ignore`) | 그대로 | 그대로 |

- **걸 때 길이**: 효과의 `길이`(`length`)·`Game.ApplyStatus(…, length: 5)`를 주면 이번에 걸 때만 정의의 길이 대신 그 길이를 쓴다(처음 걸 때와, 다시 걸 때 지속을 갱신하는 규칙일 때). 효과에서 0(코드에서 `null`)이면 정의의 길이다. 영구에는 쓰지 않는다. "짧은 기절 1턴, 긴 기절 3턴"을 상태 효과 하나로 만든다.
- **풀기**(효과 `상태 효과 풀기`·`Game.RemoveStatus`): 중첩을 주면 그만큼 줄이고, 남는 중첩이 없으면 푼다. 0(기본)이면 통째로 푼다.
- 풀어서 없애면 **끝날 때 결과는 돌지 않는다.** 끝날 때 결과는 지속이 다 돼서 끝날 때만 돈다("해체하면 터지지 않는다").
- **줄이기**(효과 `상태 효과 줄이기`·`Game.ShortenStatus`): 남은 지속을 그만큼 줄인다. 이벤트 횟수면 남은 횟수를(줄일 양은 반올림), 게임 시간이면 남은 초를. 다 되면 **지속이 다 된 것과 같이** 그 자리에서 끝난다(끝날 때 결과가 돈다, 2-2). 영구이거나 걸려 있지 않으면 아무 일도 없다(`false`). "쿨다운 −1"(5-12)·"폭탄 타이머 1턴 앞당기기"에 쓴다.
- 걸 때마다 `StatusApplied`, 풀어서 없애면 `StatusEnded`(`expired` 거짓)를 쏜다(2-8).
- 대상은 `id`가 있는 플레이어 데이터 객체 또는 그 id 글자다. 카드 한 장(`DeckCard`)처럼 싸우는 존재가 아닌 객체에도 걸 수 있다(5-9).

### 2-1b. 걸기 직전 — 의도 `상태 효과 걸기`

`Game.ApplyStatus`와 효과 `상태 효과 걸기`는 걸기 직전에 기본 제공 의도 `상태 효과 걸기`(`StatusIntent`)를 가로채기에 통과시킨다(28장 2-3). 그래서 "화상 → 푸른 화상", "독 중첩 ×2", "면역"을 코드 없이 패시브·상태 효과의 가로채기로 만든다(5-14~5-16).

```
Game.ApplyStatus(적, "burn")  또는  효과 '상태 효과 걸기'
  1. 의도를 만든다      StatusIntent { targetId, statusId = burn, stacks = 1, length = 2, sourceId, byId, kind = 디버프, maxStacks · pulse = burn의 값 }
  2. 가로채기          패시브·상태 효과의 가로채기가 차례로 고친다(statusId = blueBurn …)
  3. 고쳐진 의도로 건다  처음 걸기 / 다시 걸 때 규칙(2-1) → StatusApplied
```

| 의도 필드 | 처음 값 | 고치면 |
|---|---|---|
| `targetId` | 걸릴 대상 id | 그 id의 대상에게 건다. 데이터에서 찾지 못하면 걸지 않고 타임라인에 경고를 남긴다 |
| `statusId` | 거는 상태 효과 ID | 그 상태 효과가 대신 걸린다(화상 → 푸른 화상). 없는 ID면 예외로 그 행동이 취소된다 |
| `stacks` | 걸 중첩(1 이상. 효과면 이미 효과 배율을 곱한 값, 3-2) | 그 중첩으로 건다(독 ×2). 0 이하가 되면 걸지 않는다 |
| `length` | 걸 때 길이. 주지 않았으면 그 상태 효과의 길이 | 그 길이로 건다(디버프 지속 +20% = 곱하기 1.2) |
| `sourceId` | 출처(효과면 그 효과를 가진 항목 ID) | 걸린 것의 `source`와 `StatusApplied.source`가 된다 |
| `byId` | 건 개체 id(효과면 사용자, 코드면 `by` 인자. 없으면 빈 글자) | 걸린 것의 `by`와 `StatusApplied.by`가 된다 |
| `kind` | 그 상태 효과의 종류(2-1c) | 읽기용이다. 의도 조건으로 "디버프만"을 거른다 |
| `maxStacks` | 그 상태 효과의 최대 중첩(0 = 제한 없음) | 이번에 건 것의 최대 중첩이 된다("화상 최대 중첩 +2" = 더하기 2). 걸린 것마다 기억하고, 다시 걸 때마다 그때 의도의 값으로 바뀐다 |
| `pulse` | 그 상태 효과의 주기(초) | 이번에 건 것의 주기가 된다("틱 속도 +50%" = 곱하기 `0.6667`, 1/1.5). 걸린 것마다 기억하고(`ActiveStatus.pulse`), 다시 걸 때마다 그때 의도의 값으로 바뀐다(가로채기가 빠지면 정의의 주기로). 주기가 없던 것에 주기가 생기면 그때부터 센다 |
| `cancelled` | 거짓 | 참(의도 고치기 `막기`)이면 걸지 않는다(면역) |

- **막히면 아무것도 바뀌지 않는다.** 막혔거나 중첩이 0 이하가 되면 걸린 것도, 걸릴 때 결과도, `StatusApplied`도 없다. `Game.ApplyStatus`는 `null`을 돌려준다.
- **`length`는 처음부터 채워져 온다.** 걸 때 길이를 주지 않았으면 그 상태 효과의 길이다. 그래서 `곱하기`가 바로 된다. 길이 3 × 1.2 = 3.6이고, 이벤트 횟수면 반올림해 4번이다(2-2). 영구 상태 효과는 길이를 쓰지 않는다.
- **상태 효과를 바꾸면 길이·최대 중첩·주기도 따라간다.** 걸 때 길이를 따로 주지 않았고 `length`도 고치지 않았으면, 바뀐 상태 효과의 길이로 건다(화상 2턴 → 푸른 화상 5턴). 걸 때 길이를 줬거나 다른 가로채기가 `length`를 고쳤으면 그 값 그대로다. `maxStacks`·`pulse`도 고치지 않았으면 바뀐 상태 효과의 값이다.
- **주기를 바꾼 걸린 것**: 다시 걸 때 주기를 정의와 같은 값으로 두면(고치지 않으면) 앞서 바꾼 주기가 남는다. 다음 주기 시각은 처음 걸 때만 정한다(2-3).
- **다시 걸 때도 거친다.** 이미 걸려 있으면 고쳐진 의도로 다시 걸 때 규칙(2-1)을 따른다. 바뀐 상태 효과가 이미 걸려 있으면 그쪽의 규칙이다.
- `kind`는 처음 상태 효과의 종류 그대로다. 앞의 가로채기가 `statusId`를 바꿔도 `kind`는 바뀌지 않는다.
- 가로채기끼리의 순서는 가로채기 잎의 `order`가 작은 것부터다(28장 2-3). "화상 → 푸른 화상"과 "푸른 화상 면역"을 함께 두면 바꾸는 쪽의 `order`를 작게 둔다.
- 가로채기는 행동 안에서 돈다. Undo하면 함께 돌아간다.

### 2-1c. 종류 — 버프 · 디버프

- 상태 효과마다 DB 칸 `kind`(종류)를 고른다: `없음`(기본) · `버프` · `디버프`. 걸기·지속·결과는 종류를 보지 않는다. 묶어서 다룰 때만 쓴다.
- **세기**: `Game.StatusCount(대상, 종류)`, 조건 `상태 효과 검사`(`status`(상태 효과)를 비우고 `kind`(종류)를 고른다, 3-4). 중첩이 아니라 **가짓수**다. 독 3중첩 + 약화 1중첩 = 디버프 2.
- **정화**: `Game.RemoveStatuses(대상, 종류)`, 효과 `상태 효과 풀기`(`status`(상태 효과)를 비우고 `kind`(종류 전부)를 고른다, 3-2). 그 종류를 하나씩 통째로 푼다. 풀기라서 끝날 때 결과는 돌지 않고, 푼 것마다 `StatusEnded`(`expired` 거짓)를 쏜다. `RemoveStatuses`가 돌려주는 값은 푼 가짓수다.
- **거르기**: 의도 `상태 효과 걸기`의 `kind`(2-1b). "디버프 면역" = 의도 조건 `kind 일치 디버프` + `막기`. "디버프 지속 +20%" = 같은 조건 + `length` 곱하기 1.2.
- DB Block(`상태 효과 풀기`·`상태 효과 검사`)에서 종류를 `없음`으로 두면 검증 오류다. 그래서 `없음`인 상태 효과는 묶음에 들지 않는다. 쿨다운(5-12)·시한폭탄(5-4)처럼 정화에 풀리면 안 되는 것은 `없음`으로 둔다.

### 2-2. 지속

| 방식 (`StatusDuration`) | 길이 | 끝나는 때 |
|---|---|---|
| 영구(풀 때까지) (`Permanent`, 기본) | 쓰지 않는다 | 풀 때만. 끝날 때 결과는 돌지 않는다 |
| 이벤트 횟수 (`Events`) | 횟수(반올림, 1 이상) | 셀 이벤트를 그 횟수만큼 받은 순간. 그 이벤트를 쏜 행동 안에서 끝난다 |
| 게임 시간(초) (`Seconds`) | 초 | 게임 시계가 끝 시각을 지난 프레임 끝. 행동 하나("상태 효과 만료")로 끝난다 |

- 줄이기(2-1)로 다 되면 어느 방식이든 그 행동 안에서 바로 끝난다(시간 지속도 프레임 끝을 기다리지 않는다).
- **결과가 먼저다.** 같은 이벤트가 걸려 있는 동안 트리거와 횟수 줄이기를 둘 다 하면, 결과가 먼저 돌고 횟수가 준다. "턴 끝마다 피해 1, 3턴" = 피해 세 번 뒤에 끝난다.
- **그 이벤트를 받는 도중에 새로 건 것은 그 이벤트를 세지 않는다.** 턴 끝을 받아 도는 결과(다른 상태 효과·패시브·예약·코드)가 셀 이벤트가 턴 끝인 상태 효과를 새로 걸면, 그 턴 끝은 세지 않고 다음 턴 끝부터 센다. "턴 끝에 건 약화 2턴" = 다음 턴 끝과 그다음 턴 끝, 두 번 뒤에 끝난다. 같은 행동이라도 그 이벤트를 쏘기 **전에** 건 것은 센다. 이미 걸려 있던 것을 그 순간 다시 걸어 지속만 갱신했으면 그 이벤트도 센다(빼는 것은 새로 생긴 줄뿐이다).
- **지속이 다 돼서 끝나는 순서**(이벤트 횟수·게임 시간·줄이기 모두 같다): 걸린 것을 지우고 능력치 보정을 뗀다 → 끝날 때 결과 → `StatusEnded`(`expired` 참). 그래서 끝날 때 결과 안에서는 이미 풀려 있다(`Game.StatusStacks`는 0, 보정도 없다).
- 지속의 **가진 쪽 필드**를 고르면, 셀 이벤트의 그 필드가 가진 쪽 id일 때만 센다(예: 턴 끝 이벤트에 플레이어 id가 있으면 "내 턴이 끝날 때만"). 비우면 그 이벤트를 받을 때마다 센다.
- 셀 이벤트는 형식이 정확히 같아야 한다(상속한 형식은 따로다).
- 시간 만료도 행동이라 Undo된다(스냅샷 방식이면 되감기로 돌아온다).
- 끝날 때 결과는 가진 쪽이 아직 데이터에 있을 때만 돈다. 가진 쪽이 먼저 사라졌으면(쓰러져 전투에서 빠진 적) 그 행동이 끝날 때 결과 없이 정리된다(2-3).

### 2-3. 걸려 있는 동안

**능력치 보정** — 줄마다 `중첩 × 중첩당 값`인 Modifier 하나를 가진 쪽에 붙인다(28장 2-1의 공식). 출처는 걸린 것의 id(`$status1`)라서, 같은 상태 효과가 여러 대상에 걸려도 따로 붙고 따로 떨어진다. 중첩이 바뀌면 다시 계산하고, 풀리거나 끝나면 뗀다.

**트리거와 결과**

- 상태 효과마다 트리거를 한 번 등록해 두고, 순간마다 그 상태 효과가 걸린 대상(가진 쪽)마다 트리거를 따로 검사해 참인 가진 쪽의 결과만 돌린다(아래 **가진 쪽마다 검사**).
- 결과의 컨텍스트: `User` = 가진 쪽 객체, `Picked` = 가진 쪽 하나, `Owner` = 상태 효과 ID, `Event` = 받은 이벤트(가로채기면 의도), `IsIntercept`. 결과 안에서 중첩 수는 `Game.StatusStacks(c.User, c.Owner)`다.
- **가진 쪽 필드**를 고르면, 이벤트·의도의 그 필드가 가진 쪽 id인 대상만 검사하고 결과를 돌린다. 비우면 걸린 대상 모두를 검사한다.
- 결과 `대상에게 효과`의 대상 Block을 비우면 고른 대상 = 가진 쪽이다. `사용자 자신`도 가진 쪽이다.
- 트리거가 가로채기면 **걸려 있는 동안만 켜지는 가로채기**가 된다(28장 2-3). 한 대상의 결과가 의도를 막으면(`cancelled`) 남은 대상은 건너뛴다.
- 결과가 돌 때마다 Journal에 "결과: …"(출처 `Status`)가 남는다.
- 트리거가 조건 충족만으로 되어 있으면(이벤트 없음), 값이 바뀐 행동이 끝난 뒤의 평가에서 가진 쪽 중 하나라도 참이 되면 발동하고, 그때 참인 가진 쪽의 결과만 돈다(행동 밖 변경). 한 번 발동한 뒤 다시 발동하려면 먼저 모든 가진 쪽이 거짓이 되어야 한다. 판 값을 바꾸는 상태 효과는 이벤트 받기·가로채기로 발동시킨다.

**주기(초)** — `pulse`가 0보다 크면 걸려 있는 동안 게임 시간 그 초마다 `outcomes`(결과)를 한 번 낸다. 트리거가 없어도 된다(트리거도 있으면 둘이 같은 결과 칸을 쓴다). 걸 때 가로채기가 의도의 `pulse`를 바꿨으면 그 걸린 것은 바뀐 주기로 돈다(2-1b).

- 첫 결과는 건 뒤 한 주기가 지난 때다(걸자마자 내지 않는다). 다시 걸어도 주기 시각은 그대로다.
- 프레임 끝(고정 틱이면 틱마다, 33장)에 행동 하나("상태 효과 주기", 공개 범위 개발자)로 낸다. 같은 프레임에 주기가 된 것은 그 행동 하나에 묶인다. 같은 프레임에 시간 지속이 끝나는 것은 주기 다음에 끝난다.
- 프레임이 길어 주기가 여러 번 밀렸으면 밀린 만큼 낸다(최대 8번). 그보다 밀린 것은 버리고 다음 시각을 지금 + 주기로 둔다.
- 시간 지속이면 끝나는 시각 뒤의 주기는 내지 않는다("3초 동안 0.5초마다" = 6번). 결과가 그 상태 효과를 풀면 거기서 멈춘다.
- 게임 시계를 따른다(일시정지·배속·스냅샷 되감기). 컨텍스트는 걸려 있는 동안의 결과와 같고 `Event`는 비어 있다. `[BindTo]`로 쓰면 `(TriggerContext c)`로 받는다.

**가진 쪽마다 검사** — 순간마다(이벤트를 받을 때·의도를 가로챌 때·조건 값이 바뀔 때) 걸린 대상 중 가진 쪽 필드가 맞는 대상마다, 컨텍스트의 `User`(와 `Picked`)를 그 가진 쪽으로 두고 트리거 전체(조건 충족 잎·이벤트 조건 포함)를 따로 검사한다. 결과는 참인 가진 쪽에만 돈다. 그래서 조건 Block이 `Context.User`로 가진 쪽의 값을 본다: "가진 쪽 체력이 절반 이하일 때" = `턴 끝 받기` AND 조건 Block(`Context.User`의 체력, 4-3).

**가진 쪽이 사라지면** — 가진 쪽을 플레이어 데이터에서 뺀 행동(쓰러진 적을 전투에서 빼는 피해)이 끝나기 직전에, **그 행동 안에서** 그 대상에 걸린 상태 효과를 모두 지운다. 끝날 때 결과는 돌지 않고 `StatusEnded`도 쏘지 않는다. 그 대상의 이번 판 Modifier(상태 효과의 능력치 보정 포함, 28장 2-2)도 함께 지운다. 그 행동을 Undo하면 대상과 함께 돌아온다. 영구 Modifier는 지우지 않는다(대상이 다음 판에 다시 생긴다).

**패시브를 끔(침묵)** — `silencesPassives`(걸린 쪽의 패시브를 끔)를 켠 상태 효과가 걸려 있는 동안, 그 가진 쪽(조커·유닛·조각)이 가진 패시브(DB › 패시브, 17장 0절)는 발동·주기·가진 동안 능력치 보정이 모두 없고 `Game.Owned`도 0이다(잉크·디버프된 조커·봉인).

- 패시브의 가진 쪽 기준이다. 조각에 걸면 그 조각의 패시브가(빌려 쓰기의 원본도 되지 않는다), 목록을 품은 개체(`hero.perks`의 `hero`)에 걸면 그 개체의 패시브가 꺼진다. 다른 가진 쪽의 같은 패시브는 그대로다.
- 상태 효과 자신의 결과·능력은 끄지 않는다. 능력까지 막으려면 가로채기 `사용` + `막기`를 같은 상태 효과에 둔다(28장 4-14). 그러면 트리거·결과 한 쌍을 쓰므로 "턴마다 1씩 준다"는 둘째 상태 효과로 나눈다(1절 규칙).
- 풀리면 그 자리에서 다시 켜진다. 보정은 읽을 때 계산하므로 따로 되돌릴 것이 없다.
- 이런 상태 효과가 DB에 하나도 없으면 침묵 검사는 건너뛴다.

### 2-4. 걸린 것이 사는 곳

| 무엇 | 플레이어 데이터 키 | 구역 |
|---|---|---|
| 걸린 상태 효과 | `$statuses`(표시 이름 "상태 효과") | 세션 |
| 상태 효과의 능력치 보정 | `$modifiers`(출처 `$status1` …, 28장 2-2) | 세션 |

- 처음 걸 때 키가 저절로 정의된다. 플레이어 데이터라서 Undo·판 저장·멀티플레이가 그대로다. 판을 불러온 직후에도 보정이 바로 보인다.
- 세션 구역이라 **새 판이면 비워진다.** 전투가 끝나는 것은 시스템이 모르므로 전투가 끝나도 남는다. 전투마다 끝나야 하면 전투를 끝내는 행동에서 푼다(5-2).
- 걸린 것에는 정의 ID·가진 쪽 id·중첩·남은 지속·출처·건 개체(주기가 있으면 다음 주기 시각, 가로채기가 바꿨으면 그 주기·최대 중첩)만 들어 있다. 무엇을 하는지는 정의에서 읽는다. 정의는 게임이 켜질 때 DB의 상태 효과 전부로 등록된다.

### 2-5. 예약

- `Game.ScheduleAfter(초, 행동)`: 게임 시간으로 그만큼 지난 뒤의 **프레임 끝**에 행동 하나("예약 실행", 공개 범위 개발자)로 실행한다. 같은 프레임에 여럿이면 시각 순서다.
- `Game.ScheduleOn<이벤트>(횟수, 행동)`: 그 이벤트를 그 횟수만큼 받은 **순간에, 그 이벤트를 쏜 행동 안에서** 실행한다. 그 행동과 함께 Undo된다. 이벤트 형식은 정확히 같아야 한다.
- **넘긴 행동은 예약에 맡긴다.** 대상 필드(id가 있는 객체)는 id만 남겨 저장하고, 실행 직전에 지금 데이터의 객체로 다시 찾는다(02장 2.2와 같다). 넘긴 행동 객체는 다시 쓰지 않는다.
- **대상이 그때 없으면**(쓰러진 적) 실행하지 않고 지운다. 타임라인에 "대상이 없어 예약을 실행하지 않았습니다: (행동)"이 남는다.
- **실패하면**
  - 시간 예약: 타임라인에 경고 "예약 실행이 실패해 지웁니다: (행동) — (이유)"를 남기고 지운다(매 프레임 다시 시도하지 않는다).
  - 이벤트 예약: **그 예약이 바꾼 것만 되돌리고** 타임라인에 경고 "예약 실행이 실패해 그 예약이 바꾼 것만 되돌렸습니다: (행동) — (이유)"를 남긴다. 그 예약은 지워진다(다시 시도하지 않는다). 이벤트를 쏜 행동은 계속되고, 그 행동이 바꾼 다른 것(예약 앞뒤의 변경)은 남는다. 되돌린 변경은 그 행동의 Undo 기록에서도 빠진다(02장 2.7의 저장점).
- **저장**: `$schedule`(세션, "예약"), `permanent: true`면 `$schedule.meta`(메타, "영구 예약"). 판 저장·불러오기로 이어진다.
- **시각은 게임 시계**(`session.Clock.Time`) 기준이다. 게임 시계는 게임을 켤 때 0에서 시작하고, 판을 불러오면 그 판의 시각으로 돌아간다. 그래서 판을 넘는 시각은 정해지지 않는다. **영구 예약은 이벤트 예약(`ScheduleOn`)만** 쓸 수 있고, 시간 예약에 `permanent: true`를 주면 `InvalidOperationException`("[MomoiProject] 영구 예약은 이벤트 예약(ScheduleOn)만 쓸 수 있습니다(게임 시간은 판마다 0부터 다시 흐릅니다).")으로 그 행동이 취소된다.
- 고정 틱(33장)을 켜면 시간 예약은 틱마다 확인된다(프레임 속도와 상관없이 같은 틱에 실행).

### 2-6. 선택 대기

```
행동(카드 내기)
  └ Game.Ask(안내 글, 후보, 이어서 할 행동)
       선택을 플레이어 데이터($choices)에 넣고 ChoiceRequested를 쏜다. 다음 줄은 바로 실행된다
  행동이 끝난다                                         ─ Undo 한 단위
화면: Game.Choice를 그린다. 기다리는 동안(Game.IsWaiting) 다른 입력을 막는다
플레이어가 고른다 → Game.Answer(선택 id, 고른 것들)
  └ 행동 '선택: …'(ChoiceAnswer)
       개수·후보 검사 → 이어서 할 행동의 [Chosen] 필드에 고른 것 → 그 행동 실행   ─ Undo 한 단위
```

- **행동은 멈추지 않는다.** `Ask` 다음 줄은 고르기 전에 바로 실행된다.
- **이어서 할 행동은 예약처럼 맡긴다.** 대상 필드는 id만 저장하고 실행할 때 다시 찾는다. 고른 것은 `[Chosen]` 필드에 들어간다.
- **답이 틀리면 아무것도 바뀌지 않는다.** 개수가 최소~최대 밖이거나, 후보가 아닌 것을 골랐거나, 같은 것을 두 번 고르면 답하기가 실패하고 선택은 그대로 기다린다. 이어서 할 행동이 실패해도 같다.
- **후보가 없으면 기다리지 않는다.** 바로 이어서 할 행동을 실행한다(고른 것 없음).
- **개수**: 최소는 후보 수까지로 줄어든다. 최대는 후보 수를 넘지 않고, 0 이하면 후보 수다. 최소가 0이면 고르지 않고 답할 수 있다.
- 후보는 id로 구별한다. 같은 id가 두 번 들어오면 하나만 남는다.
- **여러 선택은 먼저 요구한 것부터.** `Game.Choice`가 맨 앞(가장 먼저 요구한 것)이다.
- **Undo**: 답하기를 Undo하면 다시 기다린다. 요구한 행동까지 Undo하면 선택도 사라진다.
- **다시 뽑기**: 결과 `가중치 표에서 고르기`로 만든 선택은 기다리는 동안 다른 행동 안에서 `Game.RerollChoice(선택 id)`로 후보를 새로 뽑는다. 같은 선택 id 그대로 후보만 바뀌고, `ChoiceRequested`를 다시 쏜다. 비용·남은 횟수는 부르는 행동이 정한다. 그 행동을 Undo하면 원래 후보로 돌아간다(4-10b).
- **판 저장**으로 이어진다. 불러온 뒤 그대로 답할 수 있다.
- 기다리는 동안 다른 입력을 막는 것은 **화면의 일**이다(`Game.IsWaiting`). 시스템은 다른 행동을 막지 않는다. 화면(35장)의 **기본 고르기 창**은 선택 대기가 생기면 저절로 뜨고, `OnClick`·`GameScreens.Do`는 기다리는 동안 다른 행동을 보내지 않는다.
- `player`(답할 플레이어, 멀티플레이용)는 기록만 한다. 그 플레이어만 답하게 하는 검사는 화면·서버가 한다.

### 2-7. 라이브러리 내부 id

Modifier `$mod1`, 걸린 상태 효과 `$status1`, 예약 `$schedule1`, 선택 `$choice1`처럼 라이브러리가 만드는 id는 `$`로 시작한다. 그래서 DB 항목 ID와 겹치지 않는다. 번호는 플레이어 데이터(`$id.$status` 같은 키, 메타 구역)에 있어 Undo·저장·멀티플레이에서도 같다. 모니터 데이터 탭에서 보이는 이름이 이것이다.

### 2-8. 걸림·끝남 이벤트

| 이벤트(표시 이름) | 필드 | 쏘는 때 |
|---|---|---|
| `StatusApplied`("상태 효과 걸림") | `holder`(가진 쪽 id) · `status`(상태 효과 ID) · `stacks`(걸린 뒤의 중첩) · `source`(출처) · `by`(이번에 건 개체 id) | 처음 걸 때(능력치 보정·걸릴 때 결과 다음), 다시 걸 때(다시 걸 때 규칙을 적용한 뒤). `무시` 규칙이라 아무것도 바뀌지 않은 다시 걸기와, 가로채기가 막아 걸리지 않은 때(2-1b)는 쏘지 않는다. `holder`·`status`는 가로채기가 고친 뒤의 값이다 |
| `StatusEnded`("상태 효과 끝남") | `holder` · `status` · `expired` | 지속이 다 돼서 끝날 때(`expired` 참, 끝날 때 결과 다음) · 풀어서 없앨 때(`expired` 거짓, 정화로 푼 것마다 하나씩) |

- 중첩만 줄인 풀기와, 가진 쪽이 데이터에서 사라져 정리될 때(2-3)는 쏘지 않는다.
- 행동 안에서 쏘이므로 로그·도전과제·다른 트리거가 받는다(10장). "독에 걸릴 때마다 1 회복" = 이벤트 받기 `상태 효과 걸림`, 이벤트 조건 `status 일치 poison`.
- 화면은 연출(반짝임·소리)만 이 이벤트로 하고, 아이콘 줄 자체는 데이터(`$statuses`)에서 다시 그린다. Undo·판 불러오기에는 이벤트가 오지 않는다(5-13).

## 3. 에디터에서 쓰는 법

### 3-1. DB › 상태 효과

`MomoiProject → DB` → 사이드바 **DB** 그룹의 **상태 효과** 탭 → **+ 새로 만들기** → 제목(= ID, 예: `poison`)을 짓는다. 저장하면 `GameIds.Status.Poison`이 생긴다. 칸 이름표는 변수 이름이고, 마우스를 올리면 `[FieldLabel]` 글자와 설명이 보인다.

| 칸 | 툴팁 | 값 |
|---|---|---|
| `kind` | 종류 / 버프·디버프. 디버프만 풀기(정화)·디버프 개수·'상태 효과 걸기' 가로채기의 종류 조건에 쓰입니다 | `없음`(기본) / `버프` / `디버프`(2-1c) |
| `silencesPassives` | 걸린 쪽의 패시브를 끔 / 켜면 이 상태 효과가 걸린 쪽(조커·유닛·조각)의 패시브가 발동·가진 동안 보정·레벨 모두 꺼집니다(Ink·디버프된 조커·봉인) | 기본 끔(2-3 **패시브를 끔**) |
| `maxStacks` | 최대 중첩 / 0이면 제한 없음 | 기본 1 |
| `reapply` | 다시 걸 때 | `중첩 더하기` / `지속 갱신` / `중첩 더하고 지속 갱신`(기본) / `무시` |
| `duration` › `kind` | 지속 › 방식 | `영구(풀 때까지)`(기본) / `이벤트 횟수` / `게임 시간(초)` |
| `duration` › `length` | 길이 / 이벤트 횟수 또는 초 | 기본 3. 이벤트 횟수·게임 시간일 때만 보인다 |
| `duration` › `tickEvent` | 셀 이벤트 | `[GameEvent]` 목록. 이벤트 횟수일 때만 보인다 |
| `duration` › `holderField` | 가진 쪽 필드 / 이 필드가 가진 쪽 id인 이벤트만 셉니다(예: 턴 끝의 플레이어 id → 내 턴이 끝날 때만). | 셀 이벤트의 필드. 비우면 "가진 쪽 모두". 이벤트 횟수일 때만 보인다 |
| `modifiers` | 능력치 보정 | 줄마다 `attribute`(능력치(숫자 필드 이름)) · `kind`(칸: `플랫(+값)` / `퍼센트(0.2 = +20%)` / `독립 곱(0.5 = ×1.5)`) · `valuePerStack`(중첩당 값) |
| `trigger` | 걸려 있는 동안 트리거 | `+ 블럭`: 이벤트 받기 · 조건 충족 · 가로채기 |
| `holderField` | 가진 쪽 필드 / 이벤트·의도의 이 필드가 가진 쪽 id일 때만 발동합니다(예: 피해 의도의 대상 id → 내가 맞을 때만). | 트리거가 고른 이벤트·의도의 필드. 비우면 "가진 쪽 모두" |
| `pulse` | 주기(초) / 0보다 크면 걸려 있는 동안 이 초(게임 시간)마다 결과를 냅니다(실시간 지속 피해·재생). 트리거가 없어도 됩니다 | 기본 0(주기 없음). 내는 결과는 `outcomes` 칸이다(2-3) |
| `outcomes` | 결과 | 트리거가 참인 가진 쪽마다(2-3), 주기마다. 결과 종류 전부 |
| `onApply` | 걸릴 때 결과 | 처음 걸 때 한 번. 결과 종류는 대상에게 효과(`선택 요구` 포함) · 플레이어 데이터(`플레이어 데이터에 주기`·`비용 내기` …) · 코딩한 결과 · 이벤트 쏘기 |
| `onExpire` | 끝날 때 결과 | 지속이 다 돼서 끝날 때만(풀 때는 돌지 않는다). 고를 수 있는 종류는 `onApply`와 같다 |
| `icon` | 아이콘 | `Sprite`. 규칙은 쓰지 않는다. 화면 코드가 상태 아이콘 줄에 그린다(5-13) |
| `hidden` | 화면에 숨김 / 쿨다운처럼 규칙에만 쓰고 상태 아이콘 줄에 보이지 않는 상태 효과 | 켜도 동작은 같다. 화면 코드가 이 값을 보고 그리지 않는다 |

- 걸릴 때·끝날 때 결과의 컨텍스트도 `User` = 가진 쪽, `Owner` = 상태 효과 ID다. 이벤트는 없다(`Event`가 비어 있다). 끝날 때 결과가 도는 때는 이미 풀린 뒤다(2-2).
- 능력치 이름은 글자라서 오타를 검증이 잡지 못한다. 걸 때 대상에 그 숫자 필드가 없으면 28장 3-1과 같은 예외로 그 행동이 취소된다.
- 라이브러리의 기본 화면은 상태 아이콘 줄을 그리지 않는다. `icon`·`hidden`은 프로젝트의 화면 코드가 읽는 칸이다(5-13).
- 검증 오류: "지속: 횟수를 셀 이벤트를 고르세요." / "지속: 횟수는 1 이상이어야 합니다." / "지속: 시간은 0보다 커야 합니다." / "능력치 보정: 능력치(숫자 필드 이름)를 적으세요." / "주기는 0 이상이어야 합니다." / "비어 있는 결과 칸이 있습니다(스크립트가 지워졌을 수 있음)."
- 검증 경고: "지속이 영구라 끝날 때 결과가 돌지 않습니다(풀어서 없앨 때는 돌지 않습니다)." / "걸려 있는 동안 트리거도 주기도 없어 결과가 돌지 않습니다." / "주기가 있는데 결과가 없습니다." / "트리거가 있는데 결과가 없습니다." 트리거·결과 자신의 검증도 함께 뜬다.

> **`[BindTo]`와 세 결과 칸** — 상태 효과 ID에 `[BindTo]`를 붙이면 코드가 `outcomes`(걸려 있는 동안의 결과)를 대신한다(4-3). DB에서도 `outcomes` 칸만 잠기고(연결된 함수 이름 · `cs 열기`), `onApply`·`onExpire`는 그대로 고친다. 두 칸은 `[OutcomeSlot(…, BindTo = false)]`라서 코드가 대신하지 않는다(13장 2-11). 걸릴 때·끝날 때 결과를 코드로 쓰려면 그 칸에 코딩한 결과 Block(`Reward`, 12장 3-2)을 둔다.

### 3-2. 효과 `상태 효과 걸기` · `상태 효과 풀기` · `상태 효과 줄이기`

결과 칸 `+ 결과 추가` → `대상에게 효과` → `+ 효과 추가` → 분류 **상태 효과**. 최종 대상마다 실행한다. `선택 요구`의 고른 것에 효과(3-3)에도 같은 목록이 나온다.

**상태 효과 걸기** — 문장 `{status} {stacks}중첩 걸기`.

| 칸 | 툴팁 | 값 |
|---|---|---|
| `status` | 상태 효과 | DB › 상태 효과 목록에서 고른다 |
| `stacks` | 중첩 | 1 이상(기본 1) |
| `length` | 길이(0이면 상태 효과의 길이) / 이번에만 쓸 지속(이벤트 횟수 또는 초) | 기본 0. 0보다 크면 이번에 걸 때만 그 길이(2-1) |

- 걸기 직전에 의도 `상태 효과 걸기`를 거친다. 가로채기가 막으면 그 대상에는 걸리지 않는다. 다른 상태 효과로 바꾸면 그것이 걸린다(2-1b).
- 이미 걸려 있으면 그 상태 효과의 `reapply` 규칙을 따른다(2-1).
- 출처(`ActiveStatus.source`)는 이 효과를 가진 항목의 ID다(컨텍스트의 `Owner`: 능력 ID, 사용 기능이 붙은 인스턴스 ID, 유물 ID, 상태 효과 ID …). 건 개체(`by`)는 사용자다.
- 거는 중첩 = `stacks` × 효과 배율(컨텍스트의 `Power`, 반올림, 최소 1). 효과 배율은 능력·패시브마다 의도 `효과 배율`로 고친다(28장 4-14). 상태 효과의 결과에서는 배율이 1이다.
- 요약: `poison 걸기`, `poison 3중첩 걸기`.
- 검증 오류: "상태 효과 걸기: 상태 효과를 고르세요." / "상태 효과 걸기: 중첩은 1 이상이어야 합니다."

**상태 효과 풀기**

| 칸 | 툴팁 | 값 |
|---|---|---|
| `status` | 상태 효과 | DB › 상태 효과 목록에서 고른다. 비우면 `kind`를 본다 |
| `kind` | 종류 전부(상태 효과를 비웠을 때) | `status`를 비우고 `버프`·`디버프`를 고르면 그 종류를 모두 통째로 푼다(정화, 2-1c). `status`를 고르면 쓰지 않는다 |
| `stacks` | 중첩(0이면 모두) | 0이면 통째로 푼다. 숫자를 적으면 그만큼 줄이고, 남는 중첩이 없으면 푼다. `status`를 골랐을 때만 쓴다 |

- 끝날 때 결과는 돌지 않는다. 종류 전부도 같다.
- 요약: `poison 풀기`, `poison 2중첩 풀기`, `디버프 모두 풀기`.
- 검증 오류: "상태 효과 풀기: 상태 효과나 종류를 고르세요."

**상태 효과 줄이기** — 문장 `{status} 남은 지속 −{amount}`.

| 칸 | 툴팁 | 값 |
|---|---|---|
| `status` | 상태 효과 | DB › 상태 효과 목록에서 고른다 |
| `amount` | 줄일 양(횟수·초) | 0보다 크게(기본 1). 이벤트 횟수면 반올림한 횟수, 게임 시간이면 초 |

- 다 되면 그 자리에서 지속이 다 된 것으로 끝난다(끝날 때 결과 → `StatusEnded`, 2-2). 영구거나 걸려 있지 않은 대상에는 아무 일도 없다.
- 요약: `fireballCd 남은 지속 −1`.
- 검증 오류: "상태 효과 줄이기: 상태 효과를 고르세요." / "상태 효과 줄이기: 줄일 양은 0보다 커야 합니다."

### 3-3. 결과 `선택 요구`

`+ 결과 추가` → 그룹 **결과** → `선택 요구`. 결과 종류가 대상에게 효과와 같아서(`OutcomeKinds.Targeted`), `대상에게 효과`를 고를 수 있는 칸이면 나온다.

| 칸 | 툴팁 | 값 |
|---|---|---|
| `prompt` | 안내 글 | 플레이어에게 보일 글(예: "버릴 카드") |
| `candidates` | 후보 | `+ 대상 추가`로 대상 Block을 더한다. `대상에게 효과`처럼 고른 대상에서 출발해 위에서부터 차례로 거른다. 비우면 고른 대상 그대로 |
| `min` | 최소 개수 | 기본 1. 0이면 고르지 않고 답할 수 있다 |
| `max` | 최대 개수 | 기본 1 |
| `effects` | 고른 것에 효과 | `+ 효과 추가`. 고른 것마다 모든 효과를 실행한다(효과의 대상 형식과 다른 것은 건너뛴다) |
| `then` | 고른 뒤 결과 | `+ 결과 추가`. 효과 다음에 한 번 돈다. 안에 `선택 요구`를 또 넣으면 이어 고르기가 된다 |

- 후보 중 `id`가 있는 객체만 후보가 된다. 후보 이름은 텍스트 표의 `<id>.name`이고, 없으면 id다. DB 원본처럼 이름 키가 있는 id는 이름이 보이고, 판 안에서 만든 개체(덱 카드 `card3`)는 id가 보인다. 그런 후보는 화면이 id로 객체를 찾아 이름을 그린다(5-10).
- 사용자·`Owner`는 요구한 순간 그대로 이어진다. 고른 것에 효과의 `User<T>()`, 고른 뒤 결과의 `User`가 요구할 때의 사용자이고, 고른 뒤 결과의 `Picked`는 고른 것들이다. 받은 이벤트는 이어지지 않는다(`Event`가 비어 있다).
- 효과·결과는 요구한 순간의 **사본**이 선택과 함께 저장된다. 그 사이 DB를 고쳐도 기다리는 선택에는 영향이 없다.
- 후보가 없으면 기다리지 않고 바로 이어 간다. 효과는 없고, 고른 뒤 결과는 돈다.
- 유물·상태 효과처럼 사용이 아닌 곳에는 고른 대상이 없으므로, 후보를 찾는 대상 Block(`모든 적` 같은)을 둔다.
- 요약: `{후보}에서 {개수} 고르기: {효과}`. 예: `손패에서 1개 고르기: free 걸기`.
- 검증 오류: "선택 요구: 개수는 최소 ≤ 최대, 최대 1 이상이어야 합니다." / "선택 요구: 최소 개수는 0 이상이어야 합니다." / "선택 요구: 비어 있는 Block이 있습니다(스크립트가 지워졌을 수 있음)."
- 검증 경고: "선택 요구: 고른 뒤 할 일(효과·결과)이 없습니다."

### 3-4. 조건 `상태 효과 검사`

Trigger 칸 `+ 블럭` → **조건 충족 · 상태 효과** → `상태 효과 검사`. 문장 `{who}의 {status} {op} {stacks}`. 사용 조건(능력·사용 기능), 트리거(상태 효과·패시브·도전과제 …), 가중치 표 줄의 조건처럼 조건 Block을 두는 곳 어디에나 둔다.

| 칸 | 툴팁 | 값 |
|---|---|---|
| `who` | 누구 | `사용자·가진 쪽`(기본) / `이벤트의 개체` |
| `eventField` | 이벤트 필드(id) | `이벤트의 개체`일 때만 보인다. 받은 이벤트(가로채기면 의도)에서 대상 id가 든 필드(`targetId`) |
| `status` | 상태 효과 / 비우고 종류를 고르면 그 종류가 몇 가지 걸려 있나 | DB › 상태 효과. 비우면 `kind`를 본다 |
| `kind` | 종류(상태 효과를 비웠을 때) | `버프` / `디버프`. 그 종류가 몇 가지 걸려 있는지 센다(2-1c) |
| `op` | 비교 | `>=`(기본) · `<=` · `>` · `<` · `==` |
| `stacks` | 중첩(종류면 가짓수) | 기본 1. 걸려 있지 않으면 중첩 0으로 본다. 종류면 중첩이 아니라 가짓수와 비교한다 |

- `사용자·가진 쪽` = 컨텍스트의 `User`. 능력·사용 기능이면 쓰는 쪽, 상태 효과·패시브의 트리거면 가진 쪽이다(가진 쪽마다 따로 검사, 2-3).
- "걸려 있을 때만" = `>= 1`(기본), "없을 때만" = `<= 0`. 쿨다운은 사용 조건 `사용자의 fireballCd <= 0`(5-12). 사용 조건이라 `Game.CanUse`도 안다.
- `이벤트의 개체`: "맞은 쪽이 젖어 있으면 감전" = 이벤트 받기 `피해` AND `이벤트의 targetId의 wet >= 1`. 이벤트가 없는 순간(값이 바뀌어 다시 볼 때)에는 대상이 없어 중첩 0이다. 이벤트 받기와 `AND`로 묶어 쓴다(11장 4-2).
- 종류: "디버프가 2가지 이상이면" = `status`(상태 효과) 비움, `kind`(종류) `디버프`, `op`(비교) `>=`, `stacks`(중첩) `2`. 독 3중첩 하나는 1가지다(5-17).
- 도전과제·가중치 표 줄처럼 사용자가 없는 곳에서 `사용자·가진 쪽`을 고르면 늘 중첩 0이다.
- 요약: `사용자의 fireballCd <= 0`, `이벤트의 targetId의 wet >= 1`, `사용자의 디버프 >= 2`.
- 검증 오류: "상태 효과 검사: 상태 효과나 종류를 고르세요." / "상태 효과 검사: 이벤트 필드를 적으세요."

### 3-4b. 대상 `상태 효과로 거르기`

`대상에게 효과`의 `+ 대상 추가` → 분류 **대상** → `상태 효과로 거르기`. 앞의 대상 중 상태 효과 중첩 비교가 참인 것만 남긴다. 칸과 비교는 3-4의 조건과 같다(대상마다 본다).

| 칸 | 툴팁 | 값 |
|---|---|---|
| `status` | 상태 효과 / 비우고 종류를 고르면 그 종류가 몇 가지 걸려 있나 | DB › 상태 효과. 비우면 `kind`를 본다 |
| `kind` | 종류(상태 효과를 비웠을 때) | `버프` / `디버프`(가짓수로 비교) |
| `op` | 비교 | `>=`(기본) · `<=` · `>` · `<` · `==` |
| `stacks` | 중첩(종류면 가짓수) | 기본 1 |

- "독에 걸린 적 모두에게 3" = 대상 `플레이어 데이터 목록`(`run` › `battle.enemies`) → `상태 효과로 거르기`(`status` `poison`, `op` `>=`, `stacks` `1`) → 효과 `피해`(3). "디버프가 없는 아군" = `kind` `디버프`, `op` `<=`, `stacks` `0`.
- 앞에 대상 Block이 없으면 고른 대상(패시브·상태 효과면 가진 쪽)을 거른다.
- 요약: `poison >= 1`, `디버프 <= 0`. 검증 오류: "상태 효과로 거르기: 상태 효과나 종류를 고르세요."

### 3-5. 어느 칸에서 쓸 수 있나

| Block | 쓸 수 있는 칸 |
|---|---|
| 상태 효과 걸기 · 풀기 · 줄이기 | `대상에게 효과`(또는 `선택 요구`의 고른 것에 효과)를 고를 수 있는 칸 전부(능력·사용 기능·도전과제·개발 명령·상태 효과·패시브·프로젝트 기능) |
| 상태 효과 검사(조건) | 조건 충족을 고를 수 있는 Trigger 칸 전부, 가중치 표 줄의 조건(`condition`) |
| 상태 효과로 거르기(대상) | 대상 Block을 둘 수 있는 곳 전부(`대상에게 효과`·`선택 요구`의 후보·`빌려 쓰기`) |
| 선택 요구 | `[OutcomeSlot]`에 `OutcomeKinds.Targeted`가 있는 칸(= 대상에게 효과와 같은 칸) |
| 가로채기(상태 효과의 트리거) | DB › 상태 효과의 `trigger`에는 처음부터 열려 있다. 결과 칸에도 `의도 고치기`가 나온다 |
| 가로채기 `상태 효과 걸기`(의도) | 가로채기를 고를 수 있는 Trigger 칸(상태 효과의 `trigger`, 패시브의 `trigger`, 잠금에 `Intercept`를 넣은 프로젝트 기능). 의도 목록에서 `상태 효과 걸기`를 고른다. 결과는 `의도 고치기` |

- 상태 효과 걸기·선택 요구는 **행동 안에서 도는 결과**에 둔다(사용 기능·능력, 이벤트 받기·가로채기로 발동한 유물·상태 효과). 도전과제의 결과는 Undo 이력 밖이라(14장) 판 값인 상태 효과·선택을 두기에 맞지 않다.

### 3-6. 모니터에서 확인하기

- **걸린 상태 효과**: **데이터** 탭에서 `$statuses`(상태 효과) → `items`를 펼치면 한 줄씩 보인다: `id` · `status`(정의 ID) · `target`(가진 쪽 id) · `stacks` · `remaining`(이벤트 지속이면 남은 횟수, 시간 지속이면 끝나는 게임 시각) · `source` · `by`(건 개체) · `nextPulse`(주기가 있으면 다음 결과를 낼 게임 시각) · `pulse`(가로채기가 바꾼 주기, 0이면 정의의 주기) · `maxStacks`(최대 중첩). 능력치 보정은 `$modifiers`에 출처 `$status1`로 보인다.
- **걸기 가로채기**: 가로채기가 의도를 고치면 그 항목의 "결과: 의도 statusId = blueBurn"·"결과: 의도 막기"(출처 `Passive`·`Status`)가 타임라인에 남는다. 바꾼 대상을 찾지 못하면 경고 "상태 효과 걸기: 가로채기가 바꾼 대상 '…'를 찾지 못해 걸지 않았습니다."(출처 `Status`)가 남는다.
- **결과**가 돌면 타임라인에 "결과: …"(출처 `Status`)가 남는다. 시간 지속의 만료는 행동 "상태 효과 만료", 주기 결과는 행동 "상태 효과 주기"(둘 다 개발자)로 남는다.
- **이벤트**: 걸고 끝날 때 `상태 효과 걸림`·`상태 효과 끝남`이 타임라인에 보인다. 모니터 **이벤트** 탭에서 직접 쏴 보면 그 이벤트를 받는 규칙만 반응한다(걸린 것은 바뀌지 않는다).
- **예약**: 데이터 탭 `$schedule`(예약)·`$schedule.meta`(영구 예약)에 남은 예약이 보인다(`at` = 실행 시각, 이벤트 예약이면 `eventType`·`remaining`). 시간 예약은 행동 "예약 실행"(개발자) 안에 예약한 행동이 이어서 보인다.
- **선택 대기**: **명령** 탭 맨 위에 "선택 대기 · (안내 글)" 패널이 생긴다(오른쪽에 "1개 고르기"·"1~2개 고르기"). 후보 버튼을 누르면 앞에 ✓가 붙고, 다시 누르면 빠진다. 하나만 고르는 선택은 다른 버튼을 누르면 바꿔 고른다. **답하기**는 `Game.Answer`와 같다. 개수가 틀리면 "1개를 골라야 합니다(고른 것 0개)." 같은 알림이 뜨고 아무것도 바뀌지 않는다. 기다리는 선택이 여럿이면 패널도 여럿이다. 게임 화면이 아직 없어도 여기서 시험할 수 있다.
- 답하기는 행동 "선택: card3"(공개)으로 **행동** 탭에 남고 Undo된다. 그 안에 이어서 할 행동이 보인다(`선택 요구` Block이면 "고른 것에 효과", 개발자).

## 4. 코드로 쓰는 법 — 문법 요소를 하나씩

### 4-1. `Game.ApplyStatus` · `Game.RemoveStatus` · `Game.ShortenStatus` — 걸기·풀기·줄이기

```csharp
Game.ApplyStatus(enemy, GameIds.Status.Poison, stacks: 3);            // 객체로
Game.ApplyStatus("hero", GameIds.Status.Rage);                         // id 글자로도
Game.ApplyStatus(enemy, GameIds.Status.Stun, length: 1);               // 이번만 1턴(정의의 길이 대신)
Game.ApplyStatus(enemy, GameIds.Status.Poison, 2, by: hero);           // 건 개체(처치 기여) = hero
Game.RemoveStatus(enemy, GameIds.Status.Poison, stacks: 1);            // 1중첩만 줄이기
Game.RemoveStatus(enemy, GameIds.Status.Poison);                       // 통째로 풀기
Game.ShortenStatus(hero, GameIds.Status.FireballCd, 1);                // 남은 지속 −1(쿨다운 −1)
int cleansed = Game.RemoveStatuses(hero, StatusKind.Debuff);           // 디버프 모두 풀기(정화). 푼 가짓수
if (Game.ApplyStatus(hero, GameIds.Status.Poison) == null) { /* 가로채기가 막았다(면역) */ }
```

| 멤버 | 뜻 |
|---|---|
| `ActiveStatus ApplyStatus(object target, string statusId, int stacks = 1, string source = null, double? length = null, object by = null)` | 건다. 걸기 직전에 의도 `상태 효과 걸기`를 거친다(2-1b). 이미 걸려 있으면 다시 걸 때 규칙을 따른다. 돌려주는 값은 걸린 것(새로 생겼거나 이미 있던 것). 가로채기가 막았으면 `null`. `stacks`가 1보다 작으면 1. `length`를 주면 이번에 걸 때만 그 길이(이벤트 횟수 또는 초, 2-1). `by`(건 개체, 객체 또는 id)는 걸린 것의 `by`·`StatusApplied.by`가 된다 |
| `bool RemoveStatus(object target, string statusId, int stacks = 0)` | 푼다. `stacks`를 주면 그만큼 줄이고 남는 중첩이 없으면 푼다. 0이면 통째로. 걸려 있지 않았으면 `false`. 끝날 때 결과는 돌지 않는다 |
| `bool ShortenStatus(object target, string statusId, double amount)` | 남은 지속을 줄인다(이벤트 횟수면 반올림한 횟수, 게임 시간이면 초). 다 되면 지속이 다 된 것으로 끝난다(끝날 때 결과가 돈다). 영구·걸려 있지 않음·`amount` 0 이하면 `false` |
| `int RemoveStatuses(object target, StatusKind kind)` | 그 종류(`StatusKind.Buff`·`Debuff`)의 상태 효과를 모두 통째로 푼다(정화, 2-1c). 푼 가짓수. 끝날 때 결과는 돌지 않는다 |

- `target`은 `id`가 있는 객체 또는 id 글자, `statusId`는 상태 효과 ID(`GameIds.Status.X`), `source`는 출처로 남길 글자(건 항목 ID, 비우면 빈 글자)다. `source`는 다시 걸어도 처음 값 그대로이고, `by`는 마지막에 건 쪽으로 바뀐다. "독으로 쓰러뜨린 쪽"은 `by`로 본다.
- 행동 안에서 부른다(Undo·저장·멀티플레이 기록).
- 없는 상태 효과면 `InvalidOperationException`("[MomoiProject] 없는 상태 효과 'poisn'입니다."), 대상에 id가 없으면 "[MomoiProject] 상태 효과를 걸 대상의 id가 없습니다." 예외로 그 행동이 취소된다. 가로채기가 없는 상태 효과로 바꿨으면 "[MomoiProject] 가로채기가 바꾼 상태 효과 'bluBurn'가 없습니다." 예외다.

### 4-2. 읽기 — `StatusStacks` · `HasStatus` · `Statuses` · `ActiveStatus`

```csharp
int stacks = Game.StatusStacks(enemy, GameIds.Status.Poison);   // 걸려 있지 않으면 0
bool shielded = Game.HasStatus(run.hero, GameIds.Status.Shield);
foreach (var s in Game.Statuses(run.hero)) icons.Add(s.status, s.stacks);   // 화면: 상태 아이콘 줄
int debuffs = Game.StatusCount(enemy, StatusKind.Debuff);                     // 디버프 가짓수(중첩 아님)
```

| 멤버 | 뜻 |
|---|---|
| `int StatusStacks(object target, string statusId)` | 중첩 수. 걸려 있지 않으면 0 |
| `bool HasStatus(object target, string statusId)` | 걸려 있는지(중첩 > 0) |
| `int StatusCount(object target, StatusKind kind)` | 그 종류가 몇 가지 걸려 있는지(2-1c) |
| `IReadOnlyList<ActiveStatus> Statuses(object target)` | 그 대상에 걸린 것 전부(새 목록) |

| `ActiveStatus` 필드 | 뜻 |
|---|---|
| `id` | 걸린 것의 id(`$status1` …). 능력치 보정의 출처이기도 하다 |
| `status` | 상태 효과 ID |
| `target` | 가진 쪽 id |
| `stacks` | 중첩 |
| `remaining` | 이벤트 지속: 남은 횟수 / 시간 지속: 끝나는 게임 시각(`session.Clock.Time` 기준. 남은 초 = `remaining − Clock.Time`) / 영구: 0 |
| `source` | 출처(건 항목 ID, 처음 건 값) |
| `by` | 마지막에 건 개체 id(다시 걸면 바뀐다) |
| `nextPulse` | 주기가 있으면 다음 결과를 낼 게임 시각(없으면 0) |
| `pulse` | 가로채기가 바꾼 이 걸린 것의 주기(초). 0이면 정의의 주기 |
| `maxStacks` | 이 걸린 것의 최대 중첩(마지막에 건 의도의 값, 0 = 제한 없음) |

값을 바꾸지 않으므로 화면 코드(행동 밖)에서 읽어도 된다. 걸린 것의 필드를 직접 고치지 않는다(걸기·풀기·줄이기로 바꾼다).

**아이콘·화면에 숨김** — 걸린 것에는 그림이 없다. 정의(DB 항목 `StatusData`)의 `icon`·`hidden`을 ID로 찾아 읽는다.

```csharp
var defs = GameDatabase.Load().All<StatusData>().ToDictionary(s => s.Id);   // 한 번만 만들어 둔다
foreach (var s in Game.Statuses(run.hero))
    if (defs.TryGetValue(s.status, out var data) && !data.hidden) icons.Add(data.icon, s.stacks);
```

DB 없이 정의만 있으면 `session.Statuses.Find(id).Hidden`(아이콘은 DB 항목에만 있다).

### 4-3. 결과를 코드로 — `[BindTo(상태 효과 ID)]`

계산이나 분기가 있으면 걸려 있는 동안의 결과를 함수 하나로 쓴다(→ `13-BindTo.md`).

```csharp
public static class StatusCode
{
    // 트리거가 이벤트 받기면 첫 매개변수가 그 이벤트
    [BindTo(GameIds.Status.Poison)]
    static void Poison(TurnEnded e, TriggerContext c)
    {
        var holder = (Fighter)c.User;                                              // 가진 쪽
        Rules.Damage(c.Game, null, holder, c.Game.StatusStacks(holder, c.Owner));   // Owner = 상태 효과 ID
    }

    // 트리거가 가로채기면 첫 매개변수가 의도
    [BindTo(GameIds.Status.Shield)]
    static void Shield(DamageIntent i, TriggerContext c) => i.amount /= 2;
}
```

- 연결된 코드는 `outcomes`(걸려 있는 동안의 결과)를 대신한다. `onApply`·`onExpire`는 대신하지 않고 DB에서 그대로 고친다(3-1).
- 트리거가 참인 가진 쪽마다 한 번씩 불린다. 가진 쪽 필드로 거르고, 트리거(조건 포함)를 그 가진 쪽으로 검사한 뒤다(2-3).
- 조건 충족만으로 된 트리거와 주기(`pulse`)에는 이벤트가 없으므로 `(TriggerContext c)`만 받는다.
- 가진 쪽에 따른 조건은 트리거의 조건 Block으로 둔다(DB에서 보이고 조립된다). 조건 Block의 `Context.User`가 그 가진 쪽이다:

```csharp
[Serializable, BlockInfo("가진 쪽 체력 절반 이하", Category = "상태 효과")]
public class HolderHpHalf : SimpleCondition
{
    protected override bool Check() => Context?.User is Fighter f && f.hp * 2 <= f.maxHp;
}
```

트리거 `턴 끝 받기` AND `가진 쪽 체력 절반 이하`. 코드 안에서 판단해도 된다: `if (((Fighter)c.User).hp * 2 > ((Fighter)c.User).maxHp) return;`

### 4-4. 정의를 코드로 — `StatusDefinition` · `session.Statuses`

게임(Unity)에서는 런타임이 시작할 때 DB의 상태 효과 전부를 등록한다. 서버·테스트처럼 세션을 직접 만들 때는 직접 등록한다.

```csharp
foreach (var status in GameDatabase.Load().All<StatusData>()) session.Statuses.Define(status.ToDefinition());

// DB 없이 코드로(테스트 등)
var poison = new StatusDefinition
{
    Id = "poison", MaxStacks = 0, Reapply = StatusReapply.AddStacksAndRefresh,
    Duration = StatusDuration.Events, Length = 3, TickEvent = typeof(TurnEnded).FullName,
    When = new EventTrigger { eventType = typeof(TurnEnded).FullName },
};
poison.Outcomes.Add(new PoisonTick());          // 코딩한 결과(Reward) 등
session.Statuses.Define(poison);

var scorch = new StatusDefinition { Id = "scorch", MaxStacks = 1, Duration = StatusDuration.Seconds, Length = 3, Pulse = 0.5 };   // 3초 동안 0.5초마다
scorch.Outcomes.Add(new TargetedOutcome { effects = { new DealDamage { amount = 2 } } });
session.Statuses.Define(scorch);
```

| `StatusDefinition` | 뜻 | DB 칸 |
|---|---|---|
| `Id` · `DisplayName` | ID · 표시 이름 | 항목 ID |
| `MaxStacks` | 최대 중첩(0 = 제한 없음, 코드 기본 0) | `maxStacks` |
| `Reapply` | 다시 걸 때(코드 기본 `AddStacks`) | `reapply` |
| `Duration` · `Length` | 지속 방식 · 길이 | `duration.kind` · `duration.length` |
| `TickEvent` · `TickHolderField` | 셀 이벤트(형식의 전체 이름) · 지속의 가진 쪽 필드 | `duration.tickEvent` · `duration.holderField` |
| `Modifiers` (`List<StatusModifier>`) | 능력치 보정(`attribute` · `kind` · `valuePerStack`) | `modifiers` |
| `When` · `HolderField` | 걸려 있는 동안 트리거 · 가진 쪽 필드 | `trigger` · `holderField` |
| `Pulse` | 주기(초). 0보다 크면 그 초마다 `Outcomes` | `pulse` |
| `Outcomes` · `OnApply` · `OnExpire` | 결과 · 걸릴 때 결과 · 끝날 때 결과 | `outcomes` · `onApply` · `onExpire` |
| `Hidden` | 화면에 숨김(규칙은 보지 않는다) | `hidden` |
| `Kind` | 종류(`StatusKind.None` · `Buff` · `Debuff`, 코드 기본 `None`) | `kind` |
| `Silences` | 걸린 쪽의 패시브를 끈다(2-3) | `silencesPassives` |

아이콘(`icon`)은 DB 항목(`StatusData`)에만 있고 정의에는 없다(4-2).

| `session.Statuses` (`StatusSystem`) | 뜻 |
|---|---|
| `Define(definition)` | 등록(같은 ID면 바꾼다). 트리거도 이때 등록한다 |
| `Find(id)` · `Definitions` | 정의 찾기 · 전부 |
| `Apply` · `Remove` · `Shorten` · `Stacks` · `Of` | `Game.ApplyStatus` · `RemoveStatus` · `ShortenStatus` · `StatusStacks` · `Statuses`와 같다 |
| `CountOfKind` · `RemoveKind` | `Game.StatusCount` · `RemoveStatuses`와 같다 |
| `Key` | `"$statuses"` |

- `StatusData.ToDefinition()`은 DB 항목을 정의로 바꾼다. 그 ID에 `[BindTo]`가 있으면 `Outcomes`가 그 코드가 된다.
- 코드 정의의 기본값은 DB와 다르다(DB는 최대 중첩 1, 다시 걸 때 `중첩 더하고 지속 갱신`). 코드로 만들 때는 두 값을 적는다.

### 4-5. Block 형식 — `ApplyStatusEffect` · `RemoveStatusEffect` · `ShortenStatusEffect` · `StatusCondition` · `StatusFilterTarget`

```csharp
var dart = new TargetedOutcome { effects = { new DealDamage { amount = 4 }, new ApplyStatusEffect { status = "poison", stacks = 3 } } };
var cleanse = new TargetedOutcome { targets = { new SelfTarget() }, effects = { new RemoveStatusEffect { status = "poison" } } };
var recharge = new TargetedOutcome { targets = { new SelfTarget() }, effects = { new ShortenStatusEffect { status = "fireballCd", amount = 1 } } };
var ready = new StatusCondition { who = StatusSubject.User, status = "fireballCd", op = CompareOp.AtMost, stacks = 0 };   // 쿨다운이 없을 때
var purify = new TargetedOutcome { targets = { new SelfTarget() }, effects = { new RemoveStatusEffect { kind = StatusKind.Debuff } } };   // 디버프 모두 풀기
var weakened = new StatusCondition { kind = StatusKind.Debuff, op = CompareOp.AtLeast, stacks = 2 };                                   // 디버프 2가지 이상
var spread = new TargetedOutcome { targets = { new DataListTarget { key = "run", path = "battle.enemies" }, new StatusFilterTarget { status = "poison" } }, effects = { new DealDamage { amount = 3 } } };   // 독에 걸린 적 모두
```

| 형식 | 화면 이름 | 필드 |
|---|---|---|
| `ApplyStatusEffect` | 상태 효과 걸기 | `status`(상태 효과 ID) · `stacks`(기본 1, × 효과 배율) · `length`(0 = 정의의 길이). 건 개체 = 사용자 |
| `RemoveStatusEffect` | 상태 효과 풀기 | `status` · `kind`(`StatusKind`, `status`가 비었을 때 그 종류 전부) · `stacks`(0 = 모두) |
| `ShortenStatusEffect` | 상태 효과 줄이기 | `status` · `amount`(기본 1) |
| `StatusCondition`(조건) | 상태 효과 검사 | `who`(`StatusSubject.User` · `EventField`) · `eventField` · `status` · `kind`(`status`가 비었을 때 그 종류의 가짓수) · `op`(`CompareOp`) · `stacks`(기본 1) |
| `StatusFilterTarget`(대상) | 상태 효과로 거르기 | `status` · `kind` · `op` · `stacks`(`StatusCondition`과 같고 `who`가 없다 — 앞의 대상마다 본다) |

### 4-5b. 의도 `StatusIntent` — 걸기를 코드로 가로채기

DB에서는 가로채기 잎 + `의도 고치기`로 만든다(5-14~5-16). 세션을 직접 만드는 테스트나, 계산이 필요한 가로채기는 코드로 쓴다.

```csharp
// 패시브 "푸른 불꽃"(화상 → 푸른 화상)을 코드로 등록할 때
var blueFlame = new PassiveDefinition
{
    Id = "blueFlame", OwnerKey = "run", OwnerPath = "relics",
    When = new InterceptTrigger { intentType = typeof(StatusIntent).FullName, filter = new FieldFilter { path = "statusId", op = FieldOp.Equal, value = "burn" } },
};
blueFlame.Outcomes.Add(new ModifyIntentOutcome { path = "statusId", op = IntentOp.Set, value = "blueBurn" });
session.Passives.Define(blueFlame);

// [BindTo]로: 디버프면 중첩 +1(계산이 들어가는 가로채기)
[BindTo(GameIds.Passive.Cruelty)]
static void Cruelty(StatusIntent i, TriggerContext c) { if (i.kind == StatusKind.Debuff) i.stacks += 1; }
```

| `StatusIntent` 필드 | 뜻 |
|---|---|
| `targetId` · `statusId` · `stacks` · `length` · `sourceId` | 걸릴 대상 id · 상태 효과 ID · 중첩 · 길이 · 출처. 고치면 그대로 걸린다(2-1b) |
| `byId` | 건 개체 id. 걸린 것의 `by`가 된다 |
| `maxStacks` · `pulse` | 이번에 걸 것의 최대 중첩(0 = 제한 없음) · 주기(초). 처음은 정의의 값(2-1b) |
| `kind` (`StatusKind`) | 처음 상태 효과의 종류(읽기용) |
| `cancelled` | 참이면 걸지 않는다 |

- `[Intent("상태 효과 걸기")]`가 붙은 기본 제공 의도다. DB 가로채기 잎의 의도 목록에 `상태 효과 걸기`로 나온다.
- `[BindTo]` 함수의 첫 매개변수가 의도다(4-3, 28장 4-10).

### 4-6. 예약 — `Game.ScheduleAfter` · `ScheduleOn` · `CancelSchedule(s)`

```csharp
string id = Game.ScheduleAfter(2.5, new DelayedHit { target = enemy, amount = 20 });               // 게임 시간 2.5초 뒤
Game.ScheduleOn<TurnStarted>(1, new DrawCards { count = 2 }, source: GameIds.Instance.Foresight);   // 턴 시작을 1번 받은 순간
Game.CancelSchedule(id);                                                                           // 하나 취소
Game.CancelSchedules(GameIds.Instance.Foresight);                                                  // 그 출처의 예약 모두 취소
```

| 멤버 | 뜻 |
|---|---|
| `string ScheduleAfter(double seconds, GameAction action, string source = null, bool permanent = false)` | 게임 시간 `seconds`초 뒤(0보다 작으면 0) 프레임 끝(고정 틱이면 그 틱)에 실행. 돌려주는 값은 예약 id(`$schedule1` …). `permanent: true`는 예외(2-5) |
| `string ScheduleOn<TEvent>(int count, GameAction action, string source = null, bool permanent = false)` | `TEvent`를 `count`번(1보다 작으면 1) 받은 순간, 그 이벤트를 쏜 행동 안에서 실행 |
| `bool CancelSchedule(string id)` | 그 예약을 지운다. 지웠으면 `true` |
| `int CancelSchedules(string source)` | 그 출처의 예약을 모두 지운다. 지운 개수 |

- `action`은 행동 객체다. 대상 필드는 id만 남고 실행 직전에 다시 찾는다(2-5). 행동 클래스는 다른 행동처럼 `[Serializable]`로 둔다.
- `source`는 나중에 한꺼번에 지울 때 쓰는 글자(보통 이 예약을 건 항목 ID)다.
- `permanent: true`면 메타 구역(프로필)에 저장되어 새 판에도 남는다. 이벤트 예약(`ScheduleOn`)만 된다. `ScheduleAfter`에 주면 `InvalidOperationException`(2-5).
- 걸기·취소 모두 행동 안에서 부른다.
- `action`이 `null`이면 `ArgumentNullException`.

### 4-8. 선택 대기 — `Game.Ask`

```csharp
// 후보 = id가 있는 객체(덱 카드·적 …)
Game.Ask("버릴 카드", handCards, new DiscardChosen(), min: 1, max: 1, label: o => Rules.CardData(Game, ((DeckCard)o).card)?.title);

// 후보 = id 글자(손패 battle.hand 같은 id 목록을 그대로, DB 원본 ID)
Game.Ask("버릴 카드", Game.Data().Run.battle.hand, new DiscardChosen());

// 후보 = 글 선택지(id와 보일 글을 직접: "공격/방어" 같은 선택)
Game.Ask("자세", new[] { new ChoiceCandidate("attack", "공격"), new ChoiceCandidate("guard", "방어") }, new ChooseStance());
```

| 멤버 | 뜻 |
|---|---|
| `string Ask(string prompt, IEnumerable<object> candidates, GameAction then, int min = 1, int max = 1, string source = null, string player = null, Func<object, string> label = null)` | 후보로 요구한다. 후보는 `id`가 있는 객체 또는 id 글자(글자 자체가 id). `label`은 후보마다 보일 이름을 만드는 함수. 비우거나 `null`을 돌려주면 텍스트 표의 `<id>.name`(없으면 id) |
| `string Ask(string prompt, IEnumerable<ChoiceCandidate> options, GameAction then, int min = 1, int max = 1, string source = null, string player = null)` | 글 선택지로 요구한다(보일 글을 직접 준다) |

- 돌려주는 값은 선택 id(`$choice1` …). 후보가 없어 바로 이어 간 경우는 `null`.
- `then`은 이어서 할 행동이다. `[Chosen]` 필드가 있어야 한다(4-9). 없으면 `InvalidOperationException`("[MomoiProject] 이어서 할 행동 'X'에 고른 것을 받을 [Chosen] 필드가 없습니다.").
- `source`는 요구한 항목 ID(기록용), `player`는 답할 플레이어(2-6).
- 행동 안에서 부른다. 다음 줄은 고르기 전에 실행된다.
- 후보가 글자면 그 글자가 id다. 카드 던전의 손패(`battle.hand`)는 덱 카드 **id 글자 리스트**라서 그대로 넘긴다. 이어서 할 행동의 `[Chosen]`이 객체 칸(`List<DeckCard>`)이면 답할 때 그 id로 지금 데이터의 덱 카드를 찾아 넣는다(4-9).
- 객체 후보 형식에 `id`가 없으면 예외다("[MomoiProject] Unit에 string id 필드가 없어 개체로 찾거나 가리킬 수 없습니다.").

### 4-9. `[Chosen]` — 고른 것을 받는 칸

```csharp
[Serializable, BlockInfo("고른 카드 버리기")]
public class DiscardChosen : GameAction
{
    [Chosen] public List<DeckCard> cards = new List<DeckCard>();   // 고른 것이 여기 들어온다
    protected override void Run() { /* cards로 할 일 */ }
}
```

| `[Chosen]` 필드 형식 | 들어오는 것 |
|---|---|
| `string` | 고른 id 하나(고르지 않았으면 `null`) |
| `id`가 있는 클래스(`DeckCard`) | 고른 객체 하나. 실행 직전에 id로 지금 데이터에서 찾는다 |
| 위의 `List<…>` · 배열 | 고른 것 여럿(고른 순서대로) |

- 한 행동에 하나만 둔다(처음 것만 쓴다). 다른 형식이면 요구할 때 "[MomoiProject] 'X.f': [Chosen] 필드는 string, id가 있는 클래스, 그 리스트·배열이어야 합니다." 예외.
- 객체 칸은 답하는 순간 다시 찾는다. 그 사이 후보가 데이터에서 사라졌으면 "… 'card3'을(를) 찾을 수 없습니다" 로 답하기가 실패한다. 사라질 수 있는 후보는 `string` 칸으로 받고 이어서 할 행동에서 `Game.Find`로 확인한다.
- 글 선택지(`ChoiceCandidate`)와 DB 원본 ID 후보는 `string` 칸으로 받는다(플레이어 데이터 객체가 아니다).
- 이어서 할 행동의 다른 필드(수치·원본 ID·대상 객체)는 요구할 때 채워 둔다. 대상 필드는 예약처럼 id만 저장된다.

### 4-10. 답하기·읽기 — `Choice` · `Choices` · `IsWaiting` · `Answer` · `CancelChoice`

```csharp
var choice = Game.Choice;                                  // 지금 기다리는 선택(없으면 null)
if (Game.IsWaiting) return;                                // 입력 막기
Game.Answer(choice.id, pickedCard);                        // 객체로
Game.Answer(choice.id, "card2", "card5");                  // id로
Game.Answer(choice.id, picked.Cast<object>().ToList());    // 목록으로
```

| 멤버 | 뜻 |
|---|---|
| `PendingChoice Choice` | 지금 답을 기다리는 선택(먼저 요구한 것). 없으면 `null` |
| `IReadOnlyList<PendingChoice> Choices` | 기다리는 선택 전부(먼저 요구한 순서) |
| `bool IsWaiting` | 기다리는 선택이 있는지 |
| `ActionRecord Answer(string choiceId, IEnumerable<object> picked)` · `Answer(string choiceId, params object[] picked)` | 답한다(행동 밖, 플레이어 입력에서). 고른 것은 객체 또는 id 글자. 행동 `ChoiceAnswer` 하나로 실행된다 |
| `bool CancelChoice(string choiceId)` | 기다리는 선택을 답 없이 지운다(이어서 할 행동은 돌지 않는다). 행동 안에서 부른다 |
| `bool RerollChoice(string choiceId)` | 표로 만든 선택의 후보를 새로 뽑는다(4-10b). 행동 안에서 부른다 |

답하기가 실패하면 예외가 `Answer`를 부른 쪽으로 온다. 플레이어에게 보일 실패라 `GameFailure`(`InvalidOperationException`을 상속, `30-Balance-Tables.md` 2-4)이고, 메시지는 텍스트 표에 그 키가 있으면 번역된 글이다.

| 경우 | 메시지(기본 문장) | 텍스트 키(`FailureKeys`) |
|---|---|---|
| 개수가 맞지 않음(최소 = 최대) | "{count}개를 골라야 합니다(고른 것 {picked}개)." | `ChooseExactly` |
| 개수가 맞지 않음(범위) | "{min}~{max}개를 골라야 합니다(고른 것 {picked}개)." | `ChooseBetween` |
| 후보가 아님 | "{item}은(는) 고를 수 있는 후보가 아닙니다." | `NotACandidate` |
| 같은 것을 두 번 | "같은 것을 두 번 골랐습니다." | `ChosenTwice` |
| 이미 답했거나 취소됨 | "이미 답했거나 취소된 선택입니다." | `ChoiceGone` |

### 4-10b. 다시 뽑기 — `Game.RerollChoice`

"보상 다시 뽑기(남은 횟수 1)"처럼 기다리는 선택의 후보를 새로 뽑는다. 결과 `가중치 표에서 고르기`(30장 3-3)로 만든 선택만 된다.

```csharp
[Serializable, BlockInfo("보상 다시 뽑기")]
public class RerollReward : GameAction
{
    public string choice;     // 기다리는 선택 id(Game.Choice.id)

    protected override void Run()
    {
        Game.Pay(GameIds.PlayerData.Run.Id, "rerolls", 1, what: "reroll.name");   // 남은 횟수가 없으면 실패 → 아무것도 바뀌지 않는다
        if (!Game.RerollChoice(choice)) throw Game.Fail("fail.cannotReroll", "다시 뽑을 수 없는 선택입니다.");
    }
}

// 화면(고르기 창의 '다시 뽑기' 버튼): 입력 창구를 거치지 않고 바로 보낸다(아래)
Game.Do(new RerollReward { choice = Game.Choice.id });
```

| 규칙 | 뜻 |
|---|---|
| 같은 표 · 같은 후보 수 | 처음 요구할 때의 표·후보 수(후보 수에 더한 숫자까지 넣은 값)·서로 다른 것만으로 다시 뽑는다. 그 사이 `countBonus`(후보 수에 더할 숫자)가 가리키는 값이 바뀌어도 후보 수는 그대로다 |
| 같은 선택 | 선택 id·안내 글·이어서 할 행동은 그대로다. 후보(`options`)만 바뀐다. 최소·최대 개수는 새 후보 수를 넘지 않게 줄인다 |
| 다시 쏘기 | `ChoiceRequested`를 같은 선택 id로 다시 쏜다. 화면은 이것을 받아 고르는 중인 표시를 비우고 새 후보를 그린다 |
| 비용 | `RerollChoice`는 비용·남은 횟수를 보지 않는다. 부르는 행동이 `Game.Pay` 등으로 정한다 |
| 난수 | 그 표의 난수 흐름을 이어서 쓴다(30장 2-3). 같은 시드·같은 순서면 같은 후보가 나온다 |
| Undo | 다시 뽑은 행동을 Undo하면 원래 후보로 돌아간다(낸 비용도) |
| `false` | 표로 만든 선택이 아니거나(`Game.Ask`·`선택 요구`), 이미 답한 선택이거나, 표에서 아무것도 나오지 않았다(모두 꽝). 그때 후보는 그대로다 |

- `false`일 때 낸 비용을 되돌리려면 위처럼 `throw Game.Fail`로 행동을 실패시킨다(바꾼 것이 모두 취소된다, 30장 2-4).
- **화면의 다시 뽑기 버튼.** 기본 고르기 창은 `GameScreens.Reroll`(선택 → 다시 뽑기 행동, null이면 숨김)을 정하면 '가중치 표에서 고르기'로 만든 선택에 '다시 뽑기' 버튼을 보인다: `GameScreens.Reroll = choice => Game.Data().Run.rerolls > 0 ? new RerollReward { choice = choice.id } : null;`(시작 코드에서 한 번). 직접 만든 고르기 창에서는 `GameScreens.Do(() => 행동, whileChoosing: true)`로 보낸다 — 보통의 `OnClick`·`GameScreens.Do`는 기다리는 동안 행동을 보내지 않는다(35장). 다시 뽑으면 기본 고르기 창의 고른 표시는 지워진다. 다시 뽑아도 최소·최대는 처음 요구한 값을 기준으로 맞춘다(후보가 줄었다 늘어도 돌아온다).

### 4-11. `PendingChoice` · `ChoiceCandidate` · `ChoiceRequested` · `ChoiceAnswer`

| `PendingChoice` 필드 | 뜻 |
|---|---|
| `id` | 선택 id(`$choice1` …) |
| `prompt` | 안내 글 |
| `player` | 답할 플레이어(비우면 누구나) |
| `source` | 요구한 항목 ID |
| `options` (`List<ChoiceCandidate>`) | 후보들 |
| `min` · `max` | 고를 개수(2-6의 규칙으로 맞춘 값) |
| `then` | 이어서 할 행동 |
| `table` · `count` · `unique` | `가중치 표에서 고르기`로 만든 선택이면 그 표 ID · 후보 수 · 서로 다른 것만(다시 뽑기용, 4-10b). 그 밖의 선택은 `table`이 비어 있다 |

- `ChoiceCandidate { id, label }` — 후보 하나. `new ChoiceCandidate(id, label)`에서 `label`을 비우면 id가 이름이다.
- `ChoiceRequested`(`[GameEvent("선택 요구")]`: `choice` · `prompt` · `player`) — 선택을 요구한 순간 쏜다. 화면은 `SubscribeAfterAction`으로 받아 고르기 창을 연다(요구한 행동이 실패하면 오지 않는다). 다시 뽑기(`Game.RerollChoice`)도 같은 선택 id로 다시 쏜다. 답하기를 Undo해서 다시 기다리게 될 때는 다시 쏘지 않는다. 창의 내용은 `Game.Choice`로 그린다(5-10).
- `ChoiceAnswer`(`choice` · `picked`) — 답하기 행동. 공개 행동이라 타임라인·행동 탭에 "선택: card3"(고르지 않았으면 "선택: 고르지 않음")으로 남는다. 멀티플레이에서는 이 행동이 서버로 간다.
- `session.Choices`(`ChoiceSystem`): `Ask(prompt, options, then, min, max, source, player)`(글 선택지 형태) · `Current`(= `Game.Choice`) · `All` · `Cancel(id)` · `Reroll(id)`(= `Game.RerollChoice`) · `MarkTable(id, table, count, unique)`(표로 만든 선택이라고 적어 둔다. 코드로 표에서 뽑아 `Ask`한 선택도 이것을 부르면 다시 뽑을 수 있다) · `Key`(`"$choices"`).

|---|---|
| `ActionReferences.Detach(action)` | 행동의 대상 필드를 id만 든 객체로 바꾼다. 예약·선택 대기가 행동을 맡을 때 쓴다 |
| `ActionReferences.CanResolve(action, game)` | 대상 필드가 가리키는 객체가 지금 데이터에 모두 있는지. 예약이 실행 전에 확인한다 |
| `StatusExpireRun` · `StatusPulseRun` · `ScheduledRun` | 시간 만료·주기 결과·시간 예약을 실행하는 라이브러리 행동(개발자, "상태 효과 만료"·"상태 효과 주기"·"예약 실행") |

### 4-14. 이벤트 `StatusApplied` · `StatusEnded`

```csharp
// 규칙 쪽(행동 안에서 받는다): 독에 걸릴 때마다 가진 쪽 방어도 +2
session.Events.Subscribe<StatusApplied>(e =>
{
    if (e.status == GameIds.Status.Poison && session.Game.Find<Fighter>(e.holder) is Fighter f) f.block += 2;
});

// 화면 쪽(성공한 행동의 이벤트만): 끝날 때 연출
GBibleRuntime.Session.Events.SubscribeAfterAction<StatusEnded>(e => { if (e.expired) PlayFade(e.holder, e.status); });
```

| 형식 | 필드 |
|---|---|
| `StatusApplied` | `holder` · `status` · `stacks`(걸린 뒤) · `source` · `by`(이번에 건 개체) |
| `StatusEnded` | `holder` · `status` · `expired`(지속이 다 됨 = 참, 풀림 = 거짓) |

쏘는 때·쏘지 않는 때는 2-8. DB에서는 이벤트 받기 `상태 효과 걸림`·`상태 효과 끝남`으로 고른다.

## 5. 상황별 예제

예제는 구현 가이드(AI/BuildGuide)의 카드 던전 형식을 쓴다(`Tools/GuideExample`). 이 장에 필요한 부분만 옮긴다.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using GBible;
using GBible.Ids;

[Serializable] public class Fighter { public string id; public string name; public int hp, maxHp, block; public bool IsDead => hp <= 0; }
[Serializable] public class Hero : Fighter { public int energyPerTurn = 3, drawPerTurn = 5; }
[Serializable] public class Enemy : Fighter { public string monster; public int intentIndex; }
[Serializable] public class DeckCard { public string id; public string card; public bool upgraded; }   // card = 원본(DB › 인스턴스) ID

[Serializable]
public class Battle
{
    public int turn, energy;
    public List<Enemy> enemies = new List<Enemy>();
    public List<string> drawPile = new List<string>(), hand = new List<string>(), discard = new List<string>();   // 덱 카드 id
}

[GameEvent("턴 끝")] public class TurnEnded { public int turn; public int damage; }
[GameEvent("턴 시작")] public class TurnStarted { public int turn; }
[Serializable, Intent("피해")] public class DamageIntent { public string sourceId, targetId; public int amount; public bool cancelled; }

// 플레이어 데이터 "run"(RunState, 세션 구역): hero · deck(List<DeckCard>) · battle(전투 밖이면 null) …
// Rules.Damage(game, source, target, amount): 가로채기(DamageIntent) → 방어도 → 체력 → 피해 이벤트 → 쓰러진 적은 전투에서 뺀다.
// Rules.CardOf(game, id): 덱 카드 찾기. Rules.CardData(game, 원본 ID): 카드 원본(Card: title · cost …) 읽기.
// EndTurn: 턴 끝(TurnEnded)을 쏜다 → 적이 공격한다 → 손패를 버린다 → 카드를 뽑는다 → 턴 시작(TurnStarted)을 쏜다.
// WinBattle(전투 승리)도 그 턴의 턴 끝을 쏜다.
```

- ID 상수(`GameIds.Status.Poison`, `GameIds.Instance.PoisonDart` …)는 DB에 항목을 만들고 저장하면 생긴다.
- 5-2는 `Fighter`에 능력치 `public double attack = 10;`(공격력)이 있다고 본다(가이드 예제에는 없다).

### 5-1. 독 — 턴 끝마다 중첩만큼 피해, 3턴

**에디터**(DB › 상태 효과 `poison`):

1. `maxStacks` `0`(제한 없음), `reapply` `중첩 더하고 지속 갱신`.
2. `duration`: `kind` `이벤트 횟수`, `length` `3`, `tickEvent` `턴 끝`. 가진 쪽 필드는 비운다.
3. `trigger`: `+ 블럭` → `이벤트 받기` → `턴 끝`. `holderField`는 비운다(턴 끝에는 가진 쪽 id가 없다. 걸린 대상 모두가 받는다).
4. 결과는 중첩 수를 읽는 계산이라 코드로 쓴다(4-3의 `StatusCode.Poison`). `outcomes` 칸은 잠기고 함수 이름이 보인다.

**카드** `poisonDart`(독침): 사용 기능 결과 `대상에게 효과` → 대상 비움(고른 적) → 효과 `피해`(4) → `상태 효과 걸기`(`poison`, 중첩 `3`). 요약 `고른 대상: 피해 4, poison 3중첩 걸기`.

숫자로 따라가기 — 고블린에게 독침을 두 번:

| 순간 | 독 피해 | 중첩 | 남은 횟수 |
|---|---|---|---|
| 턴 1: 독침 | — | 3 | 3 |
| 턴 1 끝 | 3 | 3 | 2 |
| 턴 2: 독침 한 번 더 | — | 6 | 3(갱신) |
| 턴 2 끝 | 6 | 6 | 2 |
| 턴 3 끝 | 6 | 6 | 1 |
| 턴 4 끝 | 6 | — | 0 → 끝 |

- 같은 턴 끝이 피해와 횟수 줄이기를 둘 다 하므로 피해가 먼저다(2-2). 그래서 마지막 턴 끝에도 피해가 들어간다.
- 독 피해도 `Rules.Damage`를 거치므로 보호막(5-3)·가시 갑옷 같은 가로채기를 탄다. 출처는 `null`이라 "이번 턴 준 피해"에 들어가지 않는다.
- 카드 던전은 전투 승리(`WinBattle`)도 턴 끝을 쏘므로 그때도 한 번 센다.
- 코드 없이 쓰려면 "중첩만큼 피해" 효과 Block을 하나 만들어 `outcomes` = `대상에게 효과`(대상 비움 = 가진 쪽) → 효과 `중첩만큼 피해`로 조립한다. 이 Block은 상태 효과의 결과에서만 뜻이 있다(`Owner`가 상태 효과 ID일 때).

```csharp
[Serializable, BlockInfo("중첩만큼 피해", Category = "상태 효과", Sentence = "중첩 × {perStack} 피해")]
public class StackDamage : Effect<Fighter>
{
    public int perStack = 1;
    protected override void Apply(Fighter target) =>
        Rules.Damage(Game, null, target, perStack * Game.StatusStacks(target, Use.Context.Owner));
}
```

### 5-2. 분노 — 중첩당 공격력 +10%, 최대 3

**에디터**(DB › 상태 효과 `rage`): `maxStacks` `3`, `reapply` `중첩 더하기`, `duration` › `kind` `영구(풀 때까지)`, `modifiers` 한 줄: `attribute` `attack`, `kind` `퍼센트(0.2 = +20%)`, `valuePerStack` `0.1`. 트리거·결과는 비운다.

**카드** `battleCry`(함성): 결과 `대상에게 효과` → 대상 `사용자 자신` → 효과 `상태 효과 걸기`(`rage`).

| 함성을 쓴 횟수 | 중첩 | `Game.Attribute(hero, nameof(Fighter.attack))` |
|---|---|---|
| 0 | — | 10 |
| 1 | 1 | 11 |
| 2 | 2 | 12 |
| 3 | 3 | 13 |
| 4 | 3(최대) | 13 |

- 보정은 Modifier 한 줄(출처 `$status1`, 값 0.1 × 중첩)이다. 중첩이 바뀔 때마다 다시 계산된다. `hero.attack` 필드는 10 그대로다.
- 출처가 상태 효과 ID가 아니라 걸린 것의 id라서 `능력치 보정 떼기(rage)`·`Game.RemoveModifiers("rage")`로는 떨어지지 않는다. 풀어서 뗀다.
- 영구라 풀 때까지 남는다. 전투가 끝날 때 전투 동안의 상태 효과를 모두 풀려면 전투 승리 행동에 더한다.

```csharp
// WinBattle.Run 안
var hero = Game.Data().Run.hero;
foreach (var status in Game.Statuses(hero)) Game.RemoveStatus(hero, status.status);   // 끝날 때 결과는 돌지 않는다
```

### 5-3. 보호막 — 내가 받는 피해 반감, 3턴

**에디터**(DB › 상태 효과 `shield`):

1. `maxStacks` `1`, `reapply` `지속 갱신`.
2. `duration`: `kind` `이벤트 횟수`, `length` `3`, `tickEvent` `턴 시작`.
3. `trigger`: `+ 블럭` → `가로채기` → 의도 `피해`.
4. `holderField`: `targetId`. 피해 의도의 대상이 가진 쪽일 때만 발동한다.
5. `outcomes`: `+ 결과 추가` → `의도 고치기` → 필드 `amount`, 방법 `곱하기`, 값 `0.5`.

**카드** `barrier`(방벽): 결과 `대상에게 효과` → 대상 `사용자 자신` → 효과 `상태 효과 걸기`(`shield`).

- 고블린의 공격 10 → 5. 정수 필드는 곱한 뒤 반올림한다(28장 3-4).
- **가진 쪽 필드가 "내가"를 만든다.** `targetId`를 고르면 주인공에게 걸면 주인공이 맞을 때만, 적에게 걸면 그 적이 맞을 때만 반감한다. 비우면 걸려 있는 동안 누가 맞든 반감한다. 유물 가시 갑옷(28장 5-4)이 의도 조건 `targetId 일치 hero`로 대상을 고정한 것과 다르다.
- **셀 이벤트가 턴 시작인 이유**: `EndTurn`은 턴 끝을 쏜 **다음에** 적이 공격하고, 마지막에 턴 시작을 쏜다. 턴 끝으로 세면 세 번째 턴 끝에서 먼저 끝나 세 번째 적 공격을 막지 못한다. 턴 시작으로 세면 적 공격 세 번을 막고 끝난다.
- 같은 피해에 다른 가로채기도 걸려 있으면 가로채기 잎의 순서(`order`)가 작은 것부터다(28장 5-4).
- 코드로 쓰려면 4-3의 `StatusCode.Shield`(정수 나눗셈이라 내림).

### 5-4. 3턴 뒤 폭발 — 끝날 때 결과

카드 "시한폭탄": 주인공에게 타이머를 걸고, 세 번째 턴이 끝날 때 모든 적에게 20 피해.

**에디터**(DB › 상태 효과 `bomb`):

1. `maxStacks` `1`, `reapply` `무시`(다시 써도 처음 타이머 그대로).
2. `duration`: `kind` `이벤트 횟수`, `length` `3`, `tickEvent` `턴 끝`.
3. `onExpire`(끝날 때 결과): `대상에게 효과` → 대상 `모든 적` → 효과 `피해`(20).

**카드** `timeBomb`: 결과 `대상에게 효과` → 대상 `사용자 자신` → 효과 `상태 효과 걸기`(`bomb`).

- 세 번째 턴 끝(적 공격 전)에 터진다.
- 끝날 때 결과의 사용자는 가진 쪽(주인공)이다. 그래서 `피해` Block의 출처(`User<Fighter>()`)가 주인공이다.
- 풀면 터지지 않는다. "해체" 카드 = `상태 효과 풀기`(`bomb`).
- 적에게 걸었다면, 그 적이 먼저 쓰러지면 터지지 않는다(끝날 때 결과는 가진 쪽이 있을 때만).
- `reapply`를 `지속 갱신`으로 바꾸면 다시 쓸 때 타이머가 3턴으로 돌아간다.
- 코드로 같은 일을 하려면 예약(5-6)이지만, 기획자가 DB에서 만들고 모니터에서 남은 횟수를 보려면 이 방법이 맞다.

### 5-5. 이번 턴 비용 0 — 상태 효과로

28장 5-6의 "집중"을 상태 효과로 만든다. 켜졌는지 담는 플래그(`freeCost`)·턴 끝에 되돌리는 코드·직접 등록 코드가 모두 필요 없다.

**먼저**: 카드를 내는 행동이 비용을 `Game.Pay`로 내야 가로채기 `비용 지불`을 거친다(가이드 예제의 `PlayCard`는 에너지를 직접 뺀다).

```csharp
// PlayCard.Run: 에너지를 직접 검사하고 빼던 줄을 바꾼다
var data = Rules.CardData(Game, card.card);
Game.Pay(GameIds.PlayerData.Run.Id, "battle.energy", data.cost);   // 가로채기(비용 지불) → 모자라면 실패
```

**에디터**(DB › 상태 효과 `focus`):

1. `maxStacks` `1`, `reapply` `지속 갱신`.
2. `duration`: `kind` `이벤트 횟수`, `length` `1`, `tickEvent` `턴 끝`.
3. `trigger`: `+ 블럭` → `가로채기` → 의도 `비용 지불`. 의도 조건 `filter`에 `필드 검사` → `key` `일치` `run`, `AND` `필드 검사` → `path` `일치` `battle.energy`.
4. `holderField`는 비운다.
5. `outcomes`: `의도 고치기` → 방법 `막기`.

**카드** `concentrate`(집중): 결과 `대상에게 효과` → 대상 `사용자 자신` → 효과 `상태 효과 걸기`(`focus`).

- 턴이 끝나면 지속이 다 되어 저절로 풀린다. Undo하면 함께 돌아간다.
- 가진 쪽 필드를 비운 이유: 위 `Game.Pay`는 내는 쪽(`user`)을 넘기지 않아 의도의 `userId`가 비어 있다. 그래서 이 상태 효과는 주인공에게만 건다. 내는 쪽이 여럿이면(멀티) `Game.Pay(…, user: hero)`로 넘기고 `holderField`(가진 쪽 필드)를 `userId`로 둔다(28장 4-14).
- 상점의 골드 비용(`run › gold`)은 의도 조건에 걸리지 않아 그대로 낸다.
- 버튼 미리보기: `Game.CanPay`는 가로채기 전 값이다. `Game.CanPay(GameIds.PlayerData.Run.Id, "battle.energy", cost) || Game.HasStatus(run.hero, GameIds.Status.Focus)`처럼 화면이 함께 본다.

### 5-6. 코드로 예약 — `ScheduleOn` · `ScheduleAfter`

**다음 턴 시작에 2장 더 뽑기**(카드 `foresight` "예지"의 결과):

```csharp
[BindTo(GameIds.Instance.Foresight)]
static void Foresight(TriggerContext c) =>
    c.Game.ScheduleOn<TurnStarted>(1, new DrawCards { count = 2 }, source: c.Owner);
```

`EndTurn`이 다음 턴의 카드를 뽑고 턴 시작을 쏘는 순간, 그 행동 안에서 `DrawCards`가 한 번 더 돈다. 턴 끝 Undo 한 번에 같이 돌아간다.

**2턴 뒤 그 적에게 15 피해**(카드 `cursedArrow` "저주 화살"의 결과) — 대상이 있는 행동을 맡긴다.

```csharp
[Serializable, BlockInfo("지연 피해")]
public class DelayedHit : GameAction
{
    public Fighter target;      // 맡길 때 id만 남고, 실행 직전에 지금 객체로 다시 찾는다
    public int amount;
    protected override void Run() => Rules.Damage(Game, null, target, amount);
}

[BindTo(GameIds.Instance.CursedArrow)]
static void CursedArrow(TriggerContext c)
{
    foreach (var enemy in c.Picked.OfType<Fighter>())
        c.Game.ScheduleOn<TurnEnded>(2, new DelayedHit { target = enemy, amount = 15 }, source: c.Owner);
}
```

- 그 사이 적이 쓰러졌으면 실행하지 않고 지운다. 타임라인에 "대상이 없어 예약을 실행하지 않았습니다: 지연 피해 (enemy2)".
- 예약은 판 동안 남는다. 전투가 끝나기 전에 횟수가 차지 않으면 다음 전투로 넘어간다(카드 던전은 전투 승리도 턴 끝을 쏜다). 전투마다 끝나야 하면 전투 승리 행동에서 지운다: `Game.CancelSchedules(GameIds.Instance.CursedArrow);`

**실시간이면 게임 시간으로**:

```csharp
Game.ScheduleAfter(2.5, new DelayedHit { target = enemy, amount = 20 }, source: "bomb");   // 2.5초 뒤 프레임 끝
```

일시정지·배속을 따르고, 스냅샷 되감기로 함께 돌아간다. 실행은 행동 하나("예약 실행")라 실패하면 경고만 남고 그 예약은 지워진다.

### 5-7. 카드 1장 버리기 — `Game.Ask` + `[Chosen]`

카드 `survey`(정리): "카드 2장을 뽑고, 손패에서 1장을 버린다."

```csharp
[BindTo(GameIds.Instance.Survey)]
static void Survey(TriggerContext c)
{
    var game = c.Game;
    game.Do(new DrawCards { count = 2 });
    var hand = game.Data().Run.battle.hand;                                           // 덱 카드 id 리스트를 그대로 후보로
    game.Ask("버릴 카드", hand, new DiscardChosen(), min: 1, max: 1, source: c.Owner,
        label: o => Rules.CardData(game, Rules.CardOf(game, (string)o).card)?.title);  // 보일 이름 = 카드 원본의 이름
    // 여기 아래는 고르기 전에 바로 실행된다. 고른 뒤의 일은 DiscardChosen에 쓴다.
}

[Serializable, BlockInfo("고른 카드 버리기")]
public class DiscardChosen : GameAction
{
    [Chosen] public List<DeckCard> cards = new List<DeckCard>();

    protected override void Run()
    {
        var battle = Game.Data().Run.battle ?? throw new InvalidOperationException("전투 중이 아닙니다.");
        foreach (var card in cards)
        {
            battle.hand.Remove(card.id);
            battle.discard.Add(card.id);
        }
    }
}
```

| 단계 | Undo 단위 |
|---|---|
| 정리를 낸다: 에너지 · 카드 2장 뽑기 · 선택 요구(`ChoiceRequested`) | `PlayCard` 하나 |
| 플레이어가 고른다: `Game.Answer(choice.id, card)` → 버리기 | `ChoiceAnswer` 하나 |

- Undo 한 번이면 버리기만 돌아가고 다시 고르기를 기다린다. 한 번 더 Undo하면 정리를 내기 전으로 돌아간다.
- 후보는 id 글자 그대로지만 `[Chosen]`이 `List<DeckCard>`라서 답할 때 덱 카드 객체로 찾아 넣는다. id 그대로 받고 싶으면 `[Chosen] public List<string> cardIds;`.
- `label`을 비우면 후보 이름은 텍스트 표의 `<id>.name`이다. 덱 카드 id(`card3`)에는 이름 키가 없으므로 id가 보인다. 그래서 카드 원본의 이름을 `label`로 준다.
- 손패가 비어 있으면 기다리지 않고 바로 `DiscardChosen`이 돈다(버릴 것 없음).

### 5-8. 보상 3개 중 1개 — DB 원본 ID · 글 선택지

### 5-9. 손패에서 1장 골라 이번 턴 비용 0 — `선택 요구`(DB)

기획자가 DB에서만 조립한다. 프로그래머는 처음 한 번 두 가지를 해 둔다.

**코드(한 번만)** — 대상 Block `손패`와, 카드 비용이 상태 효과 `free`를 보게 하는 한 줄.

```csharp

// PlayCard.Run(5-5의 Game.Pay 줄)
```

**에디터**:

1. DB › 상태 효과 `free`(공짜): `duration` › `kind` `이벤트 횟수`, `length` `1`, `tickEvent` `턴 끝`. 나머지는 비운다(표시만 하는 상태 효과).
2. 카드 `prepare`(준비): 사용 기능 결과 `+ 결과 추가` → `선택 요구`.
   - `prompt` `비용 0으로 만들 카드`
   - `candidates`: `+ 대상 추가` → `손패`
   - `min` `1`, `max` `1`
   - `effects`: `+ 효과 추가` → `상태 효과 걸기`(`free`)
3. 요약: `손패에서 1개 고르기: free 걸기`.

흐름:

1. 준비를 내면 `PlayCard`가 준비를 손패에서 뺀 뒤 사용 기능을 쓴다. 그래서 준비 자신은 후보에 없다.
2. `선택 요구`가 손패의 덱 카드를 후보로 선택을 요구한다. `PlayCard`가 끝난다.
3. 플레이어가 한 장을 고르면 그 덱 카드에 `free`가 걸린다(상태 효과는 id가 있는 객체면 무엇에든 걸린다).
4. 그 카드를 내면 비용 0. 턴이 끝나면 `free`가 저절로 풀린다.

- 시험: 모니터 **명령** 탭의 "선택 대기 · 비용 0으로 만들 카드" 패널에서 고른다. 버튼에는 후보 이름(텍스트 표의 `<id>.name`)이 보이는데, 덱 카드 id에는 이름 키가 없어 `card3`처럼 id가 보인다. 데이터 탭 `$statuses`에서 `target`이 그 id인 `free` 줄을 확인한다.
- 손패가 비어 있으면 기다리지 않는다(효과 없음).
- 같은 조립으로 "손패에서 2장 골라 버리기"(`max` 2, 효과 `버리기` Block), "적 하나를 골라 독"(후보 `모든 적`, 효과 `상태 효과 걸기`(`poison`))도 된다.

### 5-11. 실시간 화상 — 0.5초마다 피해 2, 3초(주기)

실시간 게임(고정 틱, 33장)에서 "불길에 닿으면 3초 동안 0.5초마다 피해 2".

**에디터**(DB › 상태 효과 `scorch`):

1. `maxStacks` `1`, `reapply` `지속 갱신`.
2. `duration`: `kind` `게임 시간(초)`, `length` `3`.
3. `pulse` `0.5`. `trigger`는 비운다.
4. `outcomes`: `대상에게 효과` → 대상 비움(= 가진 쪽) → 효과 `피해`(2).

거는 쪽: 불길에 닿은 것을 화면이 판정해 보낸 행동(판정 보고 행동, 33장)이 `Game.ApplyStatus(enemy, GameIds.Status.Scorch)`를 부르거나, 그 결과 칸에 `상태 효과 걸기`(`scorch`)를 둔다.

| 게임 시각 | 일어나는 일 |
|---|---|
| 0 | 걸림(`StatusApplied`). 다음 주기 0.5 |
| 0.5 · 1.0 · 1.5 · 2.0 · 2.5 · 3.0 | 피해 2(행동 "상태 효과 주기") |
| 3.0 | 끝남(행동 "상태 효과 만료", `StatusEnded` `expired` 참) |

- 모두 6번, 피해 12. 3.0초의 주기는 같은 프레임의 만료보다 먼저 나온다(2-3).
- 1.2초에 다시 닿으면 지속이 갱신되어 끝나는 시각만 4.2로 간다. 주기 시각(1.5, 2.0 …)은 그대로라 간격이 흔들리지 않는다.
- 로딩처럼 프레임이 0.5초보다 길게 멈췄다 오면 밀린 주기를 한 행동에서 최대 8번까지 낸다.
- 게임 시계를 따르므로 일시정지·배속을 따른다. 고르기 창이 게임 시간을 멈추면(35장) 화상도 멈춘다.
- 중첩마다 세지려면 `maxStacks` `0`, `reapply` `중첩 더하고 지속 갱신`, 결과를 `중첩만큼 피해`(5-1의 `StackDamage`)로.
- 재생("1초마다 체력 1, 10초")도 같은 모양이다. "3초 뒤 한 번 폭발"은 주기가 아니라 끝날 때 결과다(5-4 모양에 지속 게임 시간 3).

### 5-12. 쿨다운 3턴 · 쿨다운 −1

"화염구: 쓰면 3턴 동안 다시 쓸 수 없다." "재충전: 화염구의 쿨다운 −1."

**에디터**:

1. DB › 상태 효과 `fireballCd`: `maxStacks` `1`, `reapply` `지속 갱신`, `duration` › `kind` `이벤트 횟수` · `length` `3` · `tickEvent` `턴 끝`, `hidden` 켬. 트리거·결과는 비운다(세기만 하는 상태 효과).
2. DB › 능력 `fireball`:
   - `trigger`: `사용` AND `+ 블럭` → 조건 충족 · 상태 효과 → `상태 효과 검사`(`who` `사용자·가진 쪽`, `status` `fireballCd`, `op` `<=`, `stacks` `0`). 요약 `사용 AND 사용자의 fireballCd <= 0`.
   - `outcomes`: ① `대상에게 효과` → 대상 비움(고른 적) → 효과 `피해`(12) ② `대상에게 효과` → 대상 `사용자 자신` → 효과 `상태 효과 걸기`(`fireballCd`).
   - `failText`: `{ability}은(는) 아직 쓸 수 없습니다.`
3. DB › 능력 `recharge`(재충전): `outcomes` = `대상에게 효과` → `사용자 자신` → `상태 효과 줄이기`(`fireballCd`, `1`). 쿨다운이 여럿이면 줄이기 효과를 하나씩 더한다.

| 순간 | `fireballCd` 남은 횟수 | 화염구 |
|---|---|---|
| 턴 1: 화염구 | 3 | 쓴다 |
| 턴 1 끝 | 2 | 못 쓴다 |
| 턴 2: 재충전 | 1 | 못 쓴다 |
| 턴 2 끝 | 0 → 끝 | — |
| 턴 3 | — | 쓴다 |

- 재충전이 없으면 턴 3 끝에 끝나 턴 4부터 쓴다(3턴 쿨다운).
- 사용 조건이라 `Game.CanUse("fireball", hero, out var why)`가 쿨다운을 알고, `why`가 `failText`다. 버튼은 흐리게 하고 남은 턴을 그린다.

```csharp
var cd = Game.Statuses(hero).FirstOrDefault(s => s.status == GameIds.Status.FireballCd);
fireballButton.SetEnabled(Game.CanUse(GameIds.Ability.Fireball, hero, out _));
cooldownLabel.text = cd == null ? "" : $"{cd.remaining}";        // 이벤트 지속: 남은 횟수
```

- 쿨다운은 사용자마다 따로다(쓴 쪽에 건 상태 효과).
- `hidden`을 켜서 상태 아이콘 줄(5-13)에 나오지 않는다.
- 턴 끝을 받아 도는 결과가 쿨다운을 걸어도(턴 끝에 자동으로 쓰는 반격 스킬) 그 턴 끝은 세지 않는다(2-2). 그래서 늘 같은 3턴이다.
- 실시간이면 `duration`을 `게임 시간(초)`로(예: 5). 남은 초 = `cd.remaining - GBibleRuntime.Session.Clock.Time`. 쿨다운 원은 화면의 `Tick`(35장)에서 그린다. `상태 효과 줄이기` 1 = 1초.
- 쿨다운을 담는 필드(`int fireballCooldown`)도, 턴 끝마다 줄이는 코드도 필요 없다. Undo·판 저장이 그대로 따라온다.

```csharp
        foreach (var s in GBibleRuntime.Game.Statuses(hero))
        {
            if (!_defs.TryGetValue(s.status, out var data) || data.hidden) continue;   // 화면에 숨김(쿨다운 …)
            var icon = new VisualElement();
            icon.style.backgroundImage = new StyleBackground(data.icon);
            icon.Add(new Label(s.stacks > 1 ? s.stacks.ToString() : ""));
            _row.Add(icon);
        }
    }

    void Flash(string holder, string status) { /* 걸린 순간의 반짝임 */ }
}
```

- 라이브러리는 아이콘 줄을 그리지 않는다. `icon`·`hidden`은 이런 화면 코드가 읽는 칸이고, 규칙은 보지 않는다.
- 줄은 데이터(`$statuses`)에서 그린다. `StatusApplied`·`StatusEnded`는 반짝임·소리 같은 연출에만 쓴다. Undo·판 불러오기에는 이벤트가 오지 않으므로 그것으로 줄을 고치면 어긋난다.
- 이름·설명은 텍스트 표의 `<ID>.name`·`<ID>.desc`(23장).

### 5-14. 화상 → 푸른 화상 — 거는 상태 효과 바꾸기

유물 "푸른 불꽃": "화상을 걸면 대신 푸른 화상(5턴)이 걸린다." 유물은 DB › 패시브다(17장 0절).

**에디터**:

1. DB › 상태 효과 `burn`(화상): `kind`(종류) `디버프`, `duration`(지속) › `kind`(방식) `이벤트 횟수` · `length`(길이) `2` · `tickEvent`(셀 이벤트) `턴 끝`. `blueBurn`(푸른 화상): 같은 모양에 `length`(길이) `5`. 피해 결과는 각자 둔다(5-1 모양).
2. DB › 패시브 `blueFlame`: `ownerKey`·`ownerPath`(가진 목록) `run › relics`.
   - `trigger`(발동): `+ 블럭` → `가로채기` → 의도 `상태 효과 걸기`, `filter`(의도 조건) `필드 검사` → `statusId` `일치` `burn`.
   - `outcomes`(결과): `의도 고치기` → `path`(필드) `statusId`, `op`(방법) `값으로 바꾸기`, `value`(값) `blueBurn`.

| 순간 | 의도 | 걸린 것 |
|---|---|---|
| 카드 "불씨": 고블린에게 `상태 효과 걸기`(`burn`) | `statusId` burn → blueBurn, `length` 2 → 5 | 고블린에게 `blueBurn` 5턴 |
| 유물이 없을 때 | 고치지 않음 | 고블린에게 `burn` 2턴 |

- 걸 때 길이를 주지 않았으므로 푸른 화상의 길이 5로 걸린다. 카드의 효과 `상태 효과 걸기`에서 `length`(길이)를 1로 줬다면 푸른 화상도 1턴이다(2-1b).
- 의도 조건이 `statusId`만 보므로 적이 주인공에게 거는 화상도 바뀐다. 적에게 걸 때만이면 `filter`(의도 조건)에 `AND` `targetId` `아님` `hero`를 더한다.
- `StatusApplied`의 `status`는 `blueBurn`이다. 화면의 반짝임·소리도 푸른 화상으로 난다.
- 이미 `blueBurn`이 걸려 있으면 `blueBurn`의 다시 걸 때 규칙을 따른다.

### 5-15. 독 중첩 ×2 · 디버프 지속 +20% · 화상 최대 중첩 +2 — 중첩·길이·최대 중첩 고치기

유물 "사신": "독을 걸 때 중첩 2배." 유물 "모래시계": "디버프의 지속 +20%." 유물 "마그마 구슬": "화상 최대 중첩 +2, 화상 틱 속도 +50%."

**에디터**(DB › 패시브, `ownerKey`·`ownerPath`(가진 목록) `run › relics`. `trigger`(발동)는 `가로채기` → 의도 `상태 효과 걸기`, `outcomes`(결과)는 `의도 고치기`):

| 패시브 | `filter`(의도 조건) | `의도 고치기`의 `path`(필드) · `op`(방법) · `value`(값) |
|---|---|---|
| `reaper` | `statusId` `일치` `poison` | `stacks` · `곱하기` · `2` |
| `hourglass` | `kind` `일치` `디버프` | `length` · `곱하기` · `1.2` |
| `magmaOrb` | `statusId` `일치` `burn` | `maxStacks` · `더하기` · `2`, 그리고 `pulse` · `곱하기` · `0.6667`(결과 둘) |

숫자로 따라가기 — 독(이벤트 횟수 3)을 거는 독침(`poison` 3중첩, 5-1):

| 가진 유물 | 걸리는 중첩 | 남은 횟수 |
|---|---|---|
| 없음 | 3 | 3 |
| 사신 | 6 | 3 |
| 사신 + 모래시계 | 6 | 3 × 1.2 = 3.6 → 4 |

- `stacks`는 정수라 곱한 뒤 반올림한다(28장 3-4). "중첩 +1"이면 `stacks` `더하기` `1`.
- 이벤트 횟수 지속은 길이를 반올림해 쓴다(3.6 → 4). 게임 시간 지속이면 3.6초 그대로다.
- 두 유물은 서로 다른 필드를 고치므로 순서와 상관없이 결과가 같다.
- 영구 상태 효과(분노 5-2)는 길이가 없어 모래시계가 바꾸는 것이 없다.
- 마그마 구슬: 실시간 화상(최대 중첩 3, 주기 0.5초)이 최대 5중첩, 약 0.33초마다가 된다. 최대 중첩·주기는 걸린 것마다 기억하므로, 구슬을 얻기 전에 걸린 화상은 다시 걸릴 때 바뀐다(최대 중첩은 다시 걸 때마다 그때 의도의 값, 2-1b).

### 5-16. 면역 — 걸기 막기

유물 "장화": "주인공은 독에 걸리지 않는다." 상태 효과 "가호": "걸려 있는 동안 디버프에 걸리지 않는다, 2턴."

**에디터**:

1. DB › 패시브 `boots`: `ownerKey`·`ownerPath`(가진 목록) `run › relics`. `trigger`(발동): `가로채기` → `상태 효과 걸기`, `filter`(의도 조건) `statusId` `일치` `poison` `AND` `targetId` `일치` `hero`. `outcomes`(결과): `의도 고치기` → `op`(방법) `막기`.
2. DB › 상태 효과 `ward`(가호): `kind`(종류) `버프`, `duration`(지속) `이벤트 횟수` · `length`(길이) `2` · `tickEvent`(셀 이벤트) `턴 시작`. `trigger`(걸려 있는 동안 트리거): `가로채기` → `상태 효과 걸기`, `filter`(의도 조건) `kind` `일치` `디버프`. `holderField`(가진 쪽 필드) `targetId`. `outcomes`(결과): `의도 고치기` → `막기`.

- 막히면 걸린 것이 없다. `Game.ApplyStatus`는 `null`이고 `StatusApplied`도 오지 않는다. 독침의 피해(4)는 그대로 들어간다. 같은 `대상에게 효과`의 다른 효과는 막지 않는다.
- 이미 걸려 있던 디버프는 그대로다. 가호를 걸 때 함께 풀려면 `onApply`(걸릴 때 결과)에 `대상에게 효과` → 대상 비움 → `상태 효과 풀기`(`kind`(종류 전부) `디버프`)를 둔다(5-17).
- 장화는 의도 조건 `targetId 일치 hero`로 대상을 고정한다. 가진 목록 `run › relics`의 가진 쪽은 `run`(id 없음)이라 가진 쪽 필드를 쓰지 못하기 때문이다(17장 0절). 가호는 상태 효과라 가진 쪽 = 걸린 대상이고, `holderField`(가진 쪽 필드) `targetId`가 "내가 걸릴 때만"을 만든다.
- 가호 자신은 버프라 가호의 가로채기에 막히지 않는다.
- "면역!" 연출이 필요하면 같은 결과 칸에 `이벤트 쏘기`(프로젝트 이벤트)를 더하고 화면이 받는다.

### 5-17. 디버프 정화 · 디버프 개수 — 종류

카드 "정화": "내 디버프를 모두 푼다." 상태 효과 "맑은 물": "턴이 끝날 때 디버프가 2가지 이상이면 모두 푼다, 3턴."

**에디터**:

1. 디버프로 묶을 상태 효과(`poison`·`burn`·`weak` …)의 `kind`(종류)를 `디버프`로 둔다. 분노(`rage`)는 `버프`. 쿨다운(`fireballCd`)·시한폭탄(`bomb`)은 `없음` 그대로.
2. 카드 `purify`: 결과 `대상에게 효과` → 대상 `사용자 자신` → 효과 `상태 효과 풀기`(`status`(상태 효과) 비움, `kind`(종류 전부) `디버프`). 요약 `사용자 자신: 디버프 모두 풀기`.
3. DB › 상태 효과 `clearWater`: `kind`(종류) `버프`, `duration`(지속) `이벤트 횟수` · `length`(길이) `3` · `tickEvent`(셀 이벤트) `턴 끝`.
   - `trigger`(걸려 있는 동안 트리거): `턴 끝 받기` AND `상태 효과 검사`(`who`(누구) `사용자·가진 쪽`, `status`(상태 효과) 비움, `kind`(종류) `디버프`, `op`(비교) `>=`, `stacks`(중첩) `2`). 요약 `턴 끝 받기 AND 사용자의 디버프 >= 2`.
   - `outcomes`(결과): `대상에게 효과` → 대상 비움(= 가진 쪽) → `상태 효과 풀기`(`kind`(종류 전부) `디버프`).

| 주인공에게 걸린 것 | 정화 뒤 |
|---|---|
| 독 3중첩 · 약화 1중첩 · 분노 2중첩 · 쿨다운 | 분노 2중첩 · 쿨다운 |

- 독·약화가 풀리고 `StatusEnded`(`expired` 거짓)가 두 번 온다. 끝날 때 결과는 돌지 않는다.
- 맑은 물의 조건은 가짓수다. 독 5중첩 하나만이면 1가지라 풀지 않는다.
- 쿨다운·시한폭탄은 `없음`이라 풀리지 않는다. 시한폭탄을 디버프로 두면 정화로 해체된다(터지지 않는다, 5-4).
- 코드에서 개수를 쓰려면 `Game.StatusCount`: "디버프 1가지당 피해 +3" = `Rules.Damage(Game, hero, enemy, 5 + 3 * Game.StatusCount(enemy, StatusKind.Debuff));`

### 5-18. 잉크 · 버섯 — 패시브 끄기 · 턴마다 1씩 줄기

와일드프로스트식: "잉크 2: 걸린 유닛의 패시브가 꺼진다. 턴이 끝날 때마다 1 준다." "버섯 3: 턴이 끝날 때 중첩만큼 피해, 그리고 1 준다."

**에디터**(DB › 상태 효과 둘. 둘 다 `kind`(종류) `디버프`, `maxStacks` `0`, `reapply` `중첩 더하기`, `duration` › `kind` `영구(풀 때까지)`):

1. `ink`: `silencesPassives`(걸린 쪽의 패시브를 끔) 켬. `trigger` `턴 끝 받기`. `outcomes` `대상에게 효과` → 대상 비움(= 가진 쪽) → `상태 효과 풀기`(`ink`, `stacks` `1`).
2. `shroom`: `trigger` `턴 끝 받기`. `outcomes` `대상에게 효과` → 대상 비움 → `중첩만큼 피해`(5-1의 `StackDamage`) → `상태 효과 풀기`(`shroom`, `stacks` `1`).

| 순간 | 잉크 중첩 | 유닛의 패시브 | 버섯 중첩 · 피해 |
|---|---|---|---|
| 둘을 건 직후(잉크 2 · 버섯 3) | 2 | 꺼짐 | 3 · — |
| 턴 1 끝 | 1 | 꺼짐 | 2 · 3 |
| 턴 2 끝 | 0 → 풀림 | 다시 켜짐 | 1 · 2 |
| 턴 3 끝 | — | 켜짐 | 0 → 풀림 · 1 |

- 지속(이벤트 횟수)으로 만들지 않는다. 지속의 남은 횟수는 중첩과 따로 세므로, 다시 걸어 중첩이 늘어도 끝나는 턴이 같이 늘지 않는다. "중첩 = 남은 턴"이면 영구 + 풀기 1이다(1절 규칙).
- 효과 안에서 피해가 먼저, 풀기가 다음이다(효과는 위에서부터). 그래서 마지막 턴에도 1 피해가 들어간다.
- 잉크가 끄는 것은 그 유닛이 가진 패시브다. 유닛의 능력(카운터가 차서 쓰는 공격)까지 막는 "얼음(Snow)"은 트리거가 둘(가로채기 `사용` + `막기`, 그리고 턴 끝 풀기 1)이라 상태 효과 하나로 안 된다. 막는 쪽 `snow`(가로채기 `사용`, `holderField`(가진 쪽 필드) `userId`, 결과 `막기`)와 줄이는 쪽 `snowTick`(숨김, 턴 끝에 `snow`·`snowTick` 1씩 풀기)을 함께 건다. 막기를 능력의 사용 조건 `상태 효과 검사`(`snow` `<=` `0`)로 두면 `snow` 하나(잉크 모양)로 된다.

## 6. 주의할 점 · 자주 하는 실수

| 증상 | 원인과 해결 |
|---|---|
| 독이 마지막 턴에도 피해를 줌(또는 한 번 덜 줄 거라 생각함) | 같은 이벤트가 결과와 횟수 줄이기를 둘 다 하면 결과가 먼저다. "피해 1, 3턴" = 피해 세 번 뒤 끝(2-2). |
| 보호막이 세 번째 적 공격을 못 막음 | 카드 던전의 `EndTurn`은 턴 끝을 쏜 다음에 적이 공격한다. 셀 이벤트를 턴 시작으로 둔다(5-3). |
| 다른 적이 맞을 때도 보호막이 발동 | 가진 쪽 필드가 비어 있다. 피해 의도의 `targetId`를 고른다. |
| 결과를 넣었는데 돌지 않음 / 검증 경고 "걸려 있는 동안 트리거도 주기도 없어 결과가 돌지 않습니다." | 결과는 트리거나 주기와 짝이다. 결과만 있고 트리거·주기가 없거나, 그 반대다. 능력치 보정만 하는 상태 효과·쿨다운은 셋 다 비운다. |
| 턴 끝에 건 "2턴"이 그 턴 끝을 세지 않음 | 그 이벤트를 받는 도중에 새로 건 것은 그 이벤트를 세지 않는다. 다음 턴 끝부터 두 번이다(2-2). |
| 끝날 때 결과에서 중첩·보정을 읽었더니 0 | 끝날 때 결과는 걸린 것을 지우고 보정을 뗀 뒤에 돈다(2-2). 중첩에 따른 계산은 걸려 있는 동안의 결과에서 한다. |
| 주기 결과가 돌지 않음 | `pulse`가 0이거나 `outcomes`가 비었다(검증 경고). 게임 시간이 멈춰 있다(일시정지·고르는 동안 시간 멈춤). 시간 지속이 이미 끝났다. |
| 주기 결과가 0.5초 간격이 아니라 몰려서 나옴 | 프레임이 길었다. 밀린 주기를 한 행동에서 낸다(최대 8번, 2-3). |
| `상태 효과 줄이기`가 아무 일도 안 함 / `ShortenStatus`가 `false` | 영구 상태 효과이거나 그 대상에 걸려 있지 않다. 이벤트 횟수는 줄일 양을 반올림한다(0.4 → 0). |
| 쿨다운이 상태 아이콘 줄에 보임 | `hidden`을 켜고, 화면 코드가 `hidden`을 보고 건너뛴다(5-13). 라이브러리는 아이콘 줄을 그리지 않는다. |
| 다시 걸었는데 `StatusApplied`가 안 옴 | `reapply`가 `무시`다. 아무것도 바뀌지 않아 쏘지 않는다(2-8). 또는 가로채기가 막았다. |
